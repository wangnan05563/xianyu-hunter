> 任务：T01719 ｜ 日期：2026-10-10 ｜ 调研方式：公开网络资料（GitHub README / 评测站 / 社区文章）
> 对象：xianyu-hunter（闲鱼猎人 · 智能监控 · 自动抢单桌面端）

---

## 一、竞品概览

| 项目 | Stars | 定位 | 技术栈 | 形态 | 活跃度 |
|---|---|---|---|---|---|
| **Usagi-org/ai-goofish-monitor** | ~12-13k ⭐ | 闲鱼多任务实时/定时监控 + AI 智能筛选（买家侧捡漏） | Python + Playwright + Vue/shadcn-vue + SQLite | Docker / Web UI（自托管） | 高（2026-10 仍在提交） |
| **shaxiu/XianyuAutoAgent** | ~7.3k ⭐ | AI 客服机器人：自动回复、智能议价、多专家协同（卖家侧） | Python + LLM Agent | Docker / CLI | 高 |
| **zhinianboke/xianyu-auto-reply** | 1k+ ⭐ | 多账号闲鱼店铺管理：自动回复/发货/评价/订单拉取（卖家侧） | Python + Web 后台 | Docker / Web UI | 高 |
| **lubei0612/xianyu-monitor-extension** | 小型 | Chrome 扩展：页面内监控 + 自动抢拍 + 卖家识别 | JS / Manifest V3 | 浏览器扩展 | 中 |

**与 xianyu-hunter 的关系**：市面头部项目要么只做「监控+推送」（ai-goofish-monitor），要么只做「客服/卖家运营」（AutoAgent、auto-reply）。**监控 + 评估 + 自动抢单 + 客服 + 运维面板的一体化桌面产品目前只有 xianyu-hunter**——这是核心差异化，不必也不应照抄单项竞品的架构（如 Docker/Web 自托管优先）。

## 四、不建议跟进（差异化判断）

1. **照搬 ai-goofish-monitor 的 Docker/Web 优先架构**——hunter 的桌面端（托盘、本地数据、离线可用）是定位差异，部署形态做第二形态（F8）而非主形态切换；
2. **Chrome 扩展监控形态**——与桌面端功能重叠，且受 Manifest V3 限制多，投入产出低；
3. **卖家侧全面店铺管理**（批量上架/订单拉取）——与「买家侧智能抢单」定位冲突，仅保留客服议价（F4）这类与评估体系协同的能力；
4. **多平台扩展（转转等）**——当前反爬/评估/抢单链路全部深度绑定闲鱼，过早抽象会拖慢主线。

---

## 五、建议落地顺序（P0 四件套）

1. **C1 登录态统一诊断 + 自愈**（可信度地基，直接消化 T01717 系列痛点）
2. **F1 价格历史曲线 + 降价提醒**（监控类产品核心心智）
3. **C3 抢单演练测试模式**（自动抢单的安全阀）
4. **C2+F2 登录态多通道导入**（降低使用门槛，摆脱扫码单一依赖）

四项完成后，产品在「一体化桌面端」定位内即全面覆盖三个头部竞品的核心心智，且保留独有差异化。
