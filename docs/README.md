## 文档体系说明

本文档集采用**菜单驱动**的组织结构，与系统前端菜单一一对应，便于快速定位相关设计文档。每个功能域通常包含三档文档：

- **需求规格**（SRS）：业务需求、用户场景、功能范围
- **详细设计**（DDD）：接口定义、数据结构、状态机、业务逻辑
- **操作手册**：面向使用者的操作指引

**核心原则**：
- 每个菜单对应一个独立文件夹（`00-待完成` … `08-移动端`）
- 横向规范统一归入 `standards/`
- 需求分析补充文档与 PRD 归入 `requirements/`
- 历史迭代、废弃方案归入 `archive/`

## 文档维护规范

### 新增文档流程

1. **确定归属菜单**：根据功能对应的菜单项选择 `00-…08-` 文件夹
2. **命名规范**：`{功能名称}-{文档类型}.md`（如 `智能客服-概要设计.md`）；日期前缀 `YYYY-MM-DD-{功能}-{类型}.md`
3. **三档齐备**：功能文档建议包含 需求规格 / 详细设计 / 操作手册
4. **更新索引**：在本 README 对应菜单章节添加链接，保持引用准确性

### 文档类型标识

| 类型 | 说明 | 命名示例 |
|------|------|----------|
| 需求规格 | SRS | `{功能}-需求规格.md` |
| 概要设计 | SDD | `{功能}-概要设计.md` |
| 详细设计 | DDD | `{功能}-详细设计.md` |
| 操作手册 | 使用指引 | `{功能}-操作手册.md` |

| 迭代记录 | Sprint 交付 | `archive/冲刺历史记录.md` |

### 版本管理

- 文档内部使用 `版本：vX.Y` 标识
