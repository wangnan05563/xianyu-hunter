## 文档体系说明

本文档集采用**菜单驱动**的组织结构，与系统前端菜单一一对应，便于快速定位相关设计文档。

**核心原则**：
- 每个菜单对应一个独立文件夹
- 需求规格说明书作为独立分册
- 视觉规范、部署指南等横切文档单独归档
- 迭代历史记录统一归档

## 文档维护规范

### 新增文档流程

1. **确定归属菜单**：根据功能对应的菜单项选择文件夹
2. **命名规范**：`{功能名称}-{文档类型}.md`（如 `智能客服-概要设计.md`），日期前缀格式 `YYYY-MM-DD-{功能名称}-{文档类型}.md`（如 `2026-06-25-浏览器Cookie导入增强-设计.md`）
3. **更新索引**：在本 README 的对应菜单章节添加链接
4. **交叉引用**：在相关文档中添加双向链接

### 文档类型标识

| 类型 | 说明 | 命名示例 |
|------|------|----------|
| 需求规格 | SRS（Software Requirements Specification） | `{功能名称}-需求规格.md` |
| 概要设计 | SDD（Software Design Description） | `{功能名称}-概要设计.md` |
| 详细设计 | DDD（Detailed Design Document） | `{功能名称}-详细设计.md` |
| 实施计划 | 任务拆分、里程碑 | `{功能名称}-实施计划.md` |
| 评审报告 | 需求/设计评审结论 | `{功能名称}-评审报告.md` |
| 迭代记录 | Sprint 交付报告 | `sprint-{名称}-YYYY-MM-DD.md` |

### 版本管理

- 文档内部使用 `文档版本：vX.Y` 标识
- 重大变更需更新修订记录表
- 废弃文档移入 `archive/` 而非删除

## 详细设计文档编写规范

每个菜单功能的详细设计文档均包含以下 9 个章节，同时服务于开发团队和智能客服系统：

1. **文档元信息**：版本、日期、所属菜单、关联路由
2. **功能概述**：一句话说明 + 核心价值
3. **用户场景**：2-3 个典型使用场景
4. **页面布局与交互**：组件结构、关键交互说明
5. **接口定义**：API 路由表（方法/路径/请求参数/响应字段）
6. **数据结构**：数据库表字段说明、Pydantic 模型
7. **业务逻辑**：核心算法、状态机、校验规则
8. **关键代码位置**：文件路径 + 行号
9. **常见问题 FAQ**：5-10 个问答对（用于智能客服向量检索）

**双用途设计要点**：
- 开发指导：完整的 API 表、数据表字段、状态机图、算法说明、文件路径定位
- 向量检索：FAQ 问答对格式、关键词密集（阈值、状态值、超时时间等）、语义匹配友好
