# 项目目录结构规范

本文档定义闲鱼猎人项目的目录组织规范，指导团队成员正确存放文件。

## 一、目录结构总览

```
17_xianyu/
├── backend/xianyu_hunter/   # Python 后端源码（主包，不可移动）
├── frontend/            # React 前端源码（不可移动）
├── config/              # 配置文件（不可移动，代码硬编码引用）
├── tests/               # 测代码（不可移动，pyproject.toml 配置）
├── scripts/             # 启动/构建/部署脚本
├── docs/                # 项目文档
├── data/                # 运行时数据（gitignore）
├── browser-data/        # 浏览器用户数据（gitignore）
├── logs/                # 启动脚本日志/PID（gitignore）
├── assets/              # 静态资源（图标等）
├── _skill_optim/        # 技能优化规则文档
├── .env / .env.example  # 环境变量
├── 静默启动.vbs          # 根目录快捷启动入口
├── pyproject.toml       # Python 项目配置
├── requirements.txt     # Python 依赖锁定
├── requirements-lock.txt # 完整依赖版本锁定
├── Dockerfile           # Docker 镜像构建
├── docker-compose.yml   # Docker Compose 部署
├── sonar-project.properties # SonarQube 扫描配置
├── installer.iss        # Inno Setup 安装包脚本
├── check_status.ps1     # 状态检查脚本
└── README.md / CHANGELOG.md / VERSIONING.md
```

## 二、各目录用途与规则

### 2.1 `backend/xianyu_hunter/` — 后端源码

Python 主包，通过 `pyproject.toml` 的 `[tool.setuptools.packages.find]` 发现。

| 子目录                  | 用途                                                                          | 命名规范                           |
| -------------------- | --------------------------------------------------------------------------- | ------------------------------ |
| `domain/`            | 领域模型（纯数据类，无副作用）                                                             | `snake_case.py`                |
| `infra/`             | 基础设施（DB、浏览器、日志、密钥、仓储）                                                       | `snake_case.py`，仓储以 `repo_` 前缀 |
| `modules/`           | 业务模块（采集器、通知器、买家、评估器、聊天机器人等）                                                 | `snake_case.py`                |
| `modules/chatbot/`   | 智能客服子模块（含 `security/`、`tools/`、`rag_engine.py` 等）                           | `snake_case.py`                |
| `modules/collector/` | 商品采集器子模块（`_base.py` / `_detail.py` / `_parser.py` / `_search.py`）           | `_` 前缀为内部模块                    |
| `modules/notifier/`  | 通知器子模块（按渠道拆分：bark/dingtalk/serverchan/telegram/wecom/webhook/ntfy/pushplus） | `snake_case.py`                |
| `web/routes/`        | FastAPI 路由（`api_*.py` + 子模块）                                                | `api_*.py`                     |
| `web/middleware/`    | Web 中间件（认证、错误捕获、异常处理、请求 ID）                                                 | `snake_case.py`                |
| `web/app.py`         | FastAPI 应用入口                                                                | -                              |
| `web/deps.py`        | 依赖注入                                                                        | -                              |
| `paths.py`           | 路径集中管理（支持 PyInstaller 打包模式）                                                 | -                              |
| `config.py`          | 全局配置（pydantic-settings）                                                     | -                              |
| `container.py`       | 依赖容器                                                                        | -                              |
| `_build_info.py`     | 构建信息                                                                        | -                              |
| `__main__.py`        | CLI 入口（typer）                                                               | -                              |

**规则：**

- 不可移动此目录，代码中 `import xianyu_hunter` 依赖此路径
- 新增模块按职责归入 `domain/`、`infra/`、`modules/`、`web/` 之一
- 目录嵌套不超过 4 层
- 路径访问统一通过 `paths.py` 的 `get_data_dir()` / `get_config_dir()` / `get_log_dir()` 等函数，**禁止**直接 `Path("data")` 硬编码（PyInstaller 打包模式需要切换到 `%APPDATA%`）

### 2.2 `frontend/` — 前端源码

React 18 + TypeScript + Vite + Ant Design + Zustand 项目。

| 子目录               | 用途                                                                                                             |
| ----------------- | -------------------------------------------------------------------------------------------------------------- |
| `src/api/`        | API 客户端（按业务模块拆分：`task.ts` / `order.ts` / `auth.ts` / `chatbot.ts` 等）                                           |
| `src/components/` | 通用组件（按类型分子目录：`charts/` / `editors/` / `icons/` / `layout/` / `SheetWorkspace/` / `TidalForagers/`）             |
| `src/pages/`      | 页面组件（按业务模块分子目录：`Dashboard/` / `Tasks/` / `Orders/` / `Config/` / `Chatbot/` / `AntiCrawl/` / `Maintenance/` 等） |
| `src/stores/`     | Zustand 状态管理（`configStore.ts` / `sheetStore.ts`）                                                               |
| `src/hooks/`      | 自定义 Hooks（`useAutoLiveSearch.ts` / `usePersistentState.ts` / `useSheetSync.ts` 等）                              |
| `src/constants/`  | 常量定义（`eventTypes.ts` / `orderStatus.ts` / `statusColors.ts` 等）                                                 |
| `src/contexts/`   | React Context（`ThemeContext.tsx`）                                                                              |
| `src/mobile/`     | 移动端专属组件（`components/` / `hooks/` / `layout/` / `pages/` / `styles/`）                                           |
| `src/utils/`      | 共享工具（`apiError.ts` / `storage.ts` / `lazyRetry.tsx`）                                                           |

**规则：**

- 构建产物输出到 `backend/xianyu_hunter/web/static/spa/`（由 `vite.config.ts` 的 `build.outDir` 配置）
- SPA 挂载路径为 `/xianyu/`（`vite.config.ts` 的 `base: '/xianyu/'`）
- 不可移动此目录，`scripts/前端构建.bat` 依赖此路径
- 开发模式：`npm run dev` 启动 Vite，端口 5173，API 自动代理到 `http://127.0.0.1:8001`
- PWA 已启用（`vite-plugin-pwa`），断网时可访问缓存

### 2.3 `config/` — 配置文件

YAML 配置文件目录，代码中通过 `paths.get_config_dir()` 统一访问。

| 文件                    | 用途                                     |
| --------------------- | -------------------------------------- |
| `config.yaml`         | 主配置（运行时可被 Web UI 修改，首次部署需从 example 复制） |
| `eval.yaml`           | 卖家评估配置                                 |
| `config.example.yaml` | 主配置模板（供新部署参考）                          |
| `eval.example.yaml`   | 评估配置模板                                 |
| `menu_registry.yaml`  | 菜单注册表（前端菜单结构配置）                        |
| `backups/`            | 配置自动备份（gitignore，保留 10 个）              |

**规则：**

- 不可移动此目录，`yaml_config.py` 和 `api_config.py` 引用此路径
- 新增配置文件需同步提供 `.example.yaml` 模板
- 敏感字段（推送 Key、AI Key、Token）通过 `.env` 或 keyring 配置，不写入 YAML

### 2.4 `tests/` — 测试代码

| 文件模式          | 用途                |
| ------------- | ----------------- |
| `test_*.py`   | 单元测试 / 集成测试       |
| `test_e2e.py` | 端到端测试             |
| `conftest.py` | pytest 公共 fixture |

**规则：**

- 不可移动此目录，`pyproject.toml` 的 `testpaths = ["tests"]` 配置
- 测试文件命名：`test_<被测模块名>.py`
- 运行：`$env:PYTHONPATH = "backend"; python -m pytest tests/ -v`
- 异步测试模式：`asyncio_mode = "auto"`（pyproject.toml 配置）

| 文件                    | 用途                 |
| --------------------- | ------------------ |

**规则：**

- 与 `data/logs/` 不同：此目录存放启动脚本相关文件

### 2.10 `assets/` — 静态资源

## 四、版本控制规则

### 4.1 纳入版本控制

- 所有源码（`backend/`、`frontend/src/`）
- 测试代码（`tests/`）
- 配置模板（`*.example.yaml`、`.env.example`）
- 文档（`docs/`）
- 脚本（`scripts/`）
- 项目配置（`pyproject.toml`、`Dockerfile`、`docker-compose.yml`、`sonar-project.properties`、`installer.iss` 等）
- `data/.gitkeep`（占位）

### 4.2 排除版本控制

- 运行时数据（`data/`、`browser-data/`、`logs/`）
- 数据库文件（`*.db`、`*.db-*`）
- 日志文件（`*.log`、`*.out`、`*.err`）
- 敏感配置（`.env`）
- 依赖目录（`.venv/`、`node_modules/`）
- 构建产物（`backend/xianyu_hunter/web/static/spa/`）
- 配置备份（`config/backups/`）
- IDE 配置（`.idea/`、`.vscode/`）
- 临时调试产物（`.tmp_*` / `test_*.py` 根目录 / `_*.log` 等）

## 五、目录变更流程

1. **评估影响**：检查代码中是否有硬编码路径引用（应通过 `paths.py` 统一访问）
2. **更新引用**：修改所有引用旧路径的代码
3. **更新配置**：修改 `pyproject.toml`、`vite.config.ts`、`Dockerfile` 等
4. **运行测试**：`python -m pytest tests/ -v` 确保全部通过
5. **更新文档**：同步更新本规范和 README

## 六、文件分类判断标准

本节明确"什么样的文件该放在哪里"，作为添加新文件时的判定依据。

### 6.1 根目录仅允许以下文件

| 类别    | 文件                                                                                                                                                   | 说明                                      |
| ----- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------- |
| 工具配置  | `.gitignore` / `.dockerignore` / `.env.example` / `.pre-commit-config.yaml`                                                                          | 工具链相关                                   |
| 构建/依赖 | `Dockerfile` / `docker-compose.yml` / `pyproject.toml` / `requirements.txt` / `requirements-lock.txt` / `installer.iss` / `sonar-project.properties` | 项目构建                                    |
| 元文档   | `README.md` / `CHANGELOG.md` / `VERSIONING.md`                                                                                                       | 仓库根级文档                                  |
| 启动入口  | `静默启动.vbs`                                                                                                                                           | **唯一**根目录脚本，作为包装器跳转至 `scripts/静默启动.vbs` |
| 状态检查  | `check_status.ps1`                                                                                                                                   | 一次性状态检查脚本                               |

### 6.2 脚本类文件（必须放 `scripts/`）

凡是 `.py` / `.sh` / `.js` / `.ps1` / `.bat` / `.vbs` 后缀的可执行脚本，  
**必须** 位于 `scripts/` 下。命名风格：

- **Python 工具脚本**：`snake_case.py`（如 `auth_helper.py`）
- **Shell / 批处理**：中文命名更友好（如 `启动服务.bat`），便于双击启动
- **PowerShell**：`snake_case.ps1`（如 `setup-env.ps1`）
- **VBS 启动器**：`静默启动.vbs`（被根目录包装器调用）

子目录：

- `scripts/tests/`：用于 `scripts/` 下脚本的单元/集成测试（镜像 pytest 模式）

### 6.6 重定向误产物（必须拦截）

PowerShell 中 `command > filename` 会创建 `filename` 文件。常见误用：

```powershell
Get-Help less > 17_xianyu    # ❌ 创建了 less 帮助文本的垃圾文件
```

已在 `.gitignore` + `.pre-commit-config.yaml` 拦截：

```
/0
/17_xianyu
/17_xianyufrontend
/_r.json
/.tmp_diff.txt
/.s3358_lines.txt
/*.txtcd      # 异常命名后缀（如 test_result_*.txtcd 是错误输入）
```

### 6.7 添加新文件时的检查清单

在 `git add` 之前自检：

- [ ] 该文件是否应放根目录？（仅配置/构建/元文档/启动入口/状态检查）
- [ ] 若是脚本，是否放在 `scripts/`？
- [ ] 若是运行时数据，是否已被 `.gitignore` 覆盖？
- [ ] 若是日志，是否输出到 `data/logs/` 或 `logs/`？
- [ ] 是否运行了 `pre-commit run --all-files`？
- [ ] 是否避开了常见的命名陷阱（如 `0`、`17_xianyu`、`_r.json`）？

## 七、工作空间清理记录

> 本节记录历次基于 `workspace-cleanup` skill 的开发工作空间清理（与应用内「系统维护 → 系统清理」的运行时清理不同，后者面向浏览器缓存/数据库/日志，前者面向开发产物）。

### 2026-07-23 第七轮清理

**背景**：长期开发迭代后，根目录累积大量测试输出日志、SonarQube 调试产物、构建产物与缓存目录，占用约 3.12 GB 磁盘空间。
