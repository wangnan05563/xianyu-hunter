```python
def extract_brand(raw: dict | None, title: str = "", seller_candidate: str = "") -> str:
    brand_keys = {
        "brand", "brandname", "brandtext", "brandtitle", "brandvalue",
        "branddesc", "manufacturer", "maker",
    }
    raw_brand = _find_first_text_by_keys(raw or {}, brand_keys)  # ← raw=None 时跳过
    if raw_brand and raw_brand not in {"其他", "其它", "other", "OTHER"}:
        raw_brand = raw_brand.strip()
        if not title or _brand_candidate_matches_title(raw_brand, title):
            return raw_brand

    if _brand_candidate_matches_title(seller_candidate, title):
        return seller_candidate.strip()

    return infer_brand_from_title(title)  # ← 从标题推断
```

```python
def infer_brand_from_title(title: str) -> str:
```

```python
def normalize_display_brand(brand, title="", seller_candidate="") -> str:
    brand = str(brand or "").strip()
    title = str(title or "").strip()
    seller_candidate = str(seller_candidate or "").strip()

    if brand and (not title or _brand_candidate_matches_title(brand, title)):
        return brand
    if _brand_candidate_matches_title(seller_candidate, title):
        return seller_candidate
    inferred = infer_brand_from_title(title)

    return "" if title else brand  # ← 标题有值但 brand 无法被标题解释时返回空字符串
```

| 字段 | items 表有列 | refresh_item new_row 包含 | task_links.display 处理 | 详情页 detail 对象 |

## 4. 可疑点汇总

### 可疑点 1：items 表无 brand 列（架构性问题）

## 5. 综合结论

**brand 字段无法正常更新的根因**（按影响排序）：

1. **(架构性) items 表无 brand 列**：brand 只能存于 task_links.display JSON 中，但 `_enrich_eval_with_item` 仍尝试从 items 表读取，造成代码冗余。

2. **(覆盖式清空) `merge_item_display_from_detail` 强制覆盖 brand**：即使 detail.brand 为空字符串也会写入 task_links.display，**清空原本可能正确的旧 brand**。这是与 title/price/thumb_url 处理方式的关键差异。

5. **(无 DOM 提取) 详情页未实现 brand 元素的 DOM 选择器提取**：闲鱼详情页实际有品牌信息（如 "Lenovo/联想"），但代码注释直接放弃 DOM 提取，依赖标题推断兜底。

## Phase 4 完成总结

### 根因定位

评估明细列表显示金额 888 未覆盖旧快照 905 的根因在 [api_evaluations.py](file:///d:/code/otherProjects/17_xianyu/backend/xianyu_hunter/web/routes/api_evaluations.py#L234-L273) 的 `_enrich_eval_with_item` 函数：

- **数据语义冲突**：eval 事件 payload 中的 `item_price=905` 是评估时刻的**历史快照**；items 表 / task_links.display 中的 `price=888` 是 refresh_item 采集到的**最新值**
- **旧策略缺陷**：原代码对所有商品基础信息字段采用 `if payload.get("xxx") is None:` "仅缺失时填充"策略，payload 已有旧快照（905）就不会被最新值（888）覆盖

### 修复方案

对"会变动的商品基础信息"字段统一改为"有最新值则覆盖"：

| 字段 | 策略 | 说明 |
|------|------|------|
| `item_title` / `thumb_url` / `region` / `brand` / `seller_id` / `publish_time` | 非空则覆盖 | 商品基础信息会变动 |
| `item_price` / `want_cnt` / `view_cnt` | `> 0` 才覆盖 | 0 可能是采集失败，不应覆盖有效旧值 |
| `is_sold` | 总是覆盖 | 已售状态会变化（在售→已售） |

- 第 1351-1461 行：从 `task_links` 生成评估时，直接构造 `ItemDetail` 调用 `evaluator.evaluate`，**没有 PriceStrategy.check 过滤**
- 第 1498-1570 行：从已有 eval 事件重算时，同样无价格过滤

**线索 3：batch_evaluate_unevaluated 接口绕过价格过滤**
- 位置：api_evaluations.py:1582-1723
- 第 1649-1714 行：从 items 表批量评估未评估商品时，直接 `evaluator.evaluate`，**没有 PriceStrategy.check 过滤**

**线索 4：_collect_official_and_evaluate 绕过价格过滤**
- 位置：api_evaluations.py:1909-2273
- 用户在评估明细页点击"官方采集"时，直接采集+评估+写入 eval.scored 事件，**没有 PriceStrategy.check 过滤**

**线索 5：list_evaluations 不查询 task 配置**
- list_evaluations 函数中没有任何 `container.repo.get_task(task_id)` 调用
- 即使 eval 事件中混入了违反任务价格范围的商品，API 也无法二次过滤

**线索 6：任务价格范围变更后无回溯机制**
- 用户修改任务的 min_price/max_price 后，已写入的 eval.scored 事件不会被回溯过滤
- list_evaluations 仍会展示所有历史评估，包括现在已不符合新价格范围的商品

**线索 7：price_config JSON 覆盖与 min_price/max_price 列并存**
- db_models.py:51-52 有独立的 `min_price`/`max_price` 列
- db_models.py:75 又有 `price_config` JSON 字段（可包含 min_price/max_price）

**评估明细 API（list_evaluations）当前完全不支持按价格范围过滤**，既没有 `min_price`/`max_price` 查询参数，也没有调用 task 表的价格范围配置做隐式过滤。任务表的 `min_price`/`max_price`/`price_config` 字段仅在 TaskWorker 搜索流水线中通过 `PriceStrategy.check` 生效，且仅对"搜索新发现"的商品过滤；通过 recompute、batch-evaluate、官方采集三条路径写入的评估事件均绕过价格过滤，导致评估明细 API 中可能出现违反任务价格范围的商品记录。

```python

market_ctx = self._compute_market_context(new_items)

def _compute_market_context(self, items: list) -> MarketContext | None:
    """从当前批次的商品中估算市场参考价（中位数 + 全量价格列表）"""
    prices = [i.price for i in items if getattr(i, "price", None) is not None]
    if len(prices) < 3:
        return None                        # 不足 3 个样本返回 None
    prices.sort()
    n = len(prices)
    median = prices[n // 2] if n % 2 == 1 else (prices[n // 2 - 1] + prices[n // 2]) / 2
    return MarketContext(median_price=median, sample_size=n, all_prices=prices)
```

## 6. 关键发现与改造提示

1. **三条写入路径一致缺少 price.check 门禁**：recompute（1395/1551）、batch（1676）、official（2189 dead code / 1921 通过 ItemCollectionService 间接）均未调用 `price.check()`，与 worker.py:403 的标准流程不一致。如需补门禁，可在每条路径 `evaluator.evaluate(detail, seller)` 调用前插入 `price.check(detail, market_ctx)` 判定，不通过则跳过评估写入。

3. **PriceStrategy 实例可从 container 直接获取**：`container.price_strategy` 是全局实例（基于 `market_ratio=0.8` 硬编码构造，不读 `cfg.price_strategy`）。若需任务级覆盖，需调用 `container.build_worker_from_raw_task(raw)` 或自行合并 `task.min_price/max_price/price_config`。

5. **_collect_official_and_evaluate 中存在 dead code**：L1936 `return` 之后的 L1971-2273 全部不可达，但其中 L2189 的 `evaluator.evaluate` 调用模式是预期的"参考实现"。若后续要修复 dead code 或切换到直接评估路径，需先确认 L1936 的早 return 是否有意为之。
