# 闲鱼低价二手自动捡漏与抢单系统 - 需求规格说明书

> 项目代号：**XianyuHunter**
> 文档版本：v2.0
> 编写日期：2026-06-30
> 适用读者：产品、开发、测试、用户本人

---

## 1. 项目背景与目标

### 1.1 背景
闲鱼（goofish.com）是阿里旗下最大的二手闲置交易平台，C2C 模式下买家需要与卖家私聊议价后下单。热门二手商品（如 3C 数码、潮玩、演出票、球鞋等）存在"上线即被秒"的现象，手动刷新效率极低；同时市场上充斥职业卖家与翻新机，普通买家难以辨别。

本系统为个人买家提供"7×24 监控 + 卖家画像评估 + 第一时间抢单 + 即时通知"的全流程辅助工具，提升在闲鱼上抢到优质二手低价商品的概率与效率。

### 1.2 核心目标
| 目标编号 | 描述 | 可衡量指标 |
|---|---|---|
| G1 | 自动发现符合"低价"定义的商品 | 从上架到发现延迟 < 60s |
| G2 | 自动评估卖家是否为"非职业 + 信誉良好" | 4 维评分模型覆盖职业/信用/纠纷/价格异常 |
| G3 | 第一时间抢下单 | 从发现符合条件到提交订单 < 10s（全自动模式） |
| G4 | 下单后即时通知 | 微信推送到达延迟 < 30s |

### 1.3 非目标
- 不做商品发布、自动擦亮、自动回复买家咨询（卖家侧功能）
- 不做支付环节的自动化（拍下后由用户人工支付，避免资金安全风险）
- 不做多账号 / 多租户 SaaS
- 不做交易后客服、追评、退款等售后服务

## 2. 范围与约束

### 2.1 范围内（In-Scope）
- 闲鱼 Web 端（https://www.goofish.com）商品搜索与详情访问
- 卖家主页、卖家历史发布、历史交易、评价的查看
- 单账号下"我想要 / 私聊 / 拍下"的页面操作
- 微信推送通知（Server酱 / PushPlus / Bark 三选一）
- 本地 SQLite 存储任务配置、采集数据、运行日志

### 2.2 范围外（Out-of-Scope）
- 闲鱼 App 端原生操作（首版仅 Web）
- 支付宝 / 银行卡支付环节
- 同行比价、跨平台监控（仅闲鱼单平台）
- 多账号、账号池、IP 池等规模化运营能力
- 反向工程闲鱼 App 协议 / 客户端 Hook

### 2.3 关键约束
| 约束类别 | 说明 |
|---|---|
| 部署形态 | 单台 Windows 10 本地电脑（用户系统） |
| 运行时间 | 个人使用，7×24 长跑可用，但允许断电/休眠 |
| 合规边界 | 仅做"个人辅助"使用，遵守闲鱼用户协议，不做大规模数据爬取或商业转售 |
| 账号安全 | 必须保证单 IP 单账号，禁止多账号同 IP 登录 |
| 通知渠道 | 微信推送（Server酱 / PushPlus / Bark） |
| 浏览器 | Chromium（Playwright 内置）持久化用户数据目录 |

## 3. 用户与场景

### 3.1 目标用户
一名"懂技术、对二手商品有研究、希望提高捡漏效率"的中文个人买家。具备：
- 能在 Windows 上运行 Python / Node 脚本
- 能在服务器推送服务上配置一个推送 Key
- 能理解"非职业卖家""黑名单"等概念

### 3.2 典型使用场景

**场景 A：3C 捡漏**
> 用户配置 1 个任务"索尼 A7M4，预算 1.2w 以内，95 新以上，上海本地优先"。
> 系统持续监控闲鱼搜索结果，对每个新商品：
> 1. 价格 < 1.2w 才进入卖家评估
> 2. 卖家在售数量 < 10 件、芝麻信用 > 650、无差评
> 3. 评估通过 → 微信推送"发现目标商品，含卖家截图"
> 4. 用户在推送中点链接确认 → 系统自动"拍下"（不支付）
> 5. 推送"已拍下，请打开闲鱼 App 5 分钟内支付"

**场景 B：演出门票捡漏**
> 用户配置"周杰伦演唱会门票，预算 2000 以内，北京 8 月 1 日场"。
> 系统每 30 秒扫一次"演出 / 票务"分类新发布。
> 模式切到"全自动直接拍下"（票务时效性强）。
> 推送内容包含场次截图、座位图。

**场景 C：被风控时人工介入**
> 系统连续 3 次触发验证码/滑块，暂停任务，微信通知用户。
> 用户在电脑上人工扫码登录闲鱼，恢复登录态后系统自动继续。

### 4.2 闲鱼数据采集（F2）
| 编号 | 功能 | 优先级 | 说明 |
|---|---|---|---|
| F2.1 | 关键词搜索结果采集 | P0 | 通过 Playwright 渲染搜索页，滚动加载完整虚拟列表 |
| F2.2 | 商品详情采集 | P0 | 价格、标题、描述、图片、地区、发布时间、卖家 ID、想要数、浏览数 |
| F2.3 | 卖家主页采集 | P0 | 在售商品数、已售数、注册时间、芝麻信用分（如公开）、实名状态 |
| F2.4 | 卖家历史发布采集 | P1 | 最近 30 / 90 天发布的所有商品标题与价格（用于职业卖家识别） |
| F2.5 | 卖家评价采集 | P1 | 作为卖家的好评率 / 差评数（如平台可见） |
| F2.6 | 增量去重 | P0 | 已发现商品 ID 入库，不重复推送 |

### 4.3 价格策略引擎（F3）
| 编号 | 功能 | 优先级 | 说明 |
|---|---|---|---|
| F3.1 | 硬性价格上限 | P0 | 任务级配置 "price <= X" |
| F3.2 | 低于市场参考价 | P1 | 同关键词近 N 条商品均价 × 配置折扣（如 0.8） |
| F3.3 | 同类低价 TopN | P2 | 同关键词中价格最低的前 N 个 |
| F3.4 | 价格异常检测（卖家侧） | P1 | 与同款其他卖家价格偏差 > 50% 视为异常（钓鱼/引流） |
| F3.5 | 多策略可配置 | P0 | 同一任务可叠加多个条件（与/或） |

### 4.4 卖家评估模型（F4，4 维）
| 维度 | 子项 | 评估方式 | 拦截阈值（默认） |
|---|---|---|---|
| **职业卖家识别** | 在售商品数 | 卖家主页在售件数 | > 30 视为职业 |
| | 历史发布频率 | 30 / 90 天发布数 | 月均 > 15 件 视为职业 |
| | 商品类目集中度 | Top1 类目占比 | > 80% 视为职业 |
| | 描述关键词 | 含"批发 / 代理 / 代购 / 大量 / 店铺"等 | 命中即职业 |
| | 同款多账号发布 | 同一商品图哈希在多个卖家出现 | 出现 ≥ 3 次 视为职业 |
| **信用与资质** | 芝麻信用分 | 主页公开分值 | < 600 一票否决 |
| | 实名认证 | 是否完成 | 未实名 加风险分 |
| | 注册时间 | 账号注册距今天数 | < 30 天 加风险分 |
| | 历史交易笔数 | 平台公开 | < 5 笔 加风险分 |
| | 好评率 | 公开评价中好评占比 | < 95% 加风险分 |
| **历史纠纷与黑名单** | 差评 / 投诉数 | 公开评价 | > 3 条 一票否决 |
| | 平台黑名单 | 闲鱼官方标记 | 在册即拒 |
| **价格与竞价异常** | 价格异常 | 与同类差价 > 50% | 直接进入"需人工确认"队列 |
| | 大量收藏低出价 | 想要人数 >> 浏览数 | 钓鱼嫌疑 |
| | 近期调价 | 短时间内频繁涨价/降价 | 价格不稳定，谨慎 |

**输出形式**：综合评分（0~100） + 风险等级（低/中/高/极高）+ 拒绝原因列表。
**默认策略**：评分 < 60 自动拒绝；60~80 推送但半自动；> 80 全自动。

## 5. 非功能需求

### 5.1 性能
| 指标 | 目标值 |
|---|---|
| 单任务轮询周期 | 30s ~ 5min 可配（默认 60s） |
| 浏览器启动到可工作 | < 10s（持久化上下文） |
| 任务启动到首次发现 | < 1 个轮询周期 |
| 从"发现"到"推送"端到端 | < 15s（不含全自动下单） |
| 从"全自动触发"到"提交订单" | < 10s |

### 5.2 可靠性
- 单点故障：本地电脑重启后能自动拉起任务（任务状态持久化在 SQLite）
- 浏览器崩溃：Playwright 自动重建，最多重试 2 次
- 登录失效：自动暂停任务并微信通知
- 数据丢失容忍：30 天内采集数据可恢复

### 5.3 安全性
- Cookie / 推送 Key 等敏感信息本地加密存储（Windows DPAPI）
- 不上传任何账号信息到第三方
- 推送 Key 通过环境变量注入，不进仓库

### 5.4 可维护性
- 关键模块（采集 / 评估 / 下单 / 通知）解耦，通过消息队列串联
- 选择器集中管理（CSS Selector Repository），便于闲鱼改版后快速修复
- 提供 `dev` 模式可在本地浏览器中观察执行

### 5.5 可扩展性
- 任务维度可水平扩展（最多 50 个并发任务，不建议超过）
- 评估维度可插拔（新增"职业卖家识别"维度只需实现接口）
- 通知渠道可插拔（Server酱 / PushPlus / Bark 共用同一接口）

### 5.6 可观测性
- 结构化日志：每条记录含 task_id、stage、item_id、duration
- 指标：发现数、通过评估数、拍下数、被风控次数
- 本地 Web UI（可选）：实时查看日志与商品卡片

### 6.2 关键模块

| 模块 | 职责 | 输入 | 输出 |
|---|---|---|---|
| **Task Manager** | 任务调度（Cron）、启停、并发控制 | tasks 表 | 触发 Collector |
| **Collector** | 搜索/详情/卖家主页数据采集 | 关键词、过滤条件 | ItemEvent |
| **Evaluator** | 4 维卖家评估 + 价格策略 | ItemEvent | EvalResult |
| **Buyer** | 拍下 / 私聊 | EvalResult 达标 | OrderSnapshot |
| **Notifier** | 微信推送、本地提醒 | 任意事件 | 推送结果 |
| **AntiDetect** | 行为模拟、指纹修复、QPS 控制 | 全部浏览器操作 | 加固后的操作 |
| **Storage** | SQLite 表、加密 | 全部数据 | 持久化记录 |

### 6.3 技术选型
| 类别 | 选型 | 理由 |
|---|---|---|
| 浏览器自动化 | **Playwright (Python)** | 反检测好、API 现代化、社区活跃 |
| 语言 | **Python 3.10+** | 异步生态丰富、库多 |
| 异步框架 | **asyncio + aiohttp** | 单进程多任务 |
| 数据库 | **SQLite 3** | 本地零运维 |
| 通知 | **Server酱 / PushPlus / Bark** | 微信/系统推送，零成本 |
| 日志 | **loguru** | 简单可靠 |
| 配置 | **YAML + pydantic** | 校验友好 |
| 加密 | **Windows DPAPI (keyring)** | 系统级安全存储 |

## 8. 关键流程

### 8.1 任务运行主循环

```
1. Task Manager 按 Cron 触发任务
2. Collector 打开搜索页 → 等待渲染 → 滚动加载 → 抓取列表
3. 增量去重（已存在 items.id 跳过）
4. 对每个新 Item：
   a. 价格策略过滤（F3）→ 不通过丢弃
   b. 抓取商品详情
   c. 抓取卖家主页 + 历史发布
   d. Evaluator 综合 4 维评分
   e. 评分达标 → Notifier 推送
   f. 自动模式 → 调 Buyer 拍下
5. 全部完成 → 写日志 → 等待下一轮
```

### 8.2 自动下单流程

```
1. Buyer.open(item_url)
2. wait_for_selector(价格、卖家头像、立即购买/我想要)
3. 解析按钮：
   - "立即购买" → 直接点击
   - "我想要 + 拍下" → 走"我想要"→ 进入聊天 → 拍下
4. 处理可能的中间弹窗（优惠券、运费险提示等）
5. 进入"确认订单"页
6. 校验收货地址、运费（防止地址错乱）
7. 点击"提交订单"（不点击"付款"）
8. 抓取订单号、提交时间
9. 写 orders 表 + 截图
10. Notifier 推送"已拍下，请人工支付"
```

### 8.3 风控熔断流程

```
1. 任意阶段异常 → AntiDetect 上报
2. 同一任务 1 小时内 ≥ 3 次异常：
   - 暂停该任务
   - 暂停所有任务（避免牵连）
   - 微信推送"风控告警"
3. 用户在本地浏览器人工处理：
   - 扫码、验证、滑块
4. 用户点击"恢复" → 重置计数器 → 继续
```

### 8.4 登录态恢复

```
1. 启动时检查 User Data Dir 中的 Cookie 有效期
2. Cookie 失效 → 打开登录页 → 等待用户扫码
3. 扫码成功 → 自动持久化新 Cookie
4. 失败 3 次 → 推送"请人工登录"
```

## 9. 接口设计

### 9.1 模块内部接口（节选）

```python
# 采集
class ICollector(Protocol):
    async def search(self, keyword: str, page: int) -> list[ItemSummary]
    async def detail(self, item_id: str) -> ItemDetail
    async def seller_profile(self, seller_id: str) -> SellerProfile
    async def seller_history(self, seller_id: str, days: int) -> list[ItemSummary]

# 评估
class IEvaluator(Protocol):
    async def evaluate(self, item: ItemDetail, seller: SellerProfile) -> EvalResult

# 下单
class IBuyer(Protocol):
    async def buy_now(self, item: ItemDetail) -> OrderSnapshot
    async def send_message(self, seller_id: str, text: str) -> bool

# 通知
class INotifier(Protocol):
    async def notify(self, event: Event) -> NotifyResult
```

### 9.2 与闲鱼 API 的对接点（不直接调用，仅作记录）

| 接口 | URL 模式 | 用途 | 触发模块 |
|---|---|---|---|
| 搜索 | h5api.m.goofish.com/h5/mtop.taobao.idlemtopsearch.pc.search | 关键词搜索 | Collector（已可走公开搜索 s.goofish.com） |
| 详情 | g-acs.m.goofish.com/h5/mtop.taobao.idle.awesome.itemdetail | 商品详情 | Collector |

## 10. 风险与合规

### 10.1 平台风险
| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| 闲鱼改版导致选择器失效 | 高 | 高 | 选择器集中管理 + 异常快速告警 + 灰度回退 |
| 账号被风控限流 | 中 | 高 | 严格 QPS 控制 + 行为模拟 + 不做大规模并行 |
| 账号被永久封禁 | 低 | 极高 | 主账号备份 + 关键资料提前导出 |
| 闲鱼接口签名变化 | 中 | 高 | 优先用 Playwright 渲染，不依赖签名的 API |
| 验证码/滑块频繁 | 中 | 中 | 熔断 + 人工接管，不接打码平台 |

### 10.2 法律与合规
- 仅做**个人使用**，不转售数据、不做商业化
- 严格遵守闲鱼用户协议，**不绕过付费内容、不破解加密**
- 不干扰平台正常运行（QPS < 1）
- 不获取非公开数据
- 不进行价格垄断、串通、刷单等行为

### 10.3 资金安全
- **不自动支付**——订单拍下后由用户人工支付
- 单笔交易预算上限配置（默认 5000 元），超过强制半自动

### 10.4 数据隐私
- 账号 Cookie、推送 Key 本地加密（Windows DPAPI）
- 不上传任何用户数据到云端
- 项目仓库 `.gitignore` 排除 `browser-data/`、`*.sqlite`、`*.env`
