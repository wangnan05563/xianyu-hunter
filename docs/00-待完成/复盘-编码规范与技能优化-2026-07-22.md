## 二、任务执行过程中的不确定性与失败点

### 失败 1：worker.py RiskLevel 未导入

- **现象**：所有 eval.scored 事件写入失败
- **根因**：property `is_passed` 内部引用 `RiskLevel.EXTREME`，但 import 缺失
- **修复**：在 worker.py:20 同步添加 import
- **教训**：使用未导入符号时，Python NameError 会被 try/except 静默吞掉，必须搜完整 grep 确认

### 失败 2：credit_score_min=600 与闲鱼信用分范围(0-100)不匹配

- **现象**：所有商品评估 0 分
- **根因**：误用芝麻信用区间（350-950）配置闲鱼信用（0-100），触发一票否决
- **修复**：600 → 60
- **教训**：硬编码的常量必须从数据源真实范围推导，不能"抄默认值"

### 失败 3：search 任务占用 browser_lock 导致官方采集超时

- **现象**："官方采集失败，请稍后重试"
- **根因**：scheduler 与官方采集共享同一 asyncio loop + 同一把 browser_lock
- **修复**：暂停所有任务 → 重启服务
- **教训**：长任务占用共享资源时，前端无排队提示，需加 timeout 与排队反馈

### 失败 4：标题列消失（SCROLL_X 与列宽不匹配）

- **现象**：表格内标题列被压缩至 0 宽度
- **根因**：标题列无 width，固定宽度列总和与 SCROLL_X 差 20px
- **修复**：width:200 + SCROLL_X:1850
- **教训**：表格列必须显式指定 width 或 ellipsis，Ant Design 不会自动平分

### 失败 5：构建产物未包含 dimensionLabels（import 行被静默丢失）

- **现象**：minify 后 translateDimension 函数名被压缩为 1 字符，肉眼难验证
- **根因**：Vite tree-shake 严格、minify 改函数名
- **修复**：通过 Python 读取 chunk 中"职业卖家"等中文验证
- **教训**：构建后必须用脚本（不能用 grep）验证关键字符串是否被打包

### 失败 6：PowerShell 输出截断

- **现象**：含中文字符的 Python 输出在 PS 管道中被截断
- **根因**：PS 5.1 默认编码 + stdout buffer flush 行为
- **修复**：写到中间文件再 Read
- **教训**：PS 5.1 + 复杂输出时一律走"写文件 + Read 工具"

### 失败 7：测试断言未同步更新

- **现象**：修复 config 后旧测试断言失败
- **根因**：测试硬编码旧值
- **修复**：断言改为基于范围（50 ≤ credit_score_min ≤ 100）而非固定值
- **教训**：断言应使用范围/语义而非绝对值，降低耦合

## 三、可抽象的固定流程与判断逻辑

### 流程 1：Bug 根因定位（通用）

```
症状描述 → 缩小范围（前端/后端/DB/网络）→
读取最近 7 天修改的文件 → 静态分析关键路径 →
运行最小复现脚本（curl/python）→ 修复 →
回归测试 → 配置同步检查
```

**适用**：单点 bug、回归 bug、性能问题
**不适用**：架构性 bug、需求不清、用户期望与实现差异

### 流程 2：列/字段扩展

```
确认 UI 元数据定义（FieldMeta/ColumnConfig）→
抽象为 hook（持久化 + 配置面板）→
用 dnd-kit/Sortable 实现拖拽 →
Table 渲染前 applyConfig 重排 →
TypeScript 检查 → 构建后用脚本验证 chunk
```

**适用**：所有"用户可定制"的列表（评估/商品/任务/订单）
**不适用**：结构化表格（必须固定列）、打印导出

### 流程 3：英文标签本地化

```
定位后端写入 key（grep dimension_scores）→
建立 key→label 映射表（常量文件）→
保留原 key 在 title 属性供调试 →
未匹配 key 兜底返回原字符串 →
构建后用 Python 验证 chunk 含中文
```

**适用**：枚举值、状态码、reason token
**不适用**：自由文本、用户输入

### 流程 4：阈值/评分逻辑修复

```
阅读原 property → 区分硬编码 vs 配置 →
新增 should_pass(threshold) 方法 →
worker.py 增加判断分支 →
单元测试覆盖所有评分区间（含边界值）→
配置 hot-reload 文档化（get_config 单例）
```

**适用**：评分、风控、抢购、配额
**不适用**：安全相关硬编码（如 token 比较、auth）

### 流程 5：构建产物验证

```
npm run build → Python 读 .js chunk →
断言关键字符串存在（中文字符 / 函数名片段）→
清理临时文件 → 总结
```

**适用**：所有 minify 后的生产构建
**不适用**：dev server（Vite 已 HMR）

## 四、适用场景与不适用场景

| 流程/规范 | 适用 | 不适用 |
|---|---|---|
| 精确编辑（仅改必要部分） | 修 bug、加字段 | 重构、跨模块升级 |
| localStorage 持久化配置 | 用户偏好（列宽、阈值） | 系统级配置（应用 yaml） |
| 范围断言（`50 <= x <= 100`） | 配置阈值、版本兼容 | 业务计算结果（必须精确） |
| Python 读 chunk 验证 | minify 后端到端 | dev 模式（HMR 即可） |
| Write 中间文件再读 | PS 5.1 + 中文输出 | bash/zsh（直接管道即可） |
| dnd-kit 拖拽 | 用户可定制列表 | 移动端触摸优先（用 react-dnd-touch） |
| 前端翻译后端 key | 枚举/状态/拒绝原因 | 自由文本、用户输入 |
| 单元测试覆盖所有评分区间 | 评分/风控逻辑 | 纯展示型组件 |

## 六、避免的坑（反模式清单）

1. **不要**把所有列加 `responsive: ['md']` — 会让宽屏也消失
2. **不要**在 `try/except Exception` 内静默吞 NameError
3. **不要**用 `not payload.get(key)` 判定"已存在但为空字符串"
4. **不要**让 Vite minify 产物用肉眼 grep 验证（函数名会被改）
5. **不要**假设 PowerShell 5.1 输出完整（中文/长行被截）
6. **不要**在 worker.py / scheduler.py 直接用 `get_config()` 期望热更新（单例缓存）
7. **不要**让多个长任务共享一把不可超时锁
