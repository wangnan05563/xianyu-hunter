## 1. 项目背景与目标

### 1.1 背景

XianyuHunter 现有前端为桌面端 React SPA（127.0.0.1:8001），仅支持本地电脑访问。用户在通勤、外出、夜间等离开电脑的场景下，无法及时响应系统推送的"发现目标商品""风控告警""抢单待确认"等关键事件，错失捡漏机会。

本需求规格定义移动端前端版本，通过 **PWA 深化方案** + **内置内网穿透** 实现：
- 远程移动设备访问（手机浏览器或"添加到主屏"）
- 保留桌面端 80% 核心功能（监控、查看、轻量操作）
- 即时响应推送通知，移动端闭环半自动抢单确认

### 1.2 核心目标

| 目标编号 | 描述 | 可衡量指标 |
|---|---|---|
| MG1 | 移动端可远程访问系统并查看实时状态 | 首屏加载 < 1.5s（4G），SSE 事件延迟 < 2s |
| MG2 | 移动端可完成半自动抢单确认闭环 | 从推送到达到点击"拍下" < 30s |
| MG3 | 内置内网穿透，零额外安装门槛 | 一键开启远程访问，无需用户自备工具 |
| MG4 | 保留米其林设计系统品牌一致性 | 星级/红黑/Didone 视觉元素 100% 继承 |
| MG5 | PWA 可安装到主屏，支持离线查看缓存数据 | Lighthouse PWA 全项通过 |

### 1.3 非目标

- 不做原生 App（iOS/Android Native）
- 不做与桌面端完全对等的功能（重操作引导到 PC 端）
- 不做移动端支付能力（资金安全风险）
- 不做多用户/多租户移动端管理
- 不做移动端反向工程闲鱼 App

## 2. 范围与约束

### 2.1 范围内（In-Scope）

- 现有 React + Vite + PWA 前端的移动端深化适配
- 移动端专属布局（TabBar + 堆栈导航）与组件层
- 8 个核心功能模块的移动端实现（详见 §4）
- 内置内网穿透模块（后端 Python 集成）
- HTTPS 证书自动配置
- 移动端认证增强（token 刷新 + 设备绑定）
- PWA 离线缓存与推送通知
- 米其林设计系统移动端适配规范

### 2.2 范围外（Out-of-Scope）

- iOS/Android 原生 App 开发
- 移动端配置编辑（复杂表单引导到 PC 端）
- 移动端系统维护危险操作（清空数据库、批量采集等）
- 移动端反爬登录扫码（引导到 PC 端）
- 移动端错误日志详情查看（仅看摘要）
- 推送通知服务搭建（复用现有 Server酱/PushPlus/Bark/钉钉）

### 2.3 关键约束

| 约束类别 | 说明 |
|---|---|
| 技术栈 | 复用现有 React 18 + Ant Design 5 + Vite + TypeScript + PWA |
| 部署形态 | 后端仍部署在 Windows 10 本地电脑，通过内置内网穿透暴露公网 HTTPS |
| 远程访问 | 移动端通过公网域名 + HTTPS 访问，需认证 cookie 配置 `SameSite=None;Secure` |
| 网络环境 | 需兼容 4G/3G 弱网，离线可查看缓存数据 |
| 安全边界 | 移动端仅允许查看与轻量操作，危险操作二次验证或引导 PC 端 |
| 品牌一致 | 必须继承米其林设计系统（经典红 #E20613 + 星金 #C9A961 + Didone 字体） |
| 用户门槛 | 内网穿透工具内置，用户无需额外安装 frp/ngrok 等工具 |

## 3. 用户与场景

### 3.1 目标用户

与桌面端一致：一名"懂技术、对二手商品有研究、希望提高捡漏效率"的中文个人买家。移动端额外诉求：
- 通勤/外出时需要远程监控系统运行状态
- 收到推送后希望第一时间在手机上确认抢单
- 夜间不想开电脑，希望通过手机查看告警详情

### 3.2 典型使用场景

**场景 A：通勤监控**
> 用户在地铁上打开手机 PWA，查看仪表盘 KPI 星级与异常雷达，确认系统正常运行。
> 收到 SSE 推送"发现目标商品"，点击通知跳转商品卡片详情，查看卖家4维评分后点击"拍下"。

**场景 B：夜间告警响应**
> 凌晨系统触发风控熔断，推送"风控告警"到手机。
> 用户在床上打开 PWA 查看告警详情，判断是否需要起身到电脑前人工处理（扫码/验证）。

**场景 C：外出后状态同步**
> 用户在外面通过闲鱼 App 完成了某订单的支付。
> 打开 XianyuHunter PWA，进入抢单记录，将该订单状态标记为"已成功"，评估明细联动更新为"已支付"。

**场景 D：远程问询客服**
> 用户外出时对某评估结果有疑问，打开 PWA 智能客服 Tab，输入"为什么这个卖家评分只有 45？"，RAG 返回评估规则解释。

**场景 E：弱网离线恢复**
> 用户进入电梯信号中断，PWA 显示"离线"横幅，仍可查看已缓存的商品列表与订单记录。
> 出电梯网络恢复，SSE 自动重连并拉取最新数据。

## 5. 非功能需求

### 5.1 性能

| 指标 | 目标值 |
|---|---|
| 首屏内容绘制（FCP） | < 1.5s（4G 网络） |
| 可交互时间（TTI） | < 3s（4G 网络） |
| PWA 缓存后首屏 | < 500ms |
| Bundle 体积（gzip 后主包） | < 300KB |
| SSE 事件延迟 | < 2s |
| 列表滚动帧率 | 60fps |
| 内存占用 | < 100MB（避免移动端浏览器杀进程） |
| API 请求超时 | 10s（移动端网络不稳定） |
| 图片加载 | WebP/AVIF 格式，懒加载 |

### 5.2 可靠性

- **弱网降级**：3G/Edge 网络下关闭 SSE 改为 30s 轮询，图片显示低清占位
- **离线模式**：缓存已加载数据可查看，显示离线横幅，网络恢复自动同步
- **SSE 断线重连**：5s 内自动重连，支持断线回放（last-event-id）
- **token 自动刷新**：过期前 5 分钟自动刷新，无感知续期
- **崩溃恢复**：PWA Service Worker 异常不影响页面基础功能

### 5.3 安全性

| 类别 | 要求 |
|---|---|
| 传输安全 | 全链路 HTTPS（PWA 强制要求），内网穿透自动配置 TLS 证书 |
| 认证增强 | cookie 配置 `SameSite=None;Secure;HttpOnly`，移动端 token 有效期 7 天 |
| 设备绑定 | 限制同时在线移动设备数（默认 3 台），新设备登录通知原设备 |
| 操作权限 | 移动端仅允许查看与轻量操作；删除/清空/批量操作二次验证或引导 PC 端 |
| 敏感字段 | token、cookie、推送 Key 在移动端脱敏显示（仅显示前后各 4 位） |
| 本地缓存 | PWA 缓存数据不包含敏感字段，退出登录清除本地数据 |
| 速率限制 | 移动端 API 速率 ≤ 10 QPS，防止滥用 |
| 内网穿透 | 穿透域名仅允许已认证用户访问，未认证返回 401 |

### 5.4 可访问性（Accessibility）

- 对比度 ≥ WCAG 2.1 AA 级（4.5:1）
- 焦点环：2px 米其林红 outline，2px offset
- 最小可点击元素 44×44px（iOS HIG / Android MD 规范）
- 支持 VoiceOver（iOS）/ TalkBack（Android）屏幕阅读器
- 支持系统字体缩放（最大 200%）
- 颜色 + 形状双通道标识（不只依赖颜色区分状态）
- 暗色/亮色主题都通过 WCAG AA 对比度审计

### 5.5 可维护性

- 移动端组件与桌面端共用 API 层、类型定义、业务逻辑
- 移动端专属组件独立目录（`frontend/src/mobile/`），不污染桌面端代码
- 米其林设计 token 单一来源，移动端仅扩展断点与手势 token
- 内网穿透模块独立为后端 service，可插拔

### 5.6 可扩展性

- 移动端路由独立配置，新增移动端页面不影响桌面端
- 内网穿透支持多种 provider（默认 cloudflare tunnel，可扩展 frp/ngrok）
- 推送通知渠道可插拔（复用现有 Notifier 接口）

### 6.2 关键技术决策

| 决策 | 选型 | 理由 |
|---|---|---|
| 移动端方案 | **PWA 深化** | 复用现有 vite-plugin-pwa 基础，单一代码库保证功能一致性 |
| 路由策略 | **UA 检测 + 断点双轨** | `/m/*` 移动端路由组，UA 检测自动跳转，桌面端访问 `/m/*` 重定向到桌面路由 |
| UI 组件 | **antd 响应式 + 移动端专用组件** | 简单页面复用 antd 响应式；复杂交互（TabBar、左滑、下拉刷新）使用自研移动组件 |
| 状态管理 | **Zustand（复用）** | 共享 store，保证桌面/移动状态一致 |
| 内网穿透 | **内置 cloudflare-tunnel 客户端** | 零成本、自动 HTTPS、无需域名、用户无需注册第三方服务 |
| 认证 | **复用 xh_token cookie + SameSite=None** | 最小改动，cookie 配置调整即可支持跨域 |

## 9. 交互流程

### 9.1 远程监控与告警响应

```
1. 系统检测到目标商品 / 风控告警
2. Notifier 推送到微信/钉钉/Bark（含 PWA 深度链接）
3. 用户手机锁屏收到推送通知
4. 点击通知 → PWA 自动打开 → 跳转对应详情页
5. 用户查看详情后决策：
   a. 忽略（关闭页面）
   b. 标记处理（点击"已查看"按钮）
   c. 引导 PC 端操作（风控需扫码时）
```

### 9.2 半自动抢单确认

```
1. 系统评估通过 → 推送"发现目标商品"到手机
2. 用户点击推送 → PWA 打开商品卡片详情
3. 详情页展示：商品信息 + 卖家4维评分 + 风险等级
4. 用户确认后点击底部"拍下"按钮
5. 二次确认弹层："确认拍下？将在闲鱼内完成支付"
6. 用户点击"确认" → 调用 /api/orders/buy API
7. 显示拍下结果（成功/失败）
8. 成功提示："请在闲鱼 App 内 5 分钟内完成支付"
9. 跳转抢单记录查看新订单
```

### 9.3 任务远程控制

```
1. 用户打开 PWA → 底部 Tab"任务"
2. 下拉刷新任务列表与状态
3. 点击任务卡片进入详情
4. 查看任务配置（只读）与运行历史
5. 操作：
   a. 暂停/恢复（卡片开关或详情页按钮）
   b. 编辑基础字段（详情页"编辑"按钮）
   c. 删除（左滑 → 二次确认）
6. 操作结果 Toast 反馈
```

### 9.4 订单状态同步

```
1. 用户在闲鱼 App 完成某订单支付
2. 打开 XianyuHunter PWA → 底部 Tab"抢单"
3. 找到"待支付"状态的订单
4. 点击状态下拉 → 选择"已成功"
5. 后端更新 orders 表 order_status = 'paid'
6. 评估明细页"待支付"联动更新为"已支付"
7. Toast 反馈"状态已更新"
```

### 9.5 智能客服咨询

```
1. 用户点击底部 Tab"客服"
2. 输入问题（如"为什么这个卖家评分只有 45？"）
3. RAG 引擎检索知识库
4. SSE 流式返回答案（打字机效果）
5. 用户点击"赞"或"踩"
6. 连续 2 次点踩 → 提示"是否转人工？"
7. 用户确认 → 标记会话为"待人工处理"
```

### 9.6 登录与认证

```
1. 首次打开 PWA → 登录页
2. 输入用户名 + 密码（复用现有认证）
3. 登录成功 → 设置 xh_token cookie (SameSite=None;Secure)
4. 后端记录设备指纹，限制同时在线设备数
5. 后续打开 PWA → 自动登录（cookie 有效）
6. token 过期前 5 分钟自动刷新
7. 刷新失败 → 跳转登录页
8. 退出登录 → 清除本地缓存 + cookie
```

### 9.7 离线恢复

```
1. 用户进入弱网/断网区域
2. PWA 显示"离线"横幅
3. 用户可查看已缓存的商品/订单/评估数据
4. 用户操作暂存队列（如标记已支付）
5. 网络恢复 → 横幅消失
6. 自动重连 SSE + 拉取最新数据
7. 暂存操作自动同步到后端
```

### 9.8 内网穿透开启

```
1. 用户在 PC 端打开"设置" → "远程访问"
2. 点击"开启远程访问"开关
3. 后端启动 cloudflare-tunnel 客户端
4. 自动分配 HTTPS 公网域名
5. 页面显示二维码 + 域名链接
6. 用户手机扫码 → 打开 PWA
7. 输入账号密码登录 → 开始远程访问
8. 关闭开关 → 立即断开隧道，域名失效
```

## 11. 风险与缓解

### 11.1 安全风险

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| 内网穿透域名泄露导致未授权访问 | 中 | 高 | 域名不公开索引 + 认证强制 + 速率限制 |
| 移动端 cookie 被窃取 | 低 | 高 | HttpOnly + Secure + 设备绑定 + 7 天过期 |
| 弱网下 token 刷新失败循环 | 中 | 中 | 刷新失败 3 次后跳转登录页，不无限重试 |
| 移动端误操作删除数据 | 中 | 高 | 危险操作二次确认 + 引导 PC 端 |

### 11.2 兼容性风险

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| iOS Safari PWA 限制（后台杀进程） | 高 | 中 | 推送通知兜底 + 重新打开自动恢复 |
| iOS < 16.4 不支持 Push API | 中 | 中 | 降级为 SSE + 应用内通知 |
| Android 浏览器碎片化 | 中 | 低 | 测试 Top 5 浏览器，降级策略 |
| 弱网下 SSE 频繁断线 | 高 | 中 | 5s 重连 + 轮询降级 + 离线缓存 |

### 11.3 性能风险

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| antd 全量引入导致 bundle 过大 | 高 | 高 | 按需引入 + 路由分割 + Tree Shaking |
| 图片加载拖慢首屏 | 中 | 中 | WebP + 懒加载 + 占位图 |
| 内存占用过高被系统杀进程 | 中 | 高 | 限制缓存条数 + 退出页面释放资源 |
| 内网穿透带宽限制 | 低 | 中 | cloudflare-tunnel 无带宽限制 + 监控流量 |

- **SSE**：Server-Sent Events，服务器推送事件
- **TabBar**：底部标签栏导航
- **ActionSheet**：底部弹出的操作菜单
- **WCAG**：Web Content Accessibility Guidelines，Web 内容可访问性指南
- **FCP**：First Contentful Paint，首次内容绘制
- **TTI**：Time to Interactive，可交互时间
