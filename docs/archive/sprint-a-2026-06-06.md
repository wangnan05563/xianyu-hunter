## 1. UX-01 顶栏状态可下钻

### 1.1 现状问题
- [base.html:43-50](file:///d:/code/otherProjects/17_xianyu/src/xianyu_hunter/web/templates/base.html#L43-L50) `status-chip` 是纯展示 `<div>`，用户看到"X 个任务运行中"后想跳到任务列表还得点侧栏
- 移动端尤其痛：屏幕小，多一次点击放大不舒适

### 1.2 实施细节
- **HTML 改造**：`<div>` → `<a role="button" tabindex="0">`，动态 `:href`：
  - `n > 0` → `/tasks?status=running`（过滤到运行中）
  - `n == 0` → `/tasks`（完整列表）
- **可访问性**：
  - `role="button"` + `tabindex="0"`：键盘 Tab 焦点可达
  - `:aria-label` 提示"查看 N 个运行中任务 / 查看任务列表（无运行中）"
  - `:title` 鼠标 hover 提示
- **CSS（[app.css:117-120](file:///d:/code/otherProjects/17_xianyu/src/xianyu_hunter/web/static/app.css#L117-L120)）**：
  ```css
  .topbar .status-chip[role="button"] { cursor: pointer; ... }
  .topbar .status-chip[role="button"]:hover { background: var(--bg-3); ... }
  .topbar .status-chip[role="button"]:focus-visible { outline: 2px solid var(--brand); ... }
  ```

### 1.3 验证
- `/dashboard` 渲染验证：`status-chip`、`查看任务列表` aria-label 全部存在
- HTMX 5s 周期轮询无破坏

### 1.4 预期效果
- 路径：`/dashboard` → 点击顶栏 chip → 直接到过滤后的任务列表（少 2 步点击）
- 键盘用户：Tab + Enter 可完成（无障碍友好）

## 2. UX-02 抢单记录加商品列

### 2.1 现状问题
- [orders.html:48-52](file:///d:/code/otherProjects/17_xianyu/src/xianyu_hunter/web/templates/orders.html#L48-L52) 只显示 item_id 链接
- 接管决策时用户得"逐个点开"看是不是想要的那一单
- 大量订单时认知负担极重

### 2.2 实施细节

#### 后端：新文件 [api_items.py](file:///d:/code/otherProjects/17_xianyu/src/xianyu_hunter/web/routes/api_items.py)
- `GET /api/items/{item_id}/summary`：返回 `{item_id, title, price, seller_id}`；缺失时返回 `null` 而非 404
- `GET /api/items/batch?ids=id1,id2,...`：批量（≤50），返回 `{summaries: {id: {...}}, missing: [...], count: N}`
- **为什么缺失返回 null 而非 404**：列表页批量拉时个别缺失不应阻塞其他行（典型场景：订单记录指向已被清理的 items 行）

#### 前端：[orders.html](file:///d:/code/otherProjects/17_xianyu/src/xianyu_hunter/web/templates/orders.html)
- 表格列增加"商品"列：
  - 命中缓存 → 显示标题（最多 2 行截断）
  - 未命中 → 灰链显示 item_id（不空等）
  - 缺失 → 显示 `—`
- 缓存策略：**双层缓存**
  - 内存 `_itemCache: {}`
  - sessionStorage `_itemCacheKey: 'xh.order_items_titles'`（30 分钟 TTL）
- 防并发：`_itemPending` Set 防止同一 item_id 在 200ms 内被多次拉

#### CSS：[app.css:1558-1586](file:///d:/code/otherProjects/17_xianyu/src/xianyu_hunter/web/static/app.css#L1558-L1586)
- 桌面表格 2 行截断、悬停品牌色下划线
- 移动端 1 行截断

### 2.3 验证
```powershell
# /api/items/nonexistent_id/summary
{"item_id": "nonexistent_id", "title": null, "price": null, "seller_id": null}

# /api/items/batch?ids=id1,id2,id3
{"summaries": {}, "missing": ["id1", "id2", "id3"], "count": 0}

# /api/items/batch?ids=id1,id2,...,id51
→ 400 拒绝（防恶意大查询）

# /orders 页面 200 OK, 43KB, item-cell/getItemTitle/_itemCache 全部已渲染
```

### 2.4 预期效果
- 桌面：每单 1 行可见判断，**接管决策少 1 次点击 + 1 次加载**
- 移动：单卡单标题，**减少横向滚动**

- [tasks/list.html:402-414](file:///d:/code/otherProjects/17_xianyu/src/xianyu_hunter/web/templates/tasks/list.html#L402-L414) `clone()` 后 name 清空、keyword 不变

### 3.2 实施细节

#### add() 必填校验
```javascript
if (!this.form.name || !this.form.name.trim()) {
  this.toast('请先给任务起个名字再保存', 'err');
  // 焦点跳到 name 输入框
  const el = document.querySelector('[data-task-form] input[name="name"]');
  if (el) el.focus();
  return;
}
```

#### HTML 标识
- 模态框 `<div class="modal-bg" data-task-form>`：选择器锚点

### 3.3 验证

## 4. UX-05 关键错误持久化

### 4.1 现状问题
- [base.html:482](file:///d:/code/otherProjects/17_xianyu/src/xianyu_hunter/web/templates/base.html#L482) err banner 8s 自动消失
- 关键告警（"二维码加载失败"、"登录态掉线"）用户来不及截图就消失

### 4.2 实施细节

#### 改造 pushBanner()
- 解析 ev.level / ev.type / ev.message 后
- **err 级额外**调用 `_persistErrorAsNotif()` 异步落库到 `/api/notifications`

#### dedup_key 策略
```javascript
const today = new Date().toISOString().slice(0, 10);
const msgKey = message.replace(/\s+/g, ' ').trim().slice(0, 60);
const dedupKey = `banner:${type}:${msgKey}:${today}`;
```
- 同一天内同一条错误不会重复入库（数据库 dedup_key UNIQUE 约束）
- 跨天允许重新出现

#### 持久化后联动
- 通知中心 drawer 打开时 → 立即刷新列表
- 顶栏铃铛未读 badge → 立即更新
- `reset_read: false`：不抢用户已读状态

#### 容错
- fetch 失败静默降级：banner 8s 已消失，持久化失败不打扰

### 4.3 验证
```powershell
# POST /api/notifications
{"ok": true, "item": {"id": 8, "level": "err", "category": "system", "title": "⚠ test", ...}}

# GET /api/notifications/unread_count
{"unread": 1}
```

### 4.4 预期效果
- 关键告警不再丢失，**8s 后用户仍可在"通知中心"抽屉翻看**
- 误删/误点 × 时可从通知中心恢复信息

## 5. UX-06 inline 二次确认

### 5.1 现状问题
- [tasks/list.html:534/541](file:///d:/code/otherProjects/17_xianyu/src/xianyu_hunter/web/templates/tasks/list.html#L534) `confirm()` 是浏览器原生弹窗
- 打断心流、按钮样式不可控、移动端适配差

### 5.2 实施细节

#### 状态机
- `_confirmTarget: { id, action, label, hint, timer } | null`
- `_CONFIRM_TIMEOUT_MS: 5000`（5s 未确认自动撤销）

#### 分类处理
| 操作 | 类别 | 行为 |
|---|---|---|
| pause / resume | 安全（可逆） | 直接执行 + toast 反馈 |
| stop | 危险（不可逆） | inline 二次确认 |
| delete | 危险（软删除） | inline 二次确认 |

#### 触发
```javascript
// 桌面表格行内操作列：
<button @click="control(t.id, 'stop')">■</button>  // → 二次确认
<button @click="del(t.id)">🗑</button>             // → 二次确认
```

#### UI
- 行内替换操作按钮为 `[⚠ 危险标签] [确认] [取消]`
- 黄色背景 + 1px 黄边 + 0.25s 抖动动画（`@keyframes row-confirm-shake`）
- 5s 后未操作自动撤销（防止"忘了点过"导致下次操作被误认为已确认）

#### CSS（[app.css:354-379](file:///d:/code/otherProjects/17_xianyu/src/xianyu_hunter/web/static/app.css#L354-L379)）
```css
.row-confirm {
  display: inline-flex; ...
  background: rgba(234, 179, 8, 0.12);
  border: 1px solid rgba(234, 179, 8, 0.4);
  animation: row-confirm-shake 0.25s ease-out;
}
@keyframes row-confirm-shake { ... }
```

### 5.3 验证
- `/tasks` 页面 200 OK
- `row-confirm` / `_armConfirm` / `_doDelete` 全部已渲染
- `confirm` 关键字已全部移除

### 5.4 预期效果
- 危险操作打断感小（不像原生 confirm 弹整个模态）
- 误点 ■/🗑 5s 内可一键取消
- 颜色 + 抖动动画明确"现在正等待二次确认"
