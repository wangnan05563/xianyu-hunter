```

```

## 1. 背景与目标

### 1.1 背景

XianyuHunter 当前为**单用户本地工具**：全局唯一 `WEB_TOKEN`、闲鱼 Cookie 全局共享、菜单前端硬编码、任务表无 `user_id` 关联。当用户需要同时管理多个闲鱼账号（如个人号 + 业务号）时，必须退出当前账号重新登录，无法快速切换，且无法保留每个账号的独立任务与配置。

| 现状 | 痛点 |
|---|---|
| 全局唯一 `WEB_TOKEN`，所有人共用一个会话 | 无法区分操作者，无法实现账号级隔离 |
| 闲鱼 Cookie 存于全局 `cookies.json` + SQLite，不关联用户 | 切换账号需重新登录，原账号 Cookie 被覆盖丢失 |
| `TaskRow` 无 `user_id` 字段，所有任务全局共享 | 多账号任务混杂，无法按账号查看 |
| 菜单 `menuItems` 在 `MainLayout.tsx` 前端硬编码 | 无法按用户习惯定制菜单可见性与排序 |
| `unified_login.py` 内 `_session_lock` 仅允许单登录会话 | 无法保留多个已登录账号 |
| 个性化配置（如列表列设置 `useColumnConfig`）存于 localStorage | 切换账号后配置被覆盖，无法隔离 |

### 1.2 核心目标

| 目标编号 | 描述 | 可衡量指标 |
|---|---|---|
| G1 | **多账号登录切换**：在不退出当前账号的情况下快速切换至其他已登录账号 | 切换响应 P95 ≤ 500ms；支持 ≥ 5 个已登录账号共存 |
| G2 | **会话完全隔离**：不同用户使用独立 Cookie 进行身份验证 | Cookie 按 user_id 隔离存储；切换后旧账号 Cookie 不泄露 |
| G3 | **用户数据隔离**：当前登录用户显示其专属任务列表与个性化配置 | 任务/配置查询 100% 带 user_id 过滤；跨用户数据 0 泄露 |
| G4 | **菜单用户级隔离**：菜单可见性、排序、权限按用户独立配置 | 菜单配置后端可配；每个用户菜单配置独立持久化 |
| G5 | **向后兼容**：不破坏现有单用户使用体验 | 现有 103+ 测试用例无回归；现有数据平滑迁移 |

### 1.3 非目标

- ❌ 不实现多租户 SaaS（仍是本地单机部署，多账号指同一机器上的多个闲鱼账号身份）。
- ❌ 不实现云端账号同步（多账号数据仅存本地，不跨设备同步）。
- ❌ 不实现账号级权限套餐（账号权限套餐归权限模块 v1.1，本模块仅做会话与数据隔离）。
- ❌ 不重写现有闲鱼登录流程（扫码/浏览器登录/Cookie 注入三种方式保留）。
- ❌ 不实现账号合并/数据迁移工具（首版仅支持新数据按用户隔离，历史数据迁移为 default 用户）。
- ❌ 不实现 OAuth/SSO（首版仅支持闲鱼 Cookie 身份）。

## 2. 范围与约束

### 2.1 范围内（In-Scope）

- **用户身份管理**：
  - 用户表（users）与用户会话表（user_sessions）
  - 用户身份识别：从闲鱼 Cookie `unb` 字段提取闲鱼用户 ID 作为唯一键
  - 已登录账号列表管理与持久化
- **会话与 Cookie 隔离**：
  - `xh_token` cookie 升级为会话令牌（session_token → user_id 映射）
  - 闲鱼 Cookie 按 user_id 隔离存储（扩展现有 CookieStore）
  - 账号快速切换（切换 active session，加载对应 Cookie 集）
- **用户数据隔离**：
  - `tasks` 表新增 `user_id` 字段 + 索引，查询按 user_id 过滤
  - 个性化配置（列表列设置、偏好等）按 user_id 隔离
- **菜单用户级隔离**：
  - 菜单配置表（user_menu_configs）：可见性、排序、自定义分组
  - 菜单配置后端 API（CRUD）
  - 前端 MainLayout 从后端拉取菜单配置，支持用户自定义
- **数据迁移**：
  - 现有数据迁移为 `default` 用户，保证向后兼容
  - 迁移脚本与回滚策略

### 2.2 范围外（Out-of-Scope）

- 账号级权限套餐与付费（归权限模块 v1.1）
- 跨设备账号同步（归 v2.0 云同步）
- 账号合并/数据迁移工具（归 v1.2）
- 第三方账号登录（GitHub/Google 等）
- 账号级 AI 配置隔离（首版 AI 配置仍全局共享，归 v1.1）

### 2.3 关键约束

| 约束类别 | 说明 |
|---|---|
| 部署形态 | Windows 10 单机本地部署，多账号数据存于本地 SQLite |
| 身份来源 | 闲鱼 Cookie `unb` 字段为用户唯一标识；`unb` 缺失时降级为 `cookie2` 哈希 |
| 会话凭证 | `xh_token` cookie 由全局 `web_token` 升级为 `session_token`（每用户独立，64 位 URL-safe 随机串） |
| 认证白名单 | 现有 PUBLIC_PREFIXES 白名单保留；新增 `/api/auth/accounts`、`/api/auth/switch` 需评估是否加入白名单 |
| Cookie 安全 | 沿用 `httponly=True`、`samesite="lax"`、`hmac.compare_digest()` 比对约定 |
| 数据库 | SQLite，通过 schema 迁移扩展；`tasks.user_id` 需建索引；现有数据迁移为 default 用户 |
| 兼容性 | 不破坏现有单用户流程；`WEB_TOKEN` 保留作为"管理令牌"用于首次初始化与设备级认证 |
| UI 规范 | 沿用 michelin-design-system.md，不引入第三方 UI 库 |
| 性能 | 切换账号 P95 ≤ 500ms；任务列表加载 P95 ≤ 200ms；菜单配置加载 P95 ≤ 100ms |

## 3. 用户与场景

### 3.1 角色定义

| 角色 | 描述 | 主要场景 |
|---|---|---|
| **默认用户**（Default User） | 现有单用户数据迁移后的账号，user_id=`default` | 升级后首次启动自动创建；承载所有历史数据 |
| **多账号用户**（Multi-Account User） | 拥有多个闲鱼账号身份的系统用户 | 登录多个闲鱼账号；快速切换；各账号独立任务与配置 |
| **当前活跃用户**（Active User） | 当前通过 session_token 激活的用户 | 查看任务；操作菜单；执行业务 |

### 3.2 典型使用场景

**场景 A：单用户升级（向后兼容）**
> 用户升级到新版后首次启动，系统检测到无 `users` 表但存在历史 Cookie 与任务数据。
> 自动创建 `default` 用户，将现有 Cookie、任务、配置归属到 default 用户。
> 用户无感知，继续使用，体验与升级前一致。

**场景 B：添加第二个闲鱼账号**
> 用户已登录账号 A（闲鱼昵称"小明"），希望同时管理账号 B（闲鱼昵称"老王"）。
> 用户点击顶栏头像 → "添加账号" → 走扫码/Cookie 注入流程登录账号 B。
> 登录成功后，账号 B 出现在"账号列表"，但当前仍停留在账号 A，不打断当前操作。
> 用户点击账号 B → 一键切换 → 界面刷新为账号 B 的任务列表与菜单配置。

**场景 C：快速切换账号**
> 用户在账号 A 处理任务时，需临时查看账号 B 的订单。
> 点击顶栏头像下拉 → 选择账号 B → 500ms 内完成切换（Cookie/任务/菜单全部切换）。
> 查看完毕，再切回账号 A，继续原任务操作，配置无丢失。

**场景 D：自定义菜单配置**
> 用户在账号 A 下频繁使用"任务"和"商品"，很少用"评价"。
> 用户在"菜单管理"页面隐藏"评价"，将"任务"置顶。
> 切换到账号 B 后，菜单恢复为账号 B 自己的配置（如显示全部菜单）。
> 切回账号 A，菜单仍为账号 A 的自定义配置。

**场景 E：账号 Cookie 过期**
> 账号 A 的闲鱼 Cookie 过期，系统检测到 `unb` 失效。
> 账号 A 在账号列表中标记为"需重新登录"（橙色徽标）。
> 其他账号不受影响，可正常切换使用。
> 用户点击账号 A 的"重新登录" → 走登录流程 → 恢复可用。

**场景 F：退出某个账号**
> 用户不再使用账号 B，点击账号 B → "退出账号"。
> 系统清除账号 B 的 session_token、Cookie、菜单配置；**保留任务数据**（可选"同时删除任务"）。
> 账号 B 从账号列表移除，当前若在账号 B 则自动切回 default 或最近使用的账号。

## 4. 功能需求

> 编号约定：MU = Multi-User Module。优先级 P0/P1/P2 = 必须 / 应该 / 可选。

### 4.1 多用户账号管理（MU1）

| 编号 | 功能 | 优先级 | 说明 |
|---|---|---|---|
| MU1.1 | 用户身份识别 | P0 | 登录成功后从闲鱼 Cookie 提取 `unb` 字段作为闲鱼用户 ID；`unb` 缺失时降级为 `sha256(cookie2)[:16]`；以此识别或创建 users 记录 |
| MU1.2 | 用户记录创建 | P0 | 首次登录某闲鱼账号时创建 users 记录：`user_id`(闲鱼 unb)、`nickname`(闲鱼昵称)、`avatar`(头像 URL)、`created_at`、`last_active_at` |
| MU1.3 | 用户记录更新 | P0 | 每次登录/切换时更新 `last_active_at`；昵称/头像变更时同步更新 |
| MU1.4 | 已登录账号列表 | P0 | 顶栏头像下拉展示所有已登录账号：头像、昵称、状态（正常/过期）、当前活跃标记；支持搜索 |
| MU1.5 | 添加账号 | P0 | 复用现有登录流程（扫码/Cookie 注入/浏览器导入），登录成功后识别为新用户则创建记录，不覆盖当前活跃账号 |
| MU1.6 | 退出账号 | P0 | 清除指定账号的 session_token、Cookie、菜单配置；任务数据保留（可选删除）；退出后若为当前活跃账号则自动切回 |
| MU1.7 | 账号状态检测 | P0 | 定期（每 5 分钟）探测各账号 Cookie 有效性（`unb` 是否存活）；失效账号标记"需重新登录" |
| MU1.8 | 账号上限控制 | P1 | 默认上限 5 个已登录账号（可配置）；超出时提示"请先退出某账号" |
| MU1.9 | 账号昵称自定义 | P2 | 允许用户给账号起别名（如"工作号"），别名仅本地展示用，不影响 user_id |

### 4.2 会话与 Cookie 隔离（MU2）

| 编号 | 功能 | 优先级 | 说明 |
|---|---|---|---|
| MU2.1 | 会话令牌签发 | P0 | 每个用户登录成功后签发独立 `session_token`（64 位 URL-safe 随机串），写入 user_sessions 表；`xh_token` cookie 存储当前活跃 session_token |
| MU2.2 | 会话令牌校验 | P0 | `BearerAuthMiddleware` 扩展：从 `xh_token` 提取 session_token → 查 user_sessions 表映射 user_id → 注入 `request.state.user_id`；比对用 `hmac.compare_digest()` |
| MU2.3 | 会话过期与续期 | P0 | session_token 默认 30 天有效；活跃使用时自动滑动续期；过期需重新登录该账号 |
| MU2.4 | Cookie 用户级存储 | P0 | 扩展 CookieStore：所有 Cookie 读写带 `user_id` 维度；JSON 主源改为 `data/cookies_{user_id}.json`；SQLite 从源新增 `user_id` 列与复合索引 |
| MU2.5 | Cookie 切换加载 | P0 | 切换账号时，从该用户 Cookie 存储加载到 Worker 浏览器实例（`_inject_cookies_to_worker`），替换当前 Cookie 集 |
| MU2.6 | Cookie 隔离保证 | P0 | 切换后旧账号 Cookie 不残留在 Worker 上下文；通过 `delete_cookies_by_domain` + 重新注入实现 |
| MU2.7 | 并发登录互斥 | P0 | 保留 `unified_login.py` 的 `_session_lock`，但改为"同一时间仅允许一个登录流程"（不限制已登录账号数量） |
| MU2.8 | 管理令牌保留 | P1 | `WEB_TOKEN` 保留为"设备级管理令牌"，用于首次初始化、未登录态访问系统设置；不与 session_token 冲突 |
| MU2.9 | 会话审计日志 | P1 | 记录每次登录、切换、退出事件到 `user_session_events` 表，保留 90 天 |

### 4.3 用户数据隔离（MU3）

| 编号 | 功能 | 优先级 | 说明 |
|---|---|---|---|
| MU3.1 | 任务表用户关联 | P0 | `tasks` 表新增 `user_id` 字段（默认 `default`）+ 索引；所有任务查询 API 按 `request.state.user_id` 过滤 |
| MU3.2 | 任务数据迁移 | P0 | 现有任务数据迁移为 `user_id='default'`；迁移脚本幂等可重复执行 |
| MU3.3 | 个性化配置隔离 | P0 | 列表列配置（`useColumnConfig`）、分页大小、排序偏好等从 localStorage 迁移到后端 `user_preferences` 表，按 user_id 隔离 |
| MU3.4 | 配置迁移 | P0 | 首次升级时，将 localStorage 现有配置导出并归属 default 用户 |
| MU3.5 | 业务数据隔离范围 | P0 | 隔离范围：tasks、items、orders、evaluations、events、notifications；**不隔离**：全局配置（AI/价格/通知渠道）、系统维护 |
| MU3.6 | 数据隔离查询拦截 | P0 | Repository 层在 tasks/items/orders 等查询方法增加 `user_id` 参数；中间件注入的 user_id 透传到 Repository |
| MU3.7 | 全局配置共享 | P1 | AI 配置、价格策略、通知渠道、抢单策略等"系统级配置"全局共享，不按用户隔离（首版） |
| MU3.8 | 跨用户数据引用禁止 | P1 | task_links/task_deps 跨用户引用需校验：禁止 A 用户的任务依赖 B 用户的任务 |

### 4.4 菜单用户级隔离（MU4）

| 编号 | 功能 | 优先级 | 说明 |
|---|---|---|---|
| MU4.1 | 菜单配置表 | P0 | 新建 `user_menu_configs` 表：`user_id`、`menu_key`、`visible`、`sort_order`、`group`、`custom_label` |
| MU4.2 | 菜单元数据注册表 | P0 | 新建 `config/menu_registry.yaml`，定义全部菜单元数据（key、默认可见性、默认排序、分组、所需权限）；前后端共享 |
| MU4.3 | 菜单配置 API | P0 | `GET /api/menu` 返回当前用户的菜单配置（合并默认值与用户自定义）；`PUT /api/menu` 更新用户菜单配置 |
| MU4.4 | 菜单配置重置 | P0 | `POST /api/menu/reset` 重置当前用户菜单为默认配置 |
| MU4.5 | 前端菜单动态渲染 | P0 | `MainLayout.tsx` 从 `/api/menu` 拉取菜单配置动态渲染，移除硬编码 `menuItems` |
| MU4.6 | 菜单管理页面 | P1 | 新增"菜单管理"页面：可视化配置菜单可见性、拖拽排序、自定义分组与别名 |
| MU4.7 | 菜单可见性控制 | P0 | `visible=false` 的菜单项不渲染；对应路由设为"不可访问"（访问时跳 404 或重定向） |
| MU4.8 | 菜单排序持久化 | P0 | 用户拖拽排序后调用 `PUT /api/menu` 持久化；刷新后保持 |
| MU4.9 | 菜单权限联动 | P2 | 与权限模块联动：所需权限不满足时菜单自动隐藏（权限模块上线后启用） |
| MU4.10 | 菜单配置缓存 | P1 | 前端缓存菜单配置（5 分钟 TTL），切换账号时强制刷新 |

## 5. 非功能需求

### 5.1 性能指标

| 指标 | 目标 | 说明 |
|---|---|---|
| 账号切换响应时间 | P95 ≤ 500ms | 从点击切换到新账号任务列表渲染完成；含 Cookie 加载注入、会话令牌切换、任务列表查询 |
| 登录响应时间 | P95 ≤ 2s | 与现有登录流程一致（扫码/浏览器登录不纳入新指标） |
| 并发已登录账号 | ≥ 5 个 | 本地单机支持至少 5 个已登录账号共存，切换无性能衰减 |
| 任务列表加载 | P95 ≤ 200ms | 单账号任务列表查询（含 user_id 过滤索引命中） |
| 菜单配置加载 | P95 ≤ 100ms | `/api/menu` 响应（含默认值合并） |
| 账号列表加载 | P95 ≤ 100ms | `/api/auth/accounts` 响应 |
| 会话校验开销 | P99 ≤ 10ms | 中间件 session_token → user_id 查询（含缓存命中） |
| Cookie 切换注入 | P95 ≤ 300ms | Worker 浏览器实例 Cookie 替换耗时 |

### 5.2 安全性

| 维度 | 要求 |
|---|---|
| 会话令牌生成 | `secrets.token_urlsafe(48)` 生成 64 字符随机串；不可预测 |
| 会话令牌比对 | 使用 `hmac.compare_digest()` 防时序攻击（沿用现有约定） |
| 会话令牌存储 | user_sessions 表存储 sha256(session_token) 哈希；原始令牌仅存 cookie，不落库 |
| Cookie 隔离 | 切换账号时旧 Cookie 必须从 Worker 上下文清除；禁止跨账号 Cookie 残留 |
| 越权访问防护 | 所有按 user_id 隔离的查询必须带 user_id 过滤；中间件注入的 user_id 不可被请求参数覆盖 |
| 会话固定防护 | 登录成功后必须重新签发 session_token，不复用旧令牌 |
| CSRF 防护 | 沿用 `samesite="lax"` + Bearer Token 双重防护；切换账号 API 强制 POST 方法 |
| 会话过期 | session_token 30 天过期；过期后需重新登录该账号（非退出） |
| 敏感字段日志 | 严禁记录 session_token 全文、Cookie 全文；仅记录前 8 位 + 长度；user_id 可记录 |
| 并发切换安全 | 同一浏览器同一时间只有一个活跃 session_token；切换不产生并发会话 |
| 退出账号清理 | 退出账号时 session_token 立即失效（从 user_sessions 删除）；Cookie 清除 |

### 5.3 可维护性

- 用户/会话/Cookie/菜单配置模块化：`web/services/user_manager.py`、`web/services/cookie_store.py`（扩展）、`web/services/menu_manager.py`。
- 菜单元数据注册表 `config/menu_registry.yaml` 为单一事实源，前后端共享，新增菜单零代码变更。
- 数据库迁移脚本幂等可重复执行，支持回滚。
- 会话审计日志保留 90 天，便于排障。

### 5.4 兼容性说明

| 现有约束 / 模块 | 兼容性方案 |
|---|---|
| Web 进程 `with_browser=False` | 多用户会话层独立于浏览器进程，无冲突 |
| `/api/auth/*` 白名单端点 | 保留；新增 `/api/auth/accounts`、`/api/auth/switch`、`/api/menu` 需评估白名单（switch 需鉴权，不入白名单） |
| 前端 fetch `credentials: 'include'` | 沿用；session_token 通过 cookie 自动携带 |
| htmx `<meta>` credentials 配置 | 不影响：本模块前端走 fetch API |
| 401 返回 JSON `{"detail":"Unauthorized"}` | 沿用；session_token 失效返回 401 同格式 |
| `hmac.compare_digest()` token 比对 | session_token 比对沿用此约定 |
| 敏感字段日志约定 | session_token 按敏感字段处理，仅记录前 8 位 |
| WebView2 `CREATE_NEW_CONSOLE` | 不影响 |
| 不引入第三方 UI 库 | 沿用 antd + michelin CSS Token |
| 现有 `WEB_TOKEN` | 保留为设备级管理令牌；首次启动未登录时用于系统设置访问 |
| 现有 `CookieStore` JSON+SQLite 双层 | 扩展 user_id 维度，存储路径按 user_id 区分 |
| 现有 `unified_login.py` `_session_lock` | 语义改为"同一时间仅一个登录流程"，不限制已登录账号数 |
| 现有 `TaskRow` 无 user_id | 迁移新增 user_id 字段，默认 `default`，加索引 |
| 现有 localStorage 配置 | 迁移到 user_preferences 表，归属 default 用户 |
| 权限模块（未实施） | 兼容：多用户会话层在 auth 中间件之后，permission 层在多用户会话层之后叠加 |

### 5.5 可观测性

- 会话事件（登录/切换/退出/Cookie过期）写入 `user_session_events` 表，可在"实时日志"页查看。
- 账号状态探测结果写入事件总线（`infra/event_bus.py` 新增 `USER_*` 事件类型）。
- 切换账号耗时、Cookie 注入耗时打点记录，便于性能监控。

## 6. 用户流程

### 6.1 首次升级迁移流程

```
[升级启动]
   ↓
[检测无 users 表，存在历史数据]
   ↓
[创建 default 用户（user_id='default'）]
   ↓
[迁移现有 Cookie → cookies_default.json + user_id=default]
   ↓
[迁移现有 tasks → user_id=default]
   ↓
[迁移 localStorage 配置 → user_preferences（user_id=default）]
   ↓
[签发 default 用户 session_token → 写 xh_token cookie]
   ↓
[进入主界面，体验与升级前一致]
```

### 6.2 添加新账号流程

```
[顶栏头像 → "添加账号"]
   ↓
[选择登录方式：扫码 / Cookie 注入 / 浏览器导入]
   ↓
[走现有登录流程（unified_login）]
   ↓
[登录成功 → 提取 unb → 查/建 users 记录]
   ↓
[该账号 Cookie 存储到 cookies_{user_id}.json（不影响当前账号）]
   ↓
[签发该账号 session_token → 写入 user_sessions 表（不切换 xh_token）]
   ↓
[账号列表新增该账号，当前活跃账号不变]
   ↓
[提示"账号添加成功，点击切换"]
```

### 6.3 快速切换账号流程

```
[顶栏头像 → 选择目标账号]
   ↓
[POST /api/auth/switch {target_user_id}]
   ↓
[中间件校验当前 session_token 有效]
   ↓
[校验目标 user_id 在当前已登录账号列表中]
   ↓
[签发新 session_token（会话固定防护）→ 更新 xh_token cookie]
   ↓
[加载目标账号 Cookie → 注入 Worker 浏览器（清旧+注新）]
   ↓
[前端刷新：拉取 /api/menu + /api/tasks（带新 user_id）]
   ↓
[界面切换为新账号的任务列表与菜单（≤500ms）]
```

### 6.4 账号 Cookie 过期流程

```
[后台定时探测（每 5 分钟）]
   ↓
[检测某账号 unb 失效]
   ↓
[该账号状态标记 expired → 账号列表显示橙色徽标]
   ↓
[推送通知（复用 notifier 模块）："账号 X 需重新登录"]
   ↓
[用户点击"重新登录" → 走登录流程]
   ↓
[登录成功 → 更新该账号 Cookie → 状态恢复 active]
```

### 6.5 退出账号流程

```
[账号列表 → 目标账号 → "退出账号"]
   ↓
[确认对话框：是否同时删除该账号的任务数据？]
   ↓
[是：删除该 user_id 的 tasks/items/orders 等]
[否：保留任务数据，仅清除 session/cookie/菜单配置]
   ↓
[删除 user_sessions 记录 → 删除 cookies_{user_id}.json]
   ↓
[若退出的是当前活跃账号 → 自动切回 default 或最近使用账号]
   ↓
[账号列表移除该账号]
```

### 6.6 菜单自定义流程

```
[进入"菜单管理"页面]
   ↓
[展示当前菜单列表（含可见性开关、排序拖拽、别名输入）]
   ↓
[用户调整：隐藏"评价"、置顶"任务"、改名"我的任务"]
   ↓
[点击保存 → PUT /api/menu]
   ↓
[持久化到 user_menu_configs（当前 user_id）]
   ↓
[MainLayout 刷新菜单 → 立即生效]
   ↓
[切换到其他账号 → 菜单为该账号独立配置]
[切回 → 仍为自定义配置]
```

## 7. 数据模型

> 所有表存于本地 SQLite，通过 schema 迁移扩展。沿用现有小写蛇形命名约定。

### 7.1 `users`（用户表，新增）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PK | 自增 |
| `user_id` | TEXT UNIQUE | 闲鱼用户 ID（unb 字段）；default 用户固定 `default` |
| `nickname` | TEXT | 闲鱼昵称 |
| `avatar_url` | TEXT | 头像 URL（可空） |
| `custom_alias` | TEXT | 用户自定义别名（可空） |
| `status` | TEXT | active / expired / disabled |
| `created_at` | TEXT | ISO8601 创建时间 |
| `last_active_at` | TEXT | ISO8601 最近活跃时间 |
| `last_login_at` | TEXT | ISO8601 最近登录时间 |

> 索引：`(user_id)` 唯一、`(status)`。

### 7.2 `user_sessions`（用户会话表，新增）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PK | 自增 |
| `user_id` | TEXT | 关联 `users.user_id` |
| `token_hash` | TEXT | sha256(session_token) 哈希；唯一索引 |
| `issued_at` | TEXT | ISO8601 签发时间 |
| `expires_at` | TEXT | ISO8601 过期时间（issued_at + 30d） |
| `last_renewed_at` | TEXT | ISO8601 最近续期时间 |
| `client_ip` | TEXT | 登录时 IP（可空，本地通常 127.0.0.1） |
| `is_active` | BOOL | 是否当前活跃（同一用户可有多个 session，但同浏览器仅一个活跃） |

> 索引：`(token_hash)` 唯一、`(user_id, is_active)`、`(expires_at)`。

### 7.3 `user_cookies`（用户级 Cookie 存储，新增/扩展）

> 替代/扩展现有 `cookie_db.py` 的全局 Cookies 表，新增 `user_id` 维度。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PK | 自增 |
| `user_id` | TEXT | 关联 `users.user_id` |
| `host_key` | TEXT | Cookie 域名 |
| `name` | TEXT | Cookie 名 |
| `value` | TEXT | Cookie 值 |
| `path` | TEXT | 默认 `/` |
| `expires` | INTEGER | 过期时间戳 |
| `is_secure` | BOOL | |
| `is_httponly` | BOOL | |
| `updated_at` | TEXT | ISO8601 |

> 主键：`(user_id, host_key, name)` 复合主键。
> 索引：`(user_id)`、`(user_id, host_key)`。

> JSON 主源对应路径：`data/cookies_{user_id}.json`（替代全局 `cookies.json`）。

### 7.4 `tasks` 表扩展（现有表迁移）

| 新增字段 | 类型 | 说明 |
|---|---|---|
| `user_id` | TEXT | 关联 `users.user_id`，默认 `default` |

> 索引：新增 `(user_id)`、`(user_id, created_at)`、`(user_id, status)`。
> 迁移：`UPDATE tasks SET user_id='default' WHERE user_id IS NULL`。

### 7.5 `user_menu_configs`（用户菜单配置表，新增）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PK | 自增 |
| `user_id` | TEXT | 关联 `users.user_id` |
| `menu_key` | TEXT | 菜单标识（如 `tasks`、`items`、`dashboard`） |
| `visible` | BOOL | 是否可见，默认 true |
| `sort_order` | INT | 排序权重，越小越靠前 |
| `group` | TEXT | 分组（如 `data_view`、`config`、`maintenance`） |
| `custom_label` | TEXT | 自定义显示名（可空，空则用默认名） |
| `updated_at` | TEXT | ISO8601 |

> 主键：`(user_id, menu_key)` 复合主键。
> 索引：`(user_id)`、`(user_id, sort_order)`。

### 7.6 `user_preferences`（用户偏好配置表，新增）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PK | 自增 |
| `user_id` | TEXT | 关联 `users.user_id` |
| `pref_key` | TEXT | 偏好键（如 `task_list_columns`、`page_size`、`sort_field`） |
| `pref_value` | TEXT | JSON 序列化的偏好值 |
| `updated_at` | TEXT | ISO8601 |

> 主键：`(user_id, pref_key)` 复合主键。
> 索引：`(user_id)`。

### 7.7 `user_session_events`（会话事件日志表，新增）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PK | 自增 |
| `user_id` | TEXT | 关联用户（可空，系统事件） |
| `event_type` | TEXT | login / logout / switch / cookie_expired / session_renewed |
| `detail` | TEXT | JSON 详细信息（不含敏感字段） |
| `created_at` | TEXT | ISO8601 |

> 索引：`(user_id, created_at)`、`(event_type)`、`(created_at)`；保留 90 天后清理。

### 7.8 菜单元数据注册表（YAML，新文件）

**文件**：`config/menu_registry.yaml`

```yaml
# 菜单元数据单一事实源，前后端共享
menus:
  - key: dashboard
    label: 仪表盘
    group: overview
    default_visible: true
    default_sort: 0
    route: /app
  - key: tasks
    label: 任务管理
    group: data_view
    default_visible: true
    default_sort: 10
    route: /app/tasks
  - key: items
    label: 商品列表
    group: data_view
    default_visible: true
    default_sort: 20
    route: /app/items
  # ... 其余菜单项
```

### 7.9 关键字段说明

- **user_id**：闲鱼 Cookie `unb` 字段值（字符串）；`unb` 缺失时降级为 `sha256(cookie2)[:16]`；default 用户固定字符串 `default`。
- **session_token**：`secrets.token_urlsafe(48)` 生成 64 字符 URL-safe 随机串；仅存于 cookie，库内只存 sha256 哈希。
- **status 枚举**：`active`（正常）/ `expired`（Cookie 过期）/ `disabled`（已退出/禁用）。
- **menu_key**：与 `menu_registry.yaml` 中 `key` 一一对应；新增菜单只需改 YAML。

## 9. API 设计概要

> 详细字段在概要设计展开，本节列蓝图。所有需鉴权接口通过中间件注入 `request.state.user_id`。

### 9.1 账号管理 API

| 方法 | 路径 | 说明 | 鉴权 |
|---|---|---|---|
| GET | `/api/auth/accounts` | 获取已登录账号列表（含状态、昵称、头像） | 需鉴权 |
| POST | `/api/auth/switch` | 切换活跃账号，body: `{target_user_id}`；返回新 session_token（写 cookie） | 需鉴权 |
| POST | `/api/auth/logout` | 退出当前账号，body: `{delete_tasks?: bool}` | 需鉴权 |
| POST | `/api/auth/logout/{user_id}` | 退出指定账号（管理员/当前活跃账号可调） | 需鉴权 |
| GET | `/api/auth/me` | 获取当前活跃用户信息（扩展返回 user_id、昵称、头像） | 白名单 |
| POST | `/api/auth/me/refresh` | 强制刷新当前用户信息 | 需鉴权 |

### 9.2 菜单配置 API

| 方法 | 路径 | 说明 | 鉴权 |
|---|---|---|---|
| GET | `/api/menu` | 获取当前用户菜单配置（合并 menu_registry 默认值与用户自定义） | 需鉴权 |
| PUT | `/api/menu` | 更新当前用户菜单配置，body: `{items: [{menu_key, visible, sort_order, group, custom_label}]}` | 需鉴权 |
| POST | `/api/menu/reset` | 重置当前用户菜单为默认配置 | 需鉴权 |
| GET | `/api/menu/registry` | 获取菜单元数据注册表（启动时加载） | 白名单 |

### 9.3 用户偏好 API

| 方法 | 路径 | 说明 | 鉴权 |
|---|---|---|---|
| GET | `/api/preferences` | 获取当前用户所有偏好配置 | 需鉴权 |
| GET | `/api/preferences/{key}` | 获取指定偏好键值 | 需鉴权 |
| PUT | `/api/preferences/{key}` | 更新指定偏好，body: `{value: <json>}` | 需鉴权 |
| DELETE | `/api/preferences/{key}` | 删除指定偏好（恢复默认） | 需鉴权 |

### 9.4 会话事件 API

| 方法 | 路径 | 说明 | 鉴权 |
|---|---|---|---|
| GET | `/api/auth/session-events` | 查询会话事件日志（支持时间范围筛选） | 需鉴权 |

### 9.5 现有 API 改造点

| API | 改造说明 |
|---|---|
| `POST /api/auth/login`（unified_login） | 登录成功后识别/创建 users 记录；签发 session_token 而非返回全局 token；Cookie 存储到 `cookies_{user_id}.json` |
| `POST /api/auth/cookie`（cookie_inject） | 注入时识别 user_id；若为新用户则创建记录，不覆盖当前账号 |
| 所有 `/api/tasks/*` | 查询/创建按 `request.state.user_id` 过滤/填充 |
| 所有 `/api/items/*`、`/api/orders/*` 等 | 按 user_id 过滤（隔离范围内的资源） |

### 10.3 与权限模块的兼容

权限模块（v1.1）明确约束"不重写现有 Cookie 认证，在 auth 中间件后追加 permission 层"。本模块的中间件链顺序为：

```
BearerAuthMiddleware（现有，扩展为 session_token 校验）
   → MultiUserMiddleware（本模块，注入 user_id）  ← 实际可合并到 BearerAuthMiddleware
   → PermissionMiddleware（权限模块 v1.1，校验 JWT 权限）
   → 业务路由
```

本模块不冲突权限模块的机器码绑定与套餐体系：权限模块管"这台机器能用什么功能"，本模块管"当前是哪个闲鱼账号在操作"。

### 11.3 安全性测试

| 编号 | 测试点 | 操作 | 预期结果 |
|---|---|---|---|
| TC-S01 | 会话固定防护 | 登录前记录 xh_token；登录后比对 | 登录后 session_token 必须重新签发，不复用旧值 |
| TC-S02 | 越权访问（水平） | A 的 session_token 请求 `/api/tasks?user_id=B` | 返回 A 的任务；user_id 参数被忽略（以中间件注入为准） |
| TC-S03 | 伪造 session_token | 构造随机字符串作为 xh_token | 401 `{"detail":"Unauthorized"}` |
| TC-S04 | 过期 session_token | 使用过期 31 天的 token | 401；需重新登录该账号 |
| TC-S05 | 退出后令牌失效 | 退出账号 A 后用 A 的 token 请求 | 401；user_sessions 记录已删除 |
| TC-S06 | CSRF 防护 | 第三方站点构造表单 POST /api/auth/switch | 被 samesite=lax 拦截；或无 Bearer Token 返回 401 |
| TC-S07 | Cookie 残留检测 | A→B 切换后扫描 Worker 浏览器 | goofish.com 域 Cookie 仅含 B 的；A 的 unb 不存在 |
| TC-S08 | 敏感字段日志 | 查看会话事件日志 | session_token 仅显示前 8 位 + 长度；无 Cookie 全文 |
| TC-S09 | 并发切换安全 | 同一浏览器同时发起两个 switch 请求 | 仅最后一个生效；不产生两个活跃 session |
| TC-S10 | token 比对时序安全 | 多次比对正确/错误 token 计时 | 耗时差异不可区分（hmac.compare_digest） |

## 12. 风险与依赖

### 12.1 风险

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 现有数据迁移失败导致数据丢失 | 用户历史任务丢失 | 迁移前自动备份 SQLite；迁移脚本幂等；失败回滚 |
| Cookie 切换不彻底导致跨账号数据污染 | 账号隔离失效，业务异常 | 切换时先 delete_cookies_by_domain 再注入；自动化测试 TC-I01 覆盖 |
| session_token 机制引入性能开销 | 请求延迟增加 | user_sessions 查询加缓存（5 分钟 TTL）；P99 ≤ 10ms |
| 前端菜单动态渲染导致首屏白屏 | 用户体验下降 | 菜单配置前端缓存 + 骨架屏；缓存未命中时用默认菜单兜底 |
| unb 字段不稳定导致 user_id 漂移 | 同一账号被识别为不同用户 | 降级策略 + 用户手动合并（v1.1）；记录异常告警 |
| 与权限模块集成冲突 | 权限模块上线时改造困难 | 中间件链顺序明确；本模块先行，权限模块叠加在后 |
| 多账号 Cookie 同时维护内存占用 | 内存压力 | Cookie 按需加载，仅活跃账号 Cookie 常驻 Worker；非活跃账号存磁盘 |

### 12.2 依赖

| 依赖项 | 说明 |
|---|---|
| 现有 Cookie 认证模块 | 必须稳定可用（BearerAuthMiddleware、CookieStore） |
| 现有登录流程 | 扫码/Cookie 注入/浏览器导入三种方式保留复用 |
| 现有数据库迁移机制 | 需支持 alembic 或等价 schema 迁移 |
| 现有事件总线 | 用于账号状态变更事件广播 |
| 现有通知模块 | 用于 Cookie 过期提醒推送 |

## 13. 术语表

| 术语 | 定义 |
|---|---|
| user_id | 用户唯一标识，来源于闲鱼 Cookie 的 unb 字段；default 为迁移默认用户 |
| session_token | 会话令牌，每用户独立，64 位 URL-safe 随机串，存于 xh_token cookie |
| WEB_TOKEN | 现有全局管理令牌（.env），保留为设备级认证用，不再作为业务会话凭证 |
| 活跃账号 | 当前通过 session_token 激活的用户，同一浏览器仅一个 |
| 账号切换 | 切换活跃账号，加载对应 Cookie/任务/菜单配置 |
| menu_registry | 菜单元数据注册表（YAML），定义全部菜单默认值，前后端共享 |
| user_menu_configs | 用户级菜单配置表，存储可见性、排序、别名等自定义 |
| 隔离范围 | 按用户隔离的数据：tasks/items/orders/evaluations/events/notifications |
| 全局配置 | 不按用户隔离的系统级配置：AI/价格/通知渠道/抢单策略 |
