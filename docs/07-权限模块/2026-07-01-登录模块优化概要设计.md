## 1. 设计目标与原则

### 1.1 设计目标

把需求规格 §1.2 的 G1~G5 落地为可指导编码的技术方案，回答"中间件怎么改、Cookie 怎么隔离、任务怎么过滤、菜单怎么动态化、数据怎么迁移"。

### 1.2 设计原则

| 原则 | 含义 | 反例 |
|---|---|---|
| **最小入侵** | 复用现有 BearerAuthMiddleware / CookieStore / unified_login 结构，仅扩展不重写 | ❌ 推翻认证体系重写 |
| **单一事实源** | `menu_registry.yaml` 是菜单元数据唯一来源，前后端共享 | ❌ 前端硬编码 + 后端再配一份 |
| **会话与数据解耦** | 会话层（session_token → user_id）只管身份；数据层（tasks.user_id）只管过滤 | ❌ 中间件直接查 tasks 表 |
| **向后兼容** | 现有数据迁移为 default 用户；WEB_TOKEN 保留为管理令牌；现有测试零回归 | ❌ 强制用户重新登录 |
| **沿用现有约束** | `hmac.compare_digest`、JSON 401、httponly+samesite=lax、白名单逐条落实 | ❌ 引入新 token 比对方式 |
| **可回滚** | 数据库迁移幂等；CookieStore 保留全局模式兜底 | ❌ 迁移后无法回退 |

### 1.3 非目标（再次明确）

- ❌ 不做云同步 / 多租户 SaaS（仍是本地单机）
- ❌ 不做账号合并工具（首版仅支持新数据按用户隔离）
- ❌ 不重写闲鱼登录流程（扫码/Cookie注入/浏览器导入保留）
- ❌ 不做账号级 AI 配置隔离（首版 AI 配置全局共享）
- ❌ 不做 OAuth/SSO（首版仅支持闲鱼 Cookie 身份）

## 2. 总体架构

### 2.1 中间件链（改造后）

```
HTTP 请求
   │
   ▼
┌─────────────────────────────────────────────┐
│ BearerAuthMiddleware（扩展）                 │
│  1. 白名单检查（PUBLIC_PREFIXES 保留）        │
│  2. 提取 session_token（xh_token cookie 或    │
│     Authorization 头）                        │
│  3. WEB_TOKEN 管理令牌直通（设备级认证）       │
│  4. session_token → sha256 → 查 user_sessions │
│     → 注入 request.state.user_id              │
│  5. hmac.compare_digest 校验                  │
└──────────────────┬──────────────────────────┘
                   │ request.state.user_id
                   ▼
┌─────────────────────────────────────────────┐
│ PermissionMiddleware（权限模块 v1.1，未实施）  │
│  按 permission_registry.yaml 校验套餐权限     │
│  失败返回 403                                 │
└──────────────────┬──────────────────────────┘
                   │
                   ▼
              业务路由（tasks/items/orders...）
                   │ 查询带 user_id 过滤
                   ▼
              Repository 层
```

> **中间件顺序决策（D1）**：多用户会话校验合并到 `BearerAuthMiddleware` 内部（不新增独立中间件），原因：
> 1. 现有 auth.py 已经在做 token 提取与校验，天然适合扩展为 session_token；
> 2. 避免新增中间件增加请求链路开销（P99 ≤ 10ms 约束）；
> 3. 权限模块 v1.1 仍可在其后叠加，不冲突。

### 2.3 数据流总览

```
[登录流程]
  unified_login 登录成功
    → CookieStore.export_cookies(cookies, user_id)  写 cookies_{uid}.json
    → UserManager.identify_or_create(unb)            识别/创建用户
    → UserManager.issue_session(user_id)             签发 session_token
    → make_auth_response(result, session_token)      写 xh_token cookie

[请求流程]
  任意 API 请求带 xh_token=session_token
    → BearerAuthMiddleware 提取 session_token
    → UserManager.verify_session(token) → user_id
    → request.state.user_id = user_id
    → Repository 查询 WHERE user_id = ?

[切换流程]
  POST /api/auth/switch {target_user_id}
    → UserManager.issue_session(target_user_id)     新 session_token
    → CookieStore.load_for_user(target_user_id)     加载目标 Cookie
    → Worker.inject_cookies(target_cookies)         注入浏览器
    → make_auth_response(result, new_session_token) 写新 xh_token
```

#### 3.2.2 `BearerAuthMiddleware`（改造）

```python
# backend/xianyu_hunter/web/middleware/auth.py（改造后核心逻辑）

class BearerAuthMiddleware(BaseHTTPMiddleware):
    """Bearer Token 认证中间件（多用户会话版）。

    改造点：
    1. token 提取逻辑不变（header 优先，cookie 兜底）；
    2. 先尝试 WEB_TOKEN 管理令牌直通（设备级认证，未登录态访问系统设置）；
    3. 再尝试 session_token → user_sessions 校验 → 注入 request.state.user_id；
    4. 校验失败返回 401 JSON（沿用现有约定）。
    """

    async def dispatch(self, request: Request, call_next):
        # 1. 白名单直通（PUBLIC_PREFIXES 保留不变）
        for prefix in PUBLIC_PREFIXES:
            if request.url.path.startswith(prefix):
                return await call_next(request)
        if request.url.path == "/":
            return await call_next(request)

        from xianyu_hunter.config import get_settings
        from xianyu_hunter.web.services.user_manager import get_user_manager

        # 2. 提取 token（header 优先，cookie 兜底）
        auth_header = request.headers.get("authorization", "")
        if auth_header.startswith("Bearer "):
            req_token = auth_header[7:]
        else:
            req_token = request.cookies.get("xh_token", "")

        if not req_token:
            return self._unauthorized(request)

        # 3. WEB_TOKEN 管理令牌直通（设备级认证）
        # 为什么保留：未登录态访问系统设置、首次初始化、CLI 工具
        web_token = get_settings().web_token
        if hmac.compare_digest(req_token.encode(), web_token.encode()):
            # 管理令牌无 user_id，降级为 default（兼容单用户模式）
            request.state.user_id = UserManager.DEFAULT_USER_ID
            return await call_next(request)

        # 4. session_token 校验（多用户会话）
        user_manager = get_user_manager()
        user_id = user_manager.verify_session(req_token)
        if user_id:
            request.state.user_id = user_id
            return await call_next(request)

        return self._unauthorized(request)

    def _unauthorized(self, request: Request):
        """401 统一返回 JSON（沿用现有约定）"""
        if request.url.path.startswith("/api/"):
            return JSONResponse(status_code=401, content={"detail": "Unauthorized"})
        return JSONResponse(status_code=401, content={"detail": "Unauthorized"})
```

> **决策 D2：WEB_TOKEN 保留为管理令牌**。未登录态下用户需要访问系统设置、首次初始化等，WEB_TOKEN 作为设备级认证令牌保留。通过管理令牌的请求降级为 `default` 用户，兼容单用户模式。代价是管理令牌泄露后可绕过多用户隔离，但本地单机场景风险可控。

```python
    def upsert_cookie_values(self, upserts: dict[str, dict],
                             user_id: str = "default") -> bool: ...

    def load_cookies_for_user(self, user_id: str) -> list[dict]:
        """加载指定用户的 Cookie 列表（切换账号时调用）"""
        ...

    def delete_user_cookies(self, user_id: str) -> None:

```

> **决策 D3：JSON 路径按 user_id 区分而非单文件分桶**。原因：
> 1. 现有 `cookies.json` 是原子写入（tmp.replace），单文件分桶需重写并发控制；
> 2. 按 user_id 分文件天然隔离，退出账号时直接删文件，无需读改写；
> 3. 迁移简单：`cookies.json` → `cookies_default.json` 重命名即可。

```python
# backend/xianyu_hunter/web/startup.py 新增迁移逻辑

async def migrate_to_multi_user(db_path: str) -> None:
    """首次升级迁移：单用户 → 多用户（幂等可重复执行）

    迁移步骤：
    1. 检测 users 表是否存在（幂等判断）
    2. 创建 default 用户
    3. 迁移现有 cookies.json → cookies_default.json
    4. tasks 表新增 user_id 字段（ALTER TABLE，幂等）
    5. 现有 tasks.user_id 填充 'default'
    6. 签发 default 用户 session_token
    """
    # 1. 幂等判断
    if _users_table_has_default(db_path):
        return  # 已迁移

    # 2. 创建 default 用户
    now = datetime.now(timezone.utc).isoformat()
    _execute(db_path, """
        INSERT OR IGNORE INTO users (user_id, nickname, status, created_at, last_active_at)
        VALUES ('default', '默认用户', 'active', ?, ?)
    """, now, now)

    # 3. 迁移 Cookie 文件
    old_path = Path("data/cookies.json")
    new_path = Path("data/cookies_default.json")
    if old_path.exists() and not new_path.exists():
        old_path.rename(new_path)
        logger.info("迁移 cookies.json → cookies_default.json")

    # 4-5. tasks 表迁移（ALTER TABLE 幂等处理）
    _safe_add_column(db_path, "tasks", "user_id", "TEXT DEFAULT 'default'")
    _execute(db_path, "UPDATE tasks SET user_id='default' WHERE user_id IS NULL OR user_id=''")
    _create_index_if_not_exists(db_path, "idx_tasks_user", "tasks", "user_id")
    _create_index_if_not_exists(db_path, "idx_tasks_user_created", "tasks", "user_id, created_at")
    _create_index_if_not_exists(db_path, "idx_tasks_user_status", "tasks", "user_id, status")

    logger.info("多用户数据迁移完成")


def _safe_add_column(db_path: str, table: str, column: str, definition: str) -> None:
    """安全添加列（SQLite 不支持 IF NOT EXISTS for ADD COLUMN，需先检测）"""
    cols = _execute(db_path, f"PRAGMA table_info({table})")
    if not any(c[1] == column for c in cols):
        _execute(db_path, f"ALTER TABLE {table} ADD COLUMN {column} {definition}")
```

## 5. 关键算法

### 5.1 用户身份识别

```python
def identify_or_create(self, cookies: list[dict]) -> str:
    """从 Cookie 列表识别用户身份。

    优先级：unb（8位以上数字）> sha256(cookie2)[:16] > "default"
    """
    cookie_map = {c["name"]: c.get("value", "") for c in cookies}

    # 1. 优先用 unb（闲鱼用户 ID）
    unb = cookie_map.get("unb", "")
    if unb and re.match(r"^\d{8,}$", unb):
        user_id = unb
    # 2. 降级：cookie2 哈希
    elif cookie_map.get("cookie2"):
        user_id = hashlib.sha256(cookie_map["cookie2"].encode()).hexdigest()[:16]
    # 3. 最终降级
    else:
        user_id = "default"

    # 查/建用户记录
    if not self.get_user(user_id):
        nickname = self._fetch_nickname(cookies)  # 从 userinfo 拉取
        self._create_user(user_id, nickname)
    self.update_last_active(user_id)
    return user_id
```

> **决策 D4：unb 降级策略**。`unb` 是闲鱼用户 ID 字段，正常登录必返回。降级到 `sha256(cookie2)[:16]` 是为了应对极端情况（如某些 Cookie 注入场景 unb 缺失），避免无法识别用户。`default` 是最终兜底，保证不阻断流程。

### 5.2 会话令牌签发与校验

```python
def issue_session(self, user_id: str) -> str:
    """签发 session_token"""
    token = secrets.token_urlsafe(48)  # 64 字符 URL-safe
    token_hash = hashlib.sha256(token.encode()).hexdigest()

    # 旧 session 失效（会话固定防护：每次登录/切换重新签发）
    self._execute(
        "UPDATE user_sessions SET is_active=0 WHERE user_id=? AND is_active=1",
        (user_id,)
    )

    now = datetime.now(timezone.utc)
    expires = now + timedelta(days=self.SESSION_TTL_DAYS)
    self._execute(
        """INSERT INTO user_sessions
           (user_id, token_hash, issued_at, expires_at, last_renewed_at, is_active)
           VALUES (?, ?, ?, ?, ?, 1)""",
        (user_id, token_hash, now.isoformat(), expires.isoformat(), now.isoformat())
    )
    return token  # 仅返回原始 token，库内只存哈希


def verify_session(self, session_token: str) -> str | None:
    """校验 session_token → user_id"""
    if not session_token:
        return None

    token_hash = hashlib.sha256(session_token.encode()).hexdigest()

    # 缓存命中（5 分钟 TTL）
    cached = self._verify_cache.get(token_hash)
    if cached and (time.time() - cached[1]) < self._VERIFY_CACHE_TTL:
        return cached[0]

    # 查库
    now = datetime.now(timezone.utc)
    row = self._query_one(
        """SELECT user_id, expires_at FROM user_sessions
           WHERE token_hash=? AND is_active=1""",
        (token_hash,)
    )
    if not row:
        return None

    # hmac.compare_digest 比对（防时序攻击，即使已查到也走一次比对）
    stored_hash = row["token_hash"]  # 实际已通过 WHERE 匹配，此处为防御性编程
    if not hmac.compare_digest(token_hash, stored_hash):
        return None

    # 过期检查
    if datetime.fromisoformat(row["expires_at"]) < now:
        self._execute("UPDATE user_sessions SET is_active=0 WHERE token_hash=?", (token_hash,))
        return None

    # 滑动续期（距过期 < 7 天时续期）
    expires = datetime.fromisoformat(row["expires_at"])
    if (expires - now).days < 7:
        new_expires = now + timedelta(days=self.SESSION_TTL_DAYS)
        self._execute(
            "UPDATE user_sessions SET expires_at=?, last_renewed_at=? WHERE token_hash=?",
            (new_expires.isoformat(), now.isoformat(), token_hash)
        )

    # 缓存
    self._verify_cache[token_hash] = (row["user_id"], time.time())
    return row["user_id"]
```

### 5.3 Cookie 切换注入

```python
async def switch_account(target_user_id: str) -> dict:
    """切换账号：签发新 session + 加载目标 Cookie + 注入 Worker

    关键步骤：
    1. 校验目标 user_id 在已登录账号列表中
    2. 签发新 session_token（会话固定防护）
    3. 加载目标账号 Cookie
    4. 清除 Worker 浏览器旧 Cookie + 注入新 Cookie
    5. 返回新 session_token（写 cookie）
    """
    user_manager = get_user_manager()
    cookie_store = get_cookie_store()

    # 1. 校验目标用户存在且 active
    target = user_manager.get_user(target_user_id)
    if not target or target["status"] != "active":
        raise ValueError("目标账号不可用")

    # 2. 签发新 session
    new_token = user_manager.issue_session(target_user_id)

    # 3. 加载目标 Cookie
    target_cookies = cookie_store.load_cookies_for_user(target_user_id)
    if not target_cookies:
        raise ValueError("目标账号无有效 Cookie")

    # 4. 注入 Worker 浏览器（先清后注，保证隔离）
    from xianyu_hunter.web.services.cookie_db import delete_cookies_by_domain
    # 清除闲鱼/淘宝域所有旧 Cookie
    for domain in ("goofish", "taobao"):
        delete_cookies_by_domain(_get_worker_conn(), domain)
    # 注入目标 Cookie
    cookie_store._sync_to_sqlite(target_cookies, user_id=target_user_id)

    # 5. 更新活跃时间 + 记录事件
    user_manager.update_last_active(target_user_id)
    user_manager._log_event(target_user_id, "switch", {"from": "current"})

    return {"user_id": target_user_id, "session_token": new_token}
```

> **决策 D5：切换时先删后注而非直接覆盖**。直接覆盖可能残留旧账号的 Cookie（如某些域的 Cookie 新账号没有），导致跨账号数据污染。先 `delete_cookies_by_domain` 清除闲鱼/淘宝域所有 Cookie，再注入目标账号 Cookie，保证隔离彻底。代价是切换耗时增加约 50ms（删除操作），但总耗时仍 ≤ 500ms。

### 5.4 菜单配置合并

```python
def get_menu_for_user(self, user_id: str) -> list[dict]:
    """合并 registry 默认值 + 用户自定义"""
    # 1. 加载用户配置（无配置则空字典）
    user_configs = self._load_user_configs(user_id)  # {menu_key: {visible, sort_order, ...}}

    # 2. 合并：以 registry 为基底，用户配置覆盖
    result = []
    for item in self._defaults:
        key = item["key"]
        merged = {
            "key": key,
            "label": item["label"],
            "group": item["group"],
            "route": item["route"],
            "icon": item["icon"],
            "visible": item["default_visible"],
            "sort_order": item["default_sort"],
        }
        # 用户配置覆盖
        if key in user_configs:
            uc = user_configs[key]
            merged["visible"] = bool(uc.get("visible", merged["visible"]))
            merged["sort_order"] = uc.get("sort_order", merged["sort_order"])
            merged["group"] = uc.get("group_name", merged["group"]) or merged["group"]
            if uc.get("custom_label"):
                merged["label"] = uc["custom_label"]
        result.append(merged)

    # 3. 按 sort_order 升序排列
    result.sort(key=lambda x: x["sort_order"])
    return result
```

### 5.5 账号状态探测

```python
async def probe_all_accounts(self) -> None:
    """定时探测所有账号 Cookie 有效性（每 5 分钟，后台任务）

    策略：
    - 遍历 users 表所有 active 账号
    - 检查该账号 cookies_{uid}.json 中 unb 是否存活
    - 失效账号标记 expired + 发事件通知
    - 恢复账号标记 active
    """
    for user in self.list_users():
        if user["status"] == "disabled":
            continue
        cookie_store = get_cookie_store()
        is_valid, reason = cookie_store.validate_cookies_with_expiry(user["user_id"])
        if not is_valid and user["status"] == "active":
            self.set_user_status(user["user_id"], "expired")
            self._log_event(user["user_id"], "cookie_expired", {"reason": reason})
            # 推送通知（复用现有 notifier）
            _notify_cookie_expired(user)
        elif is_valid and user["status"] == "expired":
            self.set_user_status(user["user_id"], "active")
            self._log_event(user["user_id"], "cookie_recovered", {})
```

## 8. 安全设计

### 8.1 会话令牌安全

| 维度 | 措施 |
|---|---|
| 令牌生成 | `secrets.token_urlsafe(48)` 生成 64 字符 URL-safe 随机串，不可预测 |
| 令牌存储 | 库内只存 `sha256(token)` 哈希；原始令牌仅存 cookie，不落库 |
| 令牌比对 | `hmac.compare_digest()` 防时序攻击（沿用现有约定） |
| 会话固定防护 | 每次 login/switch 重新签发 token，旧 token 立即 is_active=0 |
| 会话过期 | 30 天有效；过期需重新登录该账号 |
| 滑动续期 | 距过期 < 7 天时自动续期；活跃使用无感 |

### 8.2 数据隔离安全

| 维度 | 措施 |
|---|---|
| user_id 注入 | 中间件注入 `request.state.user_id`，业务代码不可被请求参数覆盖 |
| 查询过滤 | Repository 层所有隔离范围查询必须带 `WHERE user_id = ?` |
| 越权防护 | `GET /api/tasks?user_id=B` 时忽略参数 user_id，以中间件注入为准 |
| Cookie 隔离 | 切换时先 `delete_cookies_by_domain` 再注入，禁止残留 |
| 退出清理 | 退出账号时立即删除 session + Cookie 文件 + 菜单配置 |

### 8.3 日志脱敏

```python
def mask_token(token: str) -> str:
    """日志中 session_token 只记录前 8 位 + 长度（沿用敏感字段约定）"""
    return f"{token[:8]}***(len={len(token)})" if token else ""

def mask_cookie_value(name: str, value: str) -> str:
    """Cookie 值不记录全文，仅记录是否存在"""
    return f"{name}={'present' if value else 'empty'}"
```

### 8.4 CSRF 防护

- 沿用 `samesite="lax"` + Bearer Token 双重防护
- 切换账号 API `POST /api/auth/switch` 强制 POST 方法，拒绝 GET
- 白名单不变：`/api/auth/switch` 不入白名单（需鉴权）

## 11. 风险与决策记录

### 11.1 关键设计决策

| ID | 决策 | 理由 | 替代方案 | 影响 |
|---|---|---|---|---|
| D1 | 多用户会话校验合并到 BearerAuthMiddleware | 现有 auth.py 已做 token 提取校验，天然适合扩展；避免新增中间件增加链路开销 | 新增独立 MultiUserMiddleware | 代码耦合度略增，但性能更优 |
| D2 | WEB_TOKEN 保留为管理令牌 | 未登录态需访问系统设置/首次初始化；降级为 default 用户兼容单用户模式 | 废弃 WEB_TOKEN | 管理令牌泄露可绕过隔离，但本地单机风险可控 |
| D3 | Cookie JSON 按 user_id 分文件 | 原子写入天然隔离；退出账号直接删文件；迁移简单（重命名） | 单文件分桶 | 文件数增加，但隔离更彻底 |
| D4 | unb 降级 sha256(cookie2)[:16] | 应对 unb 缺失的极端场景；避免无法识别用户 | 强制要求 unb | 某些 Cookie 注入场景无法登录 |
| D5 | 切换时先删后注 Cookie | 直接覆盖可能残留旧账号 Cookie 导致跨账号污染 | 直接覆盖 | 切换耗时 +50ms，但隔离更彻底 |
| D6 | session_token 库内只存 sha256 哈希 | 防库泄露后伪造；原始令牌仅存 cookie | 明文存储 | 查询需 sha256 后比对，性能影响可忽略 |
| D7 | menu_registry.yaml 不纳入 KB 索引 | project_memory 硬约束只索引 .md/.py/.jsonl/.txt；YAML 由 MenuManager 独立加载 | 改用 .json 格式 | 损失 YAML 可读性 |
| D8 | 会话校验结果缓存 5 分钟 | 避免每次请求查库；P99 ≤ 10ms 约束 | 每次查库 | 退出后最多 5 分钟内旧 token 仍可用（is_active=0 时缓存失效） |

### 11.2 已识别风险

| 风险 | 等级 | 缓解 |
|---|---|---|
| 数据迁移失败导致历史任务丢失 | 高 | 迁移前自动备份 SQLite；脚本幂等；失败回滚 |
| Cookie 切换不彻底导致跨账号污染 | 高 | 先删后注；自动化测试 TC-I01 覆盖 |
| unb 字段不稳定导致 user_id 漂移 | 中 | 降级策略 + v1.1 账号合并工具；记录异常告警 |
| session_token 机制引入性能开销 | 中 | 校验结果缓存 5 分钟；P99 ≤ 10ms |
| 前端菜单动态渲染导致首屏白屏 | 中 | 缓存 + 骨架屏 + registry 默认值兜底 |
| 多账号 Cookie 同时维护内存占用 | 中 | 仅活跃账号 Cookie 常驻 Worker；非活跃存磁盘 |
| 与权限模块集成冲突 | 低 | 中间件链顺序明确；本模块先行，权限模块叠加在后 |
| 会话校验缓存导致退出后仍可用 | 低 | is_active=0 时立即失效缓存；最多 5 分钟窗口 |
