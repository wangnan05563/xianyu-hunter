## 1. 背景与目标

### 1.1 背景

XianyuHunter 当前为"一次性下载即用"的本地单机工具，无任何商业回收路径。为支撑后续商业化运营，需要新增一套完整的**系统权限模块**，将"免费工具"升级为"试用 + 订阅 + 按需购买"的商业模式。

| 现状 | 痛点 |
|---|---|
| 任意用户下载后可永久使用全部功能 | 无法回收研发成本，无法做用户分层 |
| 无到期机制 | 老版本散落无法统一回收，安全补丁无法触达 |
| 无付费通道 | 用户想付费"加量"也无入口 |
| 无功能分级 | 高级能力（AI 评估、自动抢单）与基础能力混用，难以差异化定价 |

### 1.2 核心目标

| 目标编号 | 描述 | 可衡量指标 |
|---|---|---|
| G1 | **全功能授权拦截**：所有功能模块均需有效授权才能访问 | 后端 100% API 走权限中间件；前端 100% 路由有权限守卫 |
| G2 | **生命周期闭环**：到期提醒 → 续期 → 过期限制 → 重新激活 | 到期前 7/3/1 天三次提醒；过期 ≤ 24h 内功能降级生效 |
| G3 | **独立购买流程**：用户可在系统内自助购买权限套餐 | 从打开购买页到完成扫码支付 ≤ 5 步操作 |
| G4 | **灵活定价**：支持套餐、梯度、优惠码三种调价手段 | 运营可零代码上线新套餐 / 优惠券 |
| G5 | **商业闭环**：查询 → 购买 → 支付 → 激活可追溯 | 每笔订单可回溯到授权激活记录，激活成功率 ≥ 99% |

### 1.3 非目标

- ❌ 不实现软件防盗版追踪与司法取证（仅做基础机器码绑定，不做反逆向）。
- ❌ 不实现多租户 SaaS（仍是单机部署 + 云端授权服务两段式）。
- ❌ 不实现应用内广告变现（首版只走订阅 + 套餐买断）。
- ❌ 不实现积分 / 钱包 / 推广返佣体系（留待 v2.0 评估）。
- ❌ 不实现退款自动化（首版退款走人工审核 + 后台手动撤销授权）。
- ❌ 不重写现有 Cookie 认证（仅在 auth 中间件后追加 permission 层）。

## 2. 范围与约束

### 2.1 范围内（In-Scope）

- 客户端（XianyuHunter 本体）：
  - 机器码采集与本地授权校验
  - "我的授权"前端页面（状态查看、续期入口、订单记录）
  - 购买流程前端（套餐选择、优惠码、扫码支付、激活回调）
  - 到期提醒通知（复用 notifier 模块）
  - 过期功能降级机制（功能开关 + 路由守卫）
- 云端授权服务（License Server，独立部署）：
  - 套餐与定价管理（CRUD + 上下架）
  - 优惠码管理
  - 订单管理（创建、查询、回调、对账）
  - 微信 Native 支付下单与回调
  - 授权发放、激活、续期、撤销
  - 管理员后台（订单 / 用户 / 套餐 / 优惠码）
- 系统集成：
  - 与现有 Cookie 认证、通知模块、配置管理、关于页面的对接

### 2.2 范围外（Out-of-Scope）

- 微信 App 支付、支付宝、银行卡支付（首版仅微信 Native 扫码）
- 自动续费 / 微信代扣（合规与开发成本高，留待 v1.1）
- 离线激活码（首版需联网激活）
- 多语言授权文案（首版仅中文）
- 团队 / 企业账号授权池（首版一码一机）

### 2.3 关键约束

| 约束类别 | 说明 |
|---|---|
| 部署形态 | 客户端 = Windows 10 单机；云端授权服务 = Linux Docker 单实例 |
| 网络可用性 | 客户端首次启动、续期、购买需联网；日常运行允许离线 ≤ 72h（缓存授权） |
| 合规边界 | 微信支付需走商户号正规接入；优惠码需有"过期 + 次数 + 适用套餐"三重限制 |
| 账号安全 | 机器码与授权码一对一绑定；授权码不可转让；转让需管理员后台解绑 |
| 数据安全 | 微信商户密钥、API 签名密钥仅存云端；客户端只缓存授权令牌（JWT，72h 过期） |
| 性能 | 权限校验同步链路 ≤ 20ms（本地缓存命中）/ ≤ 800ms（缓存失效回源） |
| 兼容性 | 不破坏现有未授权用户的"试用模式"基础体验（见 §3.3） |

## 3. 用户与场景

### 3.1 角色定义

| 角色 | 描述 | 主要场景 |
|---|---|---|
| **试用用户**（Visitor） | 未购买任何权限的新用户 | 试用基础功能；查看套餐；下单购买 |
| **正式用户**（Licensed User） | 已购买套餐并激活的用户 | 使用已授权功能；到期前续期；升级套餐 |
| **过期用户**（Expired User） | 授权已过期未续期的用户 | 查看历史订单；续期恢复功能；功能受限下使用 |
| **运营管理员**（Operator） | 云端授权服务后台运营 | 维护套餐与定价；审核退款；查看订单报表 |
| **超级管理员**（Super Admin） | 系统级管理员 | 管理运营账号；配置支付商户号；解绑机器码 |

### 3.2 典型使用场景

**场景 A：新用户试用 → 购买专业版**
> 用户下载安装 XianyuHunter，首次启动看到"试用模式"提示，可使用基础搜索功能。
> 配置第一个任务后系统弹出"升级专业版解锁自动抢单"引导卡片，用户点击 → 跳转"我的授权"页面 → 选择"专业版月卡 ¥39" → 输入优惠码"NEW10" → 显示微信支付二维码 → 扫码支付成功 → 3 秒内自动激活 → 全功能解锁。

**场景 B：到期前续期**
> 用户专业版授权将在 3 天后到期。系统在到期前 7/3/1 天分别通过微信推送提醒。
> 用户点击提醒中的"续期"链接 → 跳转续期页 → 默认选中"原套餐续期 1 个月" → 微信扫码支付 → 授权期限顺延 30 天。

**场景 C：过期后恢复**
> 用户授权已过期 5 天，打开系统发现自动抢单功能被禁用，前端显示"授权已过期，点击续期"提示条。
> 用户点击 → 进入"我的授权"页 → 选择续期 → 支付 → 授权激活，过期期间未使用的功能恢复，过期期间产生的数据保留。

**场景 D：管理员上线优惠活动**
> 运营在云端后台"定价管理 → 优惠活动"中创建"618 大促，全场 8 折，有效期 6/15-6/20"活动。
> 活动生效期间，客户端购买页自动展示折扣价；活动结束后价格自动恢复。

**场景 E：用户换机解绑**
> 用户更换电脑，在新机器上登录时提示"该授权已绑定其他设备"。
> 用户在原机器上点击"解绑"按钮（每 90 天限 1 次）→ 在新机器重新激活。
> 若原机器已丢失，提交工单由管理员后台强制解绑。

### 3.3 试用模式策略

| 功能分类 | 试用模式可用性 | 备注 |
|---|---|---|
| 任务管理（F1） | ✅ 最多 2 个任务 | 超出引导购买 |
| 数据采集（F2） | ✅ 完整可用 | 但每任务每日限量 50 条采集 |
| 价格策略（F3） | ⚠️ 仅基础价格上限 | 高级策略需专业版 |
| 卖家评估（F4） | ⚠️ 每日限 10 次评估 | AI 评分需专业版 |
| 自动下单（F5） | ❌ 禁用 | 仅专业版及以上 |
| 通知推送（F6） | ✅ 完整可用 | 不限制 |
| 智能客服（F7） | ⚠️ 每日限 5 次对话 | 完整 KB 检索需专业版 |
| 数据导出（F8） | ❌ 禁用 | 仅专业版及以上 |
| 系统维护（F9） | ✅ 完整可用 | 不限制 |
| 关于页面（F10） | ✅ 完整可用 | 不限制 |

## 4. 功能需求

> 编号约定：L = License Module。优先级 P0/P1/P2 = 必须 / 应该 / 可选。

### 4.1 权限控制机制（L1）

| 编号 | 功能 | 优先级 | 说明 |
|---|---|---|---|
| L1.1 | 机器码生成 | P0 | 采集主板序列号 + CPU ID + 磁盘序列号 + MAC 地址 SHA256 摘要，输出 32 位机器码；首次启动生成并上报云端 |
| L1.2 | 授权令牌签发 | P0 | 云端用机器码 + 套餐 ID + 到期时间签发 JWT（HS256），客户端缓存 72h |
| L1.3 | 后端权限中间件 | P0 | 在现有 `auth.py` 后追加 `PermissionMiddleware`，按路由表配置的所需权限校验 JWT 内的 `permissions` 字段 |
| L1.4 | 前端路由守卫 | P0 | 在 `App.tsx` 路由表配置 `meta.permission`，未授权时跳"升级引导页" |
| L1.5 | 功能开关注册表 | P0 | 维护 `permission_registry.yaml`，定义功能点 → 所需权限的映射；前后端共享 |
| L1.6 | 权限缓存与回源 | P0 | 客户端缓存 JWT + 套餐信息；缓存命中走本地校验；过期或缓存失效走云端 `/license/verify` |
| L1.7 | 离线宽限期 | P1 | 超过 72h 未能联网校验，进入"宽限期"，仍可用 24h；超时后只读模式 |
| L1.8 | 权限降级行为 | P0 | 过期/无权限时：API 返回 `403 + {"detail":"Forbidden","code":"PERMISSION_DENIED","required":"pro"}`；前端展示升级引导 |
| L1.9 | 管理员后门 | P1 | 超级管理员 token 可绕过权限校验，用于排障；需在审计日志记录每次使用 |
| L1.10 | 权限审计日志 | P1 | 记录每次权限校验失败、降级触发、绕过使用，保留 90 天 |

### 4.2 权限生命周期管理（L2）

| 编号 | 功能 | 优先级 | 说明 |
|---|---|---|---|
| L2.1 | 到期日历 | P0 | 客户端"我的授权"页展示当前套餐、到期日、剩余天数，倒计时 ≤ 7 天高亮橙色 |
| L2.2 | 到期提醒推送 | P0 | 到期前 7/3/1 天，通过 notifier 模块推送提醒；支持用户自定义提醒渠道复用现有 22 种事件订阅模型 |
| L2.3 | 到期前禁用预判 | P1 | 到期前 24h，自动抢单等关键功能降级为"半自动"，避免临到期下单未支付导致纠纷 |
| L2.4 | 续期流程入口 | P0 | "我的授权"页"立即续期"按钮 → 续期页 → 默认续当前套餐 1 个周期 |
| L2.5 | 续期价格计算 | P0 | 续期价格 = 当前套餐当前价 × 周期数 × 优惠码折扣；过期 30 天内续期补差价 0 |
| L2.6 | 续期时长叠加 | P0 | 续期后到期日 = max(原到期日, now) + 购买周期；不允许"提前续期反而吃亏" |
| L2.7 | 过期功能限制 | P0 | 过期后高阶功能禁用，但允许查看历史数据；7 天宽限期后所有采集/抢单功能停用 |
| L2.8 | 过期数据保留 | P0 | 过期用户数据保留 180 天；180 天内续期则恢复全部数据；超期清理 |
| L2.9 | 自动续期（暂不实现） | P2 | v1.0 不做，预留字段 `auto_renew` |
| L2.10 | 授权撤销 | P1 | 管理员后台可撤销指定授权；客户端下次校验时拉取撤销列表，立即失效 |

| L3.5 | 升级补差价 | P1 | 已购用户升级到更高套餐，按剩余天数比例补差价 |

| L3.7 | 微信扫码支付 | P0 | 调用云端 `/order/wechat/native` 获取二维码 URL，前端用 `qrcode.js` 渲染 |

| L3.12 | 订单取消 | P1 | 未支付订单 30min 自动取消；用户可主动取消 |
| L3.13 | 退款申请 | P2 | 用户在订单记录提交退款申请（仅 7 天内未使用），人工审核 |

| L4.2 | 套餐定价 | P0 | 每套餐 × 每周期配置价格；支持原价 / 现价双字段（用于"划线价"展示） |

| L4.6 | 优惠码校验 | P0 | 客户端调用 `/coupon/validate` 实时校验优惠码，返回折后价 |

| L4.9 | 上下架控制 | P0 | 套餐可单独上下架；下架后客户端不再展示，但已购用户不受影响 |
| L4.10 | 价格报表 | P2 | 管理员后台报表：套餐销量、优惠码使用率、活动 ROI |

### 4.5 商业流程（L5）

| 编号 | 功能 | 优先级 | 说明 |
|---|---|---|---|
| L5.1 | 商业闭环主链路 | P0 | 查询授权 → 选择套餐 → 应用优惠 → 确认订单 → 扫码支付 → 自动激活 → 返回功能页 |
| L5.2 | 微信二维码生成 | P0 | 云端调用微信 Native 支付 API 获取 `code_url`，前端渲染二维码；二维码有效期 2h |
| L5.3 | 二维码刷新 | P1 | 二维码过期前 5min 自动刷新；用户也可手动点击刷新 |
| L5.4 | 支付回调签名校验 | P0 | 回调使用微信商户平台证书校验签名；失败重试 3 次后告警 |
| L5.5 | 订单幂等处理 | P0 | 同一订单多次回调只生效一次；用 `order_id` + `status` 唯一索引保证 |
| L5.6 | 授权发放 | P0 | 支付成功后云端调用 `issue_license()` 生成授权记录并签发 JWT |
| L5.7 | 授权激活 | P0 | 客户端拉取 JWT，写入本地 `license_cache.json`（仅存 JWT，不存私钥） |
| L5.8 | 续期授权 | P0 | 续期订单成功后，云端 `extend_license()` 顺延到期日，签发新 JWT |
| L5.9 | 升级授权 | P1 | 升级订单成功后，云端 `upgrade_license()` 替换套餐，立即生效 |
| L5.10 | 对账文件 | P2 | 每日生成对账 CSV：订单号、金额、套餐、支付时间、状态；管理员可下载 |
| L5.11 | 发票申请 | P2 | 用户提交发票抬头，管理员后台开票后回填发票 PDF 链接 |

## 5. 非功能需求

### 5.1 性能

| 指标 | 目标 |
|---|---|
| 权限校验本地缓存命中 | P99 ≤ 20ms |
| 权限校验缓存失效回源 | P99 ≤ 800ms |
| 套餐列表加载 | P99 ≤ 1.5s（含网络） |
| 二维码生成 | P99 ≤ 2s（云端调用微信 API） |
| 支付回调 → 客户端激活 | P99 ≤ 5s |
| 管理员后台订单查询 | P99 ≤ 2s（10 万订单规模） |

### 5.2 可用性

- 客户端授权服务可用性目标 99.5%（月度），允许单点故障 3.6h。
- 云端授权服务降级策略：微信支付不可用时，前端提示"支付通道维护中"，已购用户不受影响。
- 客户端授权缓存机制保证云端宕机 72h 内本地功能正常。

### 5.3 安全性

| 维度 | 要求 |
|---|---|
| 机器码采集 | 仅使用硬件序列号哈希，不采集 IP、用户名等可识别信息 |
| JWT 签名 | HS256 + 服务端密钥轮换（每 90 天）；密钥仅存云端环境变量 |
| 机器码绑定 | 一码一机；同一授权不可在两台机器同时激活 |
| 支付签名 | 微信商户平台 API v3，使用 SHA256-RSA 签名 |
| 优惠码防刷 | 单 IP 限频 + 单设备指纹 + 单账号限用次数三层校验 |
| 敏感字段日志 | 严禁记录 JWT 全文、支付密钥、商户号；只记录前 8 位 + 长度 |
| 数据库加密 | 客户端 `license_cache.json` 使用 AES-256 加密存储；密钥派生自机器码 |
| 传输加密 | 客户端 ↔ 云端强制 HTTPS；HSTS 启用 |
| 防重放 | JWT 内嵌 `jti`，云端维护已撤销 `jti` 列表 30 天 |
| 防时序攻击 | 授权码 / 优惠码比对使用 `hmac.compare_digest()` |

### 5.4 可维护性

- 云端授权服务模块化：`pricing` / `order` / `license` / `wechat_pay` / `admin` 五个独立模块。
- 套餐、价格、优惠码配置走数据库 + 管理后台，零代码变更。
- 权限注册表 `permission_registry.yaml` 是单一事实源，前后端共享。
- 所有商业流程步骤有审计日志，便于排障。

### 5.5 兼容性

- 客户端不破坏现有未授权用户的"试用模式"基础体验。
- 现有 SQLite schema 通过 alembic 迁移扩展，不破坏现有表。
- 现有 `auth.py` 中间件保留向后兼容，新增 `PermissionMiddleware` 在其后追加。
- 现有 orders 表保留抢单记录语义不变；权限订单走新表 `license_orders`。

### 5.6 可观测性

- 客户端：权限校验失败 / 降级 / 缓存失效事件写入本地 `permission_events` 表，可在"实时日志"页查看。
- 云端：订单创建 / 支付回调 / 授权发放 / 撤销四类事件写入 `audit_logs`，Prometheus 暴露指标。
- 告警：支付回调失败率 > 1%、激活失败率 > 0.5% 触发企业微信告警。

## 6. 用户流程

### 6.1 首次购买流程

```
[启动系统]
   ↓
[权限中间件校验] ──无有效授权──→ [试用模式引导页]
   ↓                                    ↓
[进入主界面]                    [点击"升级专业版"]
                                        ↓
                                [套餐列表页]
                                        ↓
                                [选择"专业版" + 周期"月"]
                                        ↓
                                [输入优惠码（可选）] → [应用] → [实时算价]
                                        ↓
                                [订单确认页] → [确认下单]
                                        ↓
                                [云端创建订单 + 调用微信 Native 下单]
                                        ↓
                                [前端展示二维码]
                                        ↓
                                [用户微信扫码支付]
                                        ↓
                                [前端轮询订单状态 / SSE 推送]
                                        ↓
                                [微信回调云端 → 发放授权]
                                        ↓
                                [客户端拉取 JWT → 写入本地缓存]
                                        ↓
                                [跳转"授权激活成功"页]
                                        ↓
                                [返回主界面，全功能解锁]
```

### 6.2 续期流程

```
[收到到期提醒推送]
   ↓
[点击"立即续期"]   或   [打开"我的授权"页 → 点击"续期"]
   ↓
[续期页：默认选中当前套餐 + 当前周期]
   ↓
[可选：切换周期 / 输入优惠码]
   ↓
[确认订单 → 扫码支付]
   ↓
[云端 extend_license()：new_expire = max(old_expire, now) + period]
   ↓
[客户端拉取新 JWT → 更新本地缓存]
   ↓
[续期成功提示 + 新到期日]
```

### 6.3 过期恢复流程

```
[打开系统] ──授权已过期──→ [过期提示页：仅"我的授权"和"订单记录"可访问]
                                ↓
                        [点击"续期恢复"]
                                ↓
                        [续期页（同 §6.2）]
                                ↓
                        [支付成功 → 激活]
                                ↓
                        [过期期间数据保留，功能恢复]
```

### 6.4 升级套餐流程

```
[我的授权页 → 点击"升级套餐"]
   ↓
[套餐对比表 → 选择更高套餐]
   ↓
[系统计算补差价 = 新套餐月均价 × 剩余月数 - 已付金额]
   ↓
[确认升级 → 扫码支付]
   ↓
[云端 upgrade_license() → 套餐立即变更]
   ↓
[客户端拉取新 JWT → 全功能按新套餐解锁]
```

### 6.5 管理员上线优惠活动流程

```
[运营登录云端后台]
   ↓
[定价管理 → 优惠活动 → 新建]
   ↓
[填写：活动名、适用套餐、折扣、开始/结束时间]
   ↓
[保存 → 审核通过 → 上线]
   ↓
[客户端购买页自动展示活动价（通过 /pricing/promotions 拉取）]
   ↓
[活动结束 → 价格自动恢复]
```

- **机器码**：`sha256(motherboard_serial + cpu_id + disk_serial + mac_address)` 取前 32 位，全大写。

- **订单号**：`XY-{yyyymmdd}-{8 位随机大写字母数字}`，全局唯一。
- **状态枚举**：所有 `status` 字段使用小写蛇形，与现有项目约定一致。

### 10.4 与现有约束的兼容性

| 现有约束（来自 project_memory） | 权限模块兼容性 |
|---|---|
| Web 进程必须 `with_browser=False` | 客户端校验逻辑独立于浏览器进程，无冲突 |
| `/api/auth/*` 等端点需加入认证白名单 | 新增 `/api/license/me`、`/api/license/refresh` 需加入白名单（允许在授权过期时访问） |
| 前端 fetch 必须含 `credentials: 'include'` | 新增 license 相关 fetch 沿用 `client.ts` 默认配置 |
| htmx 用 `<meta>` 配置 credentials | 不影响：本模块全部走 fetch API，不使用 htmx |
| 401 返回 JSON `{"detail":"Unauthorized"}` | 新增 403 返回 JSON `{"detail":"Forbidden","code":"PERMISSION_DENIED","required":"<perm>"}` |
| token 比对用 `hmac.compare_digest()` | 优惠码、授权码比对沿用此约定 |
| WebView2 用 `CREATE_NEW_CONSOLE` | 不影响 |
| 不引入第三方 UI 库 | 沿用 antd + michelin CSS Token |
| 配置白名单目录索引 | `permission_registry.yaml` 加入 KB 索引白名单 |

## 11. 验收标准

### 11.1 功能验收

| 编号 | 验收点 | 通过标准 |
|---|---|---|
| AC1 | 未授权用户访问受保护 API | 返回 403 + PERMISSION_DENIED |
| AC2 | 未授权用户访问受保护前端路由 | 跳转升级引导页 |
| AC3 | 试用模式功能限制生效 | 试用版创建第 3 个任务被拦截 |
| AC4 | 套餐购买全流程 | 从打开套餐页到激活成功 ≤ 5 步，全链路 ≤ 30s |
| AC5 | 续期到期日叠加 | 提前续期 new_expire = old_expire + period |
| AC6 | 过期续期到期日 | 过期后续期 new_expire = now + period |
| AC7 | 到期提醒推送 | 7/3/1 天三次推送，渠道走用户已配置的通知渠道 |
| AC8 | 过期功能降级 | 过期 ≤ 24h 内自动抢单降为半自动 |
| AC9 | 优惠码校验 | 失效码红色提示；满减未达门槛提示；过期码不可用 |
| AC10 | 优惠码防刷 | 单设备 10 次/日限频；单码单订单 |
| AC11 | 机器码绑定 | 同一授权不可在两台机器同时激活 |
| AC12 | 离线宽限期 | 联网失败 72h 内功能正常；72-96h 只读；96h 后停用 |
| AC13 | 管理员撤销授权 | 撤销后客户端下次校验立即失效 |
| AC14 | 审计日志完整性 | 每次权限变更可回溯到操作者、时间、IP、变更前后 |
| AC15 | 退款人工审核 | 用户提交退款 → 管理员审核通过 → 授权撤销 + 订单状态 refunded |

### 11.2 非功能验收

| 编号 | 验收点 | 通过标准 |
|---|---|---|
| NFR1 | 权限校验本地缓存性能 | P99 ≤ 20ms |
| NFR2 | 权限校验回源性能 | P99 ≤ 800ms |
| NFR3 | 二维码生成 | P99 ≤ 2s |
| NFR4 | 支付回调激活时延 | P99 ≤ 5s |
| NFR5 | 安全扫描通过 | SonarQube 无新增 Critical/Blocker |
| NFR6 | 客户端 license_cache.json 加密 | 文件落盘为密文，启动加载需机器码解密 |
| NFR7 | JWT 防重放 | 已撤销 jti 30 天内不可重用 |
| NFR8 | 兼容现有测试 | 现有 103+ 测试用例无回归 |

## 12. 风险与依赖

### 12.1 风险

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 微信支付商户号审核周期长 | 阻塞上线 | 提前 2 周申请；过渡期可走"个人收款码 + 人工激活" |
| 机器码采集在虚拟机/容器的稳定性 | 误判绑定失败 | 采集失败时降级到 `MAC + 用户名` 哈希；记录警告 |
| 离线宽限期被绕过（篡改系统时间） | 授权失效未触发 | JWT 内嵌 `iat`，云端校验 `now - iat ≤ 72h + 24h` |
| 优惠码被批量爬取 | 营销预算损失 | 单 IP 限频 + 设备指纹 + 滑块验证码（连续失败 3 次） |
| 客户端被逆向破解 | 盗版 | 仅做基础防护；不投入重资产反逆向；优先快速迭代 |
| 云端服务单点故障 | 全用户无法激活 | 客户端 72h 缓存 + 24h 宽限期兜底；云端 SLA 99.5% |
| 套餐定价频繁变更 | 用户感知混乱 | 定价版本化；同套餐 7 天内不重复调价 |

### 12.2 依赖

| 依赖项 | 说明 |
|---|---|
| 微信商户平台账号 | 用于 Native 支付，需提前申请 |
| 域名 + SSL 证书 | 云端授权服务对外提供 HTTPS 接口 |
| 现有 Cookie 认证模块 | 必须稳定可用 |
| 现有通知模块 | 必须支持自定义事件模板 |
| 现有事件总线 | 必须支持新增事件类型 |
| 现有数据库迁移机制 | 必须支持 alembic 或等价工具 |

## 13. 术语表

| 术语 | 定义 |
|---|---|
| 机器码 | 由客户端硬件信息哈希生成的 32 位唯一标识 |
| 授权码 | 云端签发的 UUID v4，唯一标识一份授权 |
| JWT | JSON Web Token，客户端持有的授权凭证，含套餐与到期信息 |
| 套餐 | 功能点集合的打包单位，如 trial/basic/pro/flagship |
| 周期 | 套餐的有效时长单位，月/季/年 |
| 优惠码 | 一次性或限次使用的折扣凭证 |
| 优惠活动 | 限时全量折扣，无需输入码自动生效 |
| 续期 | 同套餐延长到期日 |
| 升级 | 切换到更高阶套餐 |
| 解绑 | 解除机器码与授权的绑定关系 |
| 宽限期 | 授权过期或离线后仍允许部分功能使用的时段 |
