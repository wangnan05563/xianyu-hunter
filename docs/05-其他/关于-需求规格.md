## 1. 背景与目标

### 1.1 背景

XianyuHunter 控制台目前存在两套相互独立的文档入口，散落在三个位置：

| 现状 | 位置 | 类型 |
|---|---|---|
| 顶栏 ❓ 图标按钮 | `frontend/src/components/layout/MainLayout.tsx:545-554` | 帮助文档 SPA |
| Swagger UI | `/api/docs`（FastAPI 增强版） | API 文档（HTML 注入顶栏） |
| 主菜单底部 `<a href="/api/docs">` | `MainLayout.tsx:565-573` | API 文档链接 |

问题：
1. **入口分散**：用户需要记忆"API 文档在右上角文字链、帮助在 ❓ 图标"。
2. **风格不统一**：API 文档走原生 Swagger 浅色页，帮助文档走 antd + 米其林主题，体验断层。
3. **缺少"关于"信息**：版本号、构建时间、依赖版本、免责说明、报告问题入口都散落在 README / 配置页里，没有统一落点。
4. **缺少元信息汇总**：版权、开源许可、第三方依赖、隐私条款等没有统一呈现。

### 1.2 目标

提供一个**统一的"关于"菜单**，作为系统元信息 + 文档资源的唯一入口，实现：

- **G1 一站式入口**：版本信息、文档资源（API + 帮助）、反馈渠道、版权与许可、第三方声明，全部在 `/about` 路由可达。
- **G2 风格一致**：所有呈现的页面（包括 Swagger UI）共享同一套顶栏、字体、色板。
- **G3 移动可用**：在 360px 窄屏下不溢出，主要操作可点击。
- **G4 旧入口平滑迁移**：原 ❓、API 文档链全部归并到"关于"，迁移后旧入口保留 1 个版本作为回流入口，下个版本移除。

### 1.3 非目标

- ❌ 不实现自动 OTA 升级（"检查更新"仅做版本号比对 + 提示用户手动操作）。
- ❌ 不实现"在线反馈表单"（首版"报告问题"跳转 GitHub Issues / 邮件客户端）。
- ❌ 不重写 API 文档生成（继续用 FastAPI 内置 OpenAPI + Swagger UI）。
- ❌ 不重写 Help 页面（仅将入口归口到"关于"，/help 路由保留但作为子页面）。

## 2. 菜单位置与交互方式

### 2.1 入口位置

| 入口 | 形态 | 行为 |
|---|---|---|
| 顶栏右上角"关于"按钮（**新增**） | 圆形图标按钮，`<InfoCircleOutlined />` 图标 | 点击 → SPA 路由跳 `/about` |
| 顶栏右侧文字链 "API 文档"（**保留但降级**） | 次级文字链 | 点击 → 新窗口打开 `/api/docs`（保留作为回流入口） |
| 顶栏 ❓ 帮助按钮（**保留但降级**） | 圆形图标按钮 | 点击 → 跳 `/help`（保留作为回流入口） |
| Help 页右上角"API 文档"按钮 | 次级文字链 | 点击 → 新窗口打开 `/api/docs` |
| Swagger UI 顶栏"📖 帮助文档"按钮 | 次级按钮 | 改为跳 `/app/about`（**新行为**） |
| 侧栏底部（**新增**） | Sider 最底部一枚 `<InfoCircleOutlined />` 项 | 跳 `/about` |
| Command Palette（**新增**） | `COMMAND_ITEMS` 数组新增 `{ key: '/about', label: '关于', icon: <InfoCircleOutlined /> }` | 模糊搜索可触达 |

**为什么顶栏放两个入口（❓ + 关于）**：
- ❓ 维持"我遇到问题"的肌肉记忆用户路径；
- 关于按钮承担"我想了解这个软件是什么"的探索型用户路径；
- 视觉上 ❓ 偏 help，ℹ️ 偏 meta，两者语义不同。

### 2.2 交互方式

| 行为 | 触发 | 反馈 |
|---|---|---|
| 打开"关于"页 | 点击顶栏 / 侧栏 / Command Palette / g 快捷键 `g+a` | SPA 路由 `/about` 淡入 |
| 跳外部链接 | 点击"用户协议 / 隐私条款 / 开源声明 / 帮助文档 / 联系我们 / 官方社区 / 报告问题"任一行 | 浏览器新标签页打开（`target="_blank" rel="noopener noreferrer"`） |

| 复制版本号 | 点击版本号右侧 `<CopyOutlined />` 按钮 | 复制到剪贴板，2 秒内显示 "已复制" Tooltip |
| 折叠/展开（≥ 768px 屏） | 鼠标悬停版本卡 | 卡内 3 个二级标签（系统/前端/后端）轻浮动效展示 |

## 3. 视觉设计规范

### 3.1 设计风格定位

参考图定位为**"轻量扁平 + 极简卡片"**，与项目现有米其林风格做融合而非照搬：

| 维度 | 参考图 | XianyuHunter 现有 | 本设计决策 |
|---|---|---|---|
| 主色 | 中性灰 + 浅灰底 | 米其林红 `#E20613` + 暖米 | 主色沿用米其林红，列表底色用 `--bg-1`（不引入新色） |
| 圆角 | 8px | 6px（卡片） | 沿用 `--r-md = 6px` |
| 字体 | 系统默认无衬线 | Didone 衬线 + Inter 无衬线 | H1 用 Cormorant，正文用 Inter |

| 阴影 | 极淡 | 4px / 12px | 卡片默认 `--shadow-1`，hover `--shadow-2` |
| 暗主题 | 无 | 暗 / 亮双主题 | 暗主题自动适配，色彩 token 同 `--bg-1 / --border / --text-*` |

### 5.1 信息架构

| 区域 | 字段 | 来源 | 备注 |

| | 风险免责 | "本工具仅供个人研究学习，详见 README" | 折叠为单行 Tooltip |

### 5.2 版本号策略

- **主版本**：`__init__.py` 中 `__version__` 同步，每次发版时手动 bump。
- **构建版本**：`_build_info.py` 在构建时写入 `build_date`（UTC+8）+ `git_sha`（`git rev-parse --short HEAD`，无 git 时 `unknown`）。
- **检查更新**：调用 `GET /api/about/check-update` → 后端读取本机 `_build_info.py` → 返回 `{ current, latest, release_url, checked_at }`，前端比对。
  - 首版 `latest` 与 `current` 相同（无外网发布通道），UI 显示"已是最新"；
  - 后续若接入外网发布通道，仅需修改后端 `_fetch_latest_version()` 内部实现，前端无感。

### 5.3 开源软件声明（OpenSourceLicenses Modal）

首版策略：**前端静态写入**（避免构建时扫描 node_modules 带来复杂度）。

| 字段 | 来源 |
|---|---|
| 依赖名 | 手动维护的 `LICENSES` 常量数组 |
| 版本 | 与 `package.json` / `pyproject.toml` 同步 |
| 许可证 | 手动维护，引用 SPDX 标识符 |
| 链接 | 指向 npm / PyPI 页面 |

数据规模预估：
- 前端依赖：~30 项
- 后端依赖：~50 项
- 总计 ~80 项，按 `依字母序` 排序，前端搜索框过滤

Modal 尺寸：宽 720px、高 80% 视口、可滚动、Esc 关闭。

## 6. 权限控制要求

### 6.1 路由层

| 路由 | 鉴权 | 说明 |
|---|---|---|
| `GET /api/about` | 白名单（无需登录） | 含版本号、构建信息等公开元数据 |
| `GET /api/about/check-update` | 白名单（无需登录） | 公开端点 |
| `GET /app/about` | SPA 路由，要求登录（沿用 MainLayout 鉴权） | 与其他 SPA 页一致 |

### 6.2 后端鉴权白名单扩展

**修改点**：`src/xianyu_hunter/web/middleware/auth.py` 第 32 行附近的 `WHITELIST` 列表：

```python
WHITELIST = {
    "/api/auth/cookie",
    "/api/auth/me",
    "/api/auth/import-from-browser",
    "/import-from-browser/status",
    "/api/events/stream",
    "/api/notifications",
    "/api/notifier/",
    # 新增
    "/api/about",
    "/api/about/check-update",
    "/openapi.json",
    "/api/docs",

```

> 风险：若 `/api/about/check-update` 未来被用于拉取外网，存在 SSRF 风险（见 §10.1）。当前实现不发起外网请求，仅返回本机版本号，无 SSRF 风险。

### 6.3 前端访问控制

- `/about` 路由在 `MainLayout` 内，受 `loggedIn` 守卫（与 Dashboard 一致）；
- 不引入新角色 / 权限等级（项目无 RBAC 设计）。

### 6.4 外部链接策略

| 类型 | 链接 | 备注 |
|---|---|---|
| 站内 SPA | `Link to="/help"` | 不开新窗口 |
| 站内 Swagger | `<a href="/api/docs" target="_blank">` | 开新窗口，登录态独立 |
| 站外 | `target="_blank" rel="noopener noreferrer"` | 防 window.opener 劫持 |

## 7. 与现有系统的集成方案

### 7.1 与现有帮助文档（/help）的关系

- `/help` 路由 **保留**，作为"帮助文档"菜单项的目标；
- Help 页面顶部 "API 文档" 按钮 **保留**（用户已在 Help 上下文）；
- Swagger UI 顶栏的 "📖 帮助文档" 按钮跳转目标从 `/app/help` 改为 `/app/about`（**唯一改动**）；
- Help 页面右上加一个 "← 返回关于" 按钮（**可选**，UX 体验优化，不强求）。

### 7.2 与 Swagger UI 的整合

| 现状 | 改动后 |
|---|---|
| 顶栏 2 个按钮："控制台"、"📖 帮助文档"（→ `/app/help`） | 顶栏 3 个按钮："控制台"、"📖 关于"（→ `/app/about`）、"📖 API 文档（同窗口）"（→ `#` 关闭当前 Modal 不适用，改为 "← 返回关于"，跳 `/app/about`） |

## 10. 风险与缓解

| ID | 风险 | 等级 | 缓解 |
|---|---|---|---|
| 10.1 | `/api/about/check-update` 未来接入外网，存在 SSRF 风险 | 中 | 当前实现不发起外网请求；后续引入时白名单域名（`allowlist = ["api.github.com"]`） |
| 10.2 | `_build_info.py` 缺字段导致 About 页崩溃 | 中 | 后端用 `try/except ImportError` 兜底返回 `__version__ = "unknown"`；前端用 `--` 兜底展示 |
| 10.3 | "开源软件声明" 依赖列表与实际不一致 | 低 | 首版标注"以运行时实际安装为准"，P2 接入 `pip-licenses` / `license-checker` 自动生成 |
| 10.4 | 与米其林主题色（红 + 金）在列表项上对比度不足 | 低 | 列表项不使用品牌色，统一用 `--text-0` 保证可读性 |
| 10.5 | 旧入口（❓、文字链）双入口导致用户认知混淆 | 低 | 在按钮 Tooltip 加 "（即将迁移）" 提示，下版本移除 |
| 10.6 | Swagger UI 顶栏跳转 `/app/about` 时用户未登录被弹回登录 | 低 | `/app/about` 与 `/app/` 共享登录态（同一 SPA），不会出现未登录访问 |
