## 2. 功能概述

**一句话说明**：作为闲鱼猎人系统元信息（版本号、构建日期、Git SHA、检查更新）与文档资源（用户协议、隐私条款、开源许可、帮助/API 文档、反馈渠道）的统一入口。

**核心价值**：
- 把分散在 README、配置页、Swagger UI、MainLayout 顶栏的元信息与文档入口归口到单一页面；
- 提供本机版本与 GitHub Releases 最新版本的比对能力，自动定时检查并优雅降级；
- 静态维护前后端依赖的开源许可清单，便于合规披露；
- 与快捷键 `g+a`、命令面板 `Ctrl+K`、MainLayout 顶栏图标按钮多入口联动。

---

## 3. 入口位置

"关于"菜单共有 4 个入口，全部跳转到 `/about`：

| 入口                                       | 位置                                                            | 行为                              |
| ------------------------------------------ | --------------------------------------------------------------- | --------------------------------- |
| 侧边栏"其他"菜单 → "关于"                  | 后端 `/api/menu` 动态下发                                       | SPA 路由跳转                      |
| MainLayout 顶栏"关于"图标按钮              | `frontend/src/components/layout/MainLayout.tsx` Header 区域     | `navigate('/about')`             |
| 命令面板（Ctrl+K）                         | `MainLayout.tsx` 中 `COMMAND_ITEMS` 的 `{ key: '/about', ... }` | 选中后 `navigate('/about')`      |
| 全局快捷键 `g+a`                           | `MainLayout.tsx` 中 `G_PREFIX_MAP` 的 `a: '/about'`             | 500ms 内连按 g → a，自动 navigate |

> 注意：Header 顶部"关于"图标按钮与侧边栏菜单项功能重合，是有意为之——`ℹ️` 偏元信息（"我想了解这个软件是什么"），侧边栏菜单项归口"其他"分类，两者面向不同心智模型用户。

## 4. 路由设计

### 4.1 独立顶层路由

`/about` 在 `frontend/src/App.tsx` 中是**独立顶层路由**，不嵌套在 `MainLayout` 内：

```tsx
// frontend/src/App.tsx
<Route path="/login" element={<LazyRoute><Login /></LazyRoute>} />
<Route path="/onboarding" element={<LazyRoute><Onboarding /></LazyRoute>} />
<Route path="/help" element={<LazyRoute><Help /></LazyRoute>} />
<Route path="/about" element={<LazyRoute><About /></LazyRoute>} />
<Route path="/" element={<MainLayout />}>
  {/* 业务路由嵌套在 MainLayout 内 */}
</Route>
```

**特殊性**：
- 与 `/login`、`/onboarding`、`/help` 同级，**不被 MainLayout 的 `loggedIn` 守卫**强制包裹；
- 因此 About 页**自带 Header**（含返回控制台按钮），不复用 MainLayout 的 Sider / Header / Breadcrumb；
- 使用 `lazyRetry` 懒加载，独立 chunk，首屏不加载该页代码。

### 4.2 鉴权策略

- `/about` SPA 路由本身不要求登录态即可访问（独立于 MainLayout 之外）；
- 但页面会调用 `GET /api/about` 与 `GET /api/about/check-update`，二者在认证白名单中（见 §10），未登录访问也能正常返回元信息。

### 6.2 AboutMenuList

| onOpenLicenses  | () => void   | 触发 OpenSourceLicenses Modal |

### 6.3 OpenSourceLicenses

**文件**：`frontend/src/pages/About/OpenSourceLicenses.tsx`

**职责**：以 Modal 形式展示前后端依赖的开源许可清单，支持搜索过滤。

**Props**：

| 字段    | 类型         | 说明             |
| ------- | ------------ | ---------------- |
| open    | boolean      | Modal 是否打开   |
| onClose | () => void   | 关闭 Modal 回调   |

**依赖数据来源**：首版**前端静态写入**（注释标记 P2 接入 `license-checker` 自动生成），来自 `frontend/package.json` 的 dependencies + devDependencies 与 `requirements.txt` 的直接依赖。

**数据结构**：

```ts
interface Dependency {
  name: string     // 包名
  version: string  // 版本号（带 ^ 等前缀，与 package.json 一致）
  license: string  // SPDX 许可证标识符
  repo: string     // 仓库地址
}
```

**清单规模**：
- 前端依赖（FRONTEND_DEPS）：21 项，包括 antd / react / react-router-dom / zustand / echarts / vite / vitest 等；
- 后端依赖（BACKEND_DEPS）：21 项，包括 fastapi / uvicorn / pydantic / sqlalchemy / playwright / loguru / httpx 等；
- 合并后按包名小写字母序排序（`localeCompare`）。

**Modal 规格**：
- 宽度 720px；
- `destroyOnHidden`（关闭时销毁子树，避免 List 残留状态）；
- footer 显示 `Typography.Text` "以运行时实际安装为准"；
- 内容区上：搜索框 `Input` + `SearchOutlined` 前缀，`allowClear`；
- 内容区下：`max-height: 60vh, overflowY: auto` 的列表区；
- 空结果展示 "未找到匹配的依赖"（`emptySearch` 文案）；
- 每条依赖渲染为 `List.Item`，`Meta.title` 为包名 + 版本（点击跳仓库），`description` 为蓝色 `Tag` 许可证标识。

**搜索逻辑**：
- 关键字 `trim().toLowerCase()`；
- 匹配 `name` 或 `license` 包含关键字（不区分大小写）；
- 关键字为空时返回全部。

### 6.4 useUpdateChecker

**文件**：`frontend/src/pages/About/useUpdateChecker.ts`

**职责**：封装检查更新状态机、自动定时检查、版本号复制。

**输入**：`current: string`（当前版本号）。

**返回**：`{ state, run, copy }`。

#### 状态机定义

```ts
export type UpdateState =
  | { kind: 'idle' }
  | { kind: 'loading' }
  | { kind: 'latest' }
  | { kind: 'newer'; url: string; latest: string; publishedAt?: string }
  | { kind: 'error'; reason: 'network' | 'server' }
```

#### 状态流转

```
            ┌──── idle ────┐
            │  "检查更新"  │
            └──────┬───────┘
                   │ run() / 自动检查
                   ▼
            ┌──── loading ───┐
            │  "检查中..."   │
            └──────┬─────────┘
                   │ API resp
       ┌───────────┼───────────┬─────────────┐
       ▼           ▼           ▼             ▼
   has_update    latest      network_err   server_err
   =false       =true
       │           │           │             │
       ▼           ▼           ▼             ▼
    "已是最新"   "有新版本"   "网络异常"   "服务异常"
    绿色 ✓       蓝色 ↑       红色 !       红色 !
    3s 后回 idle  Tooltip     · 重试      · 重试
                  展示 publishedAt
                  点击跳 release_url
```

#### 关键常量

| 常量                    | 值              | 说明                                                                 |
| ----------------------- | --------------- | -------------------------------------------------------------------- |
| `IDLE_TIMEOUT_MS`       | 3000            | latest 态 3 秒后自动回 idle，让按钮恢复可点击                        |
| `AUTO_CHECK_INTERVAL_MS`| 60 * 60 * 1000  | 自动检查间隔 60 分钟（GitHub 未认证 API 限速 60/小时/IP，刚好用满配额） |
| `AUTO_CHECK_DELAY_MS`   | 5000            | 挂载后延迟 5 秒发起首次自动检查，避免阻塞首屏渲染                    |

#### 自动检查机制

- 挂载时 `setTimeout(5000)` 触发首次自动检查；
- 同时启动 `setInterval(60 * 60 * 1000)` 周期检查；
- 卸载时清理所有 timer（mountDelayTimerRef / autoCheckTimerRef / idleTimerRef）；
- `isCheckingRef` 防止自动检查与手动检查并发（已存在检查时跳过）；
- `useEffect` deps 仅 `[performCheck]`，**不包含 `current`**——避免 current 变化时重置自动检查周期。

#### 复制版本号

```ts
const copy = useCallback(async () => {
  try {
    await navigator.clipboard.writeText(current)
    message.success(TEXTS.copied)
  } catch {
    message.warning(TEXTS.copyFailed)  // 剪贴板权限被拒时降级
  }
}, [current, message])
```

#### 网络错误判定

```ts
function isNetworkError(e: unknown): boolean {
  if (typeof e === 'object' && e !== null) {
    const err = e as { response?: unknown; code?: string }
    return !err.response || err.code === 'ERR_NETWORK'
  }
  return false
}
```

- 无 `response` 字段（请求未发出）或 axios `code === 'ERR_NETWORK'` → `reason: 'network'`；
- 其余异常（包含 5xx 响应）→ `reason: 'server'`。

### 6.5 UpdateButton（BrandCard 内部子组件）

5 态按钮渲染逻辑：

| 状态     | 渲染                                                                                              |
| -------- | ------------------------------------------------------------------------------------------------- |
| idle     | `<Tooltip title="每小时自动检查一次">` + `<Button type="primary" icon={<ReloadOutlined />}>检查更新` |
| loading  | `<Button loading>检查中…`（antd Button loading 自带 spinner，无需再叠加 LoadingOutlined）          |
| latest   | `<Button type="text" icon={<CheckCircleFilled style={{ color: '#52c41a' }} />}>已是最新`           |
| newer    | `<Tooltip title="发布于 {publishedAt} 或 有新版本">` + `<Button type="primary" icon={<ArrowUpOutlined />} onClick={open release_url}>有新版本 ({latest})` |
| error    | `<Button danger type="text" icon={<WarningFilled />} onClick={onCheck}>{网络异常 \| 服务异常} · 重试` |

**newer 态点击行为**：`globalThis.open(state.url, '_blank', 'noopener,noreferrer')` 打开 GitHub release 页面。

**newer 态 publishedAt 格式化**：调用 `formatPublishDate(iso)`，将 ISO 字符串格式化为 `YYYY-MM-DD`；解析失败回退原值，避免后端格式异常导致 UI 崩溃。

## 7. 接口设计

### 7.1 API 路由表

| 方法 | 路径                       | 说明           | 鉴权       | include_in_schema |
| ---- | -------------------------- | -------------- | ---------- | ----------------- |
| GET  | `/api/about`               | 系统元信息     | 白名单     | false             |
| GET  | `/api/about/check-update`  | 检查更新       | 白名单     | false             |

> `include_in_schema=False`：减少 OpenAPI schema 噪声，前端独立消费这两个端点。

### 7.2 GET /api/about — 系统元信息

**响应字段**：

| 字段       | 类型   | 说明                                              |
| ---------- | ------ | ------------------------------------------------- |
| product    | string | 产品名（固定 `"闲鱼猎人"`）                       |
| version    | string | 版本号（来自 `_build_info.py.__version__`）       |
| build_date | string | 构建日期（`YYYY-MM-DD`，UTC+8）                   |
| git_sha    | string | Git SHA（无 git 时 `"unknown"`）                  |
| python     | string | Python 版本（`{major}.{minor}.{micro}`）         |
| platform   | string | 操作系统（`platform.system().lower()`，如 `windows` / `linux` / `darwin`） |

**响应示例**：

```json
{
  "product": "闲鱼猎人",
  "version": "0.3.0",
  "build_date": "2026-07-05",
  "git_sha": "unknown",
  "python": "3.10.12",
  "platform": "windows"
}
```

**异常处理**：`_safe_build_info()` 用 `try/except` 兜底，`_build_info` 模块缺失或字段缺失时返回 `"unknown"`，**始终返回 200**，不抛 5xx，避免阻塞前端 UI。

### 7.3 GET /api/about/check-update — 检查更新

**响应字段**：

| 字段          | 类型    | 必填 | 说明                                                                       |
| ------------- | ------- | ---- | -------------------------------------------------------------------------- |
| current       | string  | 是   | 当前版本号                                                                 |
| latest        | string  | 是   | 最新版本号（成功时来自 GitHub `tag_name`；失败降级时等于 current）         |
| has_update    | boolean | 是   | latest 是否严格大于 current                                                |
| release_url   | string  | 是   | release 跳转链接（has_update=true 时为具体 release html_url，否则为 releases 列表页） |
| checked_at    | string  | 是   | 检查时间（ISO 8601 带时区，UTC+8）                                         |
| source        | string  | 是   | `"remote"`（成功调用 GitHub）/ `"local"`（降级）                          |
| published_at  | string  | 否   | GitHub release 的 `published_at`（仅 `source=remote` 时存在，可能为空串） |
| error         | string  | 否   | 失败诊断信息（仅 `source=local` 时可能出现，不强制展示）                  |

**响应示例（成功，有更新）**：

```json
{
  "current": "0.3.0",
  "latest": "0.4.0",
  "has_update": true,
  "release_url": "https://github.com/wangnan05563/xianyu-hunter/releases/tag/v0.4.0",
  "checked_at": "2026-07-05T16:00:00+08:00",
  "source": "remote",
  "published_at": "2026-07-01T00:00:00Z"
}
```

**响应示例（成功，无更新）**：

```json
{
  "current": "0.3.0",
  "latest": "0.3.0",
  "has_update": false,
  "release_url": "https://github.com/wangnan05563/xianyu-hunter/releases",
  "checked_at": "2026-07-05T16:00:00+08:00",
  "source": "remote",
  "published_at": "2026-06-28T00:00:00Z"
}
```

**响应示例（降级，网络失败）**：

```json
{
  "current": "0.3.0",
  "latest": "0.3.0",
  "has_update": false,
  "release_url": "https://github.com/wangnan05563/xianyu-hunter/releases",
  "checked_at": "2026-07-05T16:00:00+08:00",
  "source": "local"
}
```

### 7.4 关键常量

| 常量                  | 值                                                                                  |
| --------------------- | ----------------------------------------------------------------------------------- |
| `_REPO_OWNER`         | `"wangnan05563"`                                                                    |
| `_REPO_NAME`          | `"xianyu-hunter"`                                                                   |

| `_HTTP_HEADERS`       | `{"User-Agent": "XianyuHunter-UpdateChecker/1.0", "Accept": "application/vnd.github+json"}` |

### 7.5 版本比较 `_is_newer`

```python
_SEMVER_RE = re.compile(r"^[vV]?(\d+)\.(\d+)\.(\d+)")

def _parse_version(raw: str) -> tuple[int, int, int] | None:
    """解析 'v1.2.3' / '1.2.3' / 'v1.2.3-beta' 为 (1, 2, 3)。
    非语义化版本（'unknown' / 'main' / 空串）返回 None。"""

def _is_newer(current: str, latest: str) -> bool:
    """任一端无法解析时返回 False（保守策略，避免误报让用户徒劳升级）。"""
    c = _parse_version(current)
    l = _parse_version(latest)
    if c is None or l is None:
        return False
    return l > c
```

## 8. 更新检查流程

### 8.1 主流程

```
用户点击"检查更新" or 自动检查 timer 触发
  ↓
useUpdateChecker.performCheck()
  ↓ isCheckingRef=true（防并发）
  ↓ setState(loading)
  ↓
aboutApi.checkUpdate() → GET /api/about/check-update
  ↓
api_about.py.check_update()
  ├─ 缓存命中（< 5 分钟 且 current 一致）→ 直接返回缓存
  └─ 缓存过期 → _fetch_latest_release()
                ├─ 调用 GitHub Releases API（GET _RELEASES_API）
                ├─ 200 → 解析 tag_name/html_url/published_at/name
                │        ↓
                │    _is_newer(current, latest)
                │        ↓
                │    构造响应（has_update / release_url）
                │        ↓
                │    写入 _cache（data + fetched_at = now）
                │        ↓
                │    返回 source='remote'
                ├─ 404 → 仓库无 release，返回 None → 降级 _build_local_response
                ├─ 403 → GitHub 限速，返回 None → 降级
                ├─ 其他状态码 → 返回 None → 降级
                └─ 异常（TimeoutException / HTTPError / 其他）→ 返回 None → 降级
                    ↓
                  降级响应：has_update=False, source='local'（不写缓存，便于下次重试）
  ↓
前端 useUpdateChecker 处理响应：
  ├─ has_update=true → setState(newer, {url, latest, publishedAt})
  └─ has_update=false → setState(latest) + setTimeout(3s) 后回 idle
  └─ catch → setState(error, reason=isNetworkError ? 'network' : 'server')
```

### 8.2 缓存策略

- 进程级单例字典：`_cache = {"data": None, "fetched_at": 0.0}`；
- 命中条件：缓存非空 + `(now - fetched_at) < 300s` + `cached.current == current`；
- 命中时直接返回缓存（不重新请求 GitHub）；
- 不缓存失败响应，便于下次请求立即重试；
- current 变化（构建后版本升级）时缓存自动失效，由下次轮询刷新；
- 不用 `functools.lru_cache`：lru_cache 无法缓存异常分支，且需要存储 `_cached_at` 时间戳。

### 8.3 失败降级策略

**为什么失败时仍返回 200 + has_update=False 而非 5xx**：

> `/api/about/check-update` 是元信息端点，500 会污染前端 PWA 检查逻辑；返回 200 + `source='local'` + `error` 字段让前端按需提示，UI 显示"已是最新"或异常态。

### 8.4 SSRF 防护

- 仅查询公开仓库的 release 元信息，不携带任何认证 token；
- 不发送用户身份、cookie、设备指纹等任何信息给 GitHub；
- release_url 仅作为跳转链接返回前端，由用户主动打开；
- 目标域名硬编码为 `api.github.com`，不接受用户输入。


**字段说明**：

| 字段         | 来源                                                      | 兜底值      |
| ------------ | --------------------------------------------------------- | ----------- |
| `__version__` | 从 `backend/xianyu_hunter/__init__.py` 解析 `__version__ = "x.y.z"` | `"unknown"` |
| `build_date` | `datetime.now().strftime("%Y-%m-%d")`（生成当天，无时区） | `"unknown"` |
| `git_sha`    | `git rev-parse --short HEAD`（短 SHA）                    | `"unknown"` |

### 9.2 `bump_version.py` 版本号更新流程

**路径**：`scripts/bump_version.py`

**用法**：

```
python scripts/bump_version.py major        # 1.2.3 → 2.0.0
python scripts/bump_version.py minor        # 1.2.3 → 1.3.0
python scripts/bump_version.py patch        # 1.2.3 → 1.2.4
python scripts/bump_version.py auto         # 根据 git log 自动判断
python scripts/bump_version.py 1.5.0         # 直接指定版本号
```

**同步范围**：

1. `backend/xianyu_hunter/__init__.py`（`__version__` 字段，单一源头）；
2. `pyproject.toml`（`version` 字段，从 `__init__.py` 同步）；
3. `CHANGELOG.md`（`[Unreleased]` 段落封版为新版本号 + 日期，幂等）；
4. `backend/xianyu_hunter/_build_info.py`（调用 `scripts/build_info.py` 重新生成）；
5. git tag（可选，`--tag` 参数触发，创建 `v{version}` annotated tag，未推送）。

**自动 bump 判定规则**（保守策略）：
- 任一 commit 含 `BREAKING CHANGE` 或 `!: ` 标记 → major；
- 任一 commit 以 `feat` 开头 → minor；
- 默认 → patch。

## 18. 常见问题 FAQ

### Q1：`/about` 路由是嵌套在 MainLayout 内吗？
**A**：不是。`/about` 在 `frontend/src/App.tsx` 中是独立顶层路由，与 `/login`、`/onboarding`、`/help` 同级，不被 MainLayout 的 Sider / Header / Breadcrumb 包裹。About 页自带 Header（含返回控制台按钮）。

### Q2：未登录用户能访问 `/about` 吗？
**A**：能。`/about` 路由独立于 MainLayout，不被 `loggedIn` 守卫。`/api/about` 与 `/api/about/check-update` 也在认证白名单中（`/api/about` 前缀匹配，覆盖两个端点），未登录访问能正常返回数据。

### Q3：检查更新是怎么工作的？
**A**：调用 `GET /api/about/check-update`，后端先检查 5 分钟缓存，命中则直接返回；否则调用 GitHub Releases API 查询最新 release，与当前版本做 semver 比较。失败时降级返回 `source='local'` + `has_update=false`，前端按状态机展示 idle/loading/latest/newer/error 五态。

### Q4：为什么自动检查间隔是 60 分钟？
**A**：GitHub 未认证 API 限速 60 次/小时/IP，60 分钟轮询刚好用满配额；后端还有 5 分钟缓存兜底，即使前端轮询更频繁也不会击穿限速。

### Q5：8 项菜单链接是真的可点击吗？
**A**：用户协议、隐私条款、官方社区、报告问题目前是 `https://example.com/...` 占位链接，部署时需替换为实际地址；API 文档 `/api/docs`、联系我们 `mailto:dev@example.com` 同样需替换。开源软件声明点击触发 Modal；帮助文档是 SPA 内链，跳转到 `/help` 路由。

### Q6：开源许可列表是自动生成的吗？
**A**：首版是前端静态写入的（`FRONTEND_DEPS` + `BACKEND_DEPS` 常量，共 42 项），来自 `package.json` 与 `requirements.txt`。Modal footer 标注"以运行时实际安装为准"，P2 计划接入 `license-checker` 自动生成。

### Q7：版本号 `0.3.0` 是从哪里读的？
**A**：`backend/xianyu_hunter/_build_info.py` 中的 `__version__ = "0.3.0"`，由 `scripts/build_info.py` 从 `backend/xianyu_hunter/__init__.py` 解析并写入。`bump_version.py` 用于按 major/minor/patch 规则递增版本号，并同步 `__init__.py` / `pyproject.toml` / `CHANGELOG.md` / `_build_info.py`。

### Q8：git_sha 显示为 `unknown` 怎么办？
**A**：构建环境无 git 时（如 zip 包解压部署）`git_sha` 写为 `"unknown"`。BrandCard 逻辑：`showSha = gitSha && gitSha !== 'unknown'`，仅 true 时才展示 `@{gitSha}`，避免误导用户。

### Q9：MainLayout 顶栏的"关于"图标按钮与侧边栏菜单项功能重合吗？
**A**：是。两者都跳转 `/about`。重合是有意为之——顶栏 ℹ️ 偏元信息（"我想了解这个软件是什么"），侧边栏菜单项归口"其他"分类，面向不同心智模型用户。

### Q10：检查更新失败时为什么还返回 200？
**A**：`/api/about/check-update` 是元信息端点，返回 5xx 会污染前端 PWA 检查逻辑。失败时返回 200 + `source='local'` + `has_update=false`，前端按状态机展示 error 态（"网络异常"或"服务异常"），用户可主动重试。同时不缓存失败响应，便于下次请求立即重试。
