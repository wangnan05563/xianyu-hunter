# 关于 操作手册

## 概述

"关于"是闲鱼猎人系统元信息与文档资源的统一入口，归口于侧边栏"其他"菜单下的二级菜单。在该页面可以查看当前安装版本的产品名、版本号、发布日期、Git 提交哈希；一键检查 GitHub 上的最新发布版本；查阅 8 项常用文档与反馈入口（用户协议、隐私条款、开源软件声明、帮助文档、API 文档、联系我们、官方社区、报告问题）；以及浏览前后端共 42 项依赖的开源许可清单。

**入口位置**（共 4 个，均跳转 `/about`）：

| 入口 | 位置 | 行为 |
|------|------|------|
| 侧边栏"其他" → "关于" | 后端 `/api/menu` 动态下发 | 在 SheetWorkspace 内打开新 sheet |
| MainLayout 顶栏 ℹ️ 图标按钮 | Header 右侧帮助按钮之后 | 在 SheetWorkspace 内打开新 sheet |
| 命令面板 | `Ctrl+K` → 搜索"关于"或"about" | 选中后跳转 `/about` |
| 全局快捷键 `g+a` | 先按 `g`，500ms 内按 `a` | 自动跳转 `/about` |

> 关于页**嵌入 MainLayout 的 SheetWorkspace 内**展示，与其他业务页面共用工作区、标签栏与偏好设置；不再自带顶部 Header 与"返回控制台"按钮，关闭入口由左侧标签栏的 × 按钮提供。

## 核心特性

- **版本号展示**：从后端 `_build_info.py` 读取 `__version__`（当前 `0.3.0`），与 Logo、发布日期、Git SHA 同卡展示
- **发布日期展示**：取自构建信息中的 `build_date`（当前 `2026-07-05`），格式 `YYYY-MM-DD`
- **Git SHA 展示**：取自构建信息中的 `git_sha`，仅在值非空且非 `unknown` 时以 `@sha` 形式展示，避免误导
- **一键复制版本号**：版本号右侧的复制按钮，将完整版本号写入剪贴板，权限被拒时降级提示
- **检查更新（5 态状态机）**：手动按钮 + 自动定时检查，状态机含 idle / loading / latest / newer / error 五态
- **8 项外部链接**：用户协议 / 隐私条款 / 开源软件声明 / 帮助文档 / API 文档 / 联系我们 / 官方社区 / 报告问题
- **开源软件声明 Modal**：前端 21 项 + 后端 21 项共 42 项依赖，支持按包名 / 许可证搜索
- **自动检查更新**：进入页面延迟 5 秒发起首次检查，之后每 60 分钟自动检查一次，与后端 5 分钟缓存配合避免 GitHub 限速

## 路由位置

`/about` 在 `frontend/src/App.tsx` 中**嵌入 MainLayout 路由内**，与其他业务页面同级：

```tsx

  <Route index element={<LazyRoute><Dashboard /></LazyRoute>} />
  <Route path="tasks" element={<LazyRoute><TaskList /></LazyRoute>} />
  {/* ... 其他业务路由 ... */}
  <Route path="about" element={<LazyRoute><About /></LazyRoute>} />

```

**与其他独立顶层路由的对比**：

| 路由 | 位置 | 是否带 MainLayout | 是否带自有 Header |
|------|------|-------------------|-------------------|
| `/login` | 独立顶层路由 | 否 | 自有 |
| `/onboarding` | 独立顶层路由 | 否 | 自有 |
| `/help` | 独立顶层路由 | 否 | 自有 |

### 检查更新按钮 5 态

| 状态 | 视觉 | 文案 | 行为 |
|------|------|------|------|
| idle | 蓝色主按钮 + 🔄 图标 | "检查更新" | Tooltip "每小时自动检查一次"；点击触发手动检查 |

| 属性 | 值 |

**依赖清单规模**：

- 前端依赖（FRONTEND_DEPS）：21 项，来自 `frontend/package.json` 的 dependencies + devDependencies，包括 antd / react / react-router-dom / zustand / echarts / vite / vitest 等；
- 后端依赖（BACKEND_DEPS）：21 项，来自 `requirements.txt` 直接依赖，包括 fastapi / uvicorn / pydantic / sqlalchemy / playwright / loguru / httpx 等；

**搜索逻辑**：

- 关键字 `trim().toLowerCase()`；
- 匹配 `name` 或 `license` 包含关键字（不区分大小写）；
- 关键字为空时返回全部。

## 检查更新机制

### 手动检查流程

1. 用户在 idle 态点击"检查更新"按钮；
2. 前端置 `isCheckingRef` 标志位（防止与自动检查并发），按钮进入 loading 态；
3. 调用 `GET /api/about/check-update`；
4. 后端先检查 5 分钟进程级缓存：
   - 命中（< 5 分钟且 current 一致）→ 直接返回缓存结果；
   - 未命中 → 调用 GitHub Releases API（`https://api.github.com/repos/wangnan05563/xianyu-hunter/releases/latest`）；
5. GitHub 返回 200 → 解析 `tag_name` / `html_url` / `published_at`，与当前版本做 semver 比较；
6. GitHub 返回 404 / 403 / 其他状态码 / 异常 → 降级返回 `source='local'` + `has_update=false`（**不写缓存**，便于下次重试）；
7. 前端按响应切换状态机：
   - `has_update=true` → newer 态，按钮变成"有新版本 (x.y.z)"，点击跳 release 页面；
   - `has_update=false` → latest 态，3 秒后自动回 idle；
   - 网络异常（无 response 或 `ERR_NETWORK`）→ error 态，文案"网络异常 · 重试"；
   - 其他异常（含 5xx）→ error 态，文案"服务异常 · 重试"。

### 自动检查机制

- **首次延迟**：进入关于页后延迟 **5 秒**发起首次自动检查，避免阻塞首屏渲染；
- **周期**：之后每 **60 分钟**自动检查一次；
- **并发保护**：`isCheckingRef` 标志位防止自动检查与手动检查并发，已有检查时跳过；
- **卸载清理**：组件卸载时清理所有 timer（mount 延迟 timer / 周期 timer / latest→idle 重置 timer），避免内存泄漏；
- **后端缓存**：5 分钟进程级单例缓存（`_cache` dict），命中条件为缓存非空 + 距上次 fetch < 300 秒 + cached.current 与当前版本一致；缓存失败响应不写入，便于下次立即重试。

### 为什么 60 分钟

GitHub 未认证 API 限速 60 次 / 小时 / IP，60 分钟轮询刚好用满配额；后端 5 分钟缓存兜底，即使前端轮询更频繁也不会击穿限速。GitHub API 请求超时配置为连接 3 秒 + 读取 5 秒，避免偶发慢响应阻塞 check-update。

### 状态机流转

```
            ┌──── idle ────┐
            │  "检查更新"  │
            └──────┬───────┘
                   │ run() / 自动检查
                   ▼
            ┌──── loading ───┐
            │  "检查中..."   │
            └──────┬─────────┘
                   │ API resp
       ┌───────────┼───────────┬─────────────┐
       ▼           ▼           ▼             ▼
   has_update    latest      network_err   server_err
   =true        =false
       │           │           │             │
       ▼           ▼           ▼             ▼
    "已是最新"   "有新版本"   "网络异常"   "服务异常"
    绿色 ✓       蓝色 ↑       红色 !       红色 !
    3s 后回 idle  Tooltip     · 重试      · 重试
                  展示 publishedAt
                  点击跳 release_url
```

## 构建信息来源

版本号、发布日期、Git SHA 均来自 `src/xianyu_hunter/_build_info.py`（自动生成，请勿手改）：

| 字段 | 当前值 | 来源 | 兜底值 |
|------|--------|------|--------|
| `__version__` | `0.3.0` | 从 `src/xianyu_hunter/__init__.py` 解析 `__version__ = "x.y.z"` | `"unknown"` |
| `build_date` | `2026-07-05` | `datetime.now().strftime("%Y-%m-%d")`（生成当天，UTC+8） | `"unknown"` |
| `git_sha` | `unknown` | `git rev-parse --short HEAD`（短 SHA） | `"unknown"` |

`_build_info.py` 由 `scripts/build_info.py` 在构建时生成（`scripts/重新构建.bat` 末尾自动调用），运行时不依赖 git 工具链。

**如何更新版本号**：执行 `python scripts/bump_version.py {规则}`，支持 `major` / `minor` / `patch` / `auto` / 直接指定版本号（如 `1.5.0`）。脚本会同步：

1. `src/xianyu_hunter/__init__.py`（`__version__` 字段，单一源头）；
2. `pyproject.toml`（`version` 字段）；
3. `CHANGELOG.md`（`[Unreleased]` 段落封版为新版本号 + 日期）；
4. `src/xianyu_hunter/_build_info.py`（重新生成）；
5. 可选 git tag（`--tag` 参数触发，创建 `v{version}` annotated tag，未推送）。

**auto 判定规则**（保守策略）：

- 任一 commit 含 `BREAKING CHANGE` 或 `!: ` 标记 → major；
- 任一 commit 以 `feat` 开头 → minor；
- 默认 → patch。

## 常见问题 FAQ

### Q1：从侧边栏"其他" → "关于"进入，会跳出主界面吗？

**A**：不会。`/about` 路由**嵌入 MainLayout 内**（在 `frontend/src/App.tsx` 中作为 MainLayout 的子路由），与其他业务页面同级。点击侧边栏"关于"或顶栏 ℹ️ 图标按钮时，会在 SheetWorkspace 内打开一个新 sheet（若已存在则激活），与点击任务管理、抢单记录等菜单行为完全一致，不会跳出主界面，也不存在"返回控制台"按钮。关闭入口由左侧标签栏的 × 按钮提供。

### Q2：检查更新失败怎么办？

**A**：检查更新按钮会进入 error 态，文案为"网络异常 · 重试"或"服务异常 · 重试"。点击按钮即可重新触发检查。常见失败原因：

- 网络中断或后端服务不可达 → 显示"网络异常"；
- GitHub API 限速（403）或后端 5xx → 显示"服务异常"；
- 后端会**不缓存失败响应**，下次请求立即重试，无需等待。

### Q3：版本号 `0.3.0` 是从哪里来的？

**A**：来自 `src/xianyu_hunter/_build_info.py` 中的 `__version__ = "0.3.0"`，由 `scripts/build_info.py` 在构建时从 `src/xianyu_hunter/__init__.py` 解析写入。前端通过 `GET /api/about` 接口读取，API 失败时前端用 `--` 兜底避免 UI 白屏。要更新版本号请使用 `python scripts/bump_version.py {major|minor|patch|auto|版本号}`。

### Q4：Git SHA 显示为 `unknown` 怎么办？

**A**：构建环境无 git 时（如 zip 包解压部署）`git_sha` 写为 `"unknown"`。BrandCard 逻辑：`showSha = gitSha && gitSha !== 'unknown'`，仅 true 时才展示 `@{gitSha}`，避免误导用户。重新执行 `scripts/build_info.py`（或 `scripts/重新构建.bat`）在有 git 的环境下可恢复 SHA 展示。

### Q5：开源软件声明里能搜索吗？

**A**：可以。Modal 顶部有搜索框（带 `SearchOutlined` 图标和 `allowClear`），输入关键字后实时过滤，匹配包名或许可证（不区分大小写）。关键字为空时返回全部 42 项。无匹配结果时展示"未找到匹配的依赖"。

### Q6：API 文档链接打开是 Swagger 吗？

**A**：是。"API 文档"菜单项指向 `/api/docs`，在新标签页打开 Swagger UI 页面，可在线查看与调试后端 OpenAPI 接口。注意 `/api/about` 与 `/api/about/check-update` 两个端点设置 `include_in_schema=False`，不出现在 Swagger 文档中（前端独立消费）。

### Q7：能从关于页直接登出吗？

**A**：不能。关于页不提供登出入口，请使用 MainLayout Header 右侧的用户菜单（头像 + 昵称）中的"退出"选项。

### Q8：MainLayout 顶栏的 ℹ️ 按钮和侧边栏"其他" → "关于"是同一个页面吗？

**A**：是。两者都跳转 `/about`，行为完全一致，只是入口不同。重合是有意为之——顶栏 ℹ️ 偏元信息（"我想了解这个软件是什么"），侧边栏菜单项归口"其他"分类，面向不同心智模型用户。

### Q9：为什么自动检查更新要等 5 秒？

**A**：避免阻塞首屏渲染。用户进入关于页主要查看版本信息，5 秒延迟既不突兀又能及时反馈。之后每 60 分钟自动检查一次，与后端 5 分钟缓存配合避免 GitHub 限速（未认证 60 次 / 小时 / IP）。

### Q10：链接打不开怎么办？

**A**：用户协议 / 隐私条款 / 官方社区 / 报告问题目前是 `https://example.com/...` 占位链接，联系我们 `mailto:dev@example.com` 同样为占位，部署时需替换为实际地址。如点击后无反应，可能是浏览器拦截了新标签页弹出，请允许弹窗或长按链接选择"在新标签页中打开"。

### Q11：能手动触发检查更新吗？

**A**：能。在 idle 态（按钮显示"检查更新"）点击按钮即可立即发起一次检查。loading 态按钮不可重复点击（防并发）。latest 态 3 秒后会自动回 idle 恢复可点击；newer / error 态需用户主动点击跳转 release 页面或重试。

### Q12：发布日期是哪天？

**A**：当前为 `2026-07-05`，来自 `_build_info.py` 中的 `build_date` 字段，由 `scripts/build_info.py` 在构建时按 `datetime.now().strftime("%Y-%m-%d")` 生成（UTC+8）。该日期是**构建当天的日期**，并非版本发布日期；同一版本在不同日期构建会显示不同 `build_date`。

### Q13：检查更新会发送我的信息给 GitHub 吗？

**A**：不会。后端仅查询公开仓库的 release 元信息，**不携带任何认证 token、用户身份、cookie、设备指纹**等任何信息给 GitHub；请求头仅包含 `User-Agent: XianyuHunter-UpdateChecker/1.0` 与 `Accept: application/vnd.github+json`。目标域名硬编码为 `api.github.com`，不接受用户输入，无 SSRF 风险。release_url 仅作为跳转链接返回前端，由用户主动打开。

### Q14：检查更新有缓存吗？缓存多久？

**A**：后端有 5 分钟进程级缓存，命中条件为缓存非空 + 距上次 fetch < 300 秒 + cached.current 与当前版本一致。缓存失败响应不写入，便于下次请求立即重试。current 变化（构建后版本升级）时缓存自动失效，由下次轮询刷新。前端每 60 分钟轮询一次，每小时最多发起 1 次实际 GitHub 请求。

### Q15：未登录能访问 `/about` 吗？

**A**：`/about` 路由嵌入 MainLayout 内，未登录会被 MainLayout 守卫跳转到 `/login`。但 `/api/about` 与 `/api/about/check-update` 在后端认证白名单中（`/api/about` 前缀匹配，覆盖两个端点），未登录直接调用 API 也能正常返回数据。
