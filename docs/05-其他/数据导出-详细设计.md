## 2. 功能概述

**一句话说明**：将商品、评估、订单、事件四类业务数据按用户自定义筛选条件导出为 Excel/Numbers 友好的 CSV 文件，支持任务 ID、时间范围、订单状态、事件等级多维度过滤。

**核心价值**：
- 独立页面提供完整筛选条件，弥补嵌入式 `ExportButton` 只能按当前页上下文过滤的局限；
- 复用现有 Repository 查询方法，零新增 DAO，避免数据访问层冗余；
- CSV 流式输出 + UTF-8 BOM 头，确保 Excel/Numbers 正确识别编码与字段顺序；
- 列定义预览接口让用户在导出前确认字段，避免导出后才发现列缺失；
- 浏览器原生 URL 直跳触发下载，避免大文件 blob 占用 JS 堆内存。

**入口位置**：侧边栏 → 「其他」分组 → 「数据导出」菜单项（`config/menu_registry.yaml` 中 `key=export`、`category=other`、`sort_order=302`）。

## 3. 用户场景

### 场景一：批量导出某任务下的全部商品
用户想离线分析任务 `t_001` 采集到的所有商品，进入「数据导出」页面，在「商品列表」卡片中输入 `task_id=t_001`，行数上限调整为 10000，点击「导出 CSV」，浏览器自动下载 `xh-items-20260705-103045.csv`，可直接拖入 Excel 打开。

### 场景二：导出失败订单做复盘
用户对最近一周的失败订单做复盘，进入「数据导出」页面，在「订单记录」卡片中设置时间范围为最近 7 天、订单状态输入 `failed`、行数上限 5000，点击导出后获得仅含失败订单的 CSV。

### 场景三：在评估明细页快速导出当前任务评估记录
用户在评估明细页浏览某任务的评估结果，希望快速导出当前任务的评估记录，直接点击页面顶部的 `ExportButton`（嵌入式按钮），无需跳转独立页面即可触发同源导出，参数自动带上当前 `taskId`。

### 场景四：排查异常事件
用户怀疑系统出现风控触发，进入「数据导出」页面，在「事件日志」卡片中输入事件等级 `error`、时间范围设为当日，导出当日所有 error 级别事件用于排查。

## 4. 页面布局与交互

### 4.1 组件结构

```
ExportPage (frontend/src/pages/Export/index.tsx)
├── 页面标题区
│   ├── Title：「数据导出」
│   └── Paragraph：功能说明（CSV Excel/Numbers 友好，含 UTF-8 BOM）
├── 加载态（Spin：「加载数据集...」）
└── 数据集卡片网格（Row + Col，xs=24 / lg=12，每行 2 张卡）
    └── DatasetCard × 4
        ├── 卡片头部
        │   ├── DatabaseOutlined（数据集主题色图标）
        │   ├── 中文标题（商品列表/评估记录/订单记录/事件日志）
        │   └── Tag：数据集 key（items/evaluations/orders/events）
        ├── 描述段落（来自后端 _DATASET_DESCRIPTIONS）
        ├── 列定义预览（Tag 列表，按后端返回顺序展示）
        ├── 筛选表单（依 DATASET_FILTERS 显隐）
        │   ├── 任务 ID 输入框（Input，allowClear，size=small）
        │   ├── 时间范围 RangePicker（showTime，YYYY-MM-DDTHH:mm:ss）

        │   ├── 事件等级输入框（仅 events）
        │   └── 行数上限 InputNumber（min=1，max=50000，默认 5000）
        └── 操作区
            └── 「导出 CSV」主按钮（Button，type=primary，icon=DownloadOutlined）
```

### 4.2 关键交互

| 区域             | 交互行为                                                                                  |
| ---------------- | ----------------------------------------------------------------------------------------- |
| 数据集卡片网格   | 4 张卡片两列布局，每张卡片独立维护筛选条件，切换数据集时各自的输入保留                    |
| 列定义预览       | 进入页面即拉取 `GET /api/export` 获取列定义，以 Tag 形式展示字段顺序                      |
| 拉取失败兜底     | 列定义接口失败时使用静态列定义兜底，保证页面可用（见 §7.5）                                |
| 任务 ID 输入     | `allowClear` 支持一键清空，留空时不过滤                                                   |
| 时间范围选择     | `RangePicker` 含 `showTime`，输出格式 `YYYY-MM-DDTHH:mm:ss`，与后端 `to_datetime` 兼容   |
| 订单状态输入     | 自由文本（如 `succeeded` / `failed` / `pending` / `takeover_pending`），仅 orders 卡片显示 |
| 事件等级输入     | 自由文本（如 `info` / `warning` / `error`），仅 events 卡片显示                            |
| 行数上限         | `InputNumber` 限制 `min=1`、`max=50000`，默认 5000；空值时回退为 5000                     |
| 导出按钮         | 点击后构造 URL 并触发 `globalThis.location.href` 直跳，浏览器原生下载 CSV                |
| 导出反馈         | 触发后立即 `message.success('正在导出 XX...')`；URL 直跳无法捕获响应，故失败时无回调      |
| 筛选条件保留     | 4 个数据集的筛选条件分别存于 `filters` state，切换卡片不会丢失输入                        |

## 5. 数据集定义

### 5.1 数据集一览

后端 `_DATASET_COLUMNS` 字典定义了 4 个数据集的列顺序（顺序即 CSV 列顺序）：

| 数据集 key    | 中文标题 | 列数 | 默认排序字段        | 描述                                |
| ------------- | -------- | ---- | ------------------- | ----------------------------------- |
| `items`       | 商品列表 | 11   | `first_seen` 倒序   | 商品列表（含价格、卖家、发布时间）  |
| `evaluations` | 评估记录 | 8    | `created_at` 倒序   | 评估记录（含评分、风险等级、拒绝原因） |
| `orders`      | 订单记录 | 10   | `created_at` 倒序   | 订单记录（含订单号、价格、状态、时间） |

### 5.6 DATASET_FILTERS 筛选字段矩阵

`frontend/src/pages/Export/index.tsx` 中 `DATASET_FILTERS` 控制每个数据集卡片的筛选表单显隐：

| 数据集      | task_id | time | status | level |
| ----------- | ------- | ---- | ------ | ----- |
| items       | ✅      | ✅   | ❌     | ❌    |
| evaluations | ✅      | ✅   | ❌     | ❌    |
| orders      | ✅      | ✅   | ✅     | ❌    |
| events      | ✅      | ✅   | ❌     | ✅    |

**说明**：
- `task_id`：所有数据集都支持（evaluations 通过 items 间接过滤）
- `time`：所有数据集都支持，分别按 `first_seen` / `created_at` 过滤
- `status`：仅 orders 支持，对应 `OrderRow.status`
- `level`：仅 events 支持，对应 `EventRow.level`

### 5.7 行数上限

| 项             | 值                                  |
| -------------- | ----------------------------------- |
| 默认值         | 5000                                |
| 最小值（ge）   | 1                                   |
| 最大值（le）   | 50000                               |
| 前端 InputNumber | `min=1`、`max=50000`、空值回退 5000 |
| 后端 Query 校验 | `Query(5000, ge=1, le=50000)`       |

> 超出范围时后端返回 422 校验错误（FastAPI 自动校验）。

## 6. 接口设计

### 6.1 API 路由表

| 方法 | 路径                     | 说明                   | 认证 |
| ---- | ------------------------ | ---------------------- | ---- |
| GET  | `/api/export`            | 列出可导出数据集及列定义 | 需要 |
| GET  | `/api/export/{dataset}`  | 导出指定数据集为 CSV   | 需要 |

### 6.2 列定义预览接口

**请求**：`GET /api/export`

**请求参数**：无

**响应**（200 OK）：

```json
{
  "datasets": [
    {
      "key": "items",
      "columns": ["id", "task_id", "title", "price", "publish_time", "region",
                  "seller_id", "want_cnt", "view_cnt", "first_seen", "last_seen"],
      "description": "商品列表（含价格、卖家、发布时间）"
    },
    {
      "key": "evaluations",
      "columns": ["id", "item_id", "seller_id", "score", "risk_level",
                  "dimension_scores", "reject_reasons", "created_at"],
      "description": "评估记录（含评分、风险等级、拒绝原因）"
    },
    {
      "key": "orders",
      "columns": ["id", "task_id", "item_id", "seller_id", "order_no",
                  "price", "status", "confirmed_at", "paid_at", "created_at"],
      "description": "订单记录（含订单号、价格、状态、时间）"
    },
    {
      "key": "events",
      "columns": ["id", "type", "task_id", "item_id", "stage",
                  "level", "message", "created_at"],
      "description": "事件日志（含类型、等级、消息）"
    }
  ]
}
```

**字段说明**：

| 字段        | 类型     | 说明                              |
| ----------- | -------- | --------------------------------- |
| datasets    | array    | 数据集列表（顺序固定为 items/evaluations/orders/events） |
| datasets[].key       | string   | 数据集标识                        |
| datasets[].columns   | string[] | 列定义数组（顺序即 CSV 列顺序）   |
| datasets[].description | string   | 中文描述（来自 `_DATASET_DESCRIPTIONS`） |

### 6.3 CSV 导出接口

**请求**：`GET /api/export/{dataset}`

**路径参数**：

| 参数     | 类型   | 必填 | 说明                                              |
| -------- | ------ | ---- | ------------------------------------------------- |
| dataset  | string | 是   | 数据集 key，必须 ∈ {items, evaluations, orders, events} |

**Query 参数**：

| 参数     | 类型   | 必填 | 默认值 | 校验规则                       | 说明                                       |
| -------- | ------ | ---- | ------ | ------------------------------ | ------------------------------------------ |
| task_id  | string | 否   | None   | -                              | 按任务 ID 过滤                             |
| start    | string | 否   | None   | ISO 格式（如 `2026-06-01T00:00:00`） | 起始时间（含），按对应时间字段过滤        |
| end      | string | 否   | None   | ISO 格式                       | 截止时间（含），按对应时间字段过滤        |
| status   | string | 否   | None   | -                              | 订单状态过滤（仅 orders 数据集生效）       |
| level    | string | 否   | None   | -                              | 事件等级过滤（仅 events 数据集生效）       |
| limit    | int    | 否   | 5000   | `ge=1`、`le=50000`             | 最大导出行数                               |

**响应**：

- **200 OK**：返回 `StreamingResponse`，`media_type="text/csv; charset=utf-8"`
  - 响应头：`Content-Disposition: attachment; filename="xh-{dataset}-{YYYYMMDD-HHMMSS}.csv"`
  - 响应体：UTF-8 BOM + CSV 文本流
- **400 Bad Request**：`dataset` 不在白名单时返回
  ```json
  { "detail": "未知数据集 xxx，可用: ['items', 'evaluations', 'orders', 'events']" }
  ```
- **422 Unprocessable Entity**：`limit` 超出 `ge=1`/`le=50000` 范围时由 FastAPI 自动返回
- **401 Unauthorized**：未携带 token 或 token 无效时由认证中间件返回
  ```json
  { "detail": "Unauthorized" }
  ```

**文件命名规则**：`xh-{dataset}-{datetime.now().strftime('%Y%m%d-%H%M%S')}.csv`
- 示例：`xh-items-20260705-103045.csv`

### 6.4 前端 API 客户端

`frontend/src/api/export.ts` 暴露 `exportApi` 对象：

| 方法          | 签名                                                           | 说明                                       |
| ------------- | -------------------------------------------------------------- | ------------------------------------------ |
| listDatasets  | `() => Promise<{ datasets: ExportDatasetInfo[] }>`             | 拉取列定义                                 |
| buildUrl      | `(dataset, params?) => string`                                 | 构造导出 URL（不触发下载）                 |
| download      | `(dataset, params?) => void`                                   | 触发浏览器直跳下载（`globalThis.location.href`） |

**类型定义**：

```typescript

  columns: string[]
  description: string
}

export interface ExportParams {
  task_id?: string
  start?: string      // ISO 格式：YYYY-MM-DDTHH:mm:ss
  end?: string
  status?: string     // 仅 orders
  level?: string      // 仅 events
  limit?: number      // 默认 5000，上限 50000
}
```

## 7. 导出流程与业务逻辑

### 7.1 完整导出流程

```
用户进入 /export 页面
        │
        ▼
前端 useEffect 调用 exportApi.listDatasets()
        │
        ▼
后端 GET /api/export 返回列定义 + 描述
        │
        ▼
前端渲染 4 张数据集卡片，按 DATASET_FILTERS 显隐筛选字段
        │
        ▼
用户填写筛选条件（task_id / 时间范围 / status / level / limit）
        │
        ▼
用户点击「导出 CSV」按钮
        │
        ▼
前端构造 ExportParams：
  - 仅包含非空字段（trim 后非空）
  - 时间范围格式化为 'YYYY-MM-DDTHH:mm:ss'
        │
        ▼
前端调用 exportApi.download(ds, params)
        │
        ▼
globalThis.location.href = buildUrl(dataset, params)
        │
        ▼
浏览器发起 GET /api/export/{dataset}?task_id=...&start=...&end=...&status=...&level=...&limit=...
        │  （同源请求自动携带 xh_token cookie）
        ▼
后端认证中间件校验 token（Bearer header 或 cookie）
        │
        ▼
路由 export_dataset 校验 dataset 是否在 _DATASET_COLUMNS 白名单
        │  否则返回 400
        ▼
按 dataset 分发到 4 条数据查询分支（见 §7.2~§7.5）
        │
        ▼
_filter_by_time 按 start/end 过滤行
        │
        ▼
_build_csv_response 生成 CSV 文本（含 UTF-8 BOM）
        │
        ▼
StreamingResponse 返回，浏览器触发文件下载
        │
        ▼
前端 message.success('正在导出 XX...')
```

### 7.2 items 数据集查询逻辑

```python
rows = container.repo.list_items(task_id=task_id, limit=limit)
rows = _filter_by_time(rows, "first_seen", start_dt, end_dt)
```

- 直接复用 `ItemsMixin.list_items(task_id, limit)`（`src/xianyu_hunter/infra/repo_items.py`）
- `task_id` 在 SQL 端过滤（`WHERE task_id = ?`）
- 时间范围在 Python 端按 `first_seen` 字段过滤
- 排序：`first_seen` 倒序（由 Repository 保证）

### 7.3 evaluations 数据集查询逻辑

evaluations 表本身**无 `task_id` 列**，需通过 items 表间接关联：

```python
if task_id:
    # 步骤 1：查 items 表得到该 task_id 下的所有 item_id 集合
    item_ids = {r["id"] for r in container.repo.list_items(task_id=task_id, limit=limit)}
    # 步骤 2：按 item_id 集合分批查 evaluations（避免 SQLite IN 子句参数上限）
    rows = _list_evaluations_by_items(container, item_ids, limit)
else:
    # 无 task_id 过滤时直接全表查询
    rows = _list_all_evaluations(container, limit)
rows = _filter_by_time(rows, "created_at", start_dt, end_dt)
```

**关键设计点**：
- `_list_evaluations_by_items` 分批查询，`batch_size=500`，避免 SQLite `IN` 子句默认 999 参数上限
- 分批结果合并后若超过 `limit` 立即截断并 break
- `_list_all_evaluations` 直接 `select(EvaluationRow).order_by(created_at.desc()).limit(limit)`
- 排序：`created_at` 倒序

### 7.4 orders 数据集查询逻辑

```python
rows = container.repo.list_orders(status=status, limit=limit)
if task_id:
    # task_id 在 Python 端二次过滤（list_orders 也支持 task_id 参数，但此处未传）
    rows = [r for r in rows if r.get("task_id") == task_id]
rows = _filter_by_time(rows, "created_at", start_dt, end_dt)
```

- 复用 `OrdersMixin.list_orders(status, limit)`（`src/xianyu_hunter/infra/repo_orders.py`）
- `status` 在 SQL 端过滤
- `task_id` 在 Python 端二次过滤（注意：`list_orders` 本身支持 `task_id` 参数，此处保留二次过滤是为了与 limit 解耦，避免 SQL 端过滤后行数不足）
- 时间范围按 `created_at` 字段在 Python 端过滤
- 排序：`created_at` 倒序

### 7.5 events 数据集查询逻辑

```python
rows = container.repo.list_events(level=level, task_id=task_id, limit=limit) or []
rows = _filter_by_time(rows, "created_at", start_dt, end_dt)
```

- 复用 `EventsMixin.list_events(level, task_id, limit)`（`src/xianyu_hunter/infra/repo_events.py`）
- `level` 与 `task_id` 均在 SQL 端过滤
- 时间范围按 `created_at` 字段在 Python 端过滤
- 排序：`created_at` 倒序

### 7.6 _filter_by_time 时间过滤算法

```python
def _filter_by_time(rows, time_col, start_dt, end_dt) -> list[dict]:
    """按时间范围过滤行（Python 侧过滤，避免新增 DAO 方法）"""
    if not start_dt and not end_dt:
        return list(rows)
    out = []
    for r in rows:
        t = to_datetime(r.get(time_col))
        if t is None:
            continue              # 时间字段缺失的行直接跳过
        if start_dt and t < start_dt:
            continue
        if end_dt and t > end_dt:
            continue
        out.append(r)
    return out
```

**设计意图**：
- 复用 Repository 现有查询方法，避免新增 DAO
- 用 `to_datetime()` 而非 `parse_iso_datetime()`：确保返回 aware datetime，与行内时间字段比较时不会因 naive vs aware 抛 `TypeError`
- `start` 与 `end` 均为闭区间（`<` 与 `>` 跳过边界外）

### 7.7 _build_csv_response CSV 生成

```python
def _build_csv_response(rows, columns, dataset) -> StreamingResponse:
    buf = io.StringIO()
    buf.write("\ufeff")               # UTF-8 BOM
    writer = csv.writer(buf)
    writer.writerow(columns)          # 表头
    for r in rows:
        writer.writerow([_row_value(r, c) for c in columns])
    fname = f"xh-{dataset}-{datetime.now().strftime('%Y%m%d-%H%M%S')}.csv"
    return StreamingResponse(
        iter([buf.getvalue()]),
        media_type="text/csv; charset=utf-8",
        headers={"Content-Disposition": f'attachment; filename="{fname}"'},
    )
```

**关键设计**：
- 一次性写入 `StringIO` 后用 `iter([buf.getvalue()])` 包装为单次迭代器，避免逐行 yield 的开销
- `_row_value(row, col)` 安全提取字段，缺失字段返回空字符串 `""` 而非 `None`，避免 CSV 出现 `None` 字面量
- 文件名带时间戳，避免覆盖同名文件


## 8. CSV 格式规范

### 8.1 编码

| 项             | 值                                       |
| -------------- | ---------------------------------------- |
| 字符编码       | UTF-8                                    |
| BOM 头         | `\ufeff`（写入 StringIO 开头）           |
| 兼容性         | Excel / Numbers / WPS / Google Sheets    |
| 媒体类型       | `text/csv; charset=utf-8`                |

**为什么需要 BOM**：Excel 默认按 GBK 解析 CSV，无 BOM 时中文会乱码。Numbers 与 WPS 同样依赖 BOM 识别 UTF-8。

### 8.2 列顺序

列顺序由 `_DATASET_COLUMNS` 字典定义，**与代码中数组顺序完全一致**，不会按字母重排。前端列定义预览接口返回的顺序就是 CSV 实际列顺序。

### 8.3 空值处理

| 情况                  | CSV 单元格内容         |
| --------------------- | ---------------------- |
| 字段缺失              | 空字符串（`""`）       |
| 字段为 `None`         | 空字符串（`""`）       |
| 字段为 `0` / `False`  | 原值（`0` / `False`）  |
| 时间字段为 `None`     | 空字符串               |
| 整行被时间过滤跳过    | 不写入                 |

### 8.4 特殊字段序列化

| 字段                  | 类型 | 序列化方式                                   |
| --------------------- | ---- | -------------------------------------------- |
| dimension_scores      | JSON | 直接 `str(dict)`（含 Python 单引号，非标准 JSON） |
| reject_reasons        | JSON | 直接 `str(list)`（含 Python 单引号）         |
| publish_time / 时间字段 | datetime | `str(datetime)`（如 `2026-07-05 10:30:45`） |

> **注**：`dimension_scores` 与 `reject_reasons` 在数据库中以 JSON 字符串存储，但导出时不解析原 JSON，而是按 SQLAlchemy Row → dict 后的字段值原样写入。若需标准 JSON 输出，需在 `_row_value` 中加判断（当前未做，保持简单）。

## 11. 错误处理

### 11.1 错误场景与响应

| 场景                       | 触发位置           | HTTP 状态码 | 响应体                                                                              | 前端表现                                  |
| -------------------------- | ------------------ | ----------- | ----------------------------------------------------------------------------------- | ----------------------------------------- |
| 未认证                     | 认证中间件         | 401         | `{"detail":"Unauthorized"}`                                                          | axios 拦截器跳转 `/login?redirect=...`     |
| 数据集 key 非法            | 路由 export_dataset | 400         | `{"detail":"未知数据集 xxx，可用: ['items', 'evaluations', 'orders', 'events']}"}` | 浏览器显示错误页（URL 直跳无法捕获）       |
| limit 超出范围              | FastAPI Query 校验 | 422         | FastAPI 自动生成的校验错误体                                                        | 浏览器显示错误页                          |
| 列定义接口失败              | 前端 useEffect    | -           | -                                                                                   | 使用静态列定义兜底，页面仍可渲染          |
| 导出 URL 触发后服务端错误   | 浏览器             | -           | -                                                                                   | 浏览器显示错误页，前端 `message.success` 已先弹出 |

### 11.2 前端列定义兜底

`frontend/src/pages/Export/index.tsx` 中 `useEffect` 的 `.catch` 分支使用静态列定义兜底，保证后端列定义接口失败时页面仍可渲染：

```typescript
.catch(() => {
  setDatasets([
    { key: 'items', columns: ['id', 'task_id', 'title', 'price', 'publish_time',
                              'region', 'seller_id', 'want_cnt', 'view_cnt',
                              'first_seen', 'last_seen'], description: '商品列表' },
    { key: 'evaluations', columns: ['id', 'item_id', 'seller_id', 'score', 'risk_level',
                                    'dimension_scores', 'reject_reasons', 'created_at'],
      description: '评估记录' },
    { key: 'orders', columns: ['id', 'task_id', 'item_id', 'seller_id', 'order_no',
                              'price', 'status', 'confirmed_at', 'paid_at', 'created_at'],
      description: '订单记录' },
    { key: 'events', columns: ['id', 'type', 'task_id', 'item_id', 'stage',
                              'level', 'message', 'created_at'], description: '事件日志' },
  ])
})
```

### 11.3 空数据处理

- 查询结果为空时，CSV 仅包含表头一行（无数据行），仍返回 200 OK 并触发下载
- 用户可看到只有表头的 CSV，明确知道"无符合条件的数据"
- 前端**不会**预先检查行数，避免额外的 count 查询开销

### 11.4 超限提示

- 前端 `InputNumber` 通过 `min`/`max` 限制输入范围
- 后端 `Query(5000, ge=1, le=50000)` 兜底校验，超出返回 422
- 422 响应由 FastAPI 自动生成，包含字段级错误详情

### 11.5 URL 直跳的局限

```typescript
// frontend/src/api/export.ts
download: (dataset, params) => {
  globalThis.location.href = exportApi.buildUrl(dataset, params)
}
```

**局限**：
- 浏览器原生下载无法捕获 HTTP 错误响应，失败时浏览器会显示错误页
- 前端只能立即弹出"正在导出..."成功提示，无法区分实际成功/失败
- 若需精细错误反馈，需改为 axios blob 下载（当前未采用，权衡点是简单与内存友好）

## 12. 权限与认证

### 12.1 认证要求

`/api/export` 与 `/api/export/{dataset}` **均不在 `PUBLIC_PREFIXES` 白名单中**，必须携带有效 token。

参考 `src/xianyu_hunter/web/middleware/auth.py`：
- `PUBLIC_PREFIXES` 仅包含静态资源、SPA 页面、登录相关接口、SSE 流、通知接口等
- `/api/export` 不在白名单，所有请求必须通过 `BearerAuthMiddleware` 校验

### 12.2 认证流程

```
请求到达 BearerAuthMiddleware
        │
        ▼
路径是否命中 PUBLIC_PREFIXES？  ──── 是 ───▶ 直接放行
        │ 否
        ▼
从 Authorization header 提取 Bearer token
        │
        ▼
从 xh_token cookie 提取 token
        │
        ▼
路径 1：与 .env 中 WEB_TOKEN 恒定时间比较
        │  匹配 → request.state.user_id = "default"，放行
        │  不匹配
        ▼
路径 2：调用 user_manager.verify_session(token) 校验会话
        │  匹配 → request.state.user_id = user_id，放行
        │  不匹配
        ▼
路径 3：返回 401 {"detail":"Unauthorized"}
```

### 12.3 前端凭证携带

前端 `frontend/src/api/client.ts` 配置：

```typescript
const client = axios.create({
  baseURL: '',
  timeout: 30000,
  withCredentials: true,    // 同源请求自动携带 cookie
})

client.interceptors.request.use((config) => {
  const token = localStorage.getItem('xh_token')
  if (token) {
    config.headers.Authorization = `Bearer ${token}`
  }
  return config
})
```

**导出场景特殊性**：
- 列定义接口 `GET /api/export` 通过 axios 调用，自动带上 `Authorization: Bearer xxx` header + `xh_token` cookie
- 导出下载通过 `globalThis.location.href = url` 浏览器直跳，**不会**走 axios，仅依赖同源请求自动携带的 `xh_token` cookie
- 因此导出功能要求浏览器已登录且 cookie 未过期，否则会跳转到 401 错误页

### 12.4 多用户隔离

当前 `/api/export` 路由内**未读取 `request.state.user_id`**，导出数据未做用户级隔离。所有通过认证的用户均可导出全量数据。

> **设计权衡**：本地个人工具场景下，多用户隔离优先级低于功能可用性。如需按用户隔离，需在路由内根据 `request.state.user_id` 过滤 Repository 查询参数（如 `list_items(user_id=...)`），当前未实现。

### 12.5 401 跳转

axios 响应拦截器统一处理 401：

```typescript
if (error.response?.status === 401) {
  localStorage.removeItem('xh_token')
  if (!isLoginPage && !isRedirecting) {
    isRedirecting = true
    globalThis.location.replace(`/login?redirect=${encodeURIComponent(currentPath)}`)
  }
}
```

**注意**：此跳转仅对 axios 请求生效；URL 直跳下载触发的 401 不会经过 axios，浏览器会显示原生 401 错误页。

## 14. 常见问题 FAQ

### Q1：数据导出支持哪些数据集？
**A**：共 4 个数据集：`items`（商品列表，11 列）、`evaluations`（评估记录，8 列）、`orders`（订单记录，10 列）、`events`（事件日志，8 列）。列定义由后端 `_DATASET_COLUMNS` 字典统一管理，前端通过 `GET /api/export` 拉取。

### Q2：CSV 文件为什么有 BOM 头？
**A**：UTF-8 BOM（`\ufeff`）让 Excel / Numbers / WPS 正确识别编码。无 BOM 时 Excel 默认按 GBK 解析，中文会乱码。后端在 `_build_csv_response` 中显式写入 `buf.write("\ufeff")`。

### Q3：行数上限是多少？默认多少？
**A**：默认 5000 行，最小 1，最大 50000。前端 `InputNumber` 与后端 `Query(5000, ge=1, le=50000)` 双重校验，超出范围后端返回 422。

### Q4：导出的 CSV 列顺序是怎么定的？
**A**：完全由后端 `_DATASET_COLUMNS` 字典中数组的顺序决定，不会按字母重排。前端 `GET /api/export` 返回的列顺序就是 CSV 实际列顺序，用户可在导出前在卡片中预览列定义。

### Q5：为什么 evaluations 按 task_id 过滤时还要查 items 表？
**A**：evaluations 表本身**无 `task_id` 列**（只有 `item_id`），无法直接按任务过滤。后端先查 items 表得到该 task_id 下的所有 item_id 集合，再分批查 evaluations（`batch_size=500` 避免 SQLite IN 子句参数上限）。

### Q6：导出下载为什么用浏览器直跳而不是 axios blob？
**A**：浏览器原生处理 CSV 流式响应更稳定，避免大文件 blob 占用 JS 堆内存；自动触发浏览器下载 UI，无需手写 `saveAs` 逻辑；同源请求会自动携带 `xh_token` cookie，无需额外 header。代价是无法捕获服务端错误响应。

### Q7：orders 数据集的 task_id 为什么是 Python 端二次过滤？
**A**：`OrdersMixin.list_orders` 本身支持 `task_id` 参数，但 `api_export.py` 中先以 `status` 与 `limit` 查询，再在 Python 端 `[r for r in rows if r.get("task_id") == task_id]` 二次过滤。这是为了与 `limit` 解耦——若在 SQL 端同时过滤 task_id 与 status，过滤后行数可能不足 limit，需要复杂分页。当前实现保持简单，代价是当 task_id 下订单很少时会拉取较多无关行。

### Q8：时间范围的 start 与 end 是开区间还是闭区间？
**A**：闭区间（含两端）。`_filter_by_time` 中 `if start_dt and t < start_dt: continue` 与 `if end_dt and t > end_dt: continue` 表示严格小于/大于才跳过，等于边界值的数据会被保留。

### Q9：导出功能需要认证吗？
**A**：需要。`/api/export` 与 `/api/export/{dataset}` 均不在 `PUBLIC_PREFIXES` 白名单中，必须携带有效 token。token 来源优先级：Authorization header（`Bearer xxx`）> `xh_token` cookie。导出下载走浏览器直跳，仅依赖 cookie，因此要求浏览器已登录且 cookie 未过期。

### Q10：ExportButton 和独立 Export 页面有什么区别？什么时候用哪个？
**A**：`ExportButton` 是嵌入式按钮，挂在业务页工具栏，使用调用方传入的 `params`（如当前页 `selectedTask`），适合"我正在看 X，导出当前 X"的快速场景；独立 `Export` 页面（`/export`）提供完整筛选表单（task_id / 时间范围 / status / level / limit），适合跨数据集、复杂筛选、大批量导出。两者底层共用 `exportApi.download`，CSV 生成逻辑完全一致。

### Q11：空数据导出会怎样？
**A**：查询结果为空时，CSV 仅包含表头一行（无数据行），仍返回 200 OK 并触发下载。前端不会预先检查行数，用户可看到只有表头的 CSV，明确知道"无符合条件的数据"。

### Q12：dimension_scores 与 reject_reasons 在 CSV 里是什么格式？
**A**：直接按 SQLAlchemy Row → dict 后的字段值原样写入。数据库中以 JSON 字符串存储，但导出时不解析原 JSON，会以 Python 字面量形式呈现（含单引号）。若需标准 JSON 输出，需在 `_row_value` 中加判断（当前未做，保持简单）。

### Q13：导出文件名是怎么命名的？
**A**：`xh-{dataset}-{YYYYMMDD-HHMMSS}.csv`，例如 `xh-items-20260705-103045.csv`。`dataset` 为数据集 key，时间戳取服务端 `datetime.now()`。文件名带时间戳避免覆盖同名文件。

### Q14：导出可以做用户级数据隔离吗？
**A**：当前未做。路由内未读取 `request.state.user_id`，所有通过认证的用户均可导出全量数据。如需按用户隔离，需在路由内根据 `request.state.user_id` 过滤 Repository 查询参数。本地个人工具场景下多用户隔离优先级较低，故未实现。

### Q15：4 个数据集的筛选字段有什么区别？
**A**：见 `DATASET_FILTERS` 矩阵——`task_id` 与 `time` 4 个数据集都支持；`status` 仅 orders 支持；`level` 仅 events 支持。前端按矩阵显隐筛选控件，后端按 dataset 分发到不同查询分支。
