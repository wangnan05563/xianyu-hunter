## 2. 功能概述

**一句话说明**：系统总览仪表盘，集中展示任务、订单、事件、评估的统计指标、业务 KPI、评估漏斗、异常雷达、价格直方图与实时事件流。

**核心价值**：
- 让运营人员一屏掌握整体运行状况，无需切换多个页面；
- 通过米其林星级 KPI 直观反映系统健康度；
- 通过 SSE 实时事件流和异常雷达，第一时间发现并定位问题；
- 通过评估漏斗与价格直方图，量化业务转化与市场价格分布。

---

## 3. 用户场景

### 场景一：日常巡检
运营人员每日登录后第一眼查看仪表盘，关注 KPI 卡片的星级是否为绿色（≥3 星），并扫读"今日异常"统计与异常雷达中的红色高亮项，确认系统无重大告警。

### 场景二：异常定位
当 EventStreamSection 出现 `buy.failed` 或 `waf.triggered` 事件时，运营人员点击事件条目快速跳转到对应任务或订单详情，进行人工介入。

### 场景三：业务复盘
运营人员通过 KpiSection 的"查看趋势"按钮打开 TrendModal，按日/周维度查看 `eval_pass_rate`、`order_success_rate` 等指标的历史曲线，分析业务转化瓶颈。

## 4. 页面布局与交互

### 4.1 组件结构

仪表盘主页面 `frontend/src/pages/Dashboard/index.tsx` 由 7 个子组件组合而成：

```
DashboardPage
├── StatCardsSection        # 顶部 4 张统计卡片（任务/订单/事件/评估）
├── KpiSection              # 业务 KPI 米其林星级卡片
├── EvalFunnelCard          # 评估漏斗图
├── AlertRadar              # 异常雷达图
├── EventStreamSection      # 实时事件流（SSE）
├── PriceHistogramCard      # 价格直方图
└── TrendModal              # 趋势弹窗（按需触发）
```

### 4.2 关键交互

| 组件                | 交互行为                                                                 |
| ------------------- | ------------------------------------------------------------------------ |
| StatCardsSection    | 点击卡片跳转对应列表页（/tasks、/orders、/timeline、/evaluations）        |
| KpiSection          | 根据阈值显示 0-5 星；点击"刷新"立即拉取；点击"查看趋势"打开 TrendModal    |
| EvalFunnelCard      | 鼠标悬停各阶段显示数量与转化率；点击阶段下钻到评估列表                   |
| AlertRadar          | 雷达图显示多维异常得分；红色维度点击进入对应告警详情                     |
| EventStreamSection  | 自动滚动到最新；支持暂停/恢复；断线自动重连并通过 lastEventId 回放       |
| PriceHistogramCard  | 支持切换任务范围与价格区间分桶数；悬停显示区间商品数量                   |
| TrendModal          | 支持指标切换、时间范围选择（7d/30d/90d）；折线图可下载 PNG               |

### 4.3 数据刷新策略

| 数据源              | 刷新方式     | 频率            |
| ------------------- | ------------ | --------------- |
| KPI 米其林卡片      | 轮询         | 5 分钟          |
| StatCards 概览      | 轮询         | 60 秒           |
| EvalFunnel 评估漏斗 | 轮询         | 60 秒           |
| AlertRadar 异常雷达 | 轮询         | 60 秒           |
| PriceHistogram      | 轮询         | 60 秒           |
| EventStream         | SSE 长连接   | 实时            |

## 5. 接口定义

### 5.1 API 路由表

| 方法   | 路径                       | 说明                 | 请求参数                                                                                                  | 响应字段                                                                                     |
| ------ | -------------------------- | -------------------- | --------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| GET    | `/api/stats`               | 系统总览统计         | 无                                                                                                        | `tasks_total`, `tasks_running`, `orders_today`, `events_today`, `evals_today`, `items_total` |
| GET    | `/api/stats/today`         | 今日异常汇总         | 无                                                                                                        | `waf_blocked`, `buy_failed`, `login_expired`, `task_errors`, `system_errors`                 |
| GET    | `/api/stats/business-kpi`  | 业务 KPI（米其林）   | 无                                                                                                        | `eval_pass_rate`, `order_success_rate`, `items_discovered`, `notify_failure_rate`（含星级）  |
| GET    | `/api/stats/trend`         | 指标趋势数据         | `metric` (string), `range` (7d/30d/90d)                                                                   | `dates[]`, `values[]`, `avg`, `max`, `min`                                                   |
| GET    | `/api/stats/eval-funnel`   | 评估漏斗             | `task_id` (可选)                                                                                          | `discovered`, `evaluated`, `eval_pass`, `order_triggered`, `order_succeeded`                 |
| GET    | `/api/prices/histogram`    | 价格直方图           | `task_id` (可选), `bins` (默认 20)                                                                        | `bins[]` (每桶含 `min`, `max`, `count`)                                                      |
| GET    | `/api/events/stream`       | SSE 实时事件流       | `lastEventId` (URL 参数，重连时附带)                                                                      | `id`, `type`, `task_id`, `item_id`, `level`, `message`, `created_at`                         |

### 5.2 SSE 事件格式

```
event: app_event
id: 12345
data: {"type":"buy.succeeded","task_id":"t_001","item_id":"i_998","level":"info","message":"抢单成功","created_at":"2026-06-29T10:23:11+00:00"}
```

## 6. 数据结构

### 6.1 events 表（EventRow）

仪表盘的实时事件流和异常统计均来自 `events` 表。

| 字段         | 类型    | 说明                                      |
| ------------ | ------- | ----------------------------------------- |
| id           | INTEGER | 主键，自增                                |
| type         | TEXT    | 事件类型（点分格式，如 `buy.succeeded`）  |
| task_id      | TEXT    | 关联任务 ID（可为空）                     |
| item_id      | TEXT    | 关联商品 ID（可为空）                     |
| stage        | TEXT    | 阶段（search/eval/buy/notify 等）         |
| level        | TEXT    | 级别（info/warning/error）                |
| message      | TEXT    | 事件描述                                  |
| payload      | JSON    | 事件负载（结构因 type 而异）              |
| created_at   | TEXT    | 创建时间（ISO8601，带 UTC 标记）          |

### 6.2 KPI 阈值配置

米其林星级采用 5 档阈值，覆盖 4 项核心 KPI：

| KPI 指标             | 单位  | 1 星     | 2 星     | 3 星     | 4 星     | 5 星     |
| -------------------- | ----- | -------- | -------- | -------- | -------- | -------- |
| eval_pass_rate       | %     | [0,50)   | [50,70)  | [70,85)  | [85,95)  | [95,100] |
| order_success_rate   | %     | [0,40)   | [40,60)  | [60,75)  | [75,85)  | [85,100] |
| items_discovered     | count | [0,200)  | [200,500)| [500,800)| [800,1500)| [1500,+∞)|
| notify_failure_rate  | %     | (50,100] | (20,50]  | (10,20]  | (5,10]   | [0,2]    |

> 注：`notify_failure_rate` 为负向指标，数值越小星级越高。

## 7. 业务逻辑

### 7.1 评估漏斗 5 阶段

```
discovered → evaluated → eval_pass → order_triggered → order_succeeded
   (发现)      (评估)      (通过)       (触发抢单)        (抢单成功)
```

每一阶段的转化率 = 下一阶段数量 / 当前阶段数量。漏斗图按从上至下宽度递减展示。

### 7.2 异常雷达多维度评分

AlertRadar 根据"今日异常"汇总数据计算 5 个维度的异常得分（0-100，越高越异常）：
- `waf_blocked`：WAF 拦截次数
- `buy_failed`：抢单失败次数
- `login_expired`：登录态失效次数
- `task_errors`：任务错误次数
- `system_errors`：系统错误次数

各维度按历史基线归一化后映射到雷达图顶点。

### 7.3 SSE 断线回放机制

```
[Client]                    [Server]
   │ ── 建立 SSE 连接 ─────→ │
   │                         │ (无 lastEventId)
   │ ←── 推送事件 id=N ───── │
   │                         │
   │ ── 连接断开 ──────────→ │
   │                         │
   │ (localStorage 持久化 lastEventId=N)
   │                         │
   │ ── 重连 + lastEventId=N →│
   │                         │ (从 N+1 开始回放)
   │ ←── 推送事件 id=N+1 ─── │
```

**关键实现**：
1. 每收到一条事件，将 `event.id` 写入 `localStorage.xianyu.lastEventId`；
2. `EventSource` `onerror` 触发时，按指数退避重连（1s→2s→4s…上限 30s）；
3. 重连 URL 附加 `?lastEventId=<N>`，服务端从该 ID 之后开始推送。

### 7.4 轮询与 SSE 协同策略

- SSE 提供秒级实时性，轮询保证数据最终一致；
- 当 SSE 连续失败 3 次后，临时将 EventStreamSection 切换为 30s 轮询 `/api/stats/today` 兜底；
- 页面失焦（`visibilitychange`）时暂停轮询以节省资源，恢复焦点后立即触发一次刷新。

## 9. 常见问题 FAQ

### Q1：仪表盘的数据多久刷新一次？
**A**：KPI 米其林卡片每 5 分钟轮询一次；统计卡片、评估漏斗、异常雷达、价格直方图每 60 秒轮询一次；实时事件流通过 SSE 长连接实时推送，无需轮询。

### Q2：KPI 卡片上的星星是怎么计算的？
**A**：每项 KPI 有 5 档阈值。例如 `eval_pass_rate`：[0,50) 为 1 星，[50,70) 为 2 星，[70,85) 为 3 星，[85,95) 为 4 星，[95,100] 为 5 星。`notify_failure_rate` 是负向指标，数值越小星级越高（[0,2] 为 5 星）。

### Q3：实时事件流断了会丢数据吗？
**A**：不会。客户端通过 `localStorage` 持久化 `lastEventId`，重连时附加到 URL 参数，服务端会从该 ID 之后开始回放事件，确保不丢不重。

### Q4：SSE 连续失败会怎样？
**A**：连续失败 3 次后，EventStreamSection 会临时降级为 30 秒轮询 `/api/stats/today` 作为兜底，待 SSE 恢复后自动切回实时模式。

### Q5：评估漏斗的 5 个阶段分别是什么？
**A**：discovered（发现）→ evaluated（评估）→ eval_pass（评估通过）→ order_triggered（触发抢单）→ order_succeeded（抢单成功）。每个阶段的转化率 = 下一阶段数量 / 当前阶段数量。

### Q6：异常雷达上的红色维度代表什么？
**A**：异常雷达包含 WAF 拦截、抢单失败、登录失效、任务错误、系统错误 5 个维度。各维度按历史基线归一化为 0-100 的异常得分，红色表示该维度得分超过告警阈值，点击可跳转对应详情。

### Q7：价格直方图可以筛选特定任务吗？
**A**：可以。`/api/prices/histogram` 接口接受可选的 `task_id` 参数，未传则汇总所有任务。同时支持 `bins` 参数控制分桶数（默认 20）。

### Q8：页面切到后台还会刷新吗？
**A**：不会。通过 `visibilitychange` 事件监听，页面失焦时暂停所有轮询以节省资源；恢复焦点后立即触发一次刷新，确保数据最新。

### Q9：TrendModal 支持哪些时间范围？
**A**：支持 7 天、30 天、90 天三个时间范围，可切换不同 KPI 指标（`eval_pass_rate`、`order_success_rate`、`items_discovered`、`notify_failure_rate`），折线图支持下载为 PNG。

### Q10：仪表盘上的统计卡片可以点击吗？
**A**：可以。4 张统计卡片分别对应任务、订单、事件、评估，点击后会跳转到对应的列表页（`/tasks`、`/orders`、`/timeline`、`/evaluations`），便于进一步查看明细。
