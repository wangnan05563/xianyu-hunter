## 1. 引言

### 1.1 编写目的

本需求规格说明书定义「配置管理 → 价格策略」二级菜单的完整需求规格，作为前端/后端开发、测试与验收的唯一依据。

**目标读者**：
- 后端开发工程师：依据 §3-§5、§7、§8 进行模块实现与扩展
- 前端开发工程师：依据 §3、§6 进行页面开发
- 测试工程师：依据 §7 编写测试用例与执行验收
- 项目经理：依据 §2、§7 进行范围与里程碑管理
- 智能客服 KB 训练：本文档与 [价格策略-详细设计.md](价格策略-详细设计.md) 共同作为 KB 检索素材

### 1.2 项目背景

闲鱼猎人（XianyuHunter）是一个闲鱼自动捡漏与抢单工具，已具备任务管理、商品采集、AI 评估、自动下单、多渠道通知等完整能力（详见 [requirements.md](../requirements.md)、[design.md](../design.md) 与 [概要设计文档.md](../概要设计文档.md)）。

随着系统运行规模扩大，**价格策略相关能力目前分散在多个模块**（`price_strategy.py` / `yaml_config.py` / `api_config.py` / `price_histogram.py` / `container.py` / `PriceStrategy.tsx`），缺乏统一的需求基线，导致以下痛点：

| 痛点 | 现状 | 影响 |
|------|------|------|
| 4 种策略开关无统一规格 | `PriceStrategyConfig` 字段存在但需求未文档化 | 新人难以理解策略组合语义 |
| 任务级覆盖机制缺失文档 | `Task.price_config` DB 字段存在但 SRS 未覆盖 | 单任务差异化配置无法验收 |
| 直方图预览与实际策略不一致 | 前端 `data.counts` 字段不存在导致走模拟数据 | 用户预览效果与实际效果脱节 |
| markLine 不渲染 | `chartOption.markLine` 放在顶层而非 `series[0]` | 价格阈值标记线不可见 |
| 热更新机制不透明 | `reload_config()` 行为未在 SRS 中明确 | 用户不知道保存后是否需要重启 |
| top_n 任务级覆盖未实现 | 两条调用路径均直接使用全局 | 任务级 top_n 配置无效但无文档说明 |
| 接口路径与字段易写错 | v1.0 详细设计把 `/api/prices/histogram` 写成单数 | 文档与实现不一致 |
| 策略命中预览估算口径不清 | 仅硬性上下限可预览，市场价比/TopN 无法预览 | 用户对预览精度有误解 |

**解决方案**：将 `PriceStrategyConfig`（Pydantic）+ `PriceConfig`（dataclass）+ `MarketContext`（dataclass）+ `PriceVerdict`（dataclass）+ `Task.price_config`（DB JSON）+ `PriceStrategy.tsx`（前端）+ 11 个 API 端点统一暴露；同时定义三态合并优先级、热更新机制、PATCH 三态语义、3 个已知 Bug 标注，**让价格策略配置可视化、可预览、可覆盖、可热更新**。

### 1.3 范围与约束

#### 1.3.1 包含范围（In-Scope）

- 4 种独立开关的价格过滤策略（硬性上限 / 硬性下限 / 低于市场参考价 / 同类低价 TopN）
- 全局配置 `PriceStrategyConfig`（8 个字段，Pydantic 模型校验）
- 任务级 `Task.price_config` DB JSON 字段覆盖（支持 `min_price`/`max_price`/`market_ratio` 三个字段，`top_n` 当前未实现）
- 三态合并优先级（DB 列 > price_config dict > 全局单例）
- 热更新机制（`reload_config()` 重置 `_config = None`）
- 通用配置接口 10 端点（`/api/config` 系列：get/preview/save/version/backups/rollback/restore-backup/share/export/import）
- 价格直方图接口 2 端点（`/api/prices/histogram`、`/api/prices/analyze`）
- 前端 1 个页面（`PriceStrategy.tsx`，4 个策略卡片 + 直方图预览 + Diff 预览 Modal）
- ECharts 直方图实时预览（仅硬性上下限策略可预览，市场价比与 TopN 依赖运行时 `MarketContext` 无法预览）
- 多版本备份与回滚（每次保存自动创建带时间戳的备份，最多保留 10 个）
- PATCH 三态语义（未传 / 传 null / 传 dict）用于任务级 `price_config` 字段
- 3 个已知前端 Bug 标注（counts 字段不存在 / markLine 位置错误 / 刷新预览数据空操作）
- 4 种策略 `check()` 逻辑（顺序执行、不短路、reasons 累计）

#### 1.3.2 排除范围（Out-of-Scope）

- 不实现 `top_n` 任务级覆盖（两条调用路径均直接使用全局，未来扩展需在 `build_task_price_strategy` 与 `_build_live_price_strategy` 同步补充）
- 不实现 `enabled_*` 开关的任务级覆盖（`PriceConfig` 用 `None` 表达"禁用"，任务级覆盖一旦提供 `min_price` 即视为开启下限策略）
- 不实现独立的价格策略 REST 路由（读写均通过通用配置接口 `/api/config`）
- 不修复 3 个已知前端 Bug（仅标注，修复不在本 SRS 范围内）
- 不实现前端 bins 输入框（`bins=20` 硬编码在 `useEffect` 中，用户无法调整）
- 不实现直方图市场价比/TopN 策略预览（依赖运行时 `MarketContext`，前端无法获取）
- 不实现跨任务价格策略对比（直方图按 `task_id` 单查或全量查，不并排对比）
- 不实现价格策略配置导入/导出独立接口（通过 `/api/config/export`+`/api/config/import` 全量配置导出导入）
- 不实现价格策略配置版本独立管理（通过 `/api/config/version`+`/api/config/backups`+`/api/config/rollback` 全量版本管理）

## 2. 总体描述

### 2.1 产品定位

「价格策略」是闲鱼猎人系统的**价格维度过滤配置入口**，定位为：

> 通过 4 种独立开关的价格策略（硬性上限、硬性下限、低于市场参考价、同类低价 TopN）对采集到的闲鱼商品进行价格维度过滤，并实时以 ECharts 直方图形式预览策略命中分布，所见即所得。

**核心价值**：
1. **防止 1 元引流**：硬性下限策略直接过滤低价引流商品，避免无意义通知
2. **避免高价误入评估**：硬性上限策略提前过滤超上限商品，节省 AI 评估 token
3. **自动剔除偏离市场价商品**：低于市场参考价策略基于中位数 + 样本数门槛智能过滤
4. **仅保留同类最低价**：TopN 策略保留同类中价格最低的前 N 个
5. **任务级差异化配置**：`Task.price_config` DB JSON 字段支持任务级覆盖
6. **热更新立即生效**：`reload_config()` 重置单例，下一轮调度自动用新配置

## 3. 功能需求

### FR-1 4 种价格策略配置

**FR-1.1** 硬性上限策略（`enabled_max` + `max_price`）
- 配置字段：`enabled_max: bool=True`、`max_price: int=10000`
- 策略语义：`item.price > max_price` 时拒绝，理由 `"price {p} > max {m}"`
- 默认开启，默认上限 10000 元
- 关闭时 `PriceConfig.max_price = None`，`check()` 跳过该策略

**FR-1.2** 硬性下限策略（`enabled_min` + `min_price`）
- 配置字段：`enabled_min: bool=True`、`min_price: int=100`
- 策略语义：`item.price < min_price` 时拒绝，理由 `"price {p} < min {m}"`
- 默认开启，默认下限 100 元（防 1 元引流）
- 关闭时 `PriceConfig.min_price = None`，`check()` 跳过该策略

**FR-1.3** 低于市场参考价策略（`enabled_market_ratio` + `market_ratio`）
- 配置字段：`enabled_market_ratio: bool=False`、`market_ratio: float=0.8`
- 策略语义：需同时满足以下条件才生效：
  1. `market_ratio is not None`
  2. `market_ratio < 1.0`（≥1.0 时策略不生效，与"低于市场参考价"语义相反）
  3. `market is not None`（`MarketContext` 由调度流程构建）
  4. `market.median_price is not None`
  5. `market.sample_size >= 3`（至少 3 个样本，避免中位数失真）
  6. `item.price > market.median_price * market_ratio` → 拒绝，理由 `"price {p} > median*ratio {v}"`
- 默认关闭，默认比率 0.8
- 关闭时 `PriceConfig.market_ratio = None`，`check()` 跳过该策略

**FR-1.4** 同类低价 TopN 策略（`enabled_top_n` + `top_n`）
- 配置字段：`enabled_top_n: bool=False`、`top_n: int=5`
- 策略语义：需同时满足以下条件才生效：
  1. `top_n is not None`
  2. `market is not None`
  3. `market.sample_size > top_n`（样本数小于等于 top_n 时不生效，避免全部拒绝）
  4. `cheaper = market.cheaper_count_for(item.price)`（fallback 到 `market.cheaper_seller_count`）
  5. `cheaper >= top_n` → 拒绝，理由 `"not_in_top_{n} (cheaper_count={c})"`
- 默认关闭，默认 N=5
- 关闭时 `PriceConfig.top_n = None`，`check()` 跳过该策略
- "同类"定义：**同一搜索关键词**下的商品（跨关键词不参与 TopN 计算）

**FR-1.5** 4 种策略独立开关与执行顺序
- 4 个策略完全独立，可任意组合开启/关闭
- 执行顺序固定：硬性上限 → 硬性下限 → 低于市场参考价 → 同类 TopN
- **不短路**：任一策略拒绝后 `pass_=False` 但继续执行后续策略，所有命中策略的 reason 都写入 `PriceVerdict.reasons`
- 一个商品可能同时命中多个策略（如既超上限又不在 TopN），reasons 累计

**FR-1.6** `has_any_rule()` 跳过优化
- `PriceConfig.has_any_rule()` 判断是否配置了任一价格规则（min/max/market_ratio/top_n 至少一个非 None）
- 调度流程在采集前调用此方法，返回 False 时跳过价格策略检查（直接通过）
- 避免无意义的方法调用开销

### FR-2 全局配置读写

**FR-2.1** `GET /api/config` 读取完整 `AppConfig`（已脱敏）

- 用途：保存前预览 diff，前端 `previewSave()` 调用

**FR-2.3** `POST /api/config/save` 保存配置（含 dry_run 模式 + 多版本备份）
- Body：`{payload: dict, dry_run: bool}`
- dry_run=true 时仅预览不写盘
- dry_run=false 时执行：
  1. `_load_yaml()` 读取当前 `config.yaml`
  2. `_deep_merge(new, payload)` 深度合并

  6. 调用 `reload_config()` 重置单例 `_config = None`
  7. 写盘失败时从刚生成的备份恢复
- 响应：`{ok, dry_run, saved_at?, diffs, backup?: {filename, pruned}, restart_required: true, restart_note?}`
- `restart_required=true` 仅是建议提示，配置已通过 `reload_config()` 立即生效，无需重启服务

**FR-2.4** `GET /api/config/version` 当前配置版本号
- 响应：`{version, latest_backup_ts, latest_backup_file}`

**FR-2.5** `GET /api/config/backups` 列出所有历史备份
- 响应：`{backups: [{filename, ts_raw, mtime, size, ts}], count, keep}`

**FR-2.6** `POST /api/config/rollback` 一键回滚到上一版本

**FR-2.7** `POST /api/config/restore-backup` 从指定备份恢复

- 响应：`{ok, restored_from, restored_at}`

**FR-2.8** `GET /api/config/share` 生成可分享的脱敏摘要

### FR-3 价格直方图预览

**FR-3.1** `GET /api/prices/histogram` 商品价格分档直方图
- 路径：`/api/prices/histogram`（**复数 prices**，不是 `/api/price/histogram`）
- Query 参数：
  - `bins: int=0`（0=固定 10 桶，20=自动 20 桶，其他值等同 0）
  - `task_id?: str`（任务 ID；为空或 `"all"` 时查全部任务）
- **没有** `range_hours` 参数（时间对比由后端在 `summary.compare` 字段固定返回）
- 响应：`{bins, summary, scope, mode}`（详见 §5.2）
- 数据来源：`items` 表中 `price` 字段非 NULL 的记录（按 `task_id` 过滤）
- 样本上限：单次查询 `LIMIT 10000`（防大表撑爆内存）；时间对比基线 `LIMIT 2000`（按 `publish_time` 倒序）
- 固定刻度分桶（`bins=0`）：使用预定义 `_PRICE_TICKS = [0, 50, 100, 200, 500, 1000, 2000, 5000, 10000, 20000]`，尾桶为 `[20000, +∞)`
- 自动分桶（`bins=20`）：基于 P5/P95 百分位裁剪极端值 + 任务定价范围融合，分 20 个等宽桶，首尾桶吸收范围外的极端值
- 分位数算法：`_percentile` 使用 NumPy 默认的线性插值算法

**FR-3.2** `POST /api/prices/analyze` LLM 价格分析
- Query：`task_id?: str`
- 响应：`{analysis, source, scope_label?}`
- 基于直方图数据调用 LLM 生成价格分析建议
- `httpx` 在函数内延迟导入（仅该端点用到）

**FR-3.3** 任务不存在时的响应
- `task_id` 非空且 DB 中不存在时返回空响应：
  - `bins: []`
  - `summary.count: 0`，其他统计字段为 0
  - `scope.label: "任务 {task_id}（不存在）"`

### FR-5 任务级价格策略覆盖

**FR-5.1** `Task.price_config` DB JSON 字段
- 位置：`tasks.price_config`（DB Text，JSON 序列化字符串）
- 支持覆盖的 key（与 `AppConfig.price_strategy` 子集对齐）：
  - `min_price: float` — 任务级下限
  - `max_price: float` — 任务级上限
  - `market_ratio: float` — 任务级市场价比率
  - `top_n: int` — 任务级 TopN（**当前未实现**，两条调用路径均直接使用全局）
- `enabled_*` 开关不在任务级覆盖范围内（`PriceConfig` 用 `None` 表达"禁用"）

**FR-5.2** 三态合并优先级
- 优先级从高到低：
  1. 任务级 `min_price`/`max_price` DB 列（`TaskRow.min_price`/`TaskRow.max_price`）
  2. 任务级 `price_config` dict（DB JSON 字段）
  3. 全局 `AppConfig.price_strategy`（YAML 单例）
- 具体合并规则（`container.build_task_price_strategy` 与 `api_task_links._build_live_price_strategy` 实现一致）：
  - `min_price`：DB 列优先；DB 列为 None 时取 `price_config.min_price`；都为 None 时沿用全局
  - `max_price`：DB 列优先；DB 列为 None 时取 `price_config.max_price`；都为 None 时沿用全局
  - `market_ratio`：`price_config.market_ratio` 优先；为 None 时沿用全局
  - `top_n`：**直接使用全局**，不读 `price_config.top_n`（当前实现的一致行为）
  - `enabled_*`：不读取，`PriceConfig` 用 None 表达禁用

**FR-5.3** 三个调用路径
- **Worker 注入**：`container.build_worker_from_raw_task(raw)` → 调用 `build_task_price_strategy(raw)` 构造 `PriceStrategy` 注入 `worker.price`
- **评估重算**：`container.build_task_price_strategy(raw)` 公共方法（recompute / batch_evaluate / collection_service 三条评估写入路径复用）
- **Live SSE 链路**：`api_task_links._build_live_price_strategy(container, task_id, items)` 独立函数，与 startup 注入路径行为一致

**FR-5.4** PATCH 三态语义（更新任务时）
- `PATCH /api/tasks/{id}` 时，`price_config` 字段使用 `model_dump(exclude_unset=True)` 区分三态：
  - **未传** `price_config`：字段被排除，跳过更新（保留原覆盖）
  - **传 `null`**：字段被包含，清除覆盖（`price_config` 设为 NULL，运行时回退全局）
  - **传 `dict`**：字段被包含，JSON 序列化存 DB（设置/替换覆盖）
- 序列化逻辑：`api_tasks._serialize_config_overrides`：`json.dumps(val) if val else None`（空 dict 也视为 None）

**FR-5.5** `MarketContext` 构建
- 由调度流程在同关键词下所有采集到的商品中计算（`worker._compute_market_context`）
- `median_price`：同关键词商品价格中位数
- `sample_size`：同关键词商品样本数
- `all_prices`：所有商品价格列表（升序）
- `cheaper_seller_count`：通过 `cheaper_count_for(price)` 实时计算
- 样本数 < 3 时返回 `None`，市场价比与 TopN 策略自动跳过
- Live SSE 链路在 `_build_live_price_strategy` 中复用同样逻辑

### FR-7 策略命中估算的边界情况

**FR-7.1** bin 标签无法解析
- 如 `"未知"` 等非数字标签会被 `Number.parseFloat` 解析为 `NaN`
- 比较时永远不命中（视为通过）

**FR-7.2** 策略全部关闭
- 所有 bin 都标记为 pass，`reject=0`

**FR-7.3** max_price < min_price（用户误配置）
- 所有 bin 都会被标记为 reject（同时被上下限拒绝）

#### 5.1.2 单例加载与热更新

```python
# src/xianyu_hunter/infra/yaml_config.py

_config: AppConfig | None = None

def get_config() -> AppConfig:
    """单例获取 AppConfig"""
    global _config
    if _config is None:
        _config = _load_all()  # 加载 config/*.yaml + 深度合并
    return _config

def reload_config() -> AppConfig:
    """热更新：重置单例，下次 get_config() 触发完整重载"""
    global _config
    _config = None
    return get_config()
```

**热更新流程**：
1. 前端 `confirmSave()` → `POST /api/config/save {payload, dry_run: false}`
2. 后端 `_load_yaml()` 读取当前 `config.yaml` → `_deep_merge(new, payload)` → `_validate(new)` 校验
3. 创建带时间戳备份 `config/backups/config.yaml.bak.YYYYMMDD-HHMMSS`
4. 写盘 `CONFIG_FILE.write_text(_dump_yaml(new))`
5. 调用 `reload_config()` 重置单例 `_config = None`
6. 写盘失败时从刚生成的备份恢复
7. 返回 `{ok, saved_at, diffs, backup, restart_required: true, restart_note}`

> **注意**：`restart_required=true` 仅是建议提示——配置已通过 `reload_config()` 立即生效，但正在执行的调度轮次可能继续使用旧配置直至本轮结束，下一轮必定用新配置。无需重启服务。

```python
@dataclass
class MarketContext:
    """市场参考上下文（采集器提供）"""
    median_price: float | None = None          # 同关键词中位数
    cheaper_seller_count: int = 0              # 比本商品更便宜的卖家数（逐商品计算）
    sample_size: int = 0                       # 样本数
    all_prices: list[float] | None = None      # 所有商品价格列表（排序后），供 TopN 策略逐商品计算

    def __post_init__(self) -> None:
        if self.all_prices is None:
            self.all_prices = []

    def cheaper_count_for(self, price: float) -> int:
        """计算比给定价格更便宜的卖家数（用于 TopN 策略逐商品判定）"""
        if not self.all_prices:
            return 0
        return sum(1 for p in self.all_prices if p < price)
```

### 5.3 `PriceStrategy.check()` 主逻辑

位置：`src/xianyu_hunter/modules/price_strategy.py` 第 56-116 行

策略按顺序执行，任一策略拒绝都会将 `pass_` 标记为 `False` 并记录 `reasons`（**不会短路**，所有命中策略都会写入 reasons）：

1. **硬性上限**：`max_price is not None and item.price > max_price` → 拒绝，理由 `price {p} > max {m}`
2. **硬性下限**：`min_price is not None and item.price < min_price` → 拒绝，理由 `price {p} < min {m}`
3. **低于市场参考价**：需同时满足 `market_ratio is not None`、`market_ratio < 1.0`、`market is not None`、`market.median_price is not None`、`market.sample_size >= 3`（至少 3 个样本）、`item.price > market.median_price * market_ratio` → 拒绝，理由 `price {p} > median*ratio {v}`
4. **同类 TopN**：需 `top_n is not None`、`market is not None`、`market.sample_size > top_n`，再从 `market.all_prices` 计算 `cheaper = market.cheaper_count_for(item.price)`（fallback 到 `market.cheaper_seller_count`），若 `cheaper >= top_n` → 拒绝，理由 `not_in_top_{n} (cheaper_count={c})`

### 5.4 校验规则

- **样本数门槛**：低于市场参考价策略要求 `sample_size >= 3`，避免样本过少导致中位数失真
- **TopN 样本门槛**：TopN 策略要求 `sample_size > top_n`，否则不应用（避免样本数小于 N 时全部拒绝）
- **market_ratio 范围**：策略仅在 `market_ratio < 1.0` 时生效（≥1.0 意味着"高于市场价"才拒绝，与策略语义不符）

#### 5.5.1 三态合并优先级

```
任务级 min_price/max_price（DB 列，最高优先级）
       ↓ None 时回退
任务级 price_config dict（DB JSON 字段）
       ↓ None 时回退
全局 AppConfig.price_strategy（YAML 单例）
```

具体合并规则（`container.build_task_price_strategy` 与 `api_task_links._build_live_price_strategy` 实现一致）：

| 字段 | 任务级 DB 列 | 任务级 `price_config` dict | 全局配置 |
|------|--------------|----------------------------|----------|
| `min_price` | `TaskRow.min_price` 优先 | DB 列为 None 时取 `price_config.min_price` | 都为 None 时沿用全局 |
| `max_price` | `TaskRow.max_price` 优先 | DB 列为 None 时取 `price_config.max_price` | 都为 None 时沿用全局 |
| `market_ratio` | — | `price_config.market_ratio` 优先 | 沿用全局 |
| `top_n` | — | 不读取（**直接使用全局**） | 全局 `top_n` |
| `enabled_*` | — | 不读取（**PriceConfig 用 None 表达禁用**） | 全局 `enabled_*` 转换为 None/具体值 |

> **注意**：`top_n` 在 live 链路（`_build_live_price_strategy`）中直接使用全局值，不读 `price_config.top_n`。`build_task_price_strategy` 也未读取 `top_n`。这是当前实现的一致行为，未来如需任务级 top_n 覆盖，需在两个函数中同步补充。

#### 5.5.2 PATCH 三态语义

`PATCH /api/tasks/{id}` 时，`price_config` 字段使用 `model_dump(exclude_unset=True)` 区分三态：

- **未传** `price_config`：字段被排除，跳过更新（保留原覆盖）
- **传 `null`**：字段被包含，清除覆盖（`price_config` 设为 NULL，运行时回退全局）
- **传 `dict`**：字段被包含，JSON 序列化存 DB（设置/替换覆盖）

序列化逻辑见 `api_tasks._serialize_config_overrides`：`json.dumps(val) if val else None`（空 dict 也视为 None）。

**根因**：后端 `/api/prices/histogram` 返回 `{bins, summary, scope, mode}`，其中 `bins` 是 `list[dict]`（含 `min`/`max`/`count`），**没有** `counts` 顶层字段。前端判断 `data?.counts` 永远为 `undefined`，条件不成立时 `setHistogram` 不被调用，但 `useEffect` 也不会触发 `catch`，最终 `histogram` state 保持初始 `null`，直方图区域显示为空。

**实际表现**：直方图区域柱状图为空（无数据），`previewResults` 因 `histogram=null` 返回 `{pass:0, reject:0, total:0}`，统计卡片三个值都为 0。

**正确修复方向**（不在本 SRS 范围内）：将 `data.bins: list[dict]` 映射为前端期望的 `{bins: string[], counts: number[]}` 格式。

### 8.5 FAQ / 设计权衡

**Q1：为什么价格策略没有独立的 REST 路由？**
A：价格策略是 `AppConfig` 的一个子段（`price_strategy:`），与评估规则、抢单策略、搜索参数等并列。读写均通过通用配置接口 `/api/config` 完成，避免为每个配置段单独维护 CRUD 路由。只有直方图预览走专用 `/api/prices/histogram`（因为它是查询接口而非配置接口）。

**Q2：为什么 `PriceConfig` 用 dataclass 而非 Pydantic 模型？**
A：`PriceConfig` 是运行时 dataclass（`@dataclass`），`PriceStrategyConfig` 是 Pydantic 模型。区别：
- **Pydantic 模型**：用于配置文件解析与校验，支持 YAML 序列化/反序列化、字段校验、类型转换
- **dataclass**：用于运行时计算，轻量级，无校验开销，适合在 `PriceStrategy.check()` 中传递参数

调度流程启动时从 `PriceStrategyConfig`（Pydantic）转换为 `PriceConfig`（dataclass）传入 `PriceStrategy`，分离配置层与运行时层。

**Q3：为什么 4 种策略不短路？**
A：任一策略拒绝后 `pass_=False` 但继续执行后续策略，所有命中策略的 reason 都写入 `PriceVerdict.reasons`。这是为了便于排查——一个商品可能同时命中多个策略（如既超上限又不在 TopN），所有 reason 都写入列表，便于日志分析和 Dashboard 展示。

**Q4：为什么市场价比策略要求 `sample_size >= 3`？**
A：避免样本过少导致中位数失真。如果当前关键词下采集到的商品少于 3 个，中位数无法稳定计算，策略自动跳过。

**Q5：为什么 TopN 策略要求 `sample_size > top_n`？**
A：避免样本数小于等于 N 时全部拒绝。例如设置 `top_n=5` 但同关键词只有 5 个商品时，策略不生效；需要有 6 个以上商品才会过滤掉第 6 名之后的商品。

**Q6：为什么 `market_ratio` 必须 `< 1.0` 才生效？**
A：策略语义是"低于市场参考价"——`market_ratio=0.8` 表示"价格高于市场价×0.8 时拒绝"（即只保留低于市场价 80% 的商品）。≥1.0 意味着"高于市场价才拒绝"，与策略语义相反。如需"高于市场价过滤"，请使用硬性上限策略。

**Q7：为什么 `top_n` 任务级覆盖未实现？**
A：当前 `build_task_price_strategy` 与 `_build_live_price_strategy` 两条调用路径均直接使用全局 `top_n`，不读 `price_config.top_n`。这是当前实现的一致行为，未来如需任务级 top_n 覆盖，需在两个函数中同步补充。

**Q8：为什么 `enabled_*` 开关不在任务级覆盖范围内？**
A：`PriceConfig` 用 `None` 表达"禁用"——任务级覆盖一旦提供 `min_price` 就视为开启下限策略。`enabled_*` 开关仅在全局 `PriceStrategyConfig` 层存在，转换为 `PriceConfig` 时 `enabled_*=False` 对应字段会被构造为 `None`。

**Q9：为什么 `restart_required=true` 但无需重启？**
A：`restart_required=true` 仅是建议提示——配置已通过 `reload_config()` 立即生效，但正在执行的调度轮次可能继续使用旧配置直至本轮结束，下一轮必定用新配置。无需重启服务。

**Q10：为什么直方图只预览硬性上下限策略？**
A：低于市场参考价和 TopN 策略需要运行时 `MarketContext`（中位数、样本数、全价格列表），前端在配置页面无法获取这些上下文，因此直方图仅按硬性上下限估算。完整 4 策略效果在采集调度流程中实时计算。

**Q11：为什么 v1.0 不修复 3 个已知前端 Bug？**
A：本 SRS v1.0 仅标注已知 Bug 作为验收边界与排错参考，修复不在范围内。后续修复时需同步更新详细设计 §8 与 FAQ，并补充集成测试用例。

**Q12：为什么前端 `bins=20` 硬编码？**
A：当前前端代码中不存在 bins 的 InputNumber 控件，`bins=20` 硬编码在 `useEffect` 中。用户无法在前端调整 bins 数量。后续如需用户调整，需新增 InputNumber 控件并将 bins 作为 state 传入 `priceApi.histogram()`。
