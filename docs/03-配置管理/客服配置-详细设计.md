## 2. 功能概述

**一句话说明**：通过 7 个 Tab 管理智能客服的基础配置、RAG 检索、AGENT 工具、知识库、FAQ、转人工、向量库维护、审计日志，支持 17 个 key 热更新（按 key 防抖 500ms PUT）。

**核心价值**：
- 7 个 Tab 覆盖智能客服全配置场景
- 17 个热更新 key 白名单，无需重启服务
- 静态配置（LLM 模型、知识库路径、Embedding 模型）需重启
- 知识库版本管理：rebuild/status/versions/rollback
- 审计日志仅存 sha256 hash 不存明文（敏感字段保护）
- 按 key 防抖 500ms PUT，避免 Slider/Input 高频 onChange 洪水请求
- 配置合并：yaml 基线 + DB 覆盖，DB 存热更新字段

## 3. 用户场景

### 场景 1：调整 RAG 检索参数
用户希望提高检索精度，将 `rag.similarity_threshold` 从 0.65 提高到 0.75。拖动 Slider，500ms 防抖后 PUT `/api/chatbot/config`，系统写入 DB + 审计日志，立即生效（下次对话即用新阈值）。

### 场景 2：管理 FAQ
用户添加常见问题"如何重置密码"。点击"新增 FAQ"，输入问题/答案/分类，保存。FAQMatcher 有 5 分钟 TTL 缓存，更新后最多 5 分钟内生效。

### 场景 3：回滚知识库版本
用户发现最新知识库构建后回答质量下降，查看"知识库管理"Tab 的版本列表，选择上一个版本点击"回滚"。系统调用 `/api/chatbot/kb/rollback`，回滚期间对话功能短暂不可用。

### 4.2 关键交互
- **按 key 防抖 500ms PUT**：`updateConfig(key, value)` 即时更新本地状态，500ms 防抖后 PUT。同一 key 连续修改只发一次请求，避免 Slider 拖动 / Input 输入时洪水请求。
- **配置失败回滚**：PUT 失败时重新 `chatbotApi.getConfig()` 加载，回滚本地状态。
- **组件卸载清理**：`useEffect` cleanup 清理所有防抖定时器，避免内存泄漏与卸载后状态更新。
- **嵌套字段更新**：`setNestedField(obj, path, value)` 按点分路径（如 `rag.top_k`）更新嵌套字段，保持不可变。
- **FAQ 编辑弹窗**：`FaqEditModal` 组件，新增/编辑共用，`useEffect` 在 open/faq 变化时重置表单。
- **知识库版本回滚确认**：`Modal.confirm` 确认后调用 `chatbotApi.rollbackKB(versionId)`，提示"回滚期间对话功能短暂不可用"。

## 7. 业务逻辑

### 7.1 配置合并：yaml 基线 + DB 覆盖

位置：`src/xianyu_hunter/web/routes/api_chatbot_config.py` `get_config()` 方法（第 80-141 行）

1. 以 yaml 配置为基线（`cfg = chatbot["config"]`）
2. 从 DB 读取所有热更新 key（`db_overrides = chatbot["repo"].get_all_config()`）
3. 按 key 类型转换（bool/int/float/str）覆盖基线值
4. 返回 `updatable_keys` 列表供前端参考

**为什么这样设计**：yaml 是基线（静态配置 + 默认值），DB 存热更新覆盖值。重启后 yaml 仍是基线，DB 覆盖立即生效。

### 7.2 热更新机制

位置：`src/xianyu_hunter/web/routes/api_chatbot_config.py` `update_config()` 方法（第 144-180 行）

1. `ConfigUpdateRequest.validate_updatable` 校验 key 在白名单内
2. `repo.get_config(key)` 读取旧值
3. 若 `old_value == req.value` 跳过写入（减少审计噪音）
4. `repo.set_config(key, value)` 写入 DB
5. `repo.add_audit_log(action, target, old_value_hash, new_value_hash, source)` 写审计日志
6. 返回 `{ok, key, old_value, new_value, changed}`

**热更新生效**：DB 写入后，下次 `get_config()` 读取时合并 DB 覆盖值，对话流程实时获取新配置。

### 7.3 审计日志与敏感字段保护

位置：`src/xianyu_hunter/web/routes/api_chatbot_config.py` `_hash_value()` 函数（第 73-77 行）

- 审计日志仅存 sha256 hash，不存明文
- `_hash_value(value)` = `hashlib.sha256(value.encode("utf-8")).hexdigest()`
- 用途：敏感字段（如 escalation.contact 联系方式）不暴露明文，但仍可审计变更
- 日志字段：`action` / `target` / `old_value_hash` / `new_value_hash` / `source` / `created_at`

### 7.4 按 key 防抖 500ms PUT

位置：`frontend/src/pages/Chatbot/Config.tsx` `updateConfig()` 函数（第 62-81 行）

```typescript
const updateTimersRef = useRef<Record<string, ReturnType<typeof setTimeout>>>({})

const updateConfig = (key, value) => {
  setConfig(prev => prev ? setNestedField(prev, key, value) : prev)  // 即时更新本地
  if (updateTimersRef.current[key]) clearTimeout(updateTimersRef.current[key])
  updateTimersRef.current[key] = setTimeout(async () => {
    await chatbotApi.updateConfig(key, String(value))
    delete updateTimersRef.current[key]
  }, 500)
}
```

**为什么 500ms**：Slider 拖动 / Input 输入是高频 onChange，直接 PUT 会洪水请求。500ms 防抖确保连续操作只发一次请求，同时保持即时本地更新避免 UI 回弹。

### 7.5 静态配置（需重启）

以下配置修改后需重启服务：
- `llm.model` / `llm.vision_model`：LLM 模型名
- `kb.doc_paths`：知识库扫描路径
- `kb.embedding_model` / `kb.embedding_dimensions`：Embedding 模型与维度
- `kb.chunk_size` / `kb.chunk_overlap`：分块参数
- `kb.embedding_concurrency`：Embedding 并发数

**为什么静态**：这些配置影响知识库构建（需重新 embedding）或 LLM 客户端初始化（需重新创建 client），运行时无法热切换。

### 7.6 FAQ 管理
- `list_faqs(active_only)`：按 sort_order ASC, id ASC 排序
- `upsert_faq`：id 为 None 新增，否则更新；FAQMatcher 有 5 分钟 TTL 缓存
- `delete_faq`：删除后 FAQMatcher 缓存最多 5 分钟内生效
- 字段映射：后端 `is_active` (int 0/1) ↔ 前端 `enabled` (boolean)，路由层转换

### 7.7 知识库版本管理
- `rebuild_kb(force)`：重建知识库，生成新版本
- `get_kb_status()`：当前状态（building/success/partial/failed）+ chunk_count + last_built_at
- `list_kb_versions()`：版本列表，每版本含 id/build_type/chunk_count/status/created_at/is_current
- `rollback_kb(version_id)`：回滚到指定版本，回滚期间对话功能短暂不可用

### 7.8 校验规则
- **key 白名单**：`ConfigUpdateRequest.validate_updatable` 校验 key 在 `_UPDATABLE_KEYS` 内，否则 422
- **value 长度**：`value: str = Field(..., max_length=1000)`，超长 422
- **FAQ 字段**：question `min_length=1, max_length=500`、answer `min_length=1, max_length=2000`、category `max_length=50`
- **chatbot 未启用**：`_get_chatbot_or_403()` 检查 `container.chatbot is None`，未启用返回 403 `CHATBOT_DISABLED`
- **类型转换**：DB 一律存字符串，读取时按 key 类型转换（bool/int/float/str）

## 9. 常见问题 FAQ

### Q1：哪些配置可以热更新？哪些需要重启？
**A**：17 个 key 支持热更新（见数据结构 6.3 白名单），包括 enabled/max_history_turns/rag.*/agent.*/kb.auto_update_enabled/kb.update_interval_hours/escalation.*。静态配置（需重启）：LLM 模型（llm.model/llm.vision_model）、知识库路径（kb.doc_paths）、Embedding 模型与维度（kb.embedding_model/kb.embedding_dimensions）、分块参数（kb.chunk_size/kb.chunk_overlap）。

### Q2：为什么审计日志不存明文？
**A**：审计日志仅存 sha256 hash 不存明文，这是敏感字段保护措施。例如 `escalation.contact`（转人工联系方式）可能含手机号/QQ 等个人信息，hash 后可审计变更但不泄露明文。`_hash_value(value) = hashlib.sha256(value.encode("utf-8")).hexdigest()`。

### Q3：按 key 防抖 500ms 是什么意思？
**A**：Slider 拖动 / Input 输入是高频 onChange，直接 PUT 会洪水请求。500ms 防抖确保同一 key 连续修改只发一次请求。例如拖动 `rag.similarity_threshold` Slider 从 0.65 到 0.85，期间触发多次 onChange，只有最后一次（500ms 内无新操作）会 PUT。本地状态即时更新避免 UI 回弹。

### Q4：配置合并是怎么工作的？
**A**：yaml 是基线（静态配置 + 默认值），DB 存热更新覆盖值。`get_config()` 先加载 yaml 基线，再从 DB 读取所有热更新 key，按类型转换（bool/int/float/str）覆盖基线值。重启后 yaml 仍是基线，DB 覆盖立即生效。

### Q5：FAQ 修改后多久生效？
**A**：FAQMatcher 有 5 分钟 TTL 缓存，更新后最多 5 分钟内生效（`_load_faqs` 重新加载）。如果想立即生效，可以重启服务或等待缓存自然过期。

### Q6：知识库回滚会中断对话吗？
**A**：会短暂中断。回滚期间对话功能短暂不可用（向量库索引切换中）。前端 `Modal.confirm` 会提示"回滚期间对话功能短暂不可用"，用户确认后才执行。

### Q7：智能客服未启用时访问配置会怎样？
**A**：返回 403 `CHATBOT_DISABLED`，detail="智能客服未启用"。`_get_chatbot_or_403()` 检查 `container.chatbot is None`。前端会显示"加载配置失败，请确认智能客服模块已启用"。

### Q8：value 字段为什么有 1000 字符限制？
**A**：`value: str = Field(..., max_length=1000)`，防止超长值导致 DB 存储问题或性能问题。大多数配置值（如阈值、轮数、联系方式）远小于 1000 字符。超长会返回 422。

### Q9：escalation.contact 为空时怎么显示？
**A**：`contact=""` 时显示"请联系管理员"。`contact` 字段用于转人工时给用户展示联系方式（如"QQ群 123456"），空则用默认文案。

### Q10：sanitize_pii 是什么意思？
**A**：`sanitize_pii=true` 时，转人工消息会脱敏 PII（个人身份信息），如手机号、身份证号、邮箱等会被替换为 `***`。保护用户隐私，避免敏感信息泄露给客服或记录到日志。
