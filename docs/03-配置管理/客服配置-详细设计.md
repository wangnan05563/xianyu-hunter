## 2. 功能概述

**一句话说明**：通过 8 个 Tab 管理智能客服的基础配置、RAG 检索、Agent 工具、知识库、FAQ、转人工、向量库维护、审计日志，支持 18 个 key 热更新（按 key 防抖 500ms PUT）；底层由 ChatbotOrchestrator 编排 FAQ → Intent → RAG → Agent → LLM → 转人工 完整流程，对话与会话能力通过 14 个独立 API 端点暴露。

**核心价值**：
- 8 个 Tab 覆盖智能客服全配置场景（含向量库维护）
- 18 个热更新 key 白名单，无需重启服务
- 静态配置（LLM 模型、知识库路径、Embedding 模型）需重启
- 知识库版本管理：rebuild/status/versions/rollback（两阶段提交 + 快照恢复）
- 审计日志仅存 sha256 hash 不存明文（敏感字段保护）
- 按 key 防抖 500ms PUT，避免 Slider/Input 高频 onChange 洪水请求
- 配置合并：YAML 静态基线 + DB 动态覆盖，DB 存热更新字段
- 双层配置架构：YAML 启动加载 + DB 运行时热更新
- per-session Lock：串行化同一会话编排，避免上下文错乱与内存泄漏
- AgentHarness（基于 OpenAI function_calling 多步工具调用）+ 5 个只读工具
- SSE 8 种事件类型流式响应，客户端断开自动停止
- Escalation 5 触发条件 + 降级链（LLM → RAG → 转人工）
- M1-M6 功能迭代：欢迎语引导卡 / 会话收藏 / 消息状态机 / 消息撤回 / 主动转人工 / 星级评分

## 3. 用户场景

### 场景 1：调整 RAG 检索参数（热更新）
用户希望提高检索精度，将 `rag.similarity_threshold` 从 0.65 提高到 0.75。拖动 Slider，500ms 防抖后 PUT `/api/chatbot/config`，系统写入 DB + 审计日志，立即生效（下次对话即用新阈值）。

### 场景 2：管理 FAQ
用户添加常见问题"如何重置密码"。点击"新增 FAQ"，输入问题/答案/分类，保存。FAQMatcher 有 5 分钟 TTL 缓存，更新后最多 5 分钟内生效。

### 场景 3：回滚知识库版本
用户发现最新知识库构建后回答质量下降，查看"知识库管理"Tab 的版本列表，选择上一个版本点击"回滚"。系统调用 `POST /api/chatbot/kb/rollback/{version_id}`（路径参数），回滚期间对话功能短暂不可用。

### 场景 4：M1 配置欢迎语（新增）
用户希望自定义智能客服首次对话的欢迎语。在"基础配置"Tab 修改 `welcome_message` 字段，500ms 防抖后 PUT `/api/chatbot/config`，DB 写入后立即生效。前端引导卡通过 `GET /api/chatbot/welcome` 拉取最新欢迎语展示。

### 场景 5：向量库维护（新增）
用户在"向量库维护"Tab 查看向量库健康状况、修复损坏的索引、清理孤儿快照。该 Tab 通过 `VectorAdminPanel` 组件提供运维能力，独立于"知识库管理"Tab（后者只负责版本管理）。

### 场景 6：转人工触发（新增）
用户在对话中连续点踩 2 次反馈，系统检测到负面反馈数 ≥ `escalation.feedback_threshold`，自动将会话状态置为 `escalated`，前端展示转人工提示与联系方式（来自 `escalation.contact`）。

### 4.2 关键交互
- **按 key 防抖 500ms PUT**：`updateConfig(key, value)` 即时更新本地状态，500ms 防抖后 PUT。同一 key 连续修改只发一次请求，避免 Slider 拖动 / Input 输入时洪水请求。
- **配置失败回滚**：PUT 失败时重新 `chatbotApi.getConfig()` 加载，回滚本地状态。
- **组件卸载清理**：`useEffect` cleanup 清理所有防抖定时器，避免内存泄漏与卸载后状态更新。
- **嵌套字段更新**：`setNestedField(obj, path, value)` 按点分路径（如 `rag.top_k`）更新嵌套字段，保持不可变。
- **FAQ 编辑弹窗**：`FaqEditModal` 组件，新增/编辑共用，`useEffect` 在 open/faq 变化时重置表单。
- **知识库版本回滚确认**：`Modal.confirm` 确认后调用 `chatbotApi.rollbackKB(versionId)`（路径参数 `POST /kb/rollback/{version_id}`），提示"回滚期间对话功能短暂不可用"。
- **building 状态轮询**：知识库构建中每 2 秒拉取 `/kb/status`，构建完成时整体刷新（拿到新版本列表与审计日志）。
- **错误隔离加载**：`Promise.all` 中每个请求独立 `.catch`，单个失败不影响其他状态（避免 chatbot 未启用时整体 reject 导致 kbVersions 为空）。
- **审计日志重建记录过滤**：`pickRebuildLogs` 从审计日志中过滤 `kb_rebuild`/`kb_rollback` 动作，按时间倒序取前 5 条展示在"知识库管理"Tab。

## 7. 业务逻辑

### 7.1 配置合并：YAML 基线 + DB 覆盖

位置：`api_chatbot_config.py` `get_config()` 第 155-182 行

1. 以 yaml 配置为基线（`cfg = chatbot["config"]`）
2. 从 DB 读取所有热更新 key（`db_overrides = chatbot["repo"].get_all_config()`）
3. 按 `_DB_OVERRIDE_RULES` 表驱动遍历，类型转换（bool/int/float/str）覆盖基线值
4. 返回 `updatable_keys` 列表供前端参考

**为什么这样设计**：yaml 是基线（静态配置 + 默认值），DB 存热更新覆盖值。重启后 yaml 仍是基线，DB 覆盖立即生效。表驱动遍历（`_DB_OVERRIDE_RULES`）替代 17 个重复 if 分支，主函数复杂度从 17 降至 ~3（SonarQube S3776 修复）。

### 7.2 热更新机制

位置：`api_chatbot_config.py` `update_config()` 第 185-221 行

1. `ConfigUpdateRequest.validate_updatable` 校验 key 在白名单内（18 个 key）
2. `repo.get_config(key)` 读取旧值
3. 若 `old_value == req.value` 跳过写入（减少审计噪音）
4. `repo.set_config(key, value)` 写入 DB
5. `repo.add_audit_log(action, target, old_value_hash, new_value_hash, source)` 写审计日志
6. 返回 `{ok, key, old_value, new_value, changed}`

**热更新生效**：DB 写入后，下次 `get_config()` 读取时合并 DB 覆盖值，对话流程实时获取新配置。

### 7.3 审计日志与敏感字段保护

位置：`api_chatbot_config.py` `_hash_value()` 第 95-99 行

- 审计日志仅存 sha256 hash，不存明文
- `_hash_value(value)` = `hashlib.sha256(value.encode("utf-8")).hexdigest()`
- 用途：敏感字段（如 `escalation.contact` 联系方式、`welcome_message` 欢迎语）不暴露明文，但仍可审计变更
- 日志字段：`action` / `target` / `old_value_hash` / `new_value_hash` / `source` / `created_at`

### 7.4 按 key 防抖 500ms PUT

位置：`frontend/src/pages/Chatbot/Config.tsx` `updateConfig()` 第 98-117 行

```typescript
const updateTimersRef = useRef<Record<string, ReturnType<typeof setTimeout>>>({})

const updateConfig = (key, value) => {
  setConfig(prev => prev ? setNestedField(prev, key, value) : prev)  // 即时更新本地
  if (updateTimersRef.current[key]) clearTimeout(updateTimersRef.current[key])
  updateTimersRef.current[key] = setTimeout(async () => {
    try {
      await chatbotApi.updateConfig(key, String(value))
      message.success('配置已更新')
    } catch {
      message.error('更新失败')
      const cfg = await chatbotApi.getConfig()  // 失败回滚本地
      setConfig(cfg)
    }
    delete updateTimersRef.current[key]
  }, 500)
}
```

**为什么 500ms**：Slider 拖动 / Input 输入是高频 onChange，直接 PUT 会洪水请求。500ms 防抖确保连续操作只发一次请求，同时保持即时本地更新避免 UI 回弹。

### 7.8 校验规则
- **key 白名单**：`ConfigUpdateRequest.validate_updatable` 校验 key 在 `_UPDATABLE_KEYS` 内（18 个），否则 422
- **value 长度**：`value: str = Field(..., max_length=1000)`，超长 422
- **FAQ 字段**：question `min_length=1, max_length=500`、answer `min_length=1, max_length=2000`、category `max_length=50`
- **chatbot 未启用**：`_get_chatbot_or_403()` 检查 `container.chatbot is None`，未启用返回 403 `CHATBOT_DISABLED`
- **类型转换**：DB 一律存字符串，读取时按 key 类型转换（bool/int/float/str）
- **会话/消息 ID 格式**：UUID32（无连字符 MD5 风格 hex），正则 `^[a-f0-9]{32}$`
- **消息长度**：`message: str = Field(..., min_length=1, max_length=2000)`
- **图片校验**：`images` 最多 4 张，必须 `data:image/*` 前缀，单张 ≤7M（约 5MB 原图）

```python
class ChatbotOrchestrator:
    def __init__(self, ...):
        self._session_locks: dict[str, asyncio.Lock] = {}  # session_id → Lock
        self._locks_guard = asyncio.Lock()  # 保护 _session_locks 字典本身
    
    async def _get_session_lock(self, session_id: str) -> asyncio.Lock:
        async with self._locks_guard:
            if session_id not in self._session_locks:
                self._session_locks[session_id] = asyncio.Lock()
            return self._session_locks[session_id]
```

**设计要点**：
- 串行化同一会话的编排，避免并发请求导致上下文错乱
- `ended` 状态会话主动清理 Lock（`_session_locks.pop`），防止内存泄漏
- `_locks_guard` 保护字典本身的并发访问，与 per-session Lock 区分层级

## 9. 常见问题 FAQ

### Q1：哪些配置可以热更新？哪些需要重启？
**A**：18 个 key 支持热更新（见数据结构 6.3 白名单），包括 enabled/max_history_turns/rag.*/agent.*/kb.auto_update_enabled/kb.update_interval_hours/escalation.*/welcome_message。静态配置（需重启）：LLM 模型（llm.model/llm.vision_model）、知识库路径（kb.doc_paths）、Embedding 模型与维度（kb.embedding_model/kb.embedding_dimensions）、分块参数（kb.chunk_size/kb.chunk_overlap）、ChromaDB 路径与集合（kb.persist_path/kb.collection_name/kb.project_root）。

### Q2：为什么审计日志不存明文？
**A**：审计日志仅存 sha256 hash 不存明文，这是敏感字段保护措施。例如 `escalation.contact`（转人工联系方式）、`welcome_message`（欢迎语）可能含手机号/QQ 等个人信息，hash 后可审计变更但不泄露明文。`_hash_value(value) = hashlib.sha256(value.encode("utf-8")).hexdigest()`。

### Q3：按 key 防抖 500ms 是什么意思？
**A**：Slider 拖动 / Input 输入是高频 onChange，直接 PUT 会洪水请求。500ms 防抖确保同一 key 连续修改只发一次请求。例如拖动 `rag.similarity_threshold` Slider 从 0.65 到 0.85，期间触发多次 onChange，只有最后一次（500ms 内无新操作）会 PUT。本地状态即时更新避免 UI 回弹。

### Q4：配置合并是怎么工作的？
**A**：yaml 是基线（静态配置 + 默认值），DB 存热更新覆盖值。`get_config()` 先加载 yaml 基线，再从 DB 读取所有热更新 key，按 `_DB_OVERRIDE_RULES` 表驱动类型转换（bool/int/float/str）覆盖基线值。重启后 yaml 仍是基线，DB 覆盖立即生效。表驱动替代 17 个重复 if 分支，主函数复杂度从 17 降至 ~3。

### Q5：FAQ 修改后多久生效？
**A**：FAQMatcher 有 5 分钟 TTL 缓存，更新后最多 5 分钟内生效（`_load_faqs` 重新加载）。如果想立即生效，可以重启服务或等待缓存自然过期。

### Q6：知识库回滚会中断对话吗？
**A**：会短暂中断。回滚期间对话功能短暂不可用（向量库索引切换中）。前端 `Modal.confirm` 会提示"回滚期间对话功能短暂不可用"，用户确认后才执行。回滚 API 为 `POST /api/chatbot/kb/rollback/{version_id}`（路径参数，非请求体）。

### Q7：智能客服未启用时访问配置会怎样？
**A**：返回 403 `CHATBOT_DISABLED`，detail=`{"code": "CHATBOT_DISABLED", "message": "智能客服未启用"}`。`_get_chatbot_or_403()` 检查 `container.chatbot is None`。前端会显示"智能客服模块未启用或加载失败"。

### Q8：value 字段为什么有 1000 字符限制？
**A**：`value: str = Field(..., max_length=1000)`，防止超长值导致 DB 存储问题或性能问题。大多数配置值（如阈值、轮数、联系方式、欢迎语）远小于 1000 字符。超长会返回 422。

### Q9：escalation.contact 为空时怎么显示？
**A**：`contact=""` 时显示"请联系管理员"。`contact` 字段用于转人工时给用户展示联系方式（如"QQ群 123456"），空则用默认文案。

### Q10：sanitize_pii 是什么意思？
**A**：`sanitize_pii=true` 时，转人工消息与导出会话记录会脱敏 PII（个人身份信息），如手机号、身份证号、邮箱、OpenAI API Key 等会被替换为 `<REDACTED>`。保护用户隐私，避免敏感信息泄露给客服或记录到日志。

### Q11：per-session Lock 会导致内存泄漏吗？【v2.0 新增】
**A**：不会。会话 `ended` 时主动清理 Lock：`_session_locks.pop(session_id, None)`。同时 `escalated` 状态会话再次进入也会触发清理。`_locks_guard` 保护字典本身的并发访问，与 per-session Lock 区分层级。

### Q12：知识库构建失败如何回滚？【v2.0 新增】
**A**：两阶段提交保证可回滚：阶段1导出快照到临时目录；阶段2失败时调用 `_rollback_build` 恢复快照。失败率 >50% 自动触发回滚（状态记为 `failed` 并恢复上一版本），10%~50% 记为 `partial` 保留部分结果。

### Q13：Agent 工具调用失败如何处理？【v2.0 新增】
**A**：异常统一转换为 `AgentEvent("error")`，由 Orchestrator 决定降级（走 LLM → RAG → 转人工 降级链）。工具不存在/已禁用、工具超时、工具内部 Exception 都返回 `ToolResult(success=False)`，`asyncio.CancelledError` 向上传播触发资源清理。

### Q14：本地 Embedding 与远程 Embedding 如何切换？【v2.0 新增】
**A**：通过 `.env` 中的 `EMBEDDING_BASE_URL` 配置：留空或 `local` 使用本地 sentence-transformers（BAAI/bge-small-zh-v1.5，512 维）；配置 URL 使用 OpenAI 兼容 API。`local_embedding.py` 模块顶层设置 `HF_ENDPOINT=https://hf-mirror.com` 避免国内访问超时。

### Q15：M6 星级评分如何与 positive/negative 评级对应？【v2.0 新增】
**A**：当 `star_rating` 存在时，后端自动派生 rating，防止客户端传矛盾值：4-5 星 → positive，1-3 星 → negative；`star_rating` 为 None 时沿用客户端传的 rating。反馈分类 `category` 取值 irrelevant/inaccurate/other。
