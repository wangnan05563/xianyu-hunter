## 2. 功能概述

**一句话说明**：通过版本号（=备份数量）+ 多版本备份（BACKUP_KEEP=10）+ 一键回滚 + 指定恢复 + 导入/导出 + 分享脱敏，实现配置的全生命周期管理与误操作回滚。

**核心价值**：
- 版本号 = 备份文件数量，每次保存自然递增
- 备份文件名 `config.yaml.bak.YYYYMMDD-HHMMSS`，秒级精度
- BACKUP_KEEP=10，超出自动清理旧备份
- 一键回滚（最近备份）+ 指定恢复（任意备份）双路径
- 回滚前自动备份当前配置（安全网）
- 白名单校验防目录穿越（filename 只含字母数字 + - _ .）
- 写盘失败自动从备份恢复
- 导入流程：校验 schema → 预览 diff → Modal 确认 → 写盘
- 分享配置：SENSITIVE_KEYS 替换为 ***
- 字段级回滚：configStore.getFieldOriginal/revertField 支持点分路径

## 3. 用户场景

### 场景 1：误改配置后一键回滚
用户在"评估规则"页面误改了权重，保存后发现评分异常。进入"配置版本管理"页面，点击"一键回滚"，系统自动备份当前配置后用最近备份覆盖，配置恢复到上次保存的状态。

### 场景 2：从指定备份恢复
用户想恢复到 3 天前的配置版本。在版本时间线中找到对应备份，点击"恢复"按钮，系统从该备份恢复配置。回滚前会自动备份当前配置作为安全网。

### 场景 3：导出配置迁移到新机器
用户想在新机器上复用当前配置。点击"导出配置"，浏览器下载 `xianyu_hunter_config_YYYYMMDD.json` 文件（含 schema + 元数据 + 脱敏配置）。在新机器点击"导入配置"上传该文件，预览 diff 后确认导入。

## 7. 业务逻辑

### 7.1 版本号 = 备份数量

位置：`src/xianyu_hunter/web/routes/api_config.py` `get_config_version()` 函数（第 463-477 行）

- `version = len(_list_backups())`：版本号等于备份文件数量
- 0 表示从未保存过（初始配置），前端据此决定是否显示回滚按钮
- 每次保存自然递增（自动创建新备份）

### 7.2 备份文件命名与清理

#### 命名规则
位置：`src/xianyu_hunter/web/routes/api_config.py` `_new_backup_name()` 函数（第 80-82 行）

```
config.yaml.bak.YYYYMMDD-HHMMSS
```
- 秒级精度，足够日常区分
- 例：`config.yaml.bak.20260629-100000`

#### 自动清理
位置：`src/xianyu_hunter/web/routes/api_config.py` `_prune_backups()` 函数（第 111-128 行）

- `BACKUP_KEEP=10`：保留最近 10 个备份
- 超出的旧备份自动清理（按 mtime 倒序，保留前 10）
- 单个清理失败不影响其他（`except OSError: pass`）
- 不软删除/归档：备份仅为"误改后回滚"，无需审计

### 7.3 回滚逻辑

#### 一键回滚（最近备份）
位置：`src/xianyu_hunter/web/routes/api_config.py` `rollback_config()` 函数（第 480-513 行）

1. `_list_backups()` 获取备份列表
2. 若无备份 → 404 "没有可回滚的备份"
3. 取 `backups[0]`（最新备份）作为目标
4. **回滚前先备份当前配置**（安全网）：`pre_bak = BACKUP_DIR / _new_backup_name()`，写入当前配置
5. `_prune_backups()` 清理超出 BACKUP_KEEP 的旧备份
6. 用目标备份覆盖 `CONFIG_FILE`
7. `reload_config()` 重置单例
8. 返回 `{ok, rolled_back_to, rolled_back_file, version}`

**为什么回滚前先备份**：防止误操作后无法恢复。回滚本身也是一次"配置变更"，需要可追溯。

#### 指定恢复（任意备份）
位置：`src/xianyu_hunter/web/routes/api_config.py` `restore_backup()` 函数（第 516-540 行）

1. 不传 filename → 回退到旧 `.yaml.bak`（兼容升级前已存在的备份）
2. 传 filename → `_resolve_backup(filename)` 校验白名单
3. 用目标备份覆盖 `CONFIG_FILE`
4. `reload_config()` 重置单例
5. 返回 `{ok, restored_from, restored_at}`

### 7.4 白名单校验防目录穿越

位置：`src/xianyu_hunter/web/routes/api_config.py` `_resolve_backup()` 函数（第 131-144 行）

```python
def _resolve_backup(filename: str) -> Path:
    if not filename or not filename.startswith(BACKUP_PREFIX):
        raise HTTPException(status_code=400, detail="非法的备份文件名")
    if not all(c.isalnum() or c in "-_." for c in filename):
        raise HTTPException(status_code=400, detail="备份文件名包含非法字符")
    p = BACKUP_DIR / filename
    if not p.is_file():
        raise HTTPException(status_code=404, detail=f"备份 {filename} 不存在")
    return p
```

**为什么需要**：防止 `filename` 里塞 `../` 实现目录穿越读取任意文件。白名单字符集：字母数字 + 时间戳分隔符（`-`）+ `.` + `_`。

### 7.5 写盘失败自动恢复

位置：`src/xianyu_hunter/web/routes/api_config.py` `save_config()` 函数（第 221-230 行）

```python
try:
    CONFIG_FILE.write_text(_dump_yaml(new), encoding="utf-8")
    reload_config()
except Exception as e:
    if new_bak and new_bak.exists():
        CONFIG_FILE.write_text(new_bak.read_text(encoding="utf-8"), encoding="utf-8")
    raise HTTPException(status_code=500, detail=f"写入失败，已回滚: {e}")
```

**为什么**：写盘可能因磁盘满/权限问题失败。失败后从刚生成的备份恢复，保证配置文件不损坏。

### 7.6 导入流程

位置：`src/xianyu_hunter/web/routes/api_config.py` `import_config()` 函数（第 382-460 行）

1. 校验 `schema == "xianyu_hunter.config/v1"`，否则 400
2. 校验 `config` 是 dict，否则 400
3. `_validate(incoming)` 用 AppConfig 模型校验，失败 400
4. `_diff(current, incoming)` 计算 diff
5. 若未传 `confirm=true` → 返回 `{ok: false, needs_confirm: true, diffs, diff_count}`，前端二次确认
6. 传 `confirm=true` → 备份当前文件 + 写盘 + reload
7. 写盘失败从备份恢复
8. 返回 `{ok: true, diffs, diff_count, backup, imported_at, restart_required}`

### 7.7 导出脱敏

位置：`src/xianyu_hunter/web/routes/api_config.py` `export_config()` 函数（第 347-379 行）

- `_sanitize_dict(raw)` 递归脱敏，敏感字段仅保留末 4 位
- `_SENSITIVE_KEYS = {"serverchan_key", "pushplus_token", "bark_key", "openai_api_key"}`
- `_sanitize_value(val) = "****" + val[-4:]`（长度 ≤4 时返回 `"****"`）
- 返回 JSON 文件，Content-Disposition 触发浏览器下载

### 7.8 分享配置脱敏

位置：`src/xianyu_hunter/web/routes/api_config.py` `_redact_for_share()` 函数（第 268-291 行）

- 与 `/api/config` 的 `_redact` 不同：分享场景"主动精简"，只留"工作参数"
- `_SHARE_REDACT_PATHS` 中的字段：string 替换为 `***`，dict 替换为 `{k: "***"}`，其他删除
- 输出 summary（人类可读纯文本）+ config（脱敏 dict）+ redacted_fields（被脱敏的字段名列表）

### 7.9 字段级回滚

位置：`frontend/src/stores/configStore.ts` `getFieldOriginal` / `revertField` 函数（第 121-151 行）

- `getFieldOriginal(path)`：按点分路径（如 `eval.pass_score`）从 `original` 中获取原始值
- `revertField(path)`：将 `config` 中指定 path 的值恢复为 `original` 中的值
- 路径不存在时不写入，避免在 config 上创建 undefined 键
- 深拷贝 config 避免引用问题

### 7.10 校验规则
- **schema 校验**：导入时强制 `schema == "xianyu_hunter.config/v1"`
- **AppConfig 模型校验**：`_validate(data)` 用 Pydantic 模型校验所有字段
- **filename 白名单**：`_resolve_backup` 校验只含字母数字 + `-` `_` `.`
- **BACKUP_PREFIX 前缀**：filename 必须以 `config.yaml.bak.` 开头
- **confirm 二次确认**：导入时未传 `confirm=true` 返回 `needs_confirm`

## 9. 常见问题 FAQ

### Q1：版本号是怎么算的？
**A**：版本号 = 备份文件数量。每次保存自动创建一个备份，版本号自然递增。0 表示从未保存过（初始配置）。前端据此决定是否显示回滚按钮。

### Q2：备份会占用很多磁盘空间吗？
**A**：不会。`BACKUP_KEEP=10` 保留最近 10 个备份，超出的旧备份自动清理。单个配置文件通常几 KB，10 个备份总共也就几十 KB。

### Q3：一键回滚和指定恢复有什么区别？
**A**：一键回滚（`/api/config/rollback`）自动取最新备份，不需要传 filename，回滚前会自动备份当前配置作为安全网。指定恢复（`/api/config/restore-backup?filename=xxx`）从指定备份恢复，需传 filename（带白名单校验防穿越）。

### Q4：回滚后还能再回滚回去吗？
**A**：能。回滚前会自动备份当前配置（安全网），所以回滚后想恢复到回滚前的状态，再次"一键回滚"即可（最新的备份就是回滚前的状态）。

### Q5：导入配置会覆盖现有配置吗？
**A**：会，但有保护流程：校验 schema → 预览 diff → Modal 确认 → 写盘。导入前会自动备份当前配置，写盘失败从备份恢复。未传 `confirm=true` 时返回 `needs_confirm`，前端必须二次确认。

### Q6：导出的配置包含敏感信息吗？
**A**：导出时 `_sanitize_dict` 递归脱敏，敏感字段（serverchan_key/pushplus_token/bark_key/openai_api_key）仅保留末 4 位（`****xxxx`）。但 UA/keyword 等工作参数不脱敏。分享配置（`/api/config/share`）更严格，移除 token/路径等敏感字段。

### Q7：filename 参数为什么要白名单校验？
**A**：防止目录穿越攻击。如果不校验，攻击者传 `../../../etc/passwd` 可能读取任意文件。`_resolve_backup` 校验 filename 只含字母数字 + `-` `_` `.`，且必须以 `config.yaml.bak.` 开头。

### Q8：写盘失败会怎样？
**A**：自动从刚生成的备份恢复。`save_config` 中 `try/except` 捕获写盘异常，从 `new_bak` 读取内容写回 `CONFIG_FILE`，保证配置文件不损坏。返回 500 错误提示"写入失败，已回滚"。

### Q9：字段级回滚怎么用？
**A**：在配置编辑页面（如评估规则），每个数值字段右侧有回滚按钮（仅当值与原始值不同时显示）。点击调用 `revertField(path)`，将 config 中指定 path 恢复为 original 中的值。path 支持点分（如 `eval.pass_score`）。若已保存，需通过"配置版本管理"页面整体回滚。

### Q10：分享配置会泄露我的 API Key 吗？
**A**：不会。分享时 `_redact_for_share` 移除 token/路径等敏感字段：string 替换为 `***`，dict 替换为 `{k: "***"}`。`_SHARE_REDACT_PATHS` 包含 serverchan_send_key/pushplus_token/bark_server/bark_key/browser.user_data_dir 等。分享输出还附带 `redacted_fields` 列表告知被脱敏的字段。
