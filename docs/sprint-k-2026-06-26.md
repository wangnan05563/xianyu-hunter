**背景**：
反爬登录管理菜单中"会话管理"卡片原本需要用户登录后手动点击"启动会话"按钮才能开始 TokenRenewer 后台续期。但 TokenRenewer 维持 `_m_h5_tk` 续期是后续实时搜索/详情采集的前置条件，手动启动容易遗漏导致实时搜索被闲鱼重定向到首页。本次优化将启动动作从"用户操作"降级为"登录成功后的自动副作用"。

## §1 O-15 会话管理自动启动（P2）

### 改动点

**1. 抽离 `LoginOrchestrator.start_session_default()` 便捷方法**

封装"默认 cookie_provider + 默认 renew_callback"组合，4 个登录入口复用：

- `cookie_provider` 从 `CookieStore` 读取 `_m_h5_tk`
- `renew_callback` 通过浏览器导航到 `h5.m.taobao.com` 触发（导航是用户自然行为，风控压力低于直接调用 `getTimestamp` API）
- 失败仅记录 `logger.debug` 级别日志，不抛异常（避免影响登录成功返回）
- 已活跃会话内部跳过（避免重复启动 TokenRenewer）

**2. 抽出共享 helper `web/services/session_starter.py`**

```python
def trigger_session_start() -> None:
    """登录成功后自动启动会话管理（fire-and-forget）"""
    from xianyu_hunter.modules.login_orchestrator import get_orchestrator
    orch = get_orchestrator()
    loop = asyncio.get_event_loop()
    if loop.is_running():
        asyncio.ensure_future(orch.start_session_default())
    else:
        asyncio.run(orch.start_session_default())
```

**3. 4 个登录入口接入**

| 文件 | 触发点 | 数量 |
|------|--------|------|
| `web/routes/unified_login.py` | 扫码登录 `_background_wait_qr` / 浏览器登录 `_background_wait` / `login_status` 状态轮询兜底 | 3 |
| `web/routes/browser_login.py` | 旧版浏览器登录成功路径 | 1 |
| `web/routes/browser_import.py` | `export_cookies` 之后 | 1 |
| `web/routes/cookie_inject.py` | `/api/auth/cookie` + `/api/auth/cookie/import-from-browser` | 2 |

**4. 前端兜底提示**

`AntiCrawl` 页面会话管理卡片：当 `session.active == false` 但 `cookie_layers.identity == true` 时显示黄色 Alert，让用户感知到自动启动异常（极少见，仅在浏览器未启动等异常情况下出现）。

### 关键设计决策

- **fire-and-forget 调度**：登录流程在后台线程中运行，调用 `asyncio.ensure_future` 调度到 FastAPI 主事件循环，登录成功返回不被会话启动阻塞。
- **失败安全**：自动启动失败仅记录 `logger.debug` 级别日志，不影响登录成功返回路径。已活跃会话通过 `start_session_default` 内部判断跳过，避免重复启动 TokenRenewer。
- **浏览器依赖**：`_default_renew_callback` 在浏览器不可用时返回 `False`，TokenRenewer 续期失败会自动触发 `on_renew_fail` 回调标记 session 层失效。
- **前端最小化**：仅在异常场景下显示提示（不增加常态提示），避免对正常使用流程造成干扰。
