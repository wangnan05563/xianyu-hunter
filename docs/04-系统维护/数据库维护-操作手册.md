## 1. 概述

「数据库维护」是闲鱼猎人「系统维护」菜单下的二级页面，定位为**轻量级数据库管理工具**：仅允许查看与编辑 11 张业务表（任务、商品、卖家、订单等），不可操作系统底层表，所有写操作都会写入审计日志，所有危险操作都需要二次确认。

适用于以下场景：发现某条任务的关键词配置错误需要直接修正；商品价格采集异常需要手工校准；批量清理失效任务与关联数据；导出订单数据用于对账；从外部 CSV 批量导入代理 IP；排查某次历史操作的具体时间与影响范围等。

**本菜单不提供修改表结构（增删字段）的能力**，表结构由后端 ORM 集中管理。如需调整字段，请联系开发人员修改 ORM 定义后重启服务。

**安全提示**：本菜单涉及直接修改业务数据，请谨慎操作。建议操作前先通过「导出」功能备份数据；删除操作不可恢复，但所有写操作都会自动记录到审计日志中，可随时回溯。

## 2. 核心特性

- **业务表白名单**：仅 11 张业务表可被操作，系统底层表（如 sqlite_master）一律拒绝访问，从源头防止误操作系统核心数据
- **左右分栏布局**：左侧 220px 宽度展示业务表列表，右侧为数据网格与操作工具栏，符合常见数据库管理工具的使用习惯
- **动态表单**：编辑时根据列类型自动渲染对应输入控件（数字框、开关、文本域、日期框等），无需开发人员为每张表单独编写表单
- **关键词搜索**：对所有文本列做模糊匹配，输入 400ms 防抖触发；搜索历史自动持久化到浏览器本地，便于复用
- **行级编辑**：支持单行新增、行内编辑、单行删除、批量删除（上限 1000 行），主键字段在编辑模式下禁用
- **导入导出**：CSV / JSON 双格式互转，CSV 自带 UTF-8 BOM 让 Excel 正确识别编码；导出采用流式输出，避免大表内存峰值
- **级联预览**：删除主表数据前会显示将影响哪些关联表与行数，包含级联删除与外键置空两种策略的可视化提示
- **双重确认**：所有删除与导入操作必须输入 `CONFIRM_DELETE` 才能执行（区分大小写），防止误点击与脚本恶意调用
- **审计日志**：所有新增 / 更新 / 删除 / 批量删除 / 导入操作自动写入 `events` 表，type 字段以 `db_admin.` 前缀标识，可在本页面或「实时日志」页回溯

## 3. 页面入口与布局

### 3.1 进入路径

在闲鱼猎人左侧导航栏点击「**系统维护 → 数据库维护**」即可进入。

进入后页面顶部会显示一条黄色警示条：「数据操作有风险 · 建议操作前先在「导出」中下载备份。删除操作不可恢复，审计日志可在右上角查看。」此警示条常驻显示，提醒用户谨慎操作。

### 3.3 左侧表列表

- 宽度 220px，标题为「业务表」并配有数据库图标
- 11 张业务表纵向排列，每张表显示：
  - 中文名（如「任务」）+ 表图标（橙色）
  - 英文表名（如 `tasks`）+ 当前行数（如 `12 行`）
- 当前选中的表会用浅橙色背景（`#fff5e6`）+ 左侧 3px 橙色边框（`#FF6200`）高亮
- 进入页面时默认选中第一张表（`tasks`）
- 表列表支持鼠标滚动，无搜索框（11 张表数量较少，无需搜索）

### 3.4 右侧工具栏

工具栏位于右侧主区域顶部，包含以下按钮与控件：

| 按钮 / 控件 | 用途 | 备注 |
|-------------|------|------|
| 新增 | 弹出表单新增一行数据 | 主键自动生成字段建议留空 |
| 批量删除 (N) | 删除当前勾选的多行 | N 为已勾选数；未勾选时按钮禁用 |
| 导入 | 弹出导入弹窗，支持 CSV / JSON 两种格式 | 单次最多 5000 行 |
| 导出 CSV | 下载当前表全部数据为 CSV 文件 | 含 UTF-8 BOM，Excel 友好 |
| 导出 JSON | 下载当前表全部数据为 JSON 文件 | NDJSON 流式格式 |
| 查看表结构 | 弹出右侧抽屉，展示列定义详情 | 抽屉宽度 860px |
| 搜索框 | 输入关键词后回车或点击「查询」按钮搜索 | 400ms 防抖触发 |
| 查询 | 立即触发一次搜索（与回车等效） | 绕过防抖 |
| 审计日志（页面右上角） | 弹出右侧抽屉，展示最近的数据库维护操作记录 | 抽屉宽度 720px |
| 刷新（页面右上角） | 重新加载左侧表列表与右侧数据 | 同时刷新行数与表数据 |

### 3.5 顶部警示条

页面顶部的黄色警示条用于提醒用户：

- **数据操作有风险**：直接修改业务数据可能影响系统正常运行
- **建议操作前先在「导出」中下载备份**：CSV / JSON 任选其一即可
- **删除操作不可恢复**：删除后无法通过本菜单恢复，需从备份手动还原
- **审计日志可在右上角查看**：所有写操作有据可查

## 4. 基本操作

下表汇总了页面支持的全部基本操作：

| 序号 | 操作 | 触发方式 | 结果 |
|------|------|----------|------|
| 1 | 切换业务表 | 点击左侧表列表中的某一项 | 右侧加载数据、重置搜索与排序，光标不再停在搜索框 |
| 2 | 查看表结构 | 点击工具栏「查看表结构」按钮 | 右侧抽屉弹出，展示列名 / 中文标注 / 类型 / 主键 / 可空 / 默认值 |
| 3 | 行级查询（翻页） | 点击底部分页器页码 | 加载对应页的数据，每页 50 行 |
| 4 | 关键词搜索（输入即搜） | 在搜索框输入文字 | 停止输入 400ms 后自动触发搜索，对所有文本列做模糊匹配 |
| 5 | 关键词搜索（立即搜） | 在搜索框按回车，或点击「查询」按钮 | 立即触发搜索（绕过防抖） |
| 6 | 复用历史关键词 | 点击搜索框下方的小药丸标签 | 关键词自动填入搜索框并立即搜索 |
| 7 | 清空搜索历史 | 点击「清空」按钮 | 浏览器本地存储的搜索历史被清空 |
| 8 | 列排序 | 点击表格列头（如「创建时间」） | 第一次点击降序、第二次升序、第三次取消排序 |
| 9 | 单行新增 | 点击「新增」按钮 | 弹出表单，填写完成后保存即写入新行 |
| 10 | 行内编辑 | 点击行尾的「编辑」按钮 | 弹出表单，主键字段不可修改，其他字段可改 |
| 11 | 单行删除 | 点击行尾的「删除」按钮 | 弹出确认框，需先看级联影响预览再输入确认码 |
| 12 | 批量删除 | 勾选多行后点击「批量删除 (N)」 | 弹出确认框，需先看级联影响预览再输入确认码 |
| 13 | 导出 CSV | 点击「导出 CSV」按钮 | 浏览器开始下载 `{表名}_{时间戳}.csv`，UTF-8 BOM 编码 |
| 14 | 导出 JSON | 点击「导出 JSON」按钮 | 浏览器开始下载 `{表名}_{时间戳}.json`，NDJSON 格式 |
| 15 | 导入数据 | 点击「导入」按钮 → 选择文件 → 确认导入 | 解析后调用后端接口写入，返回成功 / 跳过 / 错误数 |
| 16 | 查看审计日志 | 点击页面右上角「审计日志」按钮 | 右侧抽屉展示最近 200 条操作记录 |
| 17 | 刷新页面 | 点击页面右上角「刷新」按钮 | 同时刷新左侧表列表（含行数）与右侧数据网格 |

> **切换表时**：如果搜索框中有内容，会自动清空，避免上一次搜索词影响新表的查询结果。同时分页会重置到第 1 页，排序状态也会清空。

> **NULL 单元格显示**：数据网格中 NULL 值会以灰色斜体 `NULL` 显示，便于区分空字符串与真正的 NULL。

> **长文本截断**：单元格内容超过 80 字符时自动截断并以省略号 `…` 显示，鼠标悬停会在 Tooltip 中显示完整内容。

## 5. 11 张业务表速查

### 5.1 表清单与用途

本菜单支持操作的 11 张业务表，均与后端 ORM 定义一一对应：

| 表名 | 中文名 | 主键类型 | 用途说明 |
|------|--------|----------|----------|
| `tasks` | 任务 | UUID | 用户配置的监控任务，如「佳能 RP 镜头监控」 |
| `items` | 商品 | String | 闲鱼商品记录，含标题、价格、卖家、链接等 |
| `sellers` | 卖家 | String | 卖家画像信息，含信用、销量、评价等 |
| `evaluations` | 评估记录 | int | 商品 AI 评估结果，含建议价格、风险等 |
| `orders` | 订单 | String | 下单记录，含订单号、状态、时间等 |
| `events` | 事件日志 | int | 系统事件（含数据库维护审计日志） |
| `task_links` | 任务关联 | int | 任务与商品/卖家的多对多关联 |
| `task_deps` | 任务依赖 | int | 任务之间的依赖关系 |
| `notifications` | 业务通知 | int | 系统发出的通知消息 |
| `accounts` | 闲鱼账号 | int | 多账号管理，含 cookies、登录状态等 |
| `proxies` | 代理池 | int | 代理服务器管理，含地址、端口、协议 |

### 5.2 表关系图（外键依赖）

11 张表之间存在以下外键依赖关系，删除一行主表数据时**可能影响**关联表：

```
tasks ──┬── items ──┬── evaluations
        │           ├── orders
        │           └── events
        ├── orders
        ├── events
        ├── task_links
        └── task_deps (双向：task_id / depends_on)

sellers ──┬── items       (set_null，保留商品)
          ├── orders      (set_null，保留订单)
          └── evaluations (set_null，保留评估)
```

**关键说明**：

- `tasks` 是业务核心，删除任务会级联删除其下所有 items / orders / events / task_links / task_deps 记录
- `items` 删除会级联删除其下的 evaluations / orders / events 记录
- `sellers` 删除采用 set_null 策略，保留商品/订单/评估但断开卖家引用（业务上仍有独立查看价值）
- `task_deps` 有双向外键：`task_id`（依赖方）和 `depends_on`（被依赖方），删除任务时两个方向都会被清理
- 叶子表（`notifications` / `accounts` / `proxies`）无下游依赖，删除时不会级联影响其他表

### 5.3 表的编辑权限

| 表名 | 是否可新增 | 是否可编辑 | 是否可删除 | 特殊说明 |
|------|------------|------------|------------|----------|
| `tasks` | ✅ | ✅ | ✅ | 删除会级联删 items / orders / events / task_links / task_deps |
| `items` | ✅ | ✅ | ✅ | 删除会级联删 evaluations / orders / events |
| `sellers` | ✅ | ✅ | ✅ | 删除会让 items / orders / evaluations 的外键置空（保留商品/订单/评估） |
| `evaluations` | ✅ | ✅ | ✅ | 无级联 |
| `orders` | ✅ | ✅ | ✅ | 无级联 |
| `events` | ⚠️ 不建议 | ⚠️ 不建议 | ⚠️ 不建议 | 含审计日志，误改可能影响溯源能力 |
| `task_links` | ✅ | ✅ | ✅ | 无级联 |
| `task_deps` | ✅ | ✅ | ✅ | 无级联 |
| `notifications` | ✅ | ✅ | ✅ | 无级联 |
| `accounts` | ✅ | ✅ | ✅ | `cookies` 等字段属于敏感数据，编辑需谨慎 |
| `proxies` | ✅ | ✅ | ✅ | 无级联 |

> **联合主键的表暂不支持在线编辑**。本系统 11 张业务表均为单主键，可正常进行增删改。若未来新增联合主键表，系统会返回 400 错误「仅支持单主键表的更新/删除」。

## 8. 级联删除与安全机制

### 8.1 级联策略说明

系统在应用层实现级联删除（而非依赖 SQLite 的 ON DELETE CASCADE），分为两种策略：

| 策略 | 含义 | 适用场景 |
|------|------|----------|
| `cascade`（级联删除） | 主表行删除时，关联表中引用此行的所有记录一并删除 | 业务核心实体（任务/商品）被删时，删除其所有依赖数据，避免产生孤立记录 |
| `set_null`（外键置空） | 主表行删除时，关联表中引用此行的字段被设置为 NULL | 卖家被删时，保留商品/订单/评估但断开卖家引用（数据仍有独立查看价值） |

**为什么在应用层做而非数据库层**：

1. SQLite 建表时未声明 `ON DELETE CASCADE`，补建需 `ALTER TABLE`，成本较高
2. 应用层可精确控制策略（cascade vs set_null），并返回每张表的影响行数
3. 审计日志可记录级联细节，便于事后追溯

### 8.2 级联影响预览

**触发时机**：点击行尾「删除」按钮，或点击「批量删除 (N)」按钮时。

**展示内容**：

- 关联影响的合计行数（如「共 35 条关联数据将被处理」）
- 每条关联的描述，例如：
  - 🗑 将删除 items.task_id 中 30 条关联记录
  - ✂ 将置空外键 sellers.seller_id 中 5 条关联记录
- 无关联时显示绿色「✓ 无关联数据，可安全删除」
- 加载失败时显示灰色「级联预览加载失败」（不阻塞后续操作，可继续删除）

**预览接口说明**：

- 接口仅查询影响范围，**不执行任何写操作**
- 批量删除时一次性返回所有勾选行的级联合计，避免多次请求
- 即使预览失败，用户仍可输入确认码执行删除（不强制依赖预览结果）

**防御价值**：

- 删除前明确告知影响范围，避免「删了一条任务，结果订单也消失了」的意外
- 用户看到影响后可以主动取消，选择改用「编辑」将状态改为「已停止」等更安全的操作
- 级联行数过多时（如 100+），建议先评估业务影响再决定是否删除

### 8.3 CONFIRM_DELETE 二次确认

**适用场景**：

- 单行删除
- 批量删除
- 数据导入（CSV / JSON）

**操作要求**：

- 在确认弹窗的密码输入框中输入 `CONFIRM_DELETE`
- **严格区分大小写**（必须全大写）
- 输入正确后「确认删除」按钮才会变红可点击
- 输入错误或不输入时按钮保持灰色禁用状态

**为什么需要这一步**：

- 防止误点击（按钮误触导致数据丢失）
- 防止脚本恶意调用（无 token 拒绝执行）
- 让用户在执行前有一次「冷静思考」的机会，特别是看到级联影响后

**输入提示**：弹窗中会用粗体显示 `CONFIRM_DELETE`，可直接复制粘贴到输入框中。如输入小写 `confirm_delete` 或其他变体，按钮不会启用。

### 8.4 行数限制

| 限制项 | 上限 | 说明 |
|--------|------|------|
| 单次查询行数 | 1000 行 | 防止 SELECT * 大表拖垮界面与数据库 |
| 单页显示行数 | 50 行 | UI 友好翻页（暂不支持调整每页行数） |
| 单次批量删除 | 1000 行 | 与查询上限一致 |
| 单次导入行数 | 5000 行 | 防止一次写入过多导致 UI 卡顿 |
| 搜索历史保存条数 | 20 条 | 同一关键词只保留最近一次 |
| 审计日志返回条数 | 500 条 | 单次查询上限 |

> 以上限制为系统硬编码常量，如需调整请联系开发人员修改源码并重新部署。

### 8.5 事务原子性

级联删除涉及多张表的操作，系统会在同一事务中执行：

1. 先执行所有级联操作（cascade 删除关联行 / set_null 置空外键）
2. 再删除主表行
3. 写入审计日志
4. 提交事务

任一步骤失败，整个事务回滚，不会出现「级联删了一半主表还在」的半成品状态。这保证了数据一致性，避免产生孤立记录。

### 8.6 级联策略详表

下表列出系统定义的全部 12 条级联策略：

| 序号 | 主表 | 关联表 | 外键 | 策略 | 业务含义 |
|------|------|--------|------|------|----------|
| 1 | `tasks` | `items` | `task_id` | cascade | 删任务 → 级联删该任务下的商品 |
| 2 | `tasks` | `orders` | `task_id` | cascade | 删任务 → 级联删该任务的订单 |
| 3 | `tasks` | `events` | `task_id` | cascade | 删任务 → 级联删该任务的事件 |
| 4 | `tasks` | `task_links` | `task_id` | cascade | 删任务 → 级联删该任务的关联 |
| 5 | `tasks` | `task_deps` | `task_id` | cascade | 删任务 → 级联删该任务作为依赖方的记录 |
| 6 | `tasks` | `task_deps` | `depends_on` | cascade | 删任务 → 级联删该任务作为被依赖方的记录 |
| 7 | `items` | `evaluations` | `item_id` | cascade | 删商品 → 级联删该商品的评估 |
| 8 | `items` | `orders` | `item_id` | cascade | 删商品 → 级联删该商品的订单 |
| 9 | `items` | `events` | `item_id` | cascade | 删商品 → 级联删该商品的事件 |
| 10 | `sellers` | `items` | `seller_id` | set_null | 删卖家 → 保留商品但断开卖家引用 |
| 11 | `sellers` | `orders` | `seller_id` | set_null | 删卖家 → 保留订单但断开卖家引用 |
| 12 | `sellers` | `evaluations` | `seller_id` | set_null | 删卖家 → 保留评估但断开卖家引用 |

**设计原则**：

1. 业务核心实体（tasks / items / sellers）被删时，根据业务价值决定级联策略
2. sellers 采用 set_null 是因为卖家消失后商品/订单/评估仍有独立查看价值
3. 叶子表（events / notifications / task_links / task_deps / accounts / proxies）无下游依赖，直接删除
4. task_deps 的双向外键都会被清理，避免产生孤立的依赖关系

### 8.7 安全机制小结

本菜单采用多层安全防护：

| 防护层 | 机制 | 防御目标 |
|--------|------|----------|
| 表白名单 | 11 张业务表 + ALLOWED_TABLES 校验 | 防止误操作系统表 |
| 标识符白名单 | 列名/排序字段匹配 `^[A-Za-z_]\w*$` | 防止 ORDER BY 注入 |
| 参数化 SQL | 所有 WHERE 条件用 `:param` 绑定 | 防止 SQL 注入 |
| 双重确认 | `confirm_token=CONFIRM_DELETE` | 防止误点击与脚本恶意调用 |
| 级联预览 | 删除前展示影响范围 | 防止意外级联删除 |
| 行数限制 | 查询 1000 / 导入 5000 | 防止大表操作拖垮系统 |
| 主键约束 | 仅支持单主键表 | 简化编辑逻辑，避免歧义 |
| DDL 拒绝 | 不提供建表/改字段能力 | 防止绕过 ORM 校验 |
| 审计日志 | 所有 DML 写入 events 表 | 便于事后追溯 |

## 9. 审计日志

### 9.1 自动记录

所有数据库维护操作（新增、更新、删除、批量删除、导入）会自动写入 `events` 表，记录字段包括：

| 字段 | 说明 | 示例 |
|------|------|------|
| `type` | 操作类型，统一以 `db_admin.` 前缀 | `db_admin.create` / `db_admin.delete` |
| `level` | 严重级别 | `info`（新增/更新成功）/ `warn`（删除/导入成功）/ `err`（任何失败） |
| `stage` | 模块标识 | 固定为 `db_admin` |
| `message` | 操作描述 | `db_admin.delete tasks pk=uuid-1` |
| `payload` | 详细数据（JSON 字符串） | 含 `action` / `table` / `pk` / `detail` 四个字段 |
| `created_at` | 操作时间 | 自动填充（UTC） |
| `task_id` | 关联任务 ID | NULL（数据库维护不属于任何任务） |

### 9.2 操作类型清单

| 操作 | type | level | payload 内容 |
|------|------|-------|--------------|
| 新增成功 | `db_admin.create` | info | `{values}` 提交的字段值 |
| 新增失败 | `db_admin.create_failed` | err | `{error, values}` 错误信息 + 字段值 |
| 更新成功 | `db_admin.update` | info | `{values}` 更新的字段值 |
| 更新失败 | `db_admin.update_failed` | err | `{error}` 错误信息 |
| 删除成功 | `db_admin.delete` | warn | `{cascade}` 级联影响行数 |
| 删除失败 | `db_admin.delete_failed` | err | `{error}` 错误信息 |
| 批量删除成功 | `db_admin.batch_delete` | warn | `{requested, affected, cascade}` |
| 批量删除失败 | `db_admin.batch_delete_failed` | err | `{error, count}` 错误信息 + 行数 |
| 导入 | `db_admin.import` | info / warn | `{mode, total, inserted, skipped, errors}` |

**审计日志容错**：审计日志写入失败不会阻塞主流程，但会在后端日志中记录 `写入审计日志失败` + 完整 traceback，便于运维排查。

### 9.3 查看入口

**入口 1**：在「数据库维护」页面右上角点击「**审计日志**」按钮。

**入口 2**：在「实时日志」页面按 `db_admin.` 前缀过滤查看（与其他模块日志统一展示）。

**抽屉展示**：

- 抽屉宽度 720px，从右侧滑出
- 默认加载最近 **200 条**数据库维护相关日志
- 表格列：时间 / 操作 / 级别 / 详情
- 操作类型用蓝色标签显示，含 `failed` 的用红色标签
- 级别用颜色区分：err=红 / warn=橙 / info=绿
- 每页 20 条，可翻页查看
- 详情列展示 `message` 字段（如 `db_admin.delete tasks pk=uuid-1`）

### 9.4 失败操作的审计

**重要**：失败的操作（如主键冲突、外键约束失败、类型不匹配）也会写入审计日志，level 为 `err`。这是为了：

- 便于排查「为什么这次新增失败了」
- 记录所有尝试操作（即使失败），便于安全审计
- payload 中包含具体错误信息，便于开发人员定位问题

## 11. 常见问题 FAQ

**Q1：为什么有些表不能编辑？**
A：本系统 11 张业务表均支持编辑。但 `events` 表含审计日志，误改可能影响溯源能力，建议谨慎操作。若涉及联合主键的表（本系统暂无），系统会返回 400 错误「仅支持单主键表的更新」。

**Q2：删除后能恢复吗？**
A：不能。所有删除操作不可恢复，删除前系统会强制展示级联影响预览并要求输入 `CONFIRM_DELETE`。建议操作前先「导出 CSV / JSON」做备份。如已误删，可从备份文件中查找原数据，但需手工通过「新增」逐条恢复（无法批量回滚）。

**Q3：批量删除最多能删多少行？**
A：单次最多 1000 行。如需删除更多，请通过搜索筛选出目标数据后分批操作。注意：勾选状态不会跨页保留，切换页码后勾选会清空，需在当前页内完成勾选与删除。

**Q4：导入 CSV 报错「唯一约束冲突」怎么办？**
A：本系统默认采用「insert」模式，遇主键冲突会自动跳过并计入 `skipped`，不会报错。如果出现唯一约束冲突错误，可能是非主键的唯一索引字段（如用户名、邮箱）冲突，请检查数据中是否有重复值，或先删除冲突的现有记录再导入。

**Q5：搜索支持哪些操作符？**
A：搜索为「文本列子串匹配」（类似 SQL 的 `LIKE %关键词%`），不支持 `>` `<` `=` `!=` 等操作符。搜索范围自动覆盖表中所有文本列（VARCHAR / TEXT / CHAR / CLOB），数字与日期列会被自动跳过。如需精确筛选，建议导出 CSV 后在 Excel 中处理。

**Q6：为什么搜索输入后会延迟一下才出结果？**
A：搜索框采用 400ms 防抖机制，停止输入 400ms 后才会触发查询，避免每按一个键都打一次接口。如需立即查询，可直接按回车键或点击「查询」按钮绕过防抖。

**Q7：删除任务时为什么会同时删除商品/订单？**
A：`tasks` 表对 `items` / `orders` / `events` / `task_links` / `task_deps` 采用 cascade（级联删除）策略，删除任务会一并清理其所有依赖数据，避免产生无法追溯的孤立记录。删除前会显示级联影响预览，请仔细查看。如不想级联删除，可改用「编辑」将任务状态改为 `stopped` 而非删除。

**Q8：删除卖家后，为什么商品的 seller_id 变成 NULL？**
A：`sellers` 表对 `items` / `orders` / `evaluations` 采用 set_null（外键置空）策略，因为卖家消失后商品/订单/评估仍有独立查看价值。这样保留了历史数据但断开了卖家引用。如需彻底删除商品，需手动在 `items` 表中删除对应行。

**Q9：搜索历史会保存多久？**
A：搜索历史保存在浏览器本地（localStorage key `xh_search_history_db_admin`），跨会话保留，最多 20 条。同一关键词只保留最近一次（去重）。清除浏览器缓存或登出系统可能会清空历史。点击「清空」按钮可手动清除。隐私模式下不持久化。

**Q10：为什么导出的 CSV 用 Excel 打开是乱码？**
A：本系统导出的 CSV 已包含 UTF-8 BOM 头（`\ufeff`），Excel 应自动识别编码。如仍乱码，请按以下步骤排查：
1. 检查 Excel 版本是否过旧（建议 2016 及以上）
2. 用文本编辑器（如 Notepad++ / VSCode）打开 CSV，确认编码为 UTF-8
3. 在 Excel 中通过「数据 → 从文本/CSV」导入，手动指定编码为 UTF-8

**Q11：可以在数据库维护页面修改表结构（增删字段）吗？**
A：不可以。本菜单仅支持数据级 CRUD，表结构由后端 ORM 集中管理。如需调整表结构（如新增字段），请联系开发人员修改 ORM 定义后重启服务。这是为了防止前端绕过 ORM 校验导致下次启动失败。

**Q12：导入时 insert 和 replace 模式有什么区别？**
A：`insert` 模式遇主键冲突跳过（计入 `skipped`），不会覆盖现有数据；`replace` 模式走 INSERT OR REPLACE，会覆盖同名主键的现有记录。**当前前端仅暴露 `insert` 模式**（默认「跳过冲突」），因 replace 模式风险较高（可能丢失原有数据），如需启用请联系开发人员扩展前端。

**Q13：为什么我看不到 sqlite_master 等系统表？**
A：本菜单采用白名单机制，仅允许操作 11 张业务表，`sqlite_master` / `sqlite_sequence` 等系统表一律拒绝访问。这是为了防止误操作系统核心数据导致数据库损坏。

**Q14：审计日志能删除吗？**
A：审计日志存储在 `events` 表中，技术上可以在本菜单删除，但**强烈不建议**这样做。误删审计日志会影响溯源能力，且无法恢复。如需清理历史日志，建议通过「系统清理」菜单按时间范围批量清理。

## 12. 最佳实践

1. **操作前先备份**：对任何删除/导入操作，建议先点击「导出 CSV」或「导出 JSON」下载当前数据备份，便于误操作后回滚参考。备份文件建议按「表名_日期」命名并妥善保管。

2. **小批量验证再批量操作**：批量删除或导入前，先用少量数据（如 5 行）验证流程是否符合预期，确认无误后再放大到全量。这能避免因表头错误、类型不匹配等问题导致大批量数据异常。

3. **善用搜索历史**：经常使用的搜索关键词会自动保存为小药丸，点击即可复用，避免重复输入。如历史过多影响视觉，可点击「清空」重置。

4. **关注级联影响预览**：删除任务/商品/卖家前，务必仔细查看级联影响预览，确认能接受关联数据被删除或置空后再输入确认码。如影响行数过多（如 100+），建议先评估业务影响。

5. **events 表谨慎操作**：`events` 表包含审计日志，直接编辑或删除可能影响溯源能力。如需清理历史日志，建议通过「系统清理」菜单按时间范围批量清理，而非在本菜单手工删除。

6. **敏感字段谨慎编辑**：`accounts` 表的 `cookies` 字段、`proxies` 表的认证信息等属于敏感数据，编辑时请确保数据来源可信，避免泄露。审计日志不记录敏感字段的明文值，但建议操作时仍保持谨慎。

7. **导出 JSON 用于程序处理，导出 CSV 用于人工查看**：JSON 格式保留数据类型（数字、布尔、嵌套对象），适合后续程序化处理；CSV 格式更直观，适合人工查看与 Excel 分析。两种格式可根据用途选择。

8. **优先用「编辑」替代「删除 + 新增」**：若仅需修改字段值，直接点击「编辑」即可；不要先删后增，避免级联删除带来的不必要数据损失。例如修改任务状态应直接编辑 `status` 字段，而非删除任务后重新创建。
