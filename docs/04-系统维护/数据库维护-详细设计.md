## 2. 功能概述

**一句话说明**：本系统 SQLite 业务表的在线 CRUD 工具，定位为「轻量级 Navicat」。

**核心价值**：
- **表白名单**：仅允许操作 ORM 已声明的 11 张业务表（tasks/items/sellers/evaluations/orders/events/task_links/task_deps/notifications/accounts/proxies），禁止 `sqlite_master` 等系统表；
- **动态表结构**：通过 SQLAlchemy Inspector 反射列信息，免维护硬编码；
- **参数化查询**：所有 SQL 通过绑定参数构造，杜绝拼接注入；标识符（列名/排序字段）必须匹配 `^[A-Za-z_]\w*$` 正则；
- **审计日志**：所有 DML 写入 events 表（`type=db_admin.*`），可在「实时日志」页回溯；
- **双重确认**：危险操作（删除/批量删除/导入）需要 `confirm_token=CONFIRM_DELETE` 才执行；
- **行数限制**：单次查询最多 1000 行，导入最多 5000 行，避免误操作拖垮数据库；
- **应用层级联删除**：在应用层实现 cascade/set_null 策略，可精确控制影响范围并返回每张表的影响行数。

## 3. 用户场景

**场景 1：手动修正数据**
用户发现某个任务的关键词配置错误，进入数据库维护页面，左侧选中 `tasks` 表，在右侧数据表找到对应行点击「编辑」按钮，Modal 弹出动态生成的表单（根据 schema 列定义渲染 Input/InputNumber/Switch/TextArea），修改 `keyword` 字段后保存，审计日志记录 `db_admin.update tasks pk=xxx`。

**场景 2：批量删除脏数据**
用户发现 `items` 表中有 100 条测试数据需要清理，通过搜索框过滤出目标行，勾选多行后点击「批量删除」按钮。系统先调用 cascade-preview 接口预览级联影响（如将级联删除 evaluations/orders/events），用户在确认弹窗中输入 `CONFIRM_DELETE` 后才真正执行。

**场景 3：数据导出与迁移**
用户希望将 `sellers` 表导出为 CSV 用于离线分析，点击「导出」按钮选择 CSV 格式，后端通过 StreamingResponse 流式输出（UTF-8 BOM 头让 Excel 自动识别编码），避免大表导出导致内存峰值。

## 5. 接口定义

所有接口前缀：`/api/db-admin`，路由文件：`src/xianyu_hunter/web/routes/api_db_admin.py`。

> 注：`GET /tables/{table}/rows` 的实际查询逻辑委托给 `DbAdminSearchService`（`src/xianyu_hunter/web/services/search_services.py`），service 内部复用本模块的 `_validate_identifier` / `_serialize_row` 工具函数，保持标识符校验与行序列化行为的一致性，并统一接入慢查询埋点。

### 5.1 元数据 API

#### GET /tables
列出可管理的表及其记录数（侧边栏树数据）。

**响应**：
```json
{
  "tables": [
    {"name": "tasks", "rows": 12},
    {"name": "items", "rows": 348}
  ]
}
```

#### GET /tables/{table}/schema
表结构：列名、类型、是否主键、是否可空、默认值、中文 label。

**响应字段**：

| 字段           | 类型    | 说明                                              |
| -------------- | ------- | ------------------------------------------------- |
| `name`         | string  | 列名                                              |
| `type`         | string  | SQL 类型字符串（如 `VARCHAR`、`INTEGER`、`JSON`） |
| `nullable`     | bool    | 是否允许 NULL                                     |
| `default`      | string  | 默认值表达式，无则为 `null`                       |
| `primary_key`  | bool    | 是否主键                                          |
| `label`        | string  | 来自 `COLUMN_LABELS` 的中文语义标注                |

#### POST /tables/{table}/cascade-preview
删除前级联影响预览（不执行实际操作）。

**请求体**：`{"ids": [1, 2, 3]}`

**响应**：
```json
{
  "table": "tasks",
  "relations": [
    {"table": "items", "fk": "task_id", "action": "cascade", "count": 30, "description": "将删除 items.task_id 中 30 条关联记录"},
    {"table": "sellers", "fk": "seller_id", "action": "set_null", "count": 5, "description": "将置空外键 sellers.seller_id 中 5 条关联记录"}
  ],
  "total_affected": 35
}
```

### 5.2 数据查询 API

#### GET /tables/{table}/rows
分页查询表数据。

**Query 参数**：

| 参数       | 类型    | 默认 | 说明                                          |
| ---------- | ------- | ---- | --------------------------------------------- |
| `limit`    | int     | 50   | 1-1000                                        |
| `offset`   | int     | 0    | ≥ 0                                           |
| `order_by` | string  | -    | 列名，倒序加 `-` 前缀如 `-created_at`         |
| `search`   | string  | -    | 对所有文本列 LIKE 搜索（数字/日期列跳过）      |

**响应**：`table` / `total` / `limit` / `offset` / `rows[]`。

### 5.3 CRUD API

#### POST /tables/{table}/rows
新增一行。主键冲突返回 409；写入成功立即审计。

**请求体**：`{"values": {"keyword": "佳能RP", "mode": "auto"}}`

**响应**：`ok` / `table`。

#### PATCH /tables/{table}/rows/{pk_value:path}
按主键更新一行。`pk_value` 通过路径传入（支持 String/Integer 主键）。主键字段不可更新。

**响应**：`ok` / `affected`（更新行数；为 0 时返回 404）。

#### DELETE /tables/{table}/rows/{pk_value:path}
删除单行（含级联处理）。

**Query 参数**：`confirm_token=CONFIRM_DELETE`（必须）

**响应**：`ok` / `affected` / `cascade`（dict，key 为 `{table}.{fk}:{action}`，value 为影响行数）。

#### POST /tables/{table}/rows/batch-delete
批量删除（含级联处理），上限 1000 行/次。

**请求体**：`{"ids": [1,2,3], "confirm_token": "CONFIRM_DELETE"}`

**响应**：`ok` / `requested` / `affected` / `cascade`。

### 5.4 导入/导出 API

#### GET /tables/{table}/export
导出表数据为 CSV 或 JSON。

**Query 参数**：`format=csv|json`

**响应**：`StreamingResponse`，CSV 含 UTF-8 BOM 头（`\ufeff`）让 Excel 自动识别编码；JSON 用 NDJSON 流式输出降低内存峰值。

#### POST /tables/{table}/import
导入二维数组。

**请求体**：

| 字段            | 类型             | 说明                                          |
| --------------- | ---------------- | --------------------------------------------- |
| `rows`          | `list[list[Any]]`| 二维数组                                       |
| `headers`       | `list[str]`      | 可选，自定义列名映射，缺省按列顺序             |
| `mode`          | string           | `insert`（跳过主键冲突）/ `replace`（INSERT OR REPLACE） |
| `confirm_token` | string           | 必须为 `CONFIRM_DELETE`                        |

**响应**：`ok` / `total` / `inserted` / `skipped` / `errors[]`（前 20 条）。

### 5.5 审计日志 API

#### GET /audit-log
数据库维护相关审计日志（来自 events 表，type 前缀 `db_admin.`）。

**Query 参数**：`limit=100`（1-500）

**响应**：`items[]`，每条记录含 `id` / `type` / `level` / `message` / `payload` / `created_at`。

## 7. 业务逻辑

### 7.1 应用层级联删除

**为什么在应用层做而非 SQLite ON DELETE CASCADE**：
1. SQLite 的 `PRAGMA foreign_keys=ON` 虽然支持 CASCADE，但本系统建表时未声明 `ON DELETE CASCADE`（SQLAlchemy 默认不生成），补建需 `ALTER TABLE`；
2. 应用层可精确控制策略（cascade vs set_null），并返回每张表的影响行数；
3. 审计日志可记录级联细节。

**执行顺序**：
```
1. _cascade_delete(conn, table, [pk_val])
   - 遍历 TABLE_RELATIONS[table]
   - 校验 rel_table 也在 ALLOWED_TABLES 白名单内（防御性）
   - cascade: DELETE FROM {rel_table} WHERE {fk} IN :pks
   - set_null: UPDATE {rel_table} SET {fk} = NULL WHERE {fk} IN :pks
   - 使用 bindparam("pks", expanding=True) 支持 IN 列表
2. DELETE FROM {table} WHERE {pk_col} = :pk
3. _log_audit(action="delete", table=table, pk_value=pk_val, detail={"cascade": cascade_affected})
```

所有操作在同一事务（`engine.begin()`）中执行，保证原子性。

### 7.2 动态表单渲染

前端根据 `_get_columns` 返回的 schema 动态生成表单：

```typescript
function inferFormType(colType: string): 'text' | 'textarea' | 'number' | 'switch' | 'datetime' {
  const t = colType.toUpperCase()
  if (t.includes('INT') || t.includes('FLOAT') || t.includes('REAL') || t.includes('DOUBLE') || t.includes('NUMERIC')) return 'number'
  if (t.includes('BOOL')) return 'switch'
  if (t.includes('DATETIME') || t.includes('TIMESTAMP')) return 'datetime'
  if (t.includes('TEXT') || t.includes('JSON') || t.includes('CLOB')) return 'textarea'
  return 'text'
}
```

主键在 update 模式下禁用编辑（`disabled`），insert 模式允许手工指定（兼容 String 主键）。

### 7.3 值类型转换

`_parse_value(raw, col_type)` 根据列类型把 JSON 输入值转换为 Python 对象：

| 列类型关键字            | 转换逻辑                                                     |
| ----------------------- | ------------------------------------------------------------ |
| `INT`                   | `int(raw)`                                                   |
| `FLOAT`/`REAL`/`DOUBLE`/`NUMERIC`/`DECIMAL` | `float(raw)`                                    |
| `BOOL`                  | bool 类型直接返回；字符串 `'1'/'true'/'yes'/'on'` → `True`   |
| `DATETIME`/`TIMESTAMP`  | 数字 → `datetime.fromtimestamp(raw, tz=timezone.utc)`；字符串 → `datetime.fromisoformat()` |
| `JSON`/`TEXT`           | 字符串直接返回；其他 → `json.dumps(raw, ensure_ascii=False)` |

### 7.4 流式导出

CSV 导出使用 `io.StringIO` + 流式 yield，避免大表导出导致内存峰值：

```python
def csv_iter():
    buf = io.StringIO()
    w = csv.writer(buf)
    w.writerow(col_names)
    yield "\ufeff" + buf.getvalue()  # UTF-8 BOM
    buf.seek(0); buf.truncate()
    for r in rows:
        row = _serialize_row(dict(r), cols)
        w.writerow([row.get(c) for c in col_names])
        yield buf.getvalue()
        buf.seek(0); buf.truncate()
```

JSON 导出采用 NDJSON 风格，每行一个 JSON 记录，前后用 `[\n` 和 `\n]\n` 包裹，行间用 `,\n` 分隔。

### 7.5 安全机制

1. **表白名单**：`_validate_table` 校验 `table in ALLOWED_TABLES`，否则返回 400。
2. **标识符白名单**：`_validate_identifier` 校验列名/排序字段匹配 `^[A-Za-z_]\w*$`，防止 ORDER BY 注入。
3. **参数化查询**：所有 WHERE 条件用 `:param` 绑定，IN 列表用 `bindparam("pks", expanding=True)`。
4. **CONFIRM_TOKEN 双重确认**：删除/批量删除/导入必须传 `confirm_token=CONFIRM_DELETE`。
5. **行数限制**：`MAX_PAGE_SIZE=1000` 限制单次查询；`MAX_IMPORT_ROWS=5000` 限制单次导入。
6. **主键不可更新**：`update_row` 过滤掉 `k == pk_col["name"]` 的字段。
7. **联合主键拒绝**：`len(pk_cols) != 1` 时返回 400，仅支持单主键表的编辑/删除。
8. **DDL 拒绝**：本模块不提供建表/改字段能力，表结构由 ORM 管理（`init_db` 自动迁移）。

### 7.6 审计日志

所有 DML 操作通过 `_log_audit` 写入 events 表，`stage` 字段固定为 `db_admin`，`type` 字段以 `db_admin.` 为前缀，便于在「实时日志」页按模块过滤。

`_log_audit` 写入的 events 记录字段约定：
- `type`：`db_admin.{action}`，如 `db_admin.create`、`db_admin.delete_failed`
- `stage`：固定为 `db_admin`
- `level`：info / warn / err，反映操作严重程度
- `message`：`db_admin.{action} {table} pk={pk_value}`（pk 可选）
- `payload`：JSON 字符串，含 `action` / `table` / `pk` / `detail` 四个字段

| 操作             | type                            | level     | 说明                                              |
| ---------------- | ------------------------------- | --------- | ------------------------------------------------- |
| 新增成功         | `db_admin.create`               | info      | payload 含 values                                 |
| 新增失败         | `db_admin.create_failed`        | err       | payload 含 error 和 values                        |
| 更新成功         | `db_admin.update`               | info      | payload 含 values                                 |
| 更新失败         | `db_admin.update_failed`        | err       | payload 含 error                                  |
| 删除成功         | `db_admin.delete`               | warn      | payload 含 cascade 影响行数                       |
| 删除失败         | `db_admin.delete_failed`        | err       | payload 含 error                                  |
| 批量删除成功     | `db_admin.batch_delete`         | warn      | payload 含 requested/affected/cascade             |
| 批量删除失败     | `db_admin.batch_delete_failed`  | err       | payload 含 error 和 count                         |
| 导入             | `db_admin.import`               | info/warn | payload 含 mode/total/inserted/skipped/errors     |

## 9. 常见问题 FAQ

**Q1：为什么不能在数据库维护页面修改表结构（增删字段）？**
A：本系统表结构由 SQLAlchemy ORM 管理（`init_db` 自动迁移）。前端修改字段会绕过 ORM 校验导致下次启动失败。如需调整表结构应改后端 ORM 定义（`src/xianyu_hunter/infra/db_models.py`）后重启服务。

**Q2：删除任务时为什么会同时删除 items/orders/events 等表的数据？**
A：`TABLE_RELATIONS` 定义了级联策略。删除 `tasks` 行时会级联删除 `items`/`orders`/`events`/`task_links`/`task_deps` 中 `task_id` 匹配的记录。删除前会调用 `/cascade-preview` 接口预览影响范围，用户需在弹窗中看到影响行数并输入 `CONFIRM_DELETE` 才执行。

**Q3：删除卖家后为什么商品/订单的 seller_id 变成 NULL 而不是删除？**
A：`sellers` 表对 `items`/`orders`/`evaluations` 采用 `set_null` 策略，因为卖家消失后商品/订单/评估仍有独立查看价值。这样保留历史数据但断开卖家引用。

**Q4：为什么在应用层做级联删除而不是用 SQLite 的 ON DELETE CASCADE？**
A：三个原因：1) SQLite 建表时未声明 ON DELETE CASCADE，补建需 ALTER TABLE；2) 应用层可精确控制策略（cascade vs set_null），并返回每张表的影响行数；3) 审计日志可记录级联细节。

**Q5：导入时 insert 和 replace 模式有什么区别？**
A：`insert` 模式遇主键冲突跳过（计入 skipped）；`replace` 模式走 `INSERT OR REPLACE`，会覆盖同名主键的现有记录。`replace` 模式风险较高，可能丢失原有数据，需谨慎使用。

**Q6：导出 CSV 用 Excel 打开乱码怎么办？**
A：本系统导出的 CSV 已包含 UTF-8 BOM 头（`\ufeff`），Excel 应自动识别编码。如仍乱码，检查 Excel 版本是否过旧，或用文本编辑器打开确认编码为 UTF-8。

**Q7：单次查询/导入的行数限制是多少？能调整吗？**
A：单次查询最多 `MAX_PAGE_SIZE=1000` 行，单次导入最多 `MAX_IMPORT_ROWS=5000` 行。这些是硬编码常量（`api_db_admin.py` 第 60-62 行），调整需修改源码并重新部署。

**Q8：如何查看数据库维护的审计日志？**
A：调用 `GET /api/db-admin/audit-log`，或在「数据库维护」页面点击右上角「审计日志」按钮打开抽屉。日志来自 events 表，`type` 字段以 `db_admin.` 前缀过滤。

**Q9：联合主键的表能在数据库维护页面编辑吗？**
A：不能。代码中 `len(pk_cols) != 1` 时返回 400，仅支持单主键表的更新/删除。本系统 11 张业务表均为单主键，如有联合主键需求需扩展实现。

**Q10：为什么 order_by 参数不能传任意字符串？**
A：防止 ORDER BY 列名注入。`_validate_identifier` 校验 order_by 必须匹配 `^[A-Za-z_]\w*$` 正则（ASCII 模式），且必须在表的列名中存在。倒序通过 `-` 前缀指定（如 `-created_at`）。

**Q11：批量删除最多能删多少行？**
A：单次最多 1000 行（`MAX_PAGE_SIZE`），与单次查询上限一致。如需删除更多，分批操作或直接通过 SQL 修改。

**Q12：如何防止误删 sqlite_master 等系统表？**
A：`ALLOWED_TABLES` 白名单仅包含 11 张业务表，`_validate_table` 校验 `table in ALLOWED_TABLES`，系统表访问会返回 400。
