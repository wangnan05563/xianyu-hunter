## 2. 功能概述

**一句话说明**：提供实时日志查看、日志搜索、错误日志管理与 AI 上下文导出能力，支撑问题排查与运维。

**核心价值**：
- 实时日志页双面板设计，左侧结构化搜索、右侧原始日志/实时流并行查看；
- 错误日志页双面板设计，左侧错误列表、右侧详情 Tab（含 AI 上下文）；
- SSE 实时日志流，支持暂停/恢复与缓冲区管理；
- AI 上下文导出（JSON/Markdown），便于交接给 AI 助手辅助分析；
- 批量清理已解决/已忽略错误日志，控制存储增长。

## 3. 用户场景

### 场景一：实时排查任务异常
任务运行异常时，用户打开实时日志页，右侧实时流自动滚动展示最新日志。用户点击"暂停"冻结滚动，仔细阅读错误堆栈，定位问题后点击"恢复"继续。

### 场景二：搜索历史日志
用户怀疑某次 WAF 拦截发生在特定时间段，使用左侧结构化搜索面板按时间范围、事件类型、任务 ID 组合查询，搜索结果高亮关键词。

### 场景三：导出 AI 上下文
用户在错误日志页选中一条错误，点击"导出 AI 上下文"获取 Markdown 格式的上下文文档，粘贴到 AI 助手对话中辅助分析根因。

## 7. 业务逻辑

### 7.1 SSE 实时日志流机制

```
[后端]                              [前端]
   │                                  │
   │ ←── 建立 SSE 连接 ────────────── │
   │                                  │
   │ 每 2s 轮询 run.stdout.log 文件尾部
   │ 读取新增日志行                   │
   │                                  │
   │ ── 推送 app_event 事件 ────────→ │
   │                                  │ (addEventListener('app_event'))
   │                                  │ (追加到日志列表)
   │                                  │
   │ ── 推送 app_event 事件 ────────→ │
   │                                  │ (用户点击"暂停")
   │                                  │ (暂存到 pausedBufferRef)
   │                                  │
   │ ── 推送 app_event 事件 ────────→ │
   │                                  │ (pausedBufferRef 达到 500 上限)
   │                                  │ (丢弃最旧日志)
   │                                  │
   │                                  │ (用户点击"恢复")
   │                                  │ (flush pausedBufferRef 到界面)
```

### 7.2 暂停/恢复缓冲区算法

```typescript
const BUFFER_LIMIT = 500;
const pausedRef = useRef(false);
const pausedBufferRef = useRef<LogEntry[]>([]);

function onLogEvent(log: LogEntry) {
  if (pausedRef.current) {
    // 暂停状态：暂存到缓冲区
    pausedBufferRef.current.push(log);
    // 超限丢弃最旧日志，防止内存溢出
    if (pausedBufferRef.current.length > BUFFER_LIMIT) {
      pausedBufferRef.current.shift();
    }
  } else {
    // 恢复状态：直接追加到界面
    appendToView(log);
  }
}

function onResume() {
  pausedRef.current = false;
  // flush 缓冲区到界面
  pausedBufferRef.current.forEach(appendToView);
  pausedBufferRef.current = [];
}
```

### 7.3 AI 上下文生成流程

```
1. 用户点击"导出 AI 上下文"
2. 后端读取错误日志完整字段
3. 组装上下文结构：
   - 错误基本信息（type/message/timestamp）
   - 堆栈跟踪
   - 请求上下文（method/path/params/client_ip/user_agent）
   - 服务端环境（Python 版本/系统/应用版本）
   - 相关任务/订单/商品信息（如有）
4. 渲染为 JSON 与 Markdown 两种格式
5. 存储到 ai_context_json 与 ai_context_md 字段
6. 返回给前端展示与下载
```

### 7.4 批量清理策略

```python
def cleanup_error_logs(days: int, statuses: list[str]) -> int:
    """
    批量清理错误日志：
    - days: 清理 N 天前的错误日志
    - statuses: 仅清理指定状态（resolved/ignored）
    - 不清理 new 状态，避免误删待处理错误
    """
    cutoff = datetime.utcnow() - timedelta(days=days)
    # 仅清理 resolved/ignored 状态，保护 new 状态
    safe_statuses = [s for s in statuses if s in ("resolved", "ignored")]
    deleted = db.execute(
        "DELETE FROM error_logs WHERE updated_at < ? AND status IN (?)",
        [cutoff, safe_statuses]
    )
    return deleted.rowcount
```

## 9. 常见问题 FAQ

### Q1：实时日志和错误日志是两个页面吗？
**A**：是的。实时日志页（`/logs`）展示运行时日志流与历史日志搜索；错误日志页（`/logs/errors`）专门管理结构化错误日志，支持状态流转与 AI 上下文导出。

### Q2：实时日志流是怎么实现的？
**A**：通过 SSE（Server-Sent Events）实现。后端每 2 秒轮询 `run.stdout.log` 文件尾部，读取新增日志行后通过 `app_event` 事件推送到前端。前端通过 `addEventListener('app_event')` 接收。

### Q3：实时日志流可以暂停吗？
**A**：可以。点击"暂停"按钮冻结滚动，新日志暂存到 `pausedBufferRef` 缓冲区（上限 500 条，超限丢弃最旧日志）。点击"恢复"后 flush 缓冲区到界面。

### Q4：缓冲区上限是多少？为什么限制？
**A**：上限 500 条。限制是为了防止用户长时间暂停导致内存溢出。超限后采用 FIFO 策略丢弃最旧日志，保留最新日志。

### Q5：错误日志有哪些状态？
**A**：3 种状态：`new`（新错误，红色，待处理）、`resolved`（已解决，绿色）、`ignored`（已忽略，灰色）。状态可在详情页或批量操作中修改。

### Q6：批量操作一次最多多少条？
**A**：单次最多 500 条（`ids[]` 数组长度限制 1-500）。支持 4 种动作：`delete`（删除）、`resolve`（标记已解决）、`ignore`（标记已忽略）、`new`（重置为待处理）。

### Q7：AI 上下文是什么？有什么用？
**A**：AI 上下文是错误日志的完整上下文文档，包含错误基本信息、堆栈跟踪、请求上下文、服务端环境等，提供 JSON 与 Markdown 两种格式。用户可导出后粘贴到 AI 助手对话中，辅助分析根因。

### Q8：AI 上下文支持哪些格式？
**A**：支持 JSON 与 Markdown 两种格式。JSON 便于程序解析，Markdown 便于人类阅读与粘贴到 AI 对话。通过 `/api/error-logs/{id}/ai-context?format=json|markdown` 参数指定。

### Q9：批量清理会清理 new 状态的错误吗？
**A**：不会。批量清理仅清理 `resolved` 与 `ignored` 状态的错误日志，保护 `new` 状态避免误删待处理错误。清理按天数过滤（如清理 30 天前的已解决/已忽略错误）。

### Q10：日志可以导出吗？支持哪些格式？
**A**：可以。通过 `/api/logs/export` 接口导出，支持 CSV 与 LOG 两种格式。可按时间范围与事件类型过滤导出范围，导出文件以流式响应返回。
