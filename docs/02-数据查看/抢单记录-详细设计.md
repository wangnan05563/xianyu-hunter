## 2. 功能概述

**一句话说明**：管理抢单订单的全生命周期，支持人工接管、利润计算、状态流转与下游依赖任务自动激活。

**核心价值**：
- 统一查看所有抢单订单的状态与详情；
- 通过 TakeoverModal 三阶段流程，支撑人工接管闲鱼待付款订单；
- 内置利润计算器，按 0.6%/1.6% 费率估算净收益；
- 通过 SSE 订阅 `buy.succeeded`/`buy.failed` 事件，实时更新订单状态；
- F-16 依赖任务机制：订单成功后自动激活下游 paused 任务。

## 3. 用户场景

### 场景一：自动抢单成功
任务以 `auto` 模式运行，评估通过后自动触发抢单。订单状态从 `pending` 流转到 `succeeded`，前端通过 SSE 收到 `buy.succeeded` 事件后实时刷新列表。

### 场景二：人工接管待付款订单
某订单进入 `takeover_pending` 状态后，用户在抢单记录页点击"接管"打开 TakeoverModal。经过 confirm→progress→done 三阶段，用户完成线下支付并确认，订单流转为 `succeeded`。

### 场景三：手动抢单
用户在评估明细页对某商品点击"手动抢单"，调用 `/api/orders/manual-takeover` 创建订单并进入接管流程，适用于系统未自动触发但用户判断值得抢的商品。

### 7.2 人工接管超时机制

```python
TAKEOVER_TIMEOUT_MIN = 30  # 人工接管超时 30 分钟

# 对应闲鱼待付款订单 30 分钟自动关闭的业务规则
# 超时后订单自动流转为 cancelled，并触发 buy.failed 事件
```

**超时处理流程**：
1. 订单进入 `takeover_pending` 时记录 `takeover_deadline = now + 30min`；
2. 后台定时任务每分钟扫描超时订单；
3. 超时订单状态置为 `cancelled`，写入 `error="takeover_timeout"`；
4. 发布 `buy.failed` 事件，前端 SSE 推送。

### 7.3 TakeoverModal 三阶段

| 阶段     | 说明                                                       | 用户操作               |
| -------- | ---------------------------------------------------------- | ---------------------- |
| confirm  | 展示商品信息、价格、卖家、剩余时间倒计时                   | 点击"确认接管"         |
| progress | 显示支付进行中状态，倒计时 30 分钟，支持上传支付截图       | 完成线下支付并上传截图 |

### 7.4 利润计算器算法

```python
def calc_profit(price: float, shipping: float = 0, fee_rate: float = 0.006) -> dict:
    """
    利润计算：成交价扣除手续费与运费。
    fee_rate 默认 0.6%（个人），1.6%（商家）。
    """
    fee = price * fee_rate
    cost = price + shipping + fee
    # 假设转售价为 price * 1.2（用户可调整）
    revenue = price * 1.2
    profit = revenue - cost
    return {
        "fee": round(fee, 2),
        "cost": round(cost, 2),
        "revenue": round(revenue, 2),
        "profit": round(profit, 2),
        "margin": round(profit / revenue * 100, 2),
    }
```

### 7.5 F-16 依赖任务自动激活

```
订单 succeeded 事件触发
        │
        ▼
查询订单所属任务的下游依赖任务（F-16 配置）
        │
        ▼
遍历下游依赖任务
        │
        ├── status == paused → 自动激活为 running（发布 task.started 事件）
        ├── status == running → 跳过
        └── status == stopped → 跳过（不自动启动已停止任务）
```

**设计原则**：仅 `paused` 状态的下游任务会被自动激活，避免误启动用户主动停止的任务。

## 9. 常见问题 FAQ

### Q1：订单有哪些状态？
**A**：共 7 个状态：`pending`（待处理）、`submitting`（提交中）、`paying`（支付中）、`succeeded`（成功）、`failed`（失败）、`cancelled`（已取消）、`takeover_pending`（等待人工接管）。

### Q2：人工接管超时是多久？为什么？
**A**：30 分钟（`TAKEOVER_TIMEOUT_MIN=30`）。这对应闲鱼待付款订单 30 分钟自动关闭的业务规则，超时后订单自动流转为 `cancelled` 并触发 `buy.failed` 事件。

### Q3：TakeoverModal 有哪几个阶段？
**A**：三阶段：`confirm`（确认接管，展示商品与价格）→ `progress`（支付进行中，倒计时 30 分钟，可上传截图）→ `done`（展示结果）。阶段严格顺序流转，不可跳过。

### Q4：利润计算器的费率是多少？
**A**：默认 0.6%（个人卖家），商家为 1.6%。计算公式：净利润 = 转售价 - 成交价 - 运费 - 手续费。转售价默认按成交价 1.2 倍估算，用户可调整。

### Q5：手动抢单和自动抢单有什么区别？
**A**：自动抢单由任务以 `auto` 模式触发，评估通过后自动创建订单；手动抢单由用户在评估明细页点击"手动抢单"调用 `/api/orders/manual-takeover`，适用于系统未自动触发但用户判断值得抢的商品。

### Q6：订单成功后会触发什么？
**A**：订单成功后会发布 `buy.succeeded` 事件，前端通过 SSE 实时更新状态。同时触发 F-16 依赖任务检查：若该任务有下游依赖任务且处于 `paused` 状态，会自动激活为 `running`。

### Q7：F-16 依赖任务会激活哪些状态的任务？
**A**：仅激活 `paused` 状态的下游依赖任务。`running` 状态跳过（已在运行），`stopped` 状态跳过（避免误启动用户主动停止的任务）。

### Q8：订单失败原因在哪里查看？
**A**：订单状态为 `failed` 时，`error` 字段会填充失败原因（如 `takeover_timeout`、`waf_blocked`、`payment_failed` 等）。在订单详情页可查看完整错误信息。

### Q9：接管时上传的截图有什么用？
**A**：截图作为支付凭证存储在 `screenshot` 字段，用于后续审计与纠纷处理。在订单详情页可点击"查看截图"预览。

### Q10：订单可以取消吗？
**A**：可以。处于 `takeover_pending` 状态的订单可通过 `/api/orders/{id}/takeover/cancel` 取消，需提供取消原因。取消后状态流转为 `cancelled`，不可恢复。
