## 2. 功能概述

**一句话说明**：以任务为中心聚合商品数据，提供概要查询、轻量刷新、任务关联管理、实时搜索与导出能力，是商品数据的统一入口。

**核心价值**：
- 商品概要接口（summary/batch）专为列表页异步补全标题设计，避免拉取完整 item 大字段；
- 轻量刷新接口只采集详情页并 upsert，不触发重评估；
- 任务-内容关联（task_links）支持 DB 模式浏览 + SSE 实时搜索双轨，避免重复采集；
- 跨任务反查（lookup）与模糊搜索（search）支撑内容到任务的反向追溯；
- CSV 导出（items/evaluations/orders/events）支持按任务/时间过滤，Excel 友好。

## 3. 用户场景

### 场景一：在订单列表异步补全商品标题
订单列表只存储 `item_id`，用户难以判断"是不是想要的那一单"。前端通过 `GET /api/items/batch?ids=...` 一次拉取最多 50 个商品概要，将标题、价格、卖家 ID 异步补全到订单行。

### 场景二：轻量刷新商品状态
用户在商品列表点击商品标题链接，前端调用 `POST /api/items/{item_id}/refresh`，后端仅采集商品详情页并 upsert 到 items 表，同步 task_links.display。已售时额外写入 `sold_detected_at`，但不触发重新评估。

### 场景三：DB 模式浏览任务关联商品
用户进入任务详情"商品列表"Tab，前端调用 `GET /api/tasks/{task_id}/links?link_type=item`，按 `created_at` 倒序分页返回 DB 中已采集的商品关联记录，支持按价格/品牌/已售状态过滤。

### 场景四：SSE 实时搜索闲鱼
DB 模式数据不足时，用户切换"实时搜索"Tab，前端建立 SSE 连接 `GET /api/tasks/{task_id}/links/live`。后端调用闲鱼搜索 API，逐条推送商品结果与阶段进度事件（等待锁/搜索中/采集详情/评估/写库）。搜索结果缓存 60 秒，避免短时间重复请求闲鱼。

### 场景五：跨任务反查与模糊搜索
用户想看某个商品被哪些任务监控，调用 `GET /api/tasks/links/lookup?type=item&key=xxx` 反查任务列表；也可通过 `GET /api/tasks/links/search?q=相机&type=item` 跨任务模糊搜索商品标题。

### 场景六：导出 CSV 报表
用户点击"导出"按钮，调用 `GET /api/export/items?task_id=xxx&start=...&end=...&limit=5000` 流式下载 CSV，包含 id/title/price/seller_id/first_seen 等 11 列，按 `first_seen` 倒序。

## 5. 接口定义

### 5.1 商品概要 API（3 个）

| 方法 | 路径                              | 说明           | 请求参数                                                                                          | 响应字段                                                                                          |
| ---- | --------------------------------- | -------------- | ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| GET  | `/api/items/{item_id}/summary`    | 商品概要       | 无                                                                                                | `item_id`, `title`, `price`, `seller_id`（缺失返回 null）                                          |
| GET  | `/api/items/batch`                | 批量概要       | `ids` (逗号分隔，最多 50 个)                                                                      | `summaries` ({id: {title, price, seller_id}}), `missing` ([未找到的 id]), `count`                  |
| POST | `/api/items/{item_id}/refresh`    | 轻量刷新       | `task_id` (Query，可选，items 表无记录时回填 task_links.display)                                   | `ok`, `item_id`, `is_sold`, `title`, `price`, `brand`, `seller_id`, `region`, `want_cnt`, `view_cnt`, `thumb_url`, `image_urls`, `publish_time`, `seller_nick`, `seller_credit` |

**轻量刷新语义边界**：
- **做**：调用 `collector.detail(item_id)` 采集详情 → `upsert_item` 写 items 表 → `sync_item_display_from_detail` 同步 task_links.display → 已售时 `mark_sold` 写 `sold_detected_at`。
- **不做**：不触发 `evaluator.evaluate` 重新评估；不采集卖家主页（seller_profile）；不提取评价/留言；不写 `eval.scored` 事件、不更新 sellers 表。
- **完整官方采集**：若需 detail + seller + reviews + 重新评估 + events 写入的端到端流程，改用 `POST /api/evaluations/{item_id}/collect-official`。

### 5.2 任务-内容关联 API（9 个）

| 方法   | 路径                                       | 说明                   | 请求参数                                                                                                                                                                                | 响应字段                                                                                                                  |
| ------ | ------------------------------------------ | ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/tasks/{task_id}/links`               | 任务关联列表           | `link_type` (item/seller), `page`, `page_size`, `min_price`, `max_price`, `brand`, `is_sold`, `data_source`                                                                              | `items[]`, `total`, `page`, `page_size`                                                                                    |
| GET    | `/api/tasks/{task_id}/links/count`         | 按 type 计数           | `link_type` (item/seller)                                                                                                                                                               | `count`                                                                                                                    |
| POST   | `/api/tasks/{task_id}/links`               | 新增关联               | Body: `link_type`, `link_key`, `display` (dict, 可选), `source` (默认 manual), `note` (≤500 字符)                                                                                       | 201 + 新建关联记录                                                                                                         |
| DELETE | `/api/tasks/{task_id}/links/{link_id}`    | 解除关联               | 无                                                                                                                                                                                       | `ok`, `id`                                                                                                                 |
| POST   | `/api/tasks/{task_id}/links/refresh`       | 实时搜索并刷新 DB      | 无（后台调用闲鱼搜索并 upsert task_links）                                                                                                                                              | `ok`, `fetched_count`, `saved_count`                                                                                       |
| GET    | `/api/tasks/{task_id}/links/live`          | SSE 实时搜索（不入库） | `force_refresh` (布尔，绕过 60s 缓存)                                                                                                                                                    | SSE 事件流：逐条推送商品结果 + 阶段进度事件                                                                                |
| GET    | `/api/tasks/links/lookup`                  | 反查：内容 → 任务      | `type` (item/seller), `key`                                                                                                                                                             | `tasks[]` (任务 ID 列表)                                                                                                   |
| GET    | `/api/tasks/links/search`                  | 跨任务模糊搜索         | `q` (关键词), `type` (item/seller), `limit` (默认 50)                                                                                                                                    | `items[]`, `total`                                                                                                         |
| POST   | `/api/tasks/links/auto-migrate`            | 一次性迁移             | 无（把 items 表中 `task_id` 字段已存在但 task_links 缺失的记录同步到 task_links）                                                                                                         | `ok`, `migrated_count`                                                                                                     |

### 5.3 导出 API（2 个）

| 方法 | 路径                  | 说明                 | 请求参数                                                                                                       | 响应字段                                                                                                |
| ---- | --------------------- | -------------------- | -------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| GET  | `/api/export`         | 列出可导出数据集     | 无                                                                                                             | `datasets[]` (key/columns/description)                                                                  |
| GET  | `/api/export/{dataset}` | 导出 CSV            | `task_id` (可选), `start`, `end` (ISO), `status` (仅 orders), `level` (仅 events), `limit` (1-50000，默认 5000) | CSV 文件流（`Content-Type: text/csv; charset=utf-8`）                                                   |

**支持的 dataset**：`items` / `evaluations` / `orders` / `events`。

### 5.4 SSE 实时搜索事件格式

`/api/tasks/{task_id}/links/live` 推送两类 SSE 事件，**注意：不携带 `event:` 字段**，前端通过 `data.type` 区分：

```
data: {"type":"progress","stage":"waiting_lock","message":"等待浏览器锁...","elapsed":1.5}

data: {"type":"progress","stage":"searching","message":"正在搜索闲鱼...","elapsed":3.2}

data: {"type":"result","item":{"item_id":"98765432","title":"iPhone 14 Pro","price":4999,"seller_id":"xxx","thumb_url":"...","is_sold":false}}

data: {"type":"progress","stage":"evaluating","message":"对 5 条结果触发轻量评估...","elapsed":8.1}

data: {"type":"done","fetched_count":15,"saved_count":12,"elapsed":12.4}

data: {"type":"error","message":"采集超时","stage":"searching"}
```

**stage 取值**：`waiting_lock` / `searching` / `fetching_detail` / `evaluating` / `buying` / `done` / `error`。

**注意**：`task.search_done` 事件由独立的 `/api/events/stream` 端点推送（见"事件时间线"文档），不在 `/links/live` 中。

## 7. 业务逻辑

### 7.1 实时搜索缓存与去重机制

```python
# _live_cache: task_id -> (monotonic_timestamp, result_dict)
# 60 秒 TTL：避免短时间重复搜索闲鱼（每次搜索 15-20s），60s 内返回缓存结果
_LIVE_CACHE_TTL = 60

# _live_inflight: task_id -> asyncio.Event
# 当搜索正在进行时，后续请求等待 Event 完成后复用缓存结果
# 解决：前端轮询（15s）与用户点击可能同时发起 live 请求，第二个请求会因
# browser_lock 被持有而等待 10s 超时
_LIVE_INFLIGHT_WAIT_TIMEOUT = 35.0  # 覆盖正常搜索（30s）+ 缓冲（5s）

# _LIVE_LOCK_TOTAL_TIMEOUT = 20.0
# live 端点获取 browser_lock 的总等待时间
# Worker 一轮搜索可能持锁 30-45s，10s 内大概率拿不到；20s 配合 SSE 进度推送
```

**为什么需要 in-flight 去重**：前端轮询（15s）与用户手动点击可能同时发起 live 请求，第二个请求因 `browser_lock` 被持有而等待超时，返回"系统正在执行后台搜索任务"错误。in-flight Event 让第二个请求等待第一个完成，复用结果。

### 7.2 实时搜索身份 Cookie 校验

闲鱼搜索 API 需要身份 Cookie，缺失会导致搜索失败。后端在 live 端点入口校验：

```python
_LIVE_SEARCH_IDENTITY_COOKIES = ("cookie2", "sgcookie", "unb")

def _missing_live_search_cookie_names(cookie_names: set[str]) -> list[str]:
    """Return identity cookies required by Xianyu search but absent."""
    return [name for name in _LIVE_SEARCH_IDENTITY_COOKIES if name not in cookie_names]
```

缺失时返回明确错误信息（哪些 Cookie 缺失），前端引导用户重新登录。

### 7.3 实时搜索抢单冷却

```python
# live 抢单冷却：避免实时搜索频繁触发抢单冲击闲鱼下单接口
_live_last_buy_at: float = 0.0
_LIVE_BUY_COOLDOWN = 30.0  # 30 秒冷却

# _trigger_live_auto_buy 中检查：
# if now - _live_last_buy_at < _LIVE_BUY_COOLDOWN:
#     logger.info("[LiveAutoBuy] 冷却中（剩余 {}s），跳过 live 抢单 {}", remaining, item_id)
#     return
```

**为什么需要冷却**：live 搜索可能每分钟触发多次，不加冷却会短时间内重复尝试下单，被闲鱼风控判定为异常行为。

### 7.4 实时搜索轻量评估

live 链路对搜索结果触发轻量评估，**复用任务级 eval 配置**但走独立的 `_build_live_eval_context` 构造上下文：

```python
# 为什么 live 链路需要价格过滤：
# 上一次架构优化加入 _trigger_live_auto_buy 时，漏接价格过滤，
# 商品价格 8000 且评分 85 时，live 链路会误抢单，与 worker 行为不一致
```

**设计原则**：live 链路评估与 worker 链路评估使用相同的价格过滤与评分阈值，避免两条链路行为不一致导致误抢单。

### 7.5 数据变化高亮算法

前端基于字段签名对比检测数据变化：

```typescript
// 签名基于价格、已售状态、想要数三个字段
function dataSignature(item: ItemRow): string {
  return `${item.price}|${item.is_sold}|${item.want_cnt}`;
}

// 当新数据签名与旧数据不同时，高亮 3 秒
useEffect(() => {
  if (prevSignature !== currentSignature) {
    setHighlightId(item.id);
    const timer = setTimeout(() => setHighlightId(null), 3000);
    return () => clearTimeout(timer);
  }
}, [currentSignature]);
```

**为什么 3 秒**：低于 3 秒用户难以察觉，高于 3 秒会干扰后续行的高亮。

### 7.6 自动迁移（auto-migrate）

`POST /api/tasks/links/auto-migrate` 一次性把 items 表中 `task_id` 字段已存在但 task_links 缺失的记录同步到 task_links：

```
1. 查询 items 表中所有 task_id 非空的记录
2. 查询 task_links 表中所有 (task_id, link_type='item', link_key=item_id) 已存在的记录
3. 计算差集：items 中有但 task_links 中没有的 (task_id, item_id) 对
4. 批量 INSERT 到 task_links（source='auto'，display 从 items 表反查填充）
5. 返回 migrated_count
```

**用途**：早期版本 items 表已有数据但未同步到 task_links，运行一次 auto-migrate 即可补全，避免历史数据丢失。

## 9. 常见问题 FAQ

### Q1：商品中心和商品列表是什么关系？
**A**：菜单 label 为"商品中心"（见 `config/menu_registry.yaml`），对应文档名为"商品中心-详细设计"。v1.0 文档名为"商品列表"已废弃。商品中心不作为独立顶级页面，而是嵌入在"任务管理 → 任务详情 → 商品列表 Tab"中。

### Q2：items 表为什么没有 created_at/updated_at？
**A**：items 表实际字段是 `first_seen`/`last_seen`，语义更准确——表示"首次见到"和"最后见到"商品的时间，而非记录创建/更新时间。`last_seen` 在每次 upsert 时通过 `onupdate=_utcnow` 自动更新。

### Q3：轻量刷新和完整官方采集有什么区别？
**A**：轻量刷新（`POST /api/items/{item_id}/refresh`）只采集详情页并 upsert items 表，不触发评估、不采集卖家、不写 events。完整官方采集（`POST /api/evaluations/{item_id}/collect-official`）是端到端流程：detail + seller + reviews + 重新评估 + events 写入。

### Q4：实时搜索结果会写入数据库吗？
**A**：`/api/tasks/{tid}/links/refresh` 会写入 task_links 表；`/api/tasks/{tid}/links/live` 默认不写入，直接通过 SSE 返回结果。live 端点内部调用 `batch_upsert_item_task_links` 在搜索完成后批量写入，但用户感知到的是 SSE 流式结果。

### Q5：实时搜索为什么有 60 秒缓存？
**A**：每次闲鱼搜索耗时 15-20 秒，60 秒内重复请求返回缓存结果，避免冲击闲鱼搜索 API。可通过 `force_refresh=true` 参数绕过缓存强制重新搜索。

### Q6：为什么 live 端点需要 in-flight 去重？
**A**：前端轮询（15s）与用户手动点击可能同时发起 live 请求，第二个请求会因 `browser_lock` 被持有而等待 10s 超时。in-flight Event 让第二个请求等待第一个完成（最多 35 秒），复用结果。

### Q7：link_type 有哪些取值？
**A**：仅 `item` 和 `seller` 两类。v1.0 文档提到的 `brand`/`url` 已废弃，项目决策只保留这两类。

### Q8：task_links 表的 id 为什么是 Integer 不是 TEXT？
**A**：`task_links.id` 是自增 Integer 主键，与 items.id（String，闲鱼商品 ID）不同。DELETE 接口路径 `/api/tasks/{tid}/links/{link_id}` 中的 `link_id` 是 Integer 类型。

### Q9：实时搜索时身份 Cookie 缺失会怎样？
**A**：后端校验 `cookie2`/`sgcookie`/`unb` 三个身份 Cookie，缺失时返回明确错误信息（哪些 Cookie 缺失），前端引导用户重新登录闲鱼。

### Q10：导出 CSV 支持哪些数据集？
**A**：4 种数据集：`items`（商品列表）、`evaluations`（评估记录）、`orders`（订单记录）、`events`（事件日志）。每种有固定列定义，支持按 `task_id`/`start`/`end` 过滤，单次最多导出 50000 行。

### Q11：数据变化高亮基于哪些字段？
**A**：基于 `price|is_sold|want_cnt` 三个字段的签名对比，任意一个变化都触发高亮。高亮持续 3 秒（黄色背景），低于 3 秒用户难以察觉，高于 3 秒干扰后续行。

### Q12：auto-migrate 是做什么的？
**A**：`POST /api/tasks/links/auto-migrate` 一次性把 items 表中 `task_id` 已存在但 task_links 缺失的记录同步到 task_links。用于历史数据补全，避免早期版本未同步 task_links 的数据丢失。

### Q13：实时搜索的 SSE 事件为什么没有 event: 字段？
**A**：`/api/tasks/{tid}/links/live` 推送的 SSE 事件只有 `data:` 字段，前端通过 `data.type` 区分（`progress`/`result`/`done`/`error`）。而 `/api/events/stream` 推送的系统事件才有 `event: app_event` 字段，两者格式不同。

### Q14：品牌筛选是怎么实现的？
**A**：精确匹配 `display.brand` 字段，不是标签包含匹配。例如筛选"Canon"只返回 brand 严格等于"Canon"的商品，不返回"Canon EOS"等包含匹配。
