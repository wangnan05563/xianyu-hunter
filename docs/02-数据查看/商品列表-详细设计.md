## 2. 功能概述

**一句话说明**：展示任务采集到的闲鱼商品列表，支持实时搜索、动态字段列、客户端筛选排序与数据变化高亮。

**核心价值**：
- 统一聚合多个任务的商品数据，避免逐任务查看；
- 通过字段元数据驱动动态列，灵活适配不同任务字段配置；
- DB 模式与实时模式（liveMode）双轨切换，兼顾历史回溯与即时搜索；
- SSE 订阅 `task.search_done` 事件，新商品入库即高亮提示。

## 3. 用户场景

### 场景一：浏览历史商品
用户进入商品列表页，默认 DB 模式展示已落库商品。通过客户端筛选器按地区/品牌/是否售出过滤，并通过列配置拖拽调整列顺序，配置持久化到 localStorage。

### 场景二：实时搜索验证
用户切换到 liveMode 实时模式，输入关键词触发实时搜索，通过 SSE 订阅 `/api/tasks/{taskId}/links/live` 推送结果，无需刷新页面。

### 场景三：刷新单个商品
用户对某条疑似已售商品点击"刷新"按钮，调用 `/api/items/{id}/refresh` 重新采集该商品详情，返回后页面以高亮动画提示数据变化。

## 5. 接口定义

### 5.1 API 路由表

| 方法   | 路径                              | 说明                  | 请求参数                                                                 | 响应字段                                                                       |
| ------ | --------------------------------- | --------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------ |
| GET    | `/api/items/{id}/summary`         | 商品摘要              | 无                                                                       | `id`, `title`, `price`, `thumb_url`, `is_sold`, `seller_id`                    |
| POST   | `/api/items/batch`                | 批量获取商品          | `ids[]`                                                                  | `items[]`                                                                      |
| POST   | `/api/items/{id}/refresh`         | 刷新单个商品          | 无                                                                       | `id`, `updated_fields[]`, `is_sold`, `sold_detected_at`                        |
| GET    | `/api/tasks/{taskId}/links`       | 任务关联列表（DB）    | `page`, `page_size`, `link_type`                                         | `items[]` (含 task_links 关联信息)                                             |
| GET    | `/api/tasks/{taskId}/links/live`  | 任务关联实时搜索(SSE) | `keyword` (URL 参数)                                                     | SSE 事件流（每条含 `id`, `title`, `price`, `thumb_url`, `seller_id`）          |

### 5.2 SSE 事件格式（task.search_done）

```
event: task.search_done
id: 9876
data: {"task_id":"t_001","items_count":42,"new_items":["i_1001","i_1002"],"created_at":"2026-06-29T11:00:00+00:00"}
```

## 7. 业务逻辑

### 7.1 DB 模式 vs 实时模式

```
┌─────────────┐                    ┌─────────────────┐
│  DB 模式    │                    │  liveMode 模式  │
├─────────────┤                    ├─────────────────┤
│ 数据来源    │ 数据库 items 表    │ SSE 实时推送    │
│ 数据完整性  │ 全部历史商品       │ 仅本次搜索结果  │
│ 响应速度    │ 毫秒级（索引查询） │ 秒级（实时采集）│
│ 适用场景    │ 浏览/筛选/分析     │ 验证关键词效果  │
│ 持久化      │ 已落库             │ 临时展示        │
└─────────────┘                    └─────────────────┘
```

### 7.2 动态列渲染流程

```
1. 从任务配置读取字段元数据（field_metadata）
2. 按 type 匹配列渲染组件（image/link/price/seller/tag/text/number/datetime/status）
3. 应用 localStorage 中的列顺序与可见性配置
4. 渲染表格头部与数据行
5. 用户拖拽列头 → 更新 localStorage → 重新渲染
```

### 7.3 数据变化高亮算法

```typescript
// 通过 SSE 推送的 new_items 数组与当前列表对比
const highlightedIds = new Set(newItems);
rows.forEach(row => {
  if (highlightedIds.has(row.id)) {
    row.highlightUntil = Date.now() + 2000; // 高亮 2 秒
  }
});
// CSS 动画 .row-highlight { animation: pulse-green 2s; }
```

### 7.4 客户端筛选逻辑

| 筛选项 | 字段         | 匹配方式                       |
| ------ | ------------ | ------------------------------ |
| search | title        | 子串匹配（不区分大小写）       |
| region | region       | 精确匹配                       |
| brand  | tags.brand   | 标签包含                       |
| sold   | is_sold      | 0/1 二值过滤                   |

筛选在前端内存中执行，避免每次按键都请求后端，提升交互流畅度。

## 9. 常见问题 FAQ

### Q1：DB 模式和实时模式有什么区别？
**A**：DB 模式从数据库 `items` 表查询全部历史商品，毫秒级响应，适合浏览分析；实时模式（liveMode）通过 SSE 实时推送搜索结果，秒级响应，适合验证关键词效果，但仅展示本次搜索结果。

### Q2：商品列表的列可以自定义吗？
**A**：可以。点击工具栏"列配置"按钮，可勾选可见列、拖拽调整列顺序。配置持久化到 `localStorage`（key: `xianyu.item.column_config`），下次访问自动恢复。

### Q3：支持哪些字段类型？
**A**：支持 9 种字段类型：`image`（图片）、`link`（链接）、`price`（价格）、`seller`（卖家）、`tag`（标签）、`text`（文本）、`number`（数字）、`datetime`（日期时间）、`status`（状态）。

### Q4：新商品入库会有提示吗？
**A**：会。系统通过 SSE 订阅 `task.search_done` 事件，新商品入库后对应行会绿色高亮 2 秒，便于用户识别增量数据。

### Q5：客户端筛选和后端筛选有什么区别？
**A**：客户端筛选（search/region/brand/sold）在前端内存中即时执行，不请求后端，响应快但仅过滤当前页数据；后端筛选通过 API 参数实现，可过滤全量数据。

### Q6：商品售出状态是怎么检测的？
**A**：通过 `/api/items/{id}/refresh` 接口重新采集商品详情，若检测到售出则更新 `is_sold=1` 并记录 `sold_detected_at` 时间戳。

### Q7：一个商品可以关联多个任务吗？
**A**：可以。通过 `task_links` 表实现多对多关联，同一商品可被多个任务采集，关联信息存储在 `task_links` 表中。

### Q8：实时模式搜索结果会持久化吗？
**A**：实时模式仅展示本次搜索结果，不自动持久化。若任务处于运行状态，搜索结果会随任务调度落库到 `items` 表，可在 DB 模式中查看。

### Q9：图片列支持点击放大吗？
**A**：支持。`image` 类型列的缩略图点击后会弹出大图预览，支持图片轮播（当 `image_urls` 数组有多张图时）。

### Q10：商品列表的索引有哪些？
**A**：主要有两个索引：`ix_items_task_first_seen`（task_id, first_seen）用于按任务+时间倒序查询；`ix_items_seller`（seller_id）用于按卖家聚合查询。
