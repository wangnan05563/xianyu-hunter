## 2. 功能概述

**一句话说明**：提供任务的增删改查、启停控制、批量操作、智能建任务与模板市场能力，是整个系统的运行入口。

**核心价值**：
- 统一管理所有闲鱼监控任务的生命周期；
- 通过任务级配置覆盖机制，兼顾全局默认与单任务个性化；
- 通过状态机精确控制任务运行节奏，支持暂停/恢复/停止/重启；
- 智能建任务与模板市场降低用户配置门槛。

## 3. 用户场景

### 场景一：新建监控任务
用户在 TaskList 页面点击"新建任务"，进入 TaskEditor 填写关键词、价格区间、评估阈值、运行模式等参数，提交后任务以 `running` 状态进入调度队列。

### 场景二：批量暂停任务
夜间维护时，用户在 TaskList 勾选多个任务，点击"批量暂停"，调用 `/api/tasks/batch-control` 一次性将多个任务从 `running` 切换到 `paused`，避免逐个操作。

### 场景三：查看任务运行历史
用户点击某任务的"详情"进入 TaskDetail，查看该任务的运行记录（runs）、关联商品、关联订单与事件流，定位任务异常。

## 5. 接口定义

### 5.1 API 路由表

| 方法   | 路径                              | 说明                  | 请求参数                                                                                                                                                       | 响应字段                                                                                                |
| ------ | --------------------------------- | --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| GET    | `/api/tasks`                      | 任务列表              | `status` (可选), `mode` (可选), `keyword` (可选), `page`, `page_size`                                                                                          | `items[]`, `total`, `page`, `page_size`                                                                 |
| POST   | `/api/tasks`                      | 新建任务              | `name`, `keyword`, `min_price`, `max_price`, `mode`, `cron`, `interval_seconds`, `search_config`, `price_config`, `eval_config`, `antidetect_config`          | `id`, `status`, `created_at`                                                                            |
| GET    | `/api/tasks/{id}`                 | 任务详情              | 无                                                                                                                                                             | 完整 TaskRow 字段                                                                                       |
| PUT    | `/api/tasks/{id}`                 | 更新任务              | 同 POST 字段（部分更新）                                                                                                                                       | `id`, `updated_at`                                                                                      |
| DELETE | `/api/tasks/{id}`                 | 删除任务（软删除）    | 无                                                                                                                                                             | `id`, `status=deleted`                                                                                  |
| POST   | `/api/tasks/{id}/control`         | 任务控制              | `action` (pause/resume/stop/restart)                                                                                                                           | `id`, `status`, `next_run_at`                                                                           |
| POST   | `/api/tasks/batch-control`        | 批量控制              | `ids[]`, `action`                                                                                                                                              | `succeeded[]`, `failed[]`                                                                               |
| GET    | `/api/tasks/{id}/runs`            | 任务运行记录          | `page`, `page_size`, `start_date`, `end_date`                                                                                                                  | `items[]` (含 `run_id`, `started_at`, `finished_at`, `status`, `items_found`, `error`)                  |

### 5.2 任务控制动作语义

| 动作     | 前置状态                | 目标状态   | 说明                         |
| -------- | ----------------------- | ---------- | ---------------------------- |
| pause    | running                 | paused     | 暂停调度，保留进度           |
| resume   | paused                  | running    | 恢复调度                     |
| stop     | running/paused          | stopped    | 停止任务，需手动 restart     |
| restart  | stopped/error           | running    | 重置运行上下文并启动         |

## 7. 业务逻辑

### 7.1 任务状态机

```
        ┌──────────┐
   ┌───→│  running  │←──resume────┐
   │    └────┬─────┘              │
   │         │                    │
   │       pause                pause
   │         │                    │
   │         ▼                    │
   │    ┌──────────┐              │
   │    │  paused  │──────────────┘
   │    └────┬─────┘
   │         │ stop
   │         ▼
   │    ┌──────────┐  restart   ┌──────────┐
   │    │ stopped  │───────────→│ running  │
   │    └──────────┘            └──────────┘
   │         ▲
   │         │ error
   │    ┌──────────┐
   │    │  error   │
   │    └──────────┘
   │
   └─── (deleted 为终态，软删除)
```

### 7.2 任务模式说明

| 模式       | 行为                                                              |
| ---------- | ----------------------------------------------------------------- |
| auto       | 全自动：评估通过即自动触发抢单                                    |
| semi_auto  | 半自动：评估通过后推送通知，用户点击确认后抢单                    |
| confirm    | 确认模式：每个商品需人工确认后才进入评估                          |
| notify     | 仅通知：仅推送商品信息，不触发抢单                                |

### 7.3 任务级配置覆盖算法

```
def resolve_config(task_config: dict | None, global_config: dict) -> dict:
    """
    任务级配置覆盖：None 表示沿用全局，dict 表示深度合并覆盖。
    采用深度合并而非浅替换，确保子键仍可继承全局默认。
    """
    if task_config is None:
        return global_config
    return deep_merge(global_config, task_config)
```

**深度合并规则**：
- 任务级 `None` → 完全沿用全局；
- 任务级 `dict` → 与全局深度合并，任务级键优先；
- 列表类型直接替换（不做元素合并）。

### 7.4 调度执行流程

```
1. 调度器根据 next_run_at 唤醒任务
2. 检查 status == running，否则跳过
3. 写入 task_runs 记录（status=running）
4. 执行搜索 → 落库 items → 触发评估
5. 评估通过 → 按 mode 决定抢单/通知
6. 更新 task_runs（status=succeeded/failed, items_found=N）
7. 计算下次 next_run_at = now + interval_seconds 或 cron 推算
```

## 9. 常见问题 FAQ

### Q1：任务有哪些状态？分别是什么含义？
**A**：任务共 6 个状态：`running`（运行中）、`paused`（已暂停）、`stopped`（已停止）、`error`（异常）、`deleted`（已删除，软删除终态）。

### Q2：任务的 4 种模式有什么区别？
**A**：`auto` 全自动评估通过即抢单；`semi_auto` 评估通过后通知用户确认；`confirm` 每个商品需人工确认才评估；`notify` 仅推送商品信息不抢单。

### Q3：关键词长度有什么限制？
**A**：关键词长度限制为 1-80 字符，由 Pydantic 模型 `TaskCreate` 校验，超出范围会返回 422 错误。

### Q4：interval_seconds 的取值范围是多少？
**A**：30-3600 秒（即最短 30 秒，最长 1 小时）。过短的间隔可能触发闲鱼反爬，建议根据 `antidetect_config` 合理设置。

### Q5：eval_threshold 的取值范围是多少？
**A**：0-100。评估得分 ≥ 该阈值的商品才会进入抢单流程。阈值越高，抢单越严格，但可能漏掉部分商品。

### Q6：任务级配置覆盖是怎么工作的？
**A**：每个任务有 `search_config`、`price_config`、`antidetect_config`、`eval_config` 四个 JSON 字段。值为 `None` 表示完全沿用全局配置；值为 `dict` 则与全局配置深度合并，任务级键优先。

### Q7：批量控制接口一次最多操作多少个任务？
**A**：批量控制接口 `/api/tasks/batch-control` 接受 `ids[]` 数组，单次建议不超过 100 个，避免长事务。响应会返回 `succeeded[]` 和 `failed[]` 两个数组，便于核对结果。

### Q8：停止状态的任务怎么重新启动？
**A**：`stopped` 状态的任务需要调用 `restart` 动作恢复为 `running`。直接 `resume` 无效，因为 `resume` 仅适用于 `paused` 状态。

### Q9：cron 和 interval_seconds 可以同时设置吗？
**A**：不可以。两者互斥，至少填一个。`cron` 适合固定时刻执行（如每天 10:00），`interval_seconds` 适合固定间隔轮询。

### Q10：闲鱼筛选标签有哪些？
**A**：支持 `personal_idle`（个人闲置）、`verified`（实名认证）、`free_shipping`（包邮）、`brand_new`（全新）、`near_new`（几乎全新）、`second_hand`（二手）、`local`（同城）等标签，可在 TaskEditor 中勾选。
