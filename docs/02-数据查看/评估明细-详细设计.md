## 2. 功能概述

**一句话说明**：展示商品 AI 评估结果，支持成色评估、深度鉴伪、官方采集、手动抢单、评估反馈与阈值建议，是系统最复杂的页面。

**核心价值**：
- 多维度量化商品风险（职业度/信用/纠纷/价格 4 维评分）；
- AI 成色评估 + 多模态鉴伪，识别盗图/损坏/一致性/模板问题；
- 官方采集流程获取卖家主页与评价，提升评估数据质量；
- 阈值建议基于历史数据分布，辅助用户调优 `eval_threshold`；
- 评估反馈闭环，持续优化模型。

---

## 3. 用户场景

### 场景一：浏览评估结果
用户进入评估明细页，默认按风险等级排序。通过多维过滤（风险等级/数据质量/任务/价格区间）筛选目标商品，点击行展开查看 4 维评分明细与拒绝原因。

### 场景二：触发官方采集
用户对某条数据质量为 `insufficient` 的商品点击"官方采集"，系统调用 `/api/evaluations/{id}/collect-official`，采集详情+卖家主页+评价后重新评估。

### 场景三：调优阈值
用户点击"阈值建议"打开面板，系统基于历史评估分布给出推荐阈值。用户参考建议在任务配置中调整 `eval_threshold`，平衡通过率与误判率。

### 6.2 风险等级映射

| 风险等级 | 颜色 | 评分区间       | 说明                       |

| LOW      | 绿   | score ≥ 80     | 低风险，可放心抢单         |
| MEDIUM   | 黄   | 60 ≤ score < 80| 中等风险，需人工复核       |
| HIGH     | 橙   | 40 ≤ score < 60| 高风险，谨慎抢单           |
| EXTREME  | 红   | score < 40 或一票否决 | 极高风险，禁止抢单    |

### 6.3 评估 4 维评分

| 维度              | 字段键           | 权重 | 说明                       |
| ----------------- | ---------------- | ---- | -------------------------- |
| 职业度            | professionalism  | 25   | 卖家是否为职业商家         |
| 信用              | credit           | 30   | 卖家信用评分               |
| 纠纷              | dispute          | 20   | 历史纠纷率                 |
| 价格              | price            | 25   | 价格合理性（对比市场均价） |

> 4 维权重之和 = 100。综合评分 = Σ(维度得分 × 权重 / 100)。

### 6.4 数据质量分级

| 分级        | 条件                  | 说明                       |
| ----------- | --------------------- | -------------------------- |
| full        | 4 维均有效            | 数据完整，评估可信         |
| partial     | 1-2 维有效            | 数据部分缺失，评估仅供参考 |
| insufficient| 仅价格维度有效        | 数据严重不足，建议官方采集 |

## 7. 业务逻辑

### 7.1 AI 评估双引擎

```
                ┌─────────────────┐
                │  商品图片+文本  │
                └────────┬────────┘
                         │
              ┌──────────┴──────────┐
              │                     │
              ▼                     ▼
    ┌─────────────────┐   ┌─────────────────┐
    │  成色评估引擎   │   │  深度鉴伪引擎   │
    │ (6类关键词库)   │   │ (多模态分析)    │
    └────────┬────────┘   └────────┬────────┘
             │                     │
             ▼                     ▼
    ┌─────────────────┐   ┌─────────────────┐
    │  成色等级+置信度│   │  鉴伪报告        │
    │  (new/like_new/ │   │  - 盗图检测      │
    │   used/worn/    │   │  - 损坏检测      │
    │   broken)       │   │  - 一致性检测    │
    └─────────────────┘   │  - 模板检测      │
                          └─────────────────┘
```

### 7.2 官方采集流程

```
1. 检查 Cookie 同步状态（cookie2/sgcookie/unb）
   ├── 缺失 → 返回 403
   ├── 过期 → 返回 440
   └── 验证码 → 返回 441
2. 采集商品详情（detail）
3. 采集卖家主页（seller profile）
4. 提取卖家评价（reviews）
5. 重新评估（合并新数据计算 4 维评分）
6. 更新 evaluations 表（data_quality 升级为 full）
7. 发布 eval.scored 事件
```

### 7.3 风险等级判定算法

```python
def calc_risk_level(score: float, veto_reasons: list[str] | None = None) -> str:
    """
    风险等级判定：一票否决优先于评分区间。
    一票否决场景：盗图确认/严重损坏/纠纷率超阈值等。
    """
    if veto_reasons:
        return "EXTREME"
    if score >= 80:
        return "LOW"
    elif score >= 60:
        return "MEDIUM"
    elif score >= 40:
        return "HIGH"
    else:
        return "EXTREME"
```

### 7.4 阈值建议算法

```
1. 拉取任务近 30 天评估分布直方图（按 score 分桶）
2. 计算不同阈值下的通过率与误判率
3. 寻找通过率与误判率的帕累托最优点
4. 输出建议阈值 + 该阈值下的预期通过率
5. 用户确认后应用到任务配置 eval_config.eval_threshold
```

### 7.5 深度鉴伪 4 类检测

| 检测类型   | 说明                                                       |
| ---------- | ---------------------------------------------------------- |
| 盗图检测   | 对比图片指纹库，识别网络盗图                               |
| 损坏检测   | 多模态模型识别商品损坏部位                                 |
| 一致性检测 | 标题/描述/图片三方一致性校验                               |
| 模板检测   | 识别批量发布的模板化商品（疑似职业商家刷单）               |

## 9. 常见问题 FAQ

### Q1：评估的 4 个维度分别是什么？权重是多少？
**A**：4 维评分：职业度（professionalism，权重 25）、信用（credit，权重 30）、纠纷（dispute，权重 20）、价格（price，权重 25）。4 维权重之和为 100，综合评分 = Σ(维度得分 × 权重 / 100)。

### Q2：风险等级是怎么划分的？
**A**：LOW（≥80，绿）、MEDIUM（60-80，黄）、HIGH（40-60，橙）、EXTREME（<40 或一票否决，红）、UNKNOWN（数据不足，灰）。一票否决场景（如盗图确认、严重损坏）直接判定为 EXTREME。

### Q3：数据质量分级 full/partial/insufficient 是什么意思？
**A**：`full` 表示 4 维数据均有效，评估可信；`partial` 表示 1-2 维有效，评估仅供参考；`insufficient` 表示仅价格维度有效，建议触发官方采集补充数据。

### Q4：官方采集会采集哪些数据？
**A**：采集商品详情（detail）、卖家主页（profile）、卖家评价（reviews）三类数据，合并后重新计算 4 维评分，并将 `data_quality` 升级为 `full`。

### Q5：Cookie 同步检查的 440/403/441 分别是什么意思？
**A**：440 表示 Cookie 过期，需重新导入浏览器 Cookie；403 表示 Cookie 缺失关键字段（cookie2/sgcookie/unb）；441 表示触发验证码，需等待或切换账号。

### Q6：AI 评估包含哪些能力？
**A**：包含成色评估（基于 6 类关键词库：newness/newness_worn/used/worn/broken/completeness）和深度多模态鉴伪（盗图检测/损坏检测/一致性检测/模板检测）两大引擎。

### Q7：成色判断的关键词库有哪些？
**A**：6 类关键词库：`newness`（全新）、`newness_worn`（几乎全新）、`used`（使用过）、`worn`（磨损）、`broken`（损坏）、`completeness`（完整性）。每类包含同义关键词列表，用于匹配商品标题与描述。

### Q8：阈值建议是怎么计算的？
**A**：基于任务近 30 天评估分布直方图，计算不同阈值下的通过率与误判率，寻找帕累托最优点作为建议阈值，并给出该阈值下的预期通过率。用户确认后可一键应用到任务配置。

### Q9：评估反馈有什么用？
**A**：用户通过反馈表单标记评估结果正确或错误，反馈数据用于模型优化，持续提升评估准确率。反馈记录会关联到评估 ID，便于后续分析。

### Q10：可以批量重新计算评估吗？
**A**：可以。调用 `/api/evaluations/recompute` 接口，支持按 `task_id` 或指定 `ids[]` 数组批量重新计算。该接口异步执行，返回 `job_id` 用于查询进度。
