## 1. 项目概述

### 1.1 项目背景

闲鱼（Goofish）作为国内最大的二手交易平台之一，存在大量低价优质商品，但因信息更新快、竞争激烈，普通用户难以实时监控并抢到心仪商品。本项目旨在构建一套**自动化闲鱼捡漏与抢单系统**，通过浏览器自动化、反检测技术、智能评估、多渠道通知、智能客服和移动端访问能力，帮助用户在秒级内发现并抢购目标商品，并支持远程运维与团队协作。

### 1.2 项目目标

| 编号 | 目标 | 指标 |
|------|------|------|
| G1 | 自动发现低价商品 | 从上架到通知 < 60 秒 |
| G2 | 4 维卖家评估 | 职业卖家识别、信用资质、历史纠纷、价格异常 |
| G3 | 第一时间抢单 | 从评估通过到下单 < 10 秒 |
| G4 | 即时通知 | 多渠道推送延迟 < 30 秒 |
| G5 | 多用户隔离 | 每用户独立 Cookie/任务/数据 |
| G6 | 智能客服辅助 | 文档问答 + 任务状态查询 + 异常排查 |
| G7 | 移动端访问 | 4G 首屏 < 1.5s，SSE 延迟 < 2s |

### 1.3 核心能力

- **多任务并发监控**：支持关键词、价格区间、地域、闲鱼筛选标签、任务级配置覆盖
- **智能反检测**：stealth 脚本注入、awsc 签名伪造、Beta 分布延迟、贝塞尔曲线鼠标轨迹、QPS 限流、WAF 熔断
- **4 维卖家评估**：加权评分 + 一票否决 + 防高分掩盖，识别职业卖家与高风险卖家
- **自动抢单**：并发安全、内存+DB 双层幂等、价格容差校验
- **多渠道通知**：Server酱、PushPlus、Bark、Telegram、企业微信、钉钉、Ntfy、Webhook（8 渠道）
- **统一 Web 控制台**：FastAPI + React 18 SPA（AntD 5）+ htmx + Alpine.js 双前端，SSE 实时推送
- **AI 增强**：自然语言建任务、多模态成色评估、深度图片分析、智能客服（RAG + Agent）
- **多账号轮换**：账号池 + 代理池 + Cookie 三层状态机
- **多用户体系**：身份识别、会话签发、滑动续期、用户级数据隔离
- **反爬登录管理**：登录后自动启动会话、TokenRenewer 后台续期、Cookie 三层失效联动
- **批量采集与刷新**：APScheduler + asyncio 调度，重试 + 熔断 + 进度持久化
- **多 Sheet 页工作区**：桌面端可同时打开多个工作面板，URL 双向同步
- **Cloudflare Tunnel 远程访问**：内置零配置内网穿透
- **移动端 PWA**：响应式布局、TabBar 导航、关键功能移动化
- **About 菜单**：版本信息 + GitHub Releases 检查更新 + 开源软件声明

### 1.4 用户角色

### 2.1.1 双前端共存策略

系统同时维护两套前端，通过路由前缀隔离，互不干扰：

| 前端 | 路径 | 技术栈 | 定位 |
|------|------|--------|------|
| 旧版控制台 | `/*` | htmx + Alpine.js + Jinja2 | 实时监控、SSE 日志流、抢单记录浏览 |
| SPA 可视化控制台 | `/app/*` | React 18 + AntD 5 + Vite | 配置可视化编辑、拖拽交互、实时预览、多 Sheet 工作区 |
| 移动端 PWA | `/app/mobile/*` | React 18 + 移动端 layout 组件 | 远程查看、轻量操作、PWA 安装 |

**集成方式**：
- SPA 构建产物输出到 `src/xianyu_hunter/web/static/spa/`
- FastAPI 在 `create_app()` 中挂载 `/app/assets` 静态资源
- `/app/{full_path:path}` catch-all 路由服务 `index.html`，由 React Router 处理客户端路由
- `/app/` 加入认证白名单（页面可加载），API 调用仍需 Bearer Token
- SPA 通过 Axios `withCredentials: true` + Bearer Token 复用旧版认证体系
- PWA 使用 VitePWA + workbox（排除 SSE/auth/export）

**构建命令**：
```bash
cd frontend
npm install
npm run build    # 输出到 ../src/xianyu_hunter/web/static/spa/
```

### 2.2 依赖注入容器（Composition Root）

系统通过 `container.py` 中的 `Container` dataclass 作为**组合根**，集中管理所有单例依赖的构造与注入：

```python
@dataclass
class Container:
    config: AppConfig
    repo: Repository
    event_bus: EventBus
    browser: Any | None              # BrowserManager（with_browser=False 时为 None）
    antidetect: AntiDetect | None
    collector: Collector | None
    dedup: ItemDedup | None
    price_strategy: PriceStrategy | None
    evaluator: Evaluator | None
    buyer: Buyer | None
    notifier_hub: NotifierHub
    scheduler: TaskScheduler
    browser_lock: PriorityBrowserLock  # 优先级浏览器锁（Worker vs live 端点）
    chatbot: Any | None              # 智能客服子容器（可选依赖缺失时 None）
```

**关键设计决策**：
- **优先级浏览器锁（PriorityBrowserLock）**：high 优先级（live 端点）请求优先获取锁，low 优先级（Worker）请求主动让出。live 端点锁竞争从 5-10s 降至 1-3s
- **`with_browser=False` 模式**：Web 进程跳过浏览器启动，节省内存（约 200MB/实例）
- **`wire_notifier`**：将 NotifierHub 订阅到 EventBus，实现事件驱动的通知推送
- **智能客服子容器**：独立函数 `_build_chatbot_container()`，可选依赖（chromadb/sentence-transformers）缺失时返回 None 不影响主系统
- **任务级配置覆盖**：`build_worker_from_raw_task()` 统一 CLI 与 Web 的 Worker 构造逻辑，支持 search_config / price_config / eval_config JSON 覆盖

### 2.3 数据流

```
用户创建任务
    ↓
TaskScheduler 按 cron 调度（或 useAutoLiveSearch 自动实时搜索）
    ↓
TaskWorker.run_once()
    ├──→ Collector.search()        搜索商品列表
    ├──→ Dedup.filter()            去重（task_links 表）
    ├──→ Collector.detail()        拉取商品详情
    ├──→ Collector.seller_profile() 拉取卖家画像
    ├──→ PriceStrategy.check()     价格策略过滤（任务级 + 全局）
    ├──→ Evaluator.evaluate()      4 维卖家评估
    ├──→ Buyer.buy()               自动抢单（mode=auto）
    │     └──→ 发布 BUY_SUCCEEDED 事件
    └──→ NotifierHub.fan_out()     多渠道通知
              ↓
          EventBus（基于 asyncio.Queue）
              ↓
          ┌──── SSE Stream（推送到前端）
          ├──── DB 持久化（events 表）
          └──── NotificationEngine（业务通知规则：OrderTimeoutRule / AuthDownRule）
```

### 2.4 事件驱动架构

系统通过 `EventBus`（基于 `asyncio.Queue`）实现模块间解耦：

- **生产者**：Collector、Evaluator、Buyer、Scheduler、Chatbot 等业务模块
- **消费者**：NotifierHub（推送通知）、SSE Stream（推送到前端）
- **持久化**：所有事件写入 `events` 表，支持断线回放
- **异常隔离**：`_safe_call` 捕获所有订阅者异常，避免单点故障扩散
- **事件类型**：主系统 22 种 + 智能客服 13 种，命名约定 `domain.action`（如 `task.started`、`chatbot.session.created`）

### 2.5 多用户体系（MU1 + MU2）

从 0.3.0 版本起引入多用户隔离体系：

- **6 张多用户 ORM 表**：用户表、会话表、用户偏好、登录审计、Cookie 元数据等
- **UserManager**：身份识别 `identify_or_create`、会话签发 `issue_session`、滑动续期 `verify_session`、会话注销 `revoke_session`、用户列表/状态切换/删除/账号探测等
- **数据迁移**：`migrate_to_multi_user` 启动时自动迁移历史 Cookie 与任务到默认用户
- **CookieStore 用户隔离**：按 `user_id` 维度隔离 JSON 文件与内存缓存
- **认证中间件三路校验**：WEB_TOKEN 直通 + session_token 校验 + 401 降级，注入 `user_id` 到 `RequestContext`
- **向后兼容**：`cookie_inject` / `auth_query` 调用自动补充 `user_id=default`

### 2.6 智能客服子模块

智能客服是基于 RAG（检索增强生成）+ Agent 架构的子系统，复用主系统的 DI 容器、AI 用量统计、事件总线、认证、Prompt 热更新能力：

```
┌──────────────────────────────────────────────────────────┐
│  Web 层（web/routes/api_chatbot.py · api_kb.py）          │
├──────────────────────────────────────────────────────────┤
│  业务模块层（modules/chatbot/）                            │
│  orchestrator · rag_engine · agent · intent_classifier    │
│  kb_manager · faq_matcher · context_manager · escalation  │
│  tools/ (task_status · eval_score · config_value · error_logs)
├──────────────────────────────────────────────────────────┤
│  基础设施层（infra/）                                      │
│  embedding · vector_store · repo_chatbot                  │
│  (复用) ai_usage · event_bus · logger · auth              │
├──────────────────────────────────────────────────────────┤
│  数据层                                                    │
│  SQLite (chatbot_*) · ChromaDB (xianyu_hunter_docs)       │
└──────────────────────────────────────────────────────────┘
```

**核心能力**：
- **RAG 检索**：本地 sentence-transformers（BAAI/bge-small-zh-v1.5, dim=512）embedding + ChromaDB 向量库
- **Agent 工具调用**：task_status（任务状态查询）、eval_score（评估打分）、config_value（配置值查询）、error_logs（错误日志查询）、help_page（帮助页跳转）
- **意图分类**：基于 LLM 分类 FAQ / 工具调用 / RAG / 转人工
- **FAQ 匹配**：embedding 相似度匹配预置 FAQ
- **转人工**：会话超时自动转人工（首版仅记录）
- **知识库管理**：白名单目录（.md/.py/.jsonl/.txt，排除 web/static/、web/templates/、__pycache__/、node_modules/、.git/、dist/、build/），KBRefreshScheduler 周期刷新
- **安全护栏**：sanitizer 模块对用户输入进行脱敏，防 prompt injection

## 4. 核心功能设计

### 4.1 任务调度（F-15）

**设计目标**：支持多任务并发调度、Cron 表达式、任务依赖触发、连续失败自动暂停、任务级配置覆盖。

**核心类**：`TaskScheduler`

**关键设计**：
- `_run_lock`：全局并发锁，串行化 `run_once` 避免多窗口弹出
- `_workers_lock`：字典并发保护锁，保护 `_workers` 字典
- `_WorkerHandle`：单任务运行时句柄
- **F-16 依赖触发**：上游任务成功后自动激活下游 paused 任务
- **P1-7 Cron 模式**：按 `Task.cron` 表达式计算下次运行时间
- **useAutoLiveSearch**（前端）：任务自动实时搜索，支持倒计时、页面可见性感知、并发控制
- **TaskSchedulerConfig**：全局默认 `default_interval_seconds` / `auto_search_enabled` / `auto_search_concurrency`，支持任务级覆盖
- **连续失败保护**：连续失败 10 次自动暂停任务

**任务状态机**：

```
created → running ⇄ paused
              ↓
          stopped
              ↓
           deleted
```

**任务模式（TaskMode）**：

| 模式 | 行为 |
|------|------|
| `AUTO` | 全自动抢单 |
| `SEMI_AUTO` | 通知 + 自动抢单（需确认） |
| `CONFIRM` | 通知 + 人工确认 |
| `NOTIFY_ONLY` | 仅通知 |

### 4.2 数据采集（F-2 + 统一采集服务）

**设计目标**：高效采集闲鱼商品搜索结果、详情、卖家画像，统一封装便于实时搜索/批量采集复用。

**核心类**：`Collector`、`CollectionService`

**关键技术**：
- **route 拦截**：通过 Playwright `page.route` 拦截 mtop API 响应，直接解析 JSON
- **DOM 回退**：API 拦截失败时回退到 DOM 选择器解析
- **会话失效检测**：检测 `RGV587_ERROR`，触发登录态恢复
- **窗口复用**：单个详情页 + 单个卖家页复用（窗口数从 6 降到 2）
- **统一采集服务**：`CollectionService` 聚合 search/detail/seller_profile，复用 + 缓存
- **AWSC 签名伪造**：`AWSCSpoofer` 自动为请求附加 AWSC 签名头

**采集流程**：

```
search(keyword, filters)
    ├──→ page.route 拦截 mtop API
    ├──→ 解析 JSON 响应
    └──→ DOM 回退（API 失败时）

detail(item_id)
    └──→ 导航详情页 → 解析标题/价格/图片/描述

seller_profile(seller_id)
    └──→ 导航卖家主页 → 解析信用/在售/已售/评价
```

### 4.3 批量采集（F-新）

**设计目标**：APScheduler + asyncio 调度批量刷新商品数据，支持重试 + 熔断 + 进度持久化（断点续传）。

**核心类**：`BatchRefreshScheduler`

**关键设计**：
- **断点续传**：批量失败暂停后，恢复时从已持久化进度继续
- **熔断器**：连续失败 3 次触发熔断，剩余项标记为 skipped
- **进度持久化**：写入 `batch_refresh_history` 表
- **失败告警**：通过 `EventBus` 发布 `BATCH_REFRESH_FAILED` 事件

### 4.4 价格策略（F-3）

**设计目标**：支持多种价格过滤策略，精准识别低价商品，支持任务级覆盖。

**核心类**：`PriceStrategy`

**4 种策略**：

| 策略 | 描述 | 适用场景 |
|------|------|----------|
| 硬性上限 | `price <= max_price` | 预算控制 |
| 硬性下限 | `price >= min_price` | 防低价陷阱 |
| 低于市场参考价 | `price < market_median * ratio` | 捡漏识别 |
| 同类低价 TopN | `cheaper_count < N` | 竞争力排序 |

**MarketContext**：市场参考上下文，包含中位数和所有价格列表，用于"低于市场参考价"策略。

**任务级覆盖**：`build_task_price_strategy()` 支持 task.min_price/max_price 优先，None 时从 task.price_config JSON 取，都为 None 时沿用全局。

### 4.5 卖家评估（F-4）

**设计目标**：4 维加权评分 + 一票否决，识别职业卖家与高风险卖家。

**核心类**：`Evaluator`

**4 维评分模型**：

| 维度 | 权重 | 评估内容 |
|------|------|----------|
| 职业卖家识别 | 30 分 | 在售数、30 天发帖数、主营品类集中度、盗图检测 |
| 信用与资质 | 30 分 | 信用分、注册天数、实名认证 |
| 历史纠纷 | 25 分 | 差评数、纠纷率 |
| 价格与竞价异常 | 15 分 | 低价异常、想要数异常 |

**一票否决条件**：
- 卖家在黑名单中
- 信用分 < 600

**防高分掩盖机制**：`final_score = min(dimension_scores) + 40`，避免单维度满分掩盖其他维度低分。

**风险等级**：

| 等级 | 分数范围 | 处理 |
|------|----------|------|
| low | ≥ 80 | 自动通过 |
| medium | ≥ 60 | 通过（可配置） |
| high | ≥ 40 | 需人工确认 |
| extreme | < 40 | 自动拒绝 |

**重要细节**：Evaluator 不在构造时缓存配置阈值，每次 `evaluate()` 从 `get_config()` 实时读取，确保用户在配置页面修改 pass_score/auto_buy_score 后立即生效。

### 4.6 自动抢单（F-5）

**设计目标**：秒级抢单，并发安全，幂等保证。

**核心类**：`Buyer`

**关键设计**：
- **并发安全**：`_lock` 串行锁，避免同一商品被多次购买
- **内存幂等**：`_task_item_set` 记录已购买的 (task_id, item_id)
- **DB 幂等**：订单表唯一约束
- **价格容差校验**：下单前校验实际价格与预期价格偏差
- **接管超时**：`TakeoverTimeoutScheduler` 监控接管订单超时未支付

**抢单流程**：

```
buy(task_id, item_id)
    ├──→ 检查幂等（内存 + DB）
    ├──→ 导航商品详情页
    ├──→ 点击"立即购买"
    ├──→ 等待"提交订单"按钮
    ├──→ 提取订单号
    ├──→ 价格容差校验
    └──→ 发布 BUY_SUCCEEDED / BUY_FAILED 事件
```

### 4.12 反爬登录管理（F-反爬）

**设计目标**：登录产生的 Cookie 不能一次使用就失效，需要由 `TokenRenewer` 后台持续续期 `_m_h5_tk`，否则实时搜索/详情采集会被闲鱼重定向到首页。

**核心模块**：

| 模块 | 职责 |
|------|------|
| `modules/login_orchestrator.py` | 登录协调器。聚合 `TokenRenewer` / `CookieRotator` / `SessionHealthChecker` |
| `modules/token_renewer.py` | TokenRenewer 后台续期循环，封装 cookie_provider + renew_callback |
| `modules/cookie_rotator.py` | 多层 Cookie 管理（identity / session / fingerprint），支持按层失效 |
| `modules/session_health.py` | SessionHealthChecker 健康检查（按 checker 注册，按需触发） |
| `web/services/session_starter.py` | 登录入口共享的 `trigger_session_start()` helper（fire-and-forget） |
| `web/routes/api_anticrawl.py` | 反爬管理 API（`/api/anticrawl/session/*` 等） |
| `frontend/src/pages/AntiCrawl/index.tsx` | 反爬登录管理 SPA 页面 |

**会话状态机**：
```
inactive ──start_session()──▶ active
   ▲                            │
   └────────stop_session()──────┘
```

**关键设计**：
- **登录后自动启动会话**：用户在反爬登录管理菜单原本需要手动点击"启动会话"按钮，登录成功后改为自动调起。覆盖 4 个登录入口：
  - 统一登录 `unified_login.py`（3 处成功路径）
  - 旧版浏览器登录 `browser_login.py`（1 处）
  - 浏览器导入 `browser_import.py`（1 处）
  - Cookie 注入 `cookie_inject.py`（2 处）
- **fire-and-forget 调度**：`asyncio.ensure_future()` 调度到 FastAPI 主事件循环
- **失败安全**：自动启动失败仅记录 debug 日志，不影响登录返回
- **Cookie 层失效联动**：续期失败回调自动调用 `CookieRotator.invalidate_layer(SESSION)`
- **5 分钟冷却**：会话过期暂停后 5 分钟内禁止重复恢复，避免雪崩

### 6.2 关键技术决策

#### 6.2.1 为什么选择 Playwright 而非 Selenium？
- 现代 API：async/await 原生支持
- CDP 模式：可连接系统 Edge，指纹最真实
- 稳定性：自动等待机制
- 生态：Microsoft 维护

#### 6.2.2 为什么选择 SQLite 而非 PostgreSQL？
- 单机部署：项目定位为个人工具
- 零配置：无需安装数据库服务
- WAL 模式：支持并发读写
- 性能：单机场景下性能优于 PostgreSQL

#### 6.2.3 为什么选择 htmx + Alpine.js + React SPA 双前端？
详见 §2.1.1 双前端共存策略。

#### 6.2.4 为什么选择 ChromaDB？
- 轻量：嵌入式向量库，无需独立服务
- 持久化：本地文件存储
- 集成简单：与 sentence-transformers 搭配直接可用

#### 6.2.5 为什么选择 Cloudflare Tunnel？
- 零配置：用户无需自备 frp/ngrok
- 免费：基础域名免费
- 稳定：Cloudflare CDN 网络支撑
- HTTPS：自动配置证书

## 7. 开发规范

### 7.1 代码规范

#### 7.1.1 Python 代码规范
- **PEP 8**：遵循 PEP 8
- **类型提示**：所有公开函数必须添加类型提示
- **docstring**：模块/类/公开函数必须添加 docstring
- **注释原则**：解释"为什么"而非"做什么"
- **异步优先**：I/O 操作使用 async/await
- **f-string**：字符串格式化优先 f-string

#### 7.1.2 目录规范
- `src/xianyu_hunter/`：主源码
- `tests/`：测试代码
- `docs/`：文档
- `config/`：配置文件
- `data/`：运行时数据
- `scripts/`：辅助脚本

### 7.2 安全规范
- **Token 比较**：`hmac.compare_digest()` 防时序攻击
- **敏感字段**：不记录 token 长度等敏感信息
- **401 响应**：返回 JSON `{"detail": "Unauthorized"}`
- **前端请求**：必须 `credentials: 'include'`
- **htmx 凭证**：使用官方 `<meta>` 配置
- **认证白名单**：`/api/auth/*`、`/api/events/stream`、`/api/notifications`、`/api/notifier/`、`/api/about`、`/api/import-from-browser/status` 等
- **路径遍历防护**：`_cookie_json_path` 等路径构造必须验证
- **GitHub API 零隐私**：HTTP 头仅含 User-Agent + Accept

### 7.3 数据库规范
- **时区**：所有 datetime 列统一 UTC
- **索引**：`task_id`、`seller_id`、`first_seen`、`publish_time`、`created_at` 必须有索引
- **复合索引**：Dashboard 核心查询路径必须有复合索引
- **COUNT 查询**：`_overview()` 中使用 CASE WHEN 聚合
- **WAL 模式**：SQLite 必须启用 WAL + 外键约束 + StaticPool + busy_timeout
- **删除任务**：级联删除关联数据
- **多用户隔离**：所有 Repository 查询按 `user_id` 过滤

### 7.4 浏览器规范
- **WebView2 子进程**：`CREATE_NEW_CONSOLE` 而非 `CREATE_NO_WINDOW`
- **stdout/stderr**：不重定向到 DEVNULL
- **private_mode**：`webview.start()` 必须 `private_mode=False`
- **storage_path**：唯一 `webview_data_{pid}_{timestamp}`
- **进程清理**：`_cleanup_orphan_processes` 清理残留 msedge
- **Web 进程模式**：`with_browser=False` 节省内存

### 7.5 启动钩子规范
- **`_on_startup` / `run_migrations` / `_init_*`** 等关键路径的 `except` 必须用 `logger.exception()` 输出完整 traceback
- **`run_migrations()` 多个独立迁移块（C-01~C-05）必须各自 try/except**（强依赖场景如表重建+数据回填允许合并，但注释中必须说明合并原因）

### 7.6 智能客服规范
- **KBManager `_scan_and_chunk` 白名单**：只索引 `.md/.py/.jsonl/.txt`，排除 `web/static/`、`web/templates/`、`__pycache__/`、`node_modules/`、`.git/`、`dist/`、`build/`
- **本地 embedding**：`local_embedding.py` 顶部 `os.environ.setdefault("HF_ENDPOINT", "https://hf-mirror.com")`
- **sentence-transformers 5.x**：`getattr(model, 'get_embedding_dimension', ...)` 兼容旧 API
- **可选依赖降级**：chromadb / sentence-transformers 缺失必须 `logger.info` 而非 `logger.exception`（合法降级状态）

### 7.7 跨模块规范
- **Vision 能力检测**：使用 `api_ai.py` 的共享 `_is_vision_capable(model_name)` 函数
- **Vision 关键字集中**：`_VISION_CAPABLE_KEYWORDS` 元组在 `api_ai.py`
- **Cookie 状态恢复前置校验**：TokenRenewer 启动前必须校验 Cookie 三层状态
- **降级链日志合并**：连续降级场景必须合并日志，避免淹没

### 7.8 测试规范
- 测试框架：pytest + pytest-asyncio
- 测试覆盖：核心业务模块必须有单元测试
- 测试命名：`test_{函数名}_{场景}`
- 测试隔离：每个测试用例独立数据库/临时目录

- 移动端 PWA：`http://127.0.0.1:8000/app/mobile/`
- Swagger API 文档：`http://127.0.0.1:8000/api/docs`
- 远程访问（如开启 Tunnel）：Cloudflare 临时 HTTPS 域名

### 8.5 配置管理
- `config/config.yaml`：主配置
- `.env`：环境变量
- `config/eval.yaml`：评估配置
- 配置热更新：YAML `reload_config()`
- 备份：自动保留最近 10 个版本

### 8.6 日志管理
- **日志框架**：loguru
- **日志轮转**：按大小（默认 10MB）
- **日志保留**：最近 7 天
- **结构化日志**：events 表 + error_logs 表
- **request_id 全链路追踪**：每个请求分配流水号

### 8.7 数据备份
- 数据库备份：定期复制 `data/xianyu.db`
- Cookie 备份：`data/cookies.json`（按 user_id 隔离）
- 配置备份：`config/backups/`
- Prompt 备份：`data/prompts/`
- 向量库备份：`data/chroma/`

### 8.8 监控与运维

#### 8.8.1 健康检查
- Web 服务：`GET /healthz` 返回 200 + 检查项
- 调度器：Dashboard 顶栏状态指示灯
- 登录态：`GET /api/auth/me`

#### 8.8.2 异常告警
- 业务通知引擎：订单超时、登录态失效
- WAF 熔断器：自动检测风控
- 连续失败 10 次：自动暂停任务

#### 8.8.3 性能优化
- SQLite WAL 模式 + StaticPool
- COUNT 查询合并（CASE WHEN）
- 窗口复用
- SSE 连接数限制（10）
- Web 进程 `with_browser=False`
- 浏览器优先级锁（live 优先）

## 9. 潜在风险与应对措施

### 9.1 技术风险

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|----------|
| 闲鱼 WAF 风控升级 | 采集失败 | 高 | stealth 持续更新、WAF 熔断、多账号轮换、AWSC 伪造 |
| 闲鱼页面结构变更 | 采集失败 | 中 | selectors.py 集中管理、DOM 回退 |
| Playwright 版本不兼容 | 启动失败 | 低 | 锁定版本 |
| SQLite 并发瓶颈 | 写入失败 | 低 | WAL、StaticPool、busy_timeout |
| 内存泄漏 | 长期 OOM | 中 | 定期重启、with_browser=False |
| HuggingFace 超时 | embedding 失败 | 中 | HF_ENDPOINT 镜像、本地模型兜底 |
| ChromaDB 损坏 | 智能客服不可用 | 低 | 重置 API + 定期重建 |

### 9.2 业务风险

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|----------|
| 误判高价商品为低价 | 资金损失 | 中 | 价格容差、确认模式、阈值可配 |
| 抢到欺诈商品 | 资金损失 | 中 | 4 维评估、一票否决、AI 多模态 |
| 账号被封禁 | 无法操作 | 高 | 多账号轮换、代理、反检测 |
| 重复下单 | 资金损失 | 低 | 内存 + DB 双层幂等 |
| 登录态失效 | 采集中断 | 高 | TokenRenewer 续期、自动告警、多方式登录 |

### 9.3 多用户与安全风险

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|----------|
| 用户数据越权 | 隐私泄露 | 低 | Repository 强制 user_id 过滤 |
| Token 泄露 | 未授权访问 | 中 | hmac.compare_digest、敏感字段不日志、keyring |
| Cookie 泄露 | 账号被盗 | 中 | JSON 文件权限、按 user_id 隔离 |
| 路径遍历 | 文件越权 | 低 | _cookie_json_path 校验 |
| 智能客服 prompt injection | 异常输出 | 中 | sanitizer 模块 |

### 9.4 运维风险

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|----------|
| 磁盘空间不足 | 服务崩溃 | 中 | 日志轮转、定期清理、监控 |
| 数据库损坏 | 数据丢失 | 低 | 定期备份、WAL、事务 |
| 进程异常退出 | 服务中断 | 中 | 进程监控、自动重启、错误日志 |
| 网络中断 | 采集失败 | 中 | tenacity 重试、超时控制 |
| 配置误修改 | 服务异常 | 中 | 配置备份、dry_run、回滚 |

### 9.5 法律合规风险

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|----------|
| 违反闲鱼用户协议 | 账号封禁 | 高 | 反检测、合理频率、确认模式 |
| 自动化抢单合规性 | 法律风险 | 中 | 仅个人监控、不批量 |
| 数据隐私 | 法律风险 | 低 | 本地部署、不分享 |

### 9.6 应急预案

#### 9.6.1 WAF 触发
1. WAF 熔断器自动触发
2. 发布 `WAF_BLOCKED` 事件（critical）
3. 多渠道推送告警
4. 等待冷却（默认 30 分钟）
5. 定时尝试恢复

#### 9.6.2 登录态失效
1. 检测 `RGV587_ERROR` 或 Cookie 失效
2. 发布 `AUTH_EXPIRED` 事件
3. 推送告警
4. 5 分钟冷却（防雪崩）
5. 等待用户重新登录
6. 登录后自动启动会话

#### 9.6.3 智能客服降级
1. KB 缺失 → 提示用户重建知识库
2. LLM 失败 → FAQ 匹配 + 规则回退
3. Embedding 失败 → keyword 检索回退
4. 发布 `chatbot.degraded` 事件
