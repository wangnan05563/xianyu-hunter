> 评估范围：Web UI 全量页面 + 关键交互流程 + 已有 v1/v2/v3 优化项落地追踪
> 评估方法：界面走查 + 流程推演 + 行业最佳实践对照 + HEART 框架打分
> 受众：产品 / 前端 / 后端 / 用户本人

## 摘要：5 个核心判断

1. **系统已从"可看"升级为"可运营"，并完成 React SPA 重构**。Dashboard、通知中心、接管 Modal、移动端 PWA 已落地，高频用户的"异常巡检"和"批量管理"操作路径已大幅缩短。
2. **数据可视化已从"静态分布"升级为"趋势 + 对比基线"**。价格直方图、评估分布直方图、价格趋势对比基线、评估漏斗、业务 KPI 均已落地。
3. **键盘 / Command Palette 已落地，高频用户效率显著提升**。`Ctrl/Cmd+K` 全局命令面板 + `g d/t/o/c/l/a` 跳转 + `j/k` 时间线翻页已实现。
4. **任务管理"主战场"已补齐批量操作、模板、导入导出**。任务列表批量操作、任务模板市场（F-11）、任务依赖（F-16）、配置导入导出 + diff + 回滚均已落地。
5. **可观测性已升级为"业务指标 + 评估漏斗 + 配置变更追踪"三层**。用户改阈值后能量化"改对了还是改错了"。

## 3. 目标用户与使用场景

### 3.1 核心用户画像

> 来源：requirements.md §3.1 + design.md §6.1

- **唯一画像**：懂技术、有研究、对二手商品有追求的中文个人买家
- **技术能力**：能在 Windows 跑 Python / Node、能配推送 Key、能理解"职业卖家 / 黑名单"

  - 抢到低价优质商品的窗口期 < 60s

## 4. 优化需求清单（按 P0/P1/P2 排序）

> **校准说明**：原文档列出 30 项优化（UX-01 ~ UX-20）+ 11 项新增功能（F-AI1 ~ F-EX4），其中 32 项已在 Sprint A-E + 后续迭代中实现。本节仅保留未实现项 + 新架构下的新需求。

### 4.1 P0（1-2 周内做）：解决"长尾体验问题"

#### UX-01 接管 Modal 自动关闭 done 阶段

- **现状**：`frontend/src/pages/Orders/Orders.tsx` 接管 Modal 在"已完成"阶段需手动点"完成"
- **需求**：done 阶段 3s 后自动关闭（用 `setTimeout`），鼠标移入时清除定时器
- **预期效果**：少 1 次点击 + 不打扰

#### UX-02 草稿恢复取消时"是否保留草稿"二次确认

- **现状**：`frontend/src/pages/Tasks/TaskEditor.tsx` 取消时直接关闭 = 草稿失效
- **需求**：取消时弹 Ant Design `Modal.confirm` 询问"是否保留草稿"
- **预期效果**：避免误取消丢失草稿

#### UX-03 评估明细 / 抢单记录空态文案补"如何加速"提示

- **现状**：空态文案仅"任务运行后会逐步出现"
- **需求**：加"如何加速"链接 → 跳到帮助文档对应章节
- **预期效果**：新用户不迷茫

### 4.2 P1（1 个月内做）：解决"高级可观测性 + 协作"

#### UX-04 沉默任务检测 + 推送

- **需求**：自动发现"配置后从未触发 / 触发但无命中"的任务，提醒用户清理
- **实现**：每日 cron 扫 `tasks LEFT JOIN events ON task_id AND created_at > 7d` → 推 1 条"以下任务 7 天无活动：xxx [停用 / 调整]"
- **预期效果**：用户对"哪些任务还活着"一目了然

#### UX-05 操作审计日志

- **需求**：记录"谁 / 何时 / 改了什么配置 / 启停了什么任务"
- **实现**：后端在 `tasks`、`config` 表加 `updated_by` + `audit_log` 表
- **预期效果**：误操作可追溯、解决"我刚才是不是改了什么"的疑惑

#### UX-06 配置变更影响追踪

- **需求**：调高 pass_score 后，对比"调整前 7 天 vs 调整后 7 天"的通过率
- **实现**：每次配置保存记录"变更前 7 天均值"，30 天后展示对比
- **预期效果**：避免"改了反而更差"的情况

#### UX-07 时间线键盘 j/k 翻页

- **现状**：`frontend/src/pages/Timeline/` 仅鼠标操作
- **需求**：`j/k` 上下选中条目，`Enter` 查看详情
- **预期效果**：高频用户排查故障效率 +50%

#### UX-08 智能通知聚合

- **需求**：连续 10 条"评估通过"推送时，合并为 1 条摘要
- **实现**：Notifier 加 `aggregation_window_min` 配置 + 摘要模板
- **预期效果**：通知渠道不被刷屏

### 4.3 P2（远期规划）：解决"个性化 + 协作"

#### UX-09 Dashboard 拖拽布局 + 阈值告警

- **需求**：
  - 用户可拖拽统计卡顺序 + 隐藏不常用的卡
  - 配置阈值（如"今日失败订单 > 3 自动 banner 告警"）
- **实现**：用 `@dnd-kit`（已在前端依赖中）+ 配置存到 localStorage
- **预期效果**：每个用户的 Dashboard 个性化

#### UX-10 团队共享 Dashboard（可选）

- **需求**：硬核用户邀请 1-2 个朋友共用一个 Dashboard（"看今天又捡了什么"）
- **实现**：后端加 `share_token` + read-only 路由
- **预期效果**：增加"晒战绩"动力，间接促活

#### UX-11 个人战绩卡（分享图）

- **需求**：月底生成"本月捡漏报告"（成功 N 单 / 节省 ¥X / 最高评分 Y）
- **实现**：每月 1 日 cron 生成 HTML 截图，前端可下载或分享
- **预期效果**：增加用户成就感与社交传播
