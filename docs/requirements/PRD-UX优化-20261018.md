## 1. 背景

T02324 对 31 条路由页面做了逐菜单六维度 UX 评审，产出 200 条优化建议。T02335 复核发现：建议里真正致命的三个**根因级缺陷**（订单状态字面值前后端不一致、价格行情/数据导出「已注册但无路由」、菜单读写契约不匹配）被拆散成了十几条症状级建议；同时 5 条建议前提不成立、15 条建议的前置其实是设计决策。

本 PRD 按**评审后的裁决**组织需求：先修根因与发布阻断，再收可达性与失败态，然后统一口径，最后做结构性打磨。

## 2. 目标与成功指标

### 2.1 产品目标

- **G1 让核心链路可信**：待处理订单可见可接管、导出结果与筛选一致、清理/删除操作不再假成功。
- **G2 消灭死入口**：任何可见菜单项点击后都到达实现页面；任何按钮都不出现「点了没反应」。
- **G3 统一双模型与口径**：通知/告警只有一套计数与已读语义；统计数字只有一套字面值来源。
- **G4 消除虚假承诺**：UI 不再展示后端不存在的配置项或能力。

### 2.2 成功指标（发布后验证）

| 指标 | 现状 | 目标 |
|---|---|---|
| 可见菜单项点击后落到实现页的比例 | 29/31（价格行情、数据导出被送回首页） | 31/31 |
| 「待处理」订单卡数值与真实 `pending_pay` 行数一致 | 恒 0 | 一致（自动化断言） |
| 导出结果行数 = 筛选预期行数 | 不可判定（level 字面值错） | 一致，0 行时不弹成功 |
| UI 展示的、后端无实现的能力项 | ≥1（单日抢单上限） | 0（grep + 契约测试锁住） |
| 前端 API 请求体与后端 schema 不匹配的端点 | ≥1（`PUT /api/menu` 必 422） | 0（契约测试覆盖菜单/配置/导出） |
