## 关键经验（可复用）

### 1. Windows Git Bash 下 `du -sh` 极慢，改用 Python os.scandir
- `du -sh` 遍历根目录：**15 分钟未完成**（176k 文件，主要是 `.venv`/`.venv-build`/`node_modules`/`.git`）
- `os.scandir` 栈式遍历：**24 秒**完成全量按目录统计 + 总数
- 脚本模板已留在 `cleanup-logs/_size.py`，同类项目可直接复用

### 2. 删除必须用 `python -S`
项目开启了 safe-delete 钩子（`cleanup-config.yaml: safety.bypass_hook_mode: python_s`），
`rm`/`shutil.rmtree` 会被拦截；`python -S` 绕过 site 加载后原生删除可用。

### 3. 验证时用 `python -B` 避免复发
测 import 会重建 `__pycache__`，抵消清理成果。用 `python -B`（或 `PYTHONDONTWRITEBYTECODE=1`）。

## 追加：修复 workspace-cleanup 技能 + 配置漂移（同日）

### A. workspace-cleanup skill 修复（用户目录，非项目内）

**问题**：`~/.workbuddy/skills/workspace-cleanup/` 下 `SKILL.md` 与 `references/retrospective.md`
存在**双重编码损坏**（UTF-8 内容被误按 CP936 解码后又存为 UTF-8），且内部链接硬编码到
另一个项目（`19_Karpathy-AI+Obsidian知识库/.trae/skills/...`）。

**诊断要点（可复用）**：
- 损坏特征：`工作空间` → `宸ヤ綔绌洪棿`（UTF-8 字节被当 GBK 读）
- `?` 是 ASCII 0x3F —— 代表**字节已永久丢失**，不是可恢复的占位符
- 还有 PUA 区字符（如 `\ue219`）：CP936 解码产生的用户定义区映射，
  **Python 的 gbk/cp936 codec 无法反向编码**，`gb18030` 能编码但会改变字节长度导致错位
- 反向还原：`mojibake.encode('gbk').decode('utf-8')`，遇丢失字节后**对齐会断，再过一段自行重新同步**
  → 实测恢复率约 **62%**，不是 100%
- **结论：这类损坏不可完整机器恢复**，只能部分恢复 + 人工重建

**处理结果**：
- `SKILL.md` → **手工重写**（英文结构 100% 完好，中文含义已可辨），
  并顺带修掉硬编码路径、补入本轮验证到的经验（`python -S` 删/`python -B` 校验/
  scandir 统计/隔离区机制/配置漂移预检/三者 actions：delete·quarantine·review）
- `references/retrospective.md` → 机器恢复 + **文件头加醒目警告横幅**（标注约 62% 可信）
- `decisions.md`、`examples/cleanup-config.example.yaml` → **本来就是干净的**，未动

**顺带发现（已报告，未改）**：另外 3 个技能文件同样损坏，且**原始文件已无法解析**：
`logs-review/config.yaml`、`logs-review/config.example.yaml`、`create-bat/config/traps.md`
—— 这几个的原始文件 YAML 解析就已失败，机器恢复也修不回有效结构，**需人工重建**。
处理原则：超出授权范围 → 已还原为原始文件，只报告不擅自改。

**备份**：`~/.workbuddy/skills/.backup-20260910-mojibake/`（字节级 .orig + `_recover.py`）

### C. 技能文件乱码事故的恢复上限（约 62%，无法 100%）

`SKILL.md` / `references/decisions.md` / `references/retrospective.md` 三份文件为双重编码损坏。
上面记了"诊断"，这里补**为什么救不回来**：

1. CP936 把部分字节对映射到 **PUA 码点**（如 `\ue219`），Python 的 `gbk`/`cp936` codec
   **拒绝反编码**这类码点；

**结论：正确做法是人工重写，不是跑变换。** 字节级备份与恢复脚本留在
`skills/workspace-cleanup/.backup-20260910-mojibake/`（含 README；该目录**刻意不放
`SKILL.md`** —— 放了会被扫描成第二个技能 `workspace-cleanup:.backup-...`，本轮已把里面的
