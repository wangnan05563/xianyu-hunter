## 打包构建报错 "Could not find platform independent libraries <prefix>"

**现象**：双击 `scripts\构建打包.bat` 构建，步骤 [1/6] 报 `python.exe : Could not find platform independent libraries <prefix>`，脚本中止。

**根因**：基础 Python `F:\Program Files\Python3.14` 标准库缺失（`Lib\os.py`、`Lib\site-packages\pip` 均不存在，可能是安装被损坏/部分卸载）。`.venv-build` 的 `pyvenv.cfg` 中 `home = F:\Program Files\Python3.14`，venv 复用该基础 Python 的 stdlib，于是 `python -m pip` 直接抛 `No module named 'encodings'`。基础 python 与 venv python 报错完全一致，确认是基础 Python 本身坏了。

**环境对照**：托管 Python `C:\Users\hspcadmin\.workbuddy\binaries\python\versions\3.13.12` 完好（`os.py` 在、`venv` 模块可用），且是“preferred”运行时；项目 `requires-python = ">=3.10"`，3.13.12 完全支持。

**修复（已实施）**：
1. `scripts/build-exe.ps1` 的 `Test-BuildPip` / `Repair-BuildPip` 增加 `try/catch`：基础 Python 损坏时返回 `$false` 触发重建，而不是抛出 RemoteException 直接中止（之前因 `$ErrorActionPreference="Stop"` 导致硬中止，自愈逻辑不可达）。
2. 重写 `scripts\构建打包.bat`（原文件为 GBK+中文 echo，易踩编码坑）：改为纯 ASCII、无 BOM、CRLF，开头将托管 3.13.12 前置到 PATH（`set "MGPy=...\3.13.12"; if exist ... set "PATH=%MGPy%;%PATH%"`），使 `python -m venv` 使用完好的 3.13.12。中文 echo 转为英文（编码健壮性，符合 create-bat 技能纯 ASCII 规则；如需中文可改回 GBK）。
3. 不再手动删 `.venv-build`：修复后脚本会自愈——检测到 pip 不可用 → 删旧 venv → 用 3.13.12 重建。

**验证**：`.bat` 0 非 ASCII 字节、无 BOM；`.ps1` BOM 保留；下次双击 `构建打包.bat` 即可自动重建 venv 并继续构建。

**备注**：`F:\Program Files\Python3.14` 仍坏在 PATH 中，若用户在别处直接调 `python` 仍会失败；正式修复需重装/修复该 Python，或把它从 PATH 移除。
