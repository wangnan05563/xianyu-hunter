## 启动脚本/切换账户白板问题（已修复）

**现象**：开发模式启动服务后，浏览器自动弹到 `http://127.0.0.1:8001/`（或 `/app/`），点击切换账户后跳回 `/` 显示白板。

**根因**：前端 SPA 挂在 `/xianyu` 子路径下（`vite base:'/xianyu/'` + `BrowserRouter basename="/xianyu"`），但所有「自动打开浏览器」的入口都写成了 `http://127.0.0.1:8001/app/`（启动服务.bat / launcher.py / automation.ps1 / setup-env.ps1）。`/` 与 `/app/` 下 `index.html` 虽返回 200，但路由 basename 匹配不到 → 整页白板。切换账户代码本身正确（用 `BASE_URL`=`/xianyu/`），白板是「入口 URL 错」的连锁表现。

**修复**：把所有自动打开入口 `/app/` → `/xianyu/`（启动服务.bat:147、launcher.py:194/225/273、automation.ps1:291/366/402、setup-env.ps1:583/602），后端 `web` 命令日志也指向 `/xianyu`。

**验证**：用 `--no-with-scheduler` 起 Web 服务（8077 端口）curl 确认 `/xianyu` 返回 200 且 index.html 引用 `/xianyu/assets/index-*.js`（该 asset 也 200）；`/app/`、`/` 同样 200 但无对应路由 → 白板。验证后已关服清日志。

**结论**：用户对「优化启动脚本弹出 /xianyu」的判断正确。入口改对后，切换账户跳转 `/xianyu/` 不再白板；若旧 PWA Service Worker 缓存了旧入口 chunk，需清 SW/硬刷新一次。
