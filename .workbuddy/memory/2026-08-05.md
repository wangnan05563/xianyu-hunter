## 域名模式「请求失败」根因与修复（xianyu 项目）

**现象**：通过生产域名 `https://win-*.ts.net/xianyu/login` 访问，点击"启动浏览器窗口登录"前端报「请求失败」。

**根因**：前端以 `/xianyu/` 子路径部署（vite base + BrowserRouter basename），但所有 API 请求写成根路径 `/api/...`：
- `client.ts` axios `baseURL: ''`，接口用绝对路径 `/api/...`
- 另有 7 处绕过 axios 的原始 `fetch('/api/...')` / `new EventSource('/api/...')`（Login×2、task.ts、Chatbot、Logs、Items/ItemList、Dashboard、Orders）
域名模式下反向代理把整套应用挂在 `/xianyu`，剥离前缀后后端只收 `/xianyu/*`，根路径 `/api/*` 被代理拦截 → 请求到不了后端 → 前端兜底「请求失败」。

**修复（已实施并通过 tsc）**：
1. 新增 `frontend/src/utils/apiBase.ts`：`API_BASE = import.meta.env.BASE_URL`（构建后 `/xianyu/`）。
2. `client.ts`：`baseURL` 改为 `API_BASE`（所有 axios 接口自动带前缀）。
3. 7 处原始 fetch/EventSource 改为 `${API_BASE}api/...`。
4. 后端 `app.py`：在所有 API router 注册后，再以 `prefix="/xianyu"` 重复挂载一份（`/xianyu/api/*`），无论代理是否剥离前缀都能命中；根 `/api/*` 保留，本地打包模式不受影响。
5. `app.py` 登录引导浮层 `fetch('/api/auth/me')` 改为按 pathname 推导 `/xianyu` 前缀。
6. `vite.config.ts` 的 PWA SW：`navigateFallbackDenylist` 与 `runtimeCaching` urlPattern 同步覆盖 `/xianyu/api/`。

**注意**：即便路径修好，"启动浏览器窗口登录"在远程/域名模式下仍无法在用户本机弹窗（Playwright 浏览器起在服务器侧），远程登录应改用 Cookie 注入 / 浏览器导入 / 扫码登录。

**待验证**：实际域名代理是否剥离 `/xianyu` 前缀（决定后端双挂载是否被命中），需用户在目标环境构建部署后实测。
