## 修复：实时搜索 route 拦截 unroute 超时 + TargetClosedError "never retrieved"

### 现象
`/api/tasks/<id>/links` 实时搜索中报错：`page.unroute 超时`（WARNING）+ 两条 `Future exception was never retrieved ... TargetClosedError: Target page, context or browser has been closed`。搜索仍返回 200 OK，但日志刷屏且存在孤儿 future。

### 根因
- `_call_search_api` 的 `finally` 调 `_unroute_search_api`，原实现用 `asyncio.wait_for(page.unroute(...), 2.5)` 包裹。
- 当页面在 route handler 仍在 `route.fetch()` 等响应时被并发关闭（`scheduler.run_once` 的 `close_all_pages` 或浏览器重启 `ensure_alive→close`），`page.unroute` 会等待在飞 handler；`wait_for` 超时**取消**内层 unroute → 连带取消 route 内部响应 future，使其带 `TargetClosedError` 且无人取回 → 触发告警。
- `close_all_pages` 已会跳过 `register_external_page` 注册的页面（live search 的 page 已注册），故真正杀页面的多为**整浏览器重启**（注册集合无法拦截）。

### 修复（src/xianyu_hunter/modules/collector/_search.py `_unroute_search_api`）
1. 关闭态短接：探测 `page.is_closed()` / `context.is_closed()` / `browser.is_connected()`，已关闭则直接 return，不调 unroute（避免超时与孤儿 future）。
2. 存活态用 `asyncio.shield` 包裹 unroute：`wait_for` 超时只取消外层等待、不取消内部 `unroute_task`，让其后台自然结束；`add_done_callback` 取回异常抑制 asyncio 告警；`except Exception` 兜底并发关闭。
- `py_compile` 通过，`asyncio` 已导入。全仓库仅此一处 `page.unroute`，修复已闭环。

### 备注
- 若后续仍偶发：根因是浏览器重启杀掉已注册外部 page，可考虑在 `ensure_alive`/restart 路径对 `_external_pages` 中的 page 做迁移/标记，但属更大改动，本次未做。

## XianyuHunter 全接口性能压测（jmeter-performance-test 技能）

### 目标
对系统全接口（排除外部依赖：浏览器/LLM）做全面压测：读扩展(66端点/Phase1-4) + 受控写(7端点)，含单 worker 基线、多 worker(--workers 4)对比、峰值(200c)，并出优化建议报告。

### 关键事实/口径
- 系统：FastAPI + SQLite(WAL, QueuePool pool_size=10) + ChromaDB；web 入口 `python -m xianyu_hunter web` 默认单 worker（无 --workers）；`web/deps.get_container()` 按 `XH_WITH_SCHEDULER` 决定 `with_browser` → 调度器关则无浏览器，适合纯压测。
- WEB_TOKEN 从 .env 取；JMX 用 `${__P(web_token,)}` 注入（-Jweb_token），不过硬编码密钥。
- 真实 ID：TASK_ID=t68bc149b, ITEM_ID=1054852225970, ORDER_ID=占位(orders表空→404容忍), TABLE=tasks, ERRORLOG_ID=1, SESSION_ID=7e749a355bcf435fb63155193f41024c。
- 测试服务：自建 web-only 实例 127.0.0.1:8011（用户 8001 生产实例不受影响）。
- 排除项（用户确认）：全部触发真实闲鱼浏览器/外部 LLM 的端点不测；写压测在 DB 备份副本上做（web() 无 db_path 覆盖，故用文件级 backup/restore 保原库）。

### 交付物（scripts/perf/）
- `gen_jmx.py`：生成 `xianyu_load_test_reads.jmx`(66读/4阶段) + `xianyu_load_test_writes.jmx`(7写)。HTTP 默认配置已改 `${__P(host,${HOST})}`/`${__P(port,${PORT})}` 以支持 -Jport 多实例复用。
- `monitor_resources.py`：按端口解析 PID，采样进程+系统 CPU/内存/线程/句柄 → CSV（依赖 psutil，已装进 .venv）。
- `analyze_jtl_comprehensive.py`：解析 JTL，按 label/阶段聚合（avg/p50/p90/p95/p99/吞吐/错误率），含 SLA 判定与瓶颈排序，输出 .summary.csv/.phases.csv/.report.md。
